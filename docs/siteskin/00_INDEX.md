프로젝트: **Site-Skin-edit** · 문서 체계의 약칭: **SiteSkin**  
문서 버전: **v0.1** · 작성일: **2026-09-09 (Asia/Seoul)**  
현재 단계: **참고 사례 조사 및 실행 규약 초안 작성 완료 / 실제 원본 인수 전**

## 1. 목적과 이번 범위

SiteSkin은 기존 사이트의 기능과 콘텐츠 구조를 보존하면서, 지정된 테마에 따라 이미지와 인터페이스를 일관되게 변경하는 작업 체계다. 전체 적용 뒤에도 ID를 지정해 일부만 수정하고, 승인·고정된 결과와 수동 수정 사항을 보존하는 것을 목표로 한다.

**확인됨:** 이번에 수행한 일은 작업공간 확인, 참고 페이지의 화면·리소스·일부 비거래 동작 조사, 이 네 문서 및 조사 근거 작성이다. 실제 테마 선택, 이미지 생성, 서비스 코드 변경, 패키지 설치, 외부 서비스 연결, 계정 변경, 배포는 수행하지 않았다. 이 문서들은 실행 프로그램이나 완성된 자동화 도구가 아니다.

**확인됨:** 작업 시작 시 `E:\codexwork\Site-Skin-edit`는 비어 있었다. 해당 폴더와 `E:\codexwork`, `E:\`에서 추가 `AGENTS.md`는 발견되지 않았다. 대화로 제공된 Global Codex Instructions 및 이번 작업 요청을 적용했다. 기존 프로젝트 코드·문서·사용자 변경 파일은 발견되지 않았으며 Git을 초기화하지 않았다.

## 3. 기록 상태의 공통 정의

| 상태 | 뜻 | 기록 조건 |
|---|---|---|
| **확인됨** | 실제 화면·동작·접근 가능한 자료로 확인한 사실 | 대상, 시점, 근거, 확인 범위를 연결한다. CSS 선언 확인과 실제 상태 표시 확인도 구분한다. |
| **제안** | SiteSkin을 위해 새로 정의한 규칙·설계·제작 권고 | 원래 사이트의 구현이나 도구의 지원 사양으로 서술하지 않는다. |
| **확인 필요** | 원본이나 추가 관찰이 있어야 결정할 항목 | 필요한 입력, 조사 방법, 반영 위치를 기록한다. 미확인을 실패나 부재로 바꾸지 않는다. |
| **해당 없음** | 조사한 대상·상태에서 적용되지 않음이 확인된 항목 | 적용되지 않는 범위를 명시한다. 조사하지 않은 상태에 사용하지 않는다. |

표 전체에 상태를 선언한 경우 그 상태가 모든 행에 적용된다. 한 행에 사실과 정책이 함께 있으면 각각 표시한다. 양식의 `<입력>`은 미작성 필드이며 확인된 값이 아니다.

문서 버전(v0.1), 향후 테마 버전, 개별 결과 버전, 실행 회차는 별개다. **생성됨 → 기술 검증됨 → 디자인 승인됨 → 적용됨 → 고정됨**은 서로 다른 기록이며 자동으로 승격하지 않는다. 이 다섯 항목은 상태 플래그로 별도 관리한다.

## 4. 예시와 실제 원본의 경계

참고 대상: [COBALT | P04 V4 서비스 로비](https://snake-eyes-cinematic-demo.kexxadrix.chatgpt.site/mockups/prototype-04-v4)

**확인됨:** 위 URL의 렌더링 결과, DOM, 현재 페이지에서 관찰한 리소스 URL, 배포 CSS를 조사했다. 로컬의 다른 프로젝트는 사용하지 않았다. 배포 CSS 사본은 분석 근거이며 편집할 원본 프로젝트가 아니다.

**확인 필요:** 프로그래머가 제공할 실제 사이트의 소스, 기준 버전, 실행 명령, 주요 페이지, 공통 컴포넌트, 스타일 구조, API 및 인증 연결, 지원 화면 크기, 테스트 방법. 예시 URL이나 배포 파일 이름은 이 항목들의 증거가 될 수 없다.

예시 ID는 `REF-A###`(영역), `REF-U###`(UI 후보), `REF-R###`(이미지 역할)로 구분한다. 실제 원본의 ID는 인수 후 별도 `SRC-` 이름 공간으로 부여한다. 세부 규칙은 [공통 작업 규약](01_WORK_RULES.md)의 추적 기록 항목에 있다.

## 6. 다음 단계의 시작 조건

**제안:** 아래 입력이 오면 먼저 원본 분석을 시작한다. 테마나 생성 도구 정보가 없더라도 원본 조사는 진행할 수 있다. 누락된 생성·적용 의존 단계만 보류한다.

1. 실제 소스 위치와 기준 버전, 대상 실행 URL 또는 실행 방법을 받는다.
2. 수정 허용 범위·보존 항목·기존 수동 수정 목록을 확인한다.
3. 주요 페이지와 상태, 지원 화면 크기, 검증 환경·명령을 확인한다.
4. 자료와 실행 대상의 관계를 검증하고 기준 파일·화면·기능을 기록한다.
5. 실제 원본 분석서를 작성한다. 기존 문서 체계가 없으면 `04_SOURCE_AUDIT.md`를 추가하는 방안을 사용한다(**제안, 현재 미생성**). 이번 `02_REFERENCE_AUDIT.md`는 참고 조사로 유지한다.
6. 원본 인수 항목별 조사 방법과 반영 위치는 [01_WORK_RULES.md](01_WORK_RULES.md)의 인수 표를 따른다. 실제 테마는 [03_THEME_TEMPLATE.md](03_THEME_TEMPLATE.md)를 채운 뒤 적용 범위를 확정한다.

이미지 생성·코드 적용·외부 서비스 사용·배포는 이번 문서 작성 요청의 권한에 포함되지 않는다. 이후 요청과 이미 부여된 권한을 기준으로 진행하며 불필요한 재승인을 요구하지 않는다.
