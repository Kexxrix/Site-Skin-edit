# 별도 GPT 감사·연구 작업에 전달할 내용

이 문서는 사용자가 계획한 역할 분할을 위한 의뢰문입니다. 이 문서를 작성했다는 사실만으로 새 작업이 생성되거나 기존 AE 제작이 중단되는 것은 아닙니다.

## 복사해서 전달할 의뢰문

```text
이 저장소는 진행 중인 TITAN 영상 제작의 백업이다.
목적은 지금 제작하는 원래 작업을 감사하고, 더 나은 표현·모션 제작 방법을 연구해서 그 작업에 실행 가능한 의견을 되돌리는 것이다. 다른 환경에서 영상을 다시 만드는 일이 아니다. 현재 제작은 계속 진행하는 것이 우선이다.

먼저 docs/video-production/README.ko.md, CURRENT-STATE.ko.md, HISTORY.ko.md, WORKFLOW-AND-LESSONS.ko.md, ASSET-CATALOG.ko.md를 읽어라. 이후 지적하려는 버전의 실제 프롬프트·지시서·AEP 구조 기록·MP4·QA를 확인해라. backup의 수집 시점과 파일 해시도 확인해라.

공식 AE 마커는 06 Sportsbook, 07 Operations/refined, 08 Sudden odds shift이며 기존 09 Bets auto-blocked는 결과 마커다. 과거 04-06 폴더 이름과 s04/s05/s06 키는 가이드 별칭이다. 최신 지시와 execution-status가 옛 중단 기록보다 우선한다.

현재 완료된 이전 검토본, 진행 중 저장본, 사용자 검토 통과, 최종 채택을 구분해라. 오래된 결과 보고의 pending 문구만 보고 최신 상태를 뒤집지 마라. 기술 검증을 읽었다면 본인이 직접 재생·실행했다고 쓰지 마라.

다음 세 관점으로 감사해라.
1. 의도·의미·구도: 원래 문구와 제품 설명, 기기·타이포 역할, 가독성, 장면 위계가 유지되는가.
2. 실제 동작: 정상 속도 MP4의 텐션, 연결, 이징, 원인과 결과, 정착·읽기 시간은 어떠한가. 프레임 번호와 파일을 근거로 제시해라.
3. 제작 방법: 네이티브 편집성, 실제 3D·영상 재질, 프리셋·표현식, Computer Use를 줄일 수 있는 지점, 검증의 빈틈을 점검해라.

THE BADDEST 같은 참조의 화면 관찰과 원작의 구현 추정을 분리해라. 정확한 소스·플러그인·자동화 경로는 확인된 1차 자료가 있을 때만 확정해라. 새로운 소프트웨어·라이브러리·API의 최신 지원·라이선스는 공식 자료로 확인하고 출처를 붙여라.

결과는 확인된 문제 / 개선 제안 / 미검증 가설 / 확인 필요로 구분해라. 지적마다 파일·버전·프레임·증거·사용자 의도와의 관계를 적고, 가장 작은 수정안과 부작용, 원래 작업에 보낼 구체 지시를 작성해라. 우선순위 높은 3건부터 제시하고, 추가 표현은 한 변수만 바꾼 짧은 비교 시험으로 제안해라.

기존 제작 파일·모델·영상·지시서는 수정하지 마라. 진행 중인 AE를 조작하거나 담당 작업을 중단시키지 마라. 전체 재설계나 새 표현을 이미 승인된 것처럼 채택하지 마라. 결과를 원래 작업에 돌려주어 사용자 지시와 함께 적용 여부를 결정하게 해라.
```

## 반환할 보고 형식

| 항목 | 필요한 내용 |
| --- | --- |
| 검토 대상 | 백업 커밋, 파일, 버전, 프레임/시간, 직접 열어 본 자료 |
| 판정 | 확인된 문제 / 제안 / 가설 / 확인 필요 / 해당 없음 |
| 근거 | 실제 관찰, 지시서와의 차이, 기술 로그. 추정은 별도 표기 |
| 영향 | 가독성·의미·연결·리듬·수정성·작업 방해 중 무엇에 영향을 주는지 |
| 최소 개선 | 변경할 대상·구간·속성. 보존해야 할 구간 |
| 확인 방법 | 수정 전후 정상 속도 비교, 프레임·설정·재열기 등 해당 검사 |
| 실행 지시 | 원래 제작 작업에 복사해 보낼 수 있는 짧고 구체적인 문장 |

각 제안에는 실제 시험 여부를 표시합니다. 한 번의 성공을 전체 자동화의 성공으로 확대하지 않고, 지적한 문제가 이미 최신 작업에서 수정됐는지도 먼저 확인합니다. 원래 제작은 백업 이후에도 진행하므로 원본 작업의 최신 완료 보고와 대조할 필요가 있습니다.
