# AE 제작 방식과 확인된 교훈

아래 내용은 이 프로젝트의 실행 결과에 한정합니다. 특정 기능을 지원한다는 사실을 해당 표현의 품질 검증과 동일하게 취급하지 않습니다. 상세 수치와 원본 로그는 [자료 목록](ASSET-CATALOG.ko.md)의 버전별 보고서를 참조하십시오.

## 실제 제작 경로

1. 사용자 카피·기능 의미·순서와 가이드의 역할을 먼저 정합니다. 읽는 문구와 배경 장식 타이포를 분리하고, 각 장면에서 다음 장면으로 넘길 선·도트·좌표·기기를 지정합니다.
2. 실제 프롬프트, 참조 이미지 역할, 생성 결과, 수정 이유를 같은 실행 폴더에 보관합니다. 생성 이미지가 통과해도 영상의 제어·자막 고정·UI 보존은 실제 MP4로 따로 확인합니다.
3. 구체 제작 지시서를 절대 프레임, 구간 경계, 이징, 시작·정착 자세, 화면 입력·재질, 검증 항목으로 작성합니다. 문서의 씬 묶음과 AE 마커를 명시적으로 매핑합니다.
4. AE의 현재 버전·열린 프로젝트·dirty 상태를 확인합니다. 필요한 보존본과 새 출력 경로를 만든 뒤 작업합니다. 이전 스크립트를 다시 실행하는 행위는 기존 프로젝트에 항목을 중복 추가할 수 있으므로 자동 재실행하지 않습니다.
5. MCP로 네이티브 Text/Shape/Null/Camera/GLB, 키프레임과 표현식을 구성합니다. 프리셋은 실제 적용 레이어와 CTI를 기록합니다. 모델 영상 재질의 메뉴 선택은 필요할 때 UI로 처리했습니다.
6. 실제 평가값·렌더 프레임·정상 속도 영상·저장 후 재열기를 확인합니다. 보고서에는 직접 확인한 내용, 담당 작업 보고로 확인한 내용, 아직 확인하지 못한 내용을 구분합니다.

## 이 환경에서 확인된 제어 범위

| 항목 | 근거와 범위 | 확대 해석하지 않을 것 |
| --- | --- | --- |
| 타이포·도형 | 네이티브 레이어, 문자별 등장, 마스크, 위치·스케일·회전, 기준선 및 밑줄을 구성 | 모든 단어의 자동 경로 모핑 |
| 키프레임·표현식 | 실제 AE 평가값과 목표 곡선 비교; 프레임 단위 정착·hold 확인 | 숫자 곡선 일치만으로 리듬·가독성 통과 |
| 실제 3D 기기 | GLB와 Camera/Null/환경을 사용, Advanced 3D 하위 컴프를 2D 마스터에 합성 | 평면 스크린샷에 기울기를 준 것과 혼동 |
| 움직이는 기기 화면 | Beta 27.0x43의 영상 레이어 재질 연결, 정면·사선·뒷면 가림, 저장 후 재열기 시험 | 재질 메뉴 선택까지 전부 MCP로 자동화됐다는 주장 |
| 프리셋 활용 | 첫 5.7초에 Adobe .ffx 3종을 7개 Text 레이어에 적용. 후속 v002에는 Adobe 적용·단축과 aftr wordReveal의 네이티브 이식·조정 기록이 추가됨 | aftr 패널 설치, 원형 Offset 동작의 동일 사용, Rebound 등 조사만 한 다른 라이브러리 채택 주장 |
| 참조 분석 | THE BADDEST의 일부 시점·연속 동작·공개 GIF 관찰 | 원작의 전체 AE/C4D 소스나 정확한 플러그인·키프레임을 알고 있다는 주장 |

작업 당시 MCP 구현 메모는 `@kumoproductions/mcp-aftereffects` 0.2.0을 대상으로 합니다. `batch`의 `stopOnError`는 원상복구 트랜잭션이 아니므로 중첩 실패·경고와 실제 상태를 확인해야 합니다. `eval`과 보안 설정 변경을 임의로 켜는 방식으로 진행하지 않았습니다. 안정적인 ID를 사용하고 오래된 레이어 인덱스에 의존하지 않습니다.

## 실패에서 확인한 것

| 관찰한 문제 | 수행한 대응 | 아직 단정할 수 없는 것 |
| --- | --- | --- |
| 생성형 영상에서 글자·작은 UI가 변하거나 문구가 화면에 남은 채 복제 글자만 움직임 | 원래 요소의 동작인지 추가 장식인지 분리해 검토, 실제 퇴장·복귀와 읽기 구간 평가 | 모든 생성형 영상 도구의 보편적 한계 |
| 고정·정지·확대량 지시와 실제 영상이 다름 | 전체 프레임 움직임과 표본 시각 검수를 함께 기록 | 강한 프롬프트 문장만으로 정밀 제어가 해결됨 |
| 초기 AE 두 컷에서 밑줄 레이어가 사라짐 | 실패 AEP 보존, 별도 v002에서 밑줄만 복원, 마지막 hold 재검사 | 사용자의 수동 조작이나 특정 도구를 원인으로 확정 |
| 3D 모델에 삼각형 형태의 렌더 이상 | AE 장면 원점·카메라 거리·스케일을 조정하고 모델은 보존 | 깊이 정밀도가 유일한 확정 원인 |
| 영상 재질 연결 직후 회색 화면 | 실제 연결·재열기·렌더를 비교하고 Save/Reopen으로 회복 확인 | 모든 회색 화면이 같은 원인이라는 주장 |
| 8초 테스트의 텐션·연결이 약함 | 사용자의 성공 판정과 개선 의견을 함께 기록, 후속 본 제작의 짧은 시간표에 반영 | 늘린 테스트 길이만이 유일한 원인 |
| 같은 경로 AEP의 크기·해시가 기존 보고와 다름 | 현재본과 미저장본 보존, 구조·프레임 비교 후 새 버전 제작 | 바이트 차이가 반드시 화면 변화 또는 손상을 뜻함 |
| 가이드 묶음 번호와 AE 마커 혼선 | 사용자 스크린샷·기존 마커로 06/07/08 확정, 지시서·JSON·전달 기록 정정 | 옛 파일명을 보고 마커를 다시 추론 |

## 필요한 품질 판단

- **가독성:** 안정 구간에서 철자·기준선·커닝·글자 구멍이 정상이고 실제 표시 크기에서 읽히는지 봅니다. 배경 도형이 본문을 가리는지 별도로 확인합니다.
- **동작 연결:** 앞 장면의 위치·방향·속도가 다음 장면에서 이어지는지 봅니다. 큰 이동, 분해, 회전을 동시에 넣을 경우 주동작이 무엇인지 판단합니다.
- **기능 의미:** `Sudden odds shift`는 특정 상승·하락만 뜻하지 않습니다. 한도 변경은 다음 라운드 적용, 수익금은 자동 계산·기록이며 지급 완료로 바꾸지 않습니다.
- **3D와 화면:** 실제 기기의 정면·사선·뒷면, 앞뒤 가림, 스크린 비율·방향, 영상 진행과 시간 구간을 확인합니다. GLB 내부 축 설명과 실제 AE 가져오기 결과를 비교합니다.
- **시간:** 절대 마스터 프레임과 하위 컴프 프레임을 구분합니다. 30fps에서 N프레임 길이는 N÷30초이고, 마지막 프레임 시각은 (N−1)÷30초입니다.
- **원본 보존:** 원본 파일 해시, 기존 네이티브 항목, 지정 보호 구간의 평가값·픽셀을 비교합니다. GPU 3D의 미세한 비결정적 픽셀 차이는 수치와 위치를 보고하되 자동으로 완전 동일 판정을 하지 않습니다.
- **실제 재생:** 표본 프레임으로 구도는 볼 수 있지만 전체 정상 속도 동작과 텐션을 대체하지 못합니다. 재생을 했는지, 일부만 봤는지, 보고서를 읽었는지 구분합니다.

## 이후 연구할 가치가 있는 질문

아래는 새로 검증할 과제이며 현재 제작을 변경하는 지시가 아닙니다.

1. 글자·밑줄·도트·슬라이더·기기 테두리의 공통 접점을 이용해 장면 전환을 더 자연스럽게 만들 수 있는가.
2. 현재 시간표에서 읽기 시간과 큰 액션의 비율을 어떻게 조정하면 강약이 좋아지는가.
3. 네이티브 Text를 유지할 구간과 파생 Shape가 필요한 한두 획 변형을 어떻게 분리하는가.
4. 현재 Beta에서 영상 재질 선택을 줄일 재사용 구조가 있는가. 공개 문서와 실제 제어 경로를 확인하고, 테스트하지 않은 API를 존재한다고 가정하지 않는가.
5. 실제 MP4를 기준으로 위계·연결·리듬의 개선을 비교할 수 있는 최소 시험은 무엇인가.

기존 표현 연구와 무료 리소스 조사는 [상세 이력](HISTORY.ko.md)에 연결돼 있습니다. 외부 자료의 라이선스·버전은 도입 시점에 다시 확인해야 하며, 설치된 Adobe 상용 프리셋 자체를 이 백업에 재배포하지 않습니다.
