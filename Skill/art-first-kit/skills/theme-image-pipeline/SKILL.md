# Theme Image Pipeline

최우선 결과물은 한 테마의 일관된 이미지다. 사이트는 요청된 경우 이미지 배치를 확인하는 후속 단계이며, 사이트 스펙·Figma·캐릭터를 이미지 생성의 필수 입력으로 요구하지 않는다.

## 현재 실행 기본값

- **Codex 내장 이미지 생성 도구**를 사용한다. 기존 GPT 웹 대화를 열거나 새 GPT 스레드를 만들지 않는다. API 키·별도 이미지 서비스도 요구하지 않는다. 사용자가 다른 경로 또는 프롬프트만을 요청하면 그 지시를 따른다.
- 현재 환경의 내장 이미지 생성 도구와 이미지 스킬이 있으면 그 사용법을 따른다. 없으면 해당 실행만 불가하다고 알리고 프롬프트·참조 목록을 보존한다. 웹으로 자동 전환하지 않는다.
- 한 호출에 독립 이미지 한 장. 사용자가 5장을 요청하면 5개 결과를 만든다. 과거의 10장 랜덤 뽑기를 모든 역할의 기본값으로 재적용하지 않는다. 콜라주를 여러 장으로 세지 않는다.
- 참조는 실제 이미지로 확인하고 첨부한다. 로컬 경로가 있는 참조는 경로 첨부 기능을 사용하고 프롬프트에 첨부 순서·상속 역할을 명시한다. 프롬프트에 파일명만 적는 것은 첨부가 아니다.
- 생성 완료 후 도구가 반환한 실제 파일·형식·크기를 검증한다. 저장 경로는 사용자가 지정한 위치가 우선이며, 이 사용자 환경에서는 `D:/WebDL`이 있으면 그 아래 새 작업 폴더, 없으면 프로젝트 `artifacts/<run-id>`를 사용한다.
- 매번 이번 결과만 별도 이름으로 보존한다. 기존 생성·원본·선택본을 덮어쓰지 않는다. 도구의 저장 위치와 최종 저장 위치, 이동/복사 여부를 기록한다.

## 시작과 재개

최소 입력: 테마, 필요한 이미지 역할과 수량. 브랜드 문구가 필요하면 정확한 표기를 확보한다. 팔레트·소재가 없으면 테마에 맞는 제안으로 정하되 사용자 요구와 구분한다. 전체 이미지 세트 제작을 맡겼다면 허용된 범위에서 선택·검수를 진행하고 모든 단계마다 승인을 다시 요구하지 않는다.

[실행 기록 템플릿](assets/run.template.json)을 새 작업 폴더에 복사해 실제 값으로 채운다. 이 기록은 재개용이며 스케줄러나 무인 실행 서비스가 아니다.

- 기존 기준이 있으면 실제 경로·내용·승인 상태를 확인하고 그 단계부터 재개한다.
- `generated`, `qa_pass`, `selected_by_agent`, `accepted_by_user`, `adopted`를 구분한다. 사용자가 맡긴 선택은 `selected_by_agent`로 진행할 수 있지만 사용자 승인으로 꾸미지 않는다.
- 사용자가 직접 선택·편집하기로 한 지점은 그 결과를 기다린다. 이미 승인된 결과를 다시 승인받지 않는다.
- 생성 중 중복 제출하지 않는다. 실패나 타임아웃은 실패 이유와 마지막 상태를 기록한다. 명시된 예산이 없으면 같은 결함의 수정 재생성은 한 번 비교 후 남은 문제를 보고하며 무한 재시도하지 않는다. 원래 요청한 나머지 독립 결과는 계속 수행할 수 있다.

## 제작 순서

1. **컨셉 → 배경:** 텍스트만으로 시작 가능. 분위기·세계관·소재·조명을 먼저 정한다. 컨셉 이미지가 실제 배경 용도에 맞으면 같은 결과를 채택하고 중복 생성하지 않는다. 카지노 서비스여도 테이블·슬롯 같은 소품은 요청된 경우에만 넣는다.
2. **선택적 캐릭터:** 필요할 때만 생성. 배경과 카메라·광원·색온도·배치가 맞아야 한다. 특정 인물·의상을 반복할 때는 [인물 공정](references/character-workflow.md)을 읽는다.
3. **공유 시각 규칙:** 선택된 배경/컨셉과 사용 중인 캐릭터에서 팔레트·소재·명암·광원·입체감·장식 밀도를 짧은 텍스트로 기록한다. 얼굴이나 의상 장식을 모든 UI의 필수 모티브로 확대하지 않는다.
4. **요청된 UI 역할:** 헤더 글자 로고와 메인 로고를 구분한다. 그 뒤 타이틀 패널 → GNB 패널 → 개별 아이콘을 필요한 순서로 생성한다. 준비된 역할은 건너뛴다. 각 결과의 다음 참조 사용 여부를 명확히 선택한다.
5. **실사용 후처리:** [편집·검수](references/editing-and-qa.md)에 따라 투명 처리, 지각적 크롭, 3슬라이스를 필요한 에셋에 적용한다. 배경 전체에 자동으로 투명 제거를 하지 않는다.
6. **납품:** 원본, 후처리본, 실제 프롬프트, 참조 순서와 해시, 검수 결과를 저장한다. 사이트 적용은 요청된 경우만 수행하고 사이트 스타일링 전에 `$site-font-setup`을 적용한다.

일반 이미지와 UI의 구체적 프롬프트는 [테마·에셋 템플릿](references/theme-and-ui-prompts.md)을 사용한다. 연속 UI 에셋은 가장 가까운 선택된 부모를 주 참조로, 컨셉/배경은 필요한 분위기 정보만 보조 참조로 사용한다. 다른 아이콘의 의미나 패널 전체 형태를 아이콘에 복제하지 않는다.

## 품질과 검증 범위

실제 표시 크기에서 실루엣·라벨 공간·대비를 확인한다. 생성 성공은 채택 성공이 아니다. 모델 내부 버전이나 웹과의 보편적 품질 동일성을 추정하지 않는다. 이 패키지의 [검증 이력](references/provenance.md)은 성공 사례와 남은 한계를 분리한다.

역할별 필수 검수:
- 배경: 테마 전달, 화면에서 실제로 보이는 영역, UI를 놓을 여유.
- 인물: 정체성, 상체 체형, 전신 비례, 의상, 몸통·고개·눈, 프레임 잘림, 바닥 접점을 각각 확인.
- 로고: 정확한 한글·숫자·영문 표기, 헤더에서의 판독성.
- 패널: 타이틀용과 버튼용 장식 비중 구분, 끝 장식 보존, 절단면.
- 아이콘: 한 이미지에 한 의미, 세트의 재질·광원·시점 일관성, 실제 메뉴 크기에서의 적정 비중.
