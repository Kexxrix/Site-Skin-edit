# ALDEBARAN R15 적용 지침 — 기존 운영 문서에 병합

## 범위와 우선순위

이번 작업은 R15-01~05를 한 번에 적용하는 것이다. 최신 현지 소스와 사용자의 직접 수정 사항을 출발점으로 삼는다. 과거 버전 reset, R12~R14 패키지 재적용, 다른 사이트 이식은 하지 않는다.

운영 문서는 기존 AGENTS.md / STATE.md / DESIGN_SPEC.md / DECISIONS.md 네 개를 유지하고 이 변경분을 병합한다. resources의 조사 문서는 보조 근거이고, 이번 적용 사양과 충돌하면 DESIGN_SPEC.md의 명시적인 변경분을 따른다. 현지 상위 지침과 권한을 우회하지 않는다.

R14의 작업 범위 ‘두 개만’, 마켓 데이터/계산 보존 조건은 그 당시 작업에 한정된다. 이번에는 경기 데이터와 마켓 구성·숫자 집계를 변경하도록 사용자가 지시했다. 버튼의 시각 표현과 이전 완료 UI는 보존한다.

## 구현 원칙

- sports-demo-03 안에서 최소 변경한다. 공통 전역 CSS 변경으로 MERCURY·SIRIUS·타이탄에 영향을 주지 않는다.
- 앱 진입점·현재 데이터 생성부·선택 ID·마켓 renderer·슬립 연결을 먼저 확인한다. 이 패키지의 데이터 구조를 새 프레임워크로 강제하지 말고 현지 구조에 매핑한다.
- UI 변경은 지정된 버튼·계정 패널·중앙 텍스트로 한정한다. 디자인 전면 재설계나 새 반응형을 만들지 않는다.
- 경기 수는 fixture 목록, N+는 상세 마켓 목록에서 계산한다. 표시 숫자를 별도 상수·난수로 두지 않는다.
- 새 야구 경기는 야구 팀·이닝·런라인·야구 기준값을 가진 독립 데이터다. 기존 NFL을 이름만 바꾸어 재활용하지 않는다.
- 마켓 카탈로그는 구현 후보 목록이다. 반복 렌더링으로 개수를 채우지 말고 질문·구간·대상·기준값의 차이를 가진 항목을 구현한다. 적용 가능한 계열을 예시 몇 개만 만들고 끝내지 않는다.
- 경기별 프로필은 재현 가능해야 한다. 렌더링 때마다 배당이나 마켓 수가 변하는 Math.random은 사용하지 않는다.
- 실시간 배당 피드·최신 경기·선수 명단을 연동했다고 허위로 표시하지 않는다. 기존 합성 데모 성격을 유지한다. 선수는 확인된 명단과 소속이 있는 경우에 적용하며, 명단 부족으로 나머지 마켓 확장을 막지 않는다.
- 각 신규 선택은 현재 슬립에 경기·마켓·구간·대상·기준값이 정확히 연결되어야 한다. 새 마켓 유형을 모두 기존 ‘기타’ 문구 하나로 저장하지 않는다.
- 기존 베팅 조합 제한과 같은 경기 선택 규칙을 보존한다. 새 SGP나 정산 엔진·실거래 제출 기능은 만들지 않는다.
- 변하지 않는 경기/선택의 ID와 저장 상태를 최대한 보존한다. 삭제·교체된 경기의 오래된 선택은 현재 유효 ID로 검증해 제거/무효 처리하며 계정·전체 저장소를 초기화하지 않는다.
- 중앙 웨이트 감량은 원래 resolved font-weight에서 정확히 한 번 적용한다. 실제 배당과 N+는 의미 기준으로 보호한다. 전역 lighter, 중복 감소, 임의 폰트 교체는 하지 않는다.
- 계정 캡처의 GUEST·LV·금액은 레이아웃 참고 값이다. 실제 계정 데이터나 잔액을 이 값으로 바꾸지 않는다.

## 진행 순서

1. 최신 현지 문서/소스/미커밋 변경을 확인하고 이번 5개 변경분을 병합한다.
2. 61경기 데이터와 종목 분류를 맞춘다. 배구 0의 빈 상태를 연결한다.
3. 현지 마켓 모델을 확장해 종목별 유형과 경기별 제공 프로필을 적용한다. 같은 데이터로 N+·필터·상세·슬립을 연결한다.
4. 베팅하기 색상·우측 계정 패널·중앙 웨이트를 적용한다. 신규 마켓에도 같은 텍스트 규칙을 사용한다.
5. 아래의 한정 검증과 기존 build를 마친 후 기존 주소에 기존 방식으로 반영한다. 보고서에 실제 결과와 제외 사유를 기록한다.

## 한정 검증

UI 색/배치 변경을 위해 새 테스트 체계를 만들지 않는다. 데이터 개수·ID·배당 유효성·마켓 유형·슬립 연결은 이번 변경의 실제 위험이므로 기존 검증 도구나 작은 데이터 검사로 확인한다.

모든 61경기의 개수/ID 검증, 종목별 대표 2경기의 상세·선택 연결, 3자리 N+·다중 선택지·장문 이름을 확인한다. 웨이트는 실제 계산값 전후와 시각 결과를 함께 본다. 이후 기존 build 1회와 build에 포함되지 않은 현지 필수 타입 검사만 수행하며, 실패 해결에 필요한 경우에만 반복한다.

기존 로컬 미리보기 우선, 1920×1080/브라우저 100%로 확인한다. 로컬 검증 후 기존 동일 주소에 기존 배포 흐름을 사용한다. 배포 접근이나 연결이 없으면 가능한 로컬 구현·검증을 끝내고 해당 장애만 보고한다. 새 프로젝트를 만들어 대체하지 않는다.

실제 계정 생성, 충전/환전/베팅 제출은 검증에 포함하지 않는다. 기존 데모 동작은 보존한다. 독립 감사 스레드·Jev·새 플러그인/의존성·WOG 재참조·GitHub 백업 작업을 추가하지 않는다.
