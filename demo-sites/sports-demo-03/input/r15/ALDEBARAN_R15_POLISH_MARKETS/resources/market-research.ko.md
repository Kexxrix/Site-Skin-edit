# ALDEBARAN — 추가 마켓 조사 및 구현 기준

조사일: 2026-09-23. 상태: 조사·설계 자료 작성 완료, 사이트 적용 전.

## 결론

현재의 종목별 고정 숫자를 없애고, 경기마다 제공하는 실제 상세 마켓 구성에서 숫자를 계산한다. 경기·팀·구간·기준 라인을 조합하면 선수 마켓 없이도 축구 50개 이상을 구성할 수 있다. 선수 명단이 있는 주요 경기에는 선수 기록 마켓을 더한다.

공식 운영사 자료로 마켓 계열의 존재를 확인했다. 아래의 템플릿 분류, 적용 구간 조합, 구현 목표 수량은 ALDEBARAN 데모를 위한 설계안이다. 특정 사이트의 현재 경기별 평균 수량이나 모든 경기의 제공 목록을 실측한 결과가 아니다. 공식 규정의 전체 문장을 복제하거나 여러 회사의 정산 규정을 하나로 합치지 않았다.

수량은 아래 정의의 ‘개별 마켓’ 기준이다. 모든 경기의 할당량이나 반드시 채워야 하는 최솟값이 아니다. 지원 데이터가 적은 친선·프리시즌 경기는 더 적게 제공한다. 높은 숫자를 먼저 배정하고 내용을 복제해서 채우지 않는다. 구현 완료 후 실제 생성 결과를 집계한다.

## 숫자의 의미를 고정

- **마켓 계열:** 핸디캡, 총 득점, 선수 득점 같은 유형.
- **개별 마켓:** 한 경기의 특정 구간·대상·기준값으로 정의된 하나의 질문.
- **선택지:** 그 질문에 대한 홈/무/원정, 언더/오버 등의 답.
- **화면 그룹:** 같은 유형을 묶는 아코디언. 그룹 수와 개별 마켓 수는 다르다.

예: 핸디캡 5개 라인 × 각 2개 선택지는 **5개 마켓 / 10개 선택지**다. 정확한 스코어 20개 선택지는 **1개 마켓**이다. 선수 6명의 독립적인 득점 O/U는 **6개 마켓 / 12개 선택지**다.

버튼은 기존 `N+` 모양을 유지한다. N은 해당 경기의 **상세 화면 전체 제공 마켓 수**로 정의하며, 미리보기에서 노출한 기본 마켓도 한 번만 포함한다. 접근성 설명은 ‘전체 마켓 N개 보기’로 맞춘다. +는 상세 진입 표식이다. 현재 선택된 ‘핸디캡’ 필터나 아코디언 접힘 여부로 N이 바뀌면 안 된다.

동일한 정규화 배열로 상세 화면과 숫자를 생성한다. 렌더링 가능한 유효 배당과 선택지 구조를 가진 마켓만 집계한다. 상세가 없는 숫자, 숨긴 준비중 마켓, 빈 선수 목록, 같은 마켓의 미리보기 복제는 제외한다. 정지 상태를 도입한다면 제공 수와 클릭 가능 수의 정책을 별도로 명시한다. 이번 데모 기본 집계는 활성 마켓 기준이다.

동일 구간의 무승부 환불/아시안 핸디캡 0, 첫 이닝 득점 유무/첫 이닝 0.5 O/U, 선수 2개 이상/1.5 오버 등 동일 조건의 별칭을 중복 집계하지 않는다.

## 선수 없이 축구 68개를 만드는 설계 예시

| 구성 | 실제 마켓 수 |
| --- | ---: |
| 전체 승무패·더블찬스·무승부 환불 | 3 |
| 전체 아시안 핸디캡 7라인·3방향 핸디캡 3라인 | 10 |
| 전체 총 득점 7라인·팀 득점 각 3라인 | 13 |
| 전체 양팀 득점·정확한 스코어·정확한 총 득점·홀짝·전반/최종 | 5 |
| 전반: 승무패 1 + 핸디캡 3 + 총 득점 3 + 팀 득점 각 1 + 양팀 득점 1 | 10 |
| 후반: 위와 같은 구조 | 10 |
| 전체 코너: 총합 3 + 핸디캡 3 + 팀별 각 1 | 8 |
| 전체 카드: 총합 3 + 팀별 각 1 + 퇴장 여부 1 | 6 |
| 팀 무실점 각 1 + 선제 득점 팀 1 | 3 |
| **합계** | **68** |

숫자는 계산 가능한 구성 예시다. 모든 경기에 이 68개 세트를 그대로 복제하지 않는다. 아시안 핸디캡 7라인에는 위에서 별도 표시한 무승부 환불과 중복되는 0라인을 넣지 않는다. 선수 또는 고급 기록 지원이 없더라도 이 정도의 상세 분량을 만드는 방향이다.

## 템플릿 목록 읽는 법

아래 한 행은 재사용 가능한 마켓 계열이며, 버튼의 개별 마켓 1개를 뜻하지 않는다. 구간·팀·선수·기준 라인의 조합 중 실제 구현·가격 생성·화면 표시가 가능한 것만 생성한다. ‘전체’의 연장 포함 여부는 종목별 정산 범위와 함께 저장한다. 선수 선택 목록 하나와 선수별 독립 질문을 혼동하지 않는다.

출처는 해당 마켓 계열의 참고 근거다. 제안한 모든 구간 조합을 해당 운영사가 항상 판매한다는 뜻은 아니다.

## 경기마다 다르게 만드는 규칙

1. 경기별 설정에 리그 형식, 정규/친선/프리시즌, 통계 지원, 선수 명단, 선발투수/골리, 제공 프로필을 저장한다. 이 자료의 목표 구간을 실제 사이트 평균으로 쓰지 않는다.
2. 기본·확장·선수 포함 프로필을 지원 조건에 맞춰 배정한다. 같은 종목 안에서도 코너/카드 제공 여부, 하프/쿼터 제공 범위, 대체 라인 개수, 선수 수와 기록 종류가 달라지게 한다.
3. 라인은 경기별 중심값 주변으로 생성한다. 모든 축구를 2.5, 모든 농구를 218.5로 고정하지 않는다. 기존 배당 모델과 동일한 경기 파라미터를 이용한다.
4. 데이터가 없어도 임의 선수 이름이나 실제와 다른 소속을 만들어 채우지 않는다. 검증한 명단을 스냅샷으로 사용하거나 해당 선수 마켓을 제외한다. 선수 조건 때문에 경기·팀 마켓 확장을 보류하지 않는다.
5. 데모의 추가 변주는 fixture ID와 버전으로 재현 가능하게 만든다. 렌더링 중 Math.random으로 수량·배당을 바꾸지 않는다. 같은 숫자가 자연스럽게 겹치는 것은 허용한다. 모든 경기 수를 억지로 다르게 만들 필요는 없다.
6. 마지막에 실제 생성 배열에서 N을 계산한다. 목표 수량이 미달하더라도 빈 행·중복 항목으로 메우지 않고, 구현 보고서에 이유와 실제 수량을 기록한다.

## 종목별 정확성

- 축구: 일반 전체 마켓은 정규시간+추가시간을 기준으로 설계한다. 연장전·승부차기·진출 마켓을 같은 범위로 섞지 않는다. 카드 개수와 카드 포인트를 구별하고 집계 규칙을 명시한다.
- 농구: 리그의 하프/쿼터 형식을 반영한다. 전체·후반·4쿼터의 연장 포함 정책은 운영사마다 마켓 예외가 있으므로 전역 추정으로 처리하지 않는다. 선택한 데모 규칙을 제목·메타데이터에 일치시킨다.
- 야구: 첫 5이닝과 단일 5회는 다른 마켓이다. 초·말은 공격팀에 귀속한다. 승패 2방향의 동점 환불과 3방향 승무패를 구분한다. 총 루타는 총 출루나 도루가 아니다. 선발투수 변경/선발 타순 전제도 메타데이터로 남긴다.
- 하키: 정규 60분 승무패와 연장·슛아웃 포함 승패를 분리한다. 팀 스코어에 반영하는 슛아웃 결과와 선수 개인 골 통계를 같은 방식으로 취급하지 않는다. 1~3피리어드에 농구의 ‘쿼터’ 라벨을 재사용하지 않는다.

공식 규정은 회사·마켓별로 다르다. 본 자료는 실제 서비스 정산 약관이나 정산 엔진을 완성한 문서가 아니다. 데모에서도 범위가 불명확한 마켓은 표시 전에 규칙을 결정한다.

## 배당과 데이터 구조

각 마켓에 fixtureId, canonicalType, period, settlementScope, subjectId, line, variant, displayGroup, status, selections를 갖춘다. 각 선택지는 고유 ID와 라벨·배당을 갖는다. 동일 조건은 같은 ID를 재사용하여 목록/상세/슬립의 선택이 연결되게 한다.

현재 데모의 합성 배당 구조를 확장한다. 조사한 사이트의 실시간 배당을 수집·연동했다는 표현은 하지 않는다. 대체 라인의 난도가 올라가면 같은 방향 배당도 자연스럽게 변해야 한다. 같은 경기의 기본 승패·핸디캡·총점·팀 총점은 같은 모델에서 나오게 한다. 복합 기록이나 결과 조합의 배당을 독립 확률의 단순 곱으로 임의 생성하지 않는다. 지원할 수 없는 유형은 템플릿 후보로 남기고 노출·집계에서 제외한다.

## 화면 적용

- 왼쪽 경기 카드의 대표 배당 3줄과 프레임은 유지한다. 상세 마켓의 확장은 오른쪽 영역에 적용한다.
- 기존 전체/승무패/핸디캡/언더·오버/기타 필터 체계를 우선 유지한다. 승패는 승무패 계열로 묶고 기타는 득점·코너·카드·선수 등 이름 있는 아코디언으로 구분한다.
- 2방향, 3방향, 예/아니오, 스코어 다중 선택지, 선수별 목록을 지원한다. 모든 마켓을 홈/원정 두 칸으로 억지로 렌더링하지 않는다.
- 같은 유형의 여러 라인은 한 카드 안에 묶는다. 150개 마켓을 150개의 외곽 박스로 만들지 않는다. 내부 카드 스타일과 1px 주황 포인트를 유지한다.
- 기본 3~5개 그룹은 펼치고 나머지는 접는 방식으로 분량을 관리할 수 있다. 접힌 항목도 열면 실제 내용이 있어야 한다. 독립 스크롤을 유지한다.
- `99+`, `100+`, `188+`도 기존 내용 기반 폭으로 중앙 정렬한다. 배당 청녹색과 숫자+ 라벨의 기존 웨이트는 앞서 합의한 폰트 감량 대상에서 제외한다.
- 상세에 진입한 경기와 왼쪽 선택 경기의 제목·ID·마켓·슬립 대상이 같아야 한다. 신규 마켓은 실제로 선택/해제되고 슬립에 정확한 구간·기준값이 표시되어야 한다.

## 이번 확장에 포함하지 않는 것

시즌 우승·장기 선수상 등 단일 경기와 무관한 항목은 경기별 숫자에 넣지 않는다. ‘다음 공’, ‘다음 타석’, ‘다음 공격’처럼 진행 상황이 필요한 인플레이 전용 유형도 현재 프리매치 수량에 섞지 않는다. SGP/벳빌더는 조합 기능이므로 가능한 모든 조합을 별도 마켓으로 만들어 수량을 부풀리지 않는다.

## 기존 피드백과 함께 적용할 때의 연결점

- R14 숫자+ 버튼과 새 배너 6장 반영은 사용자가 완료 확인했다. 최신 기준으로 보존한다.
- 경기 수는 축구 32 + 농구 6 + 야구 16 + 배구 0 + 아이스하키 7 = 전체 61 구성을 제안한 상태다. 실제 fixture 목록과 종목 탭을 같은 데이터에서 집계한다.
- 이전 데이터에 NFL 16경기가 남아 있다면 이름만 야구로 바꾸지 않는다. 야구 팀·경기·마켓을 가진 새 데이터로 교체하고 오래된 저장 선택을 안전하게 처리한다.
- 베팅하기 버튼 노랑, 우측 계정 패널 정리, 중앙 일반 텍스트 웨이트 한 단계 감량은 별도 누적 피드백이다. 이번 파일은 추가 마켓 조사 자료이며 전체 다음 차수 UI 작업지시서를 대신하지 않는다.

## 완료 판정에 필요한 확인

1. 모든 61경기에 대해 종목·마켓 수·선택지 수·제공 프로필을 집계한 표를 출력한다. 종목 합계 61, 배구 실제 데이터 0을 확인한다.
2. 버튼 N과 해당 경기의 고유 활성 상세 마켓 수가 일치하는지 전체 데이터로 검증한다. 아코디언 개수나 배당 버튼 개수로 잘못 집계하지 않았는지 확인한다.
3. 중복 ID, 다른 종목 구간, 빈 선택지, NaN/무한대/유효 범위 밖 배당, 별칭 중복을 검증한다.
4. 종목당 서로 다른 제공 프로필의 경기 2개 정도를 열어 구성 차이·필터·슬립 동작을 확인한다. 야구 첫 5이닝, 하키 정규/연장 구분, 농구 쿼터, 축구 코너/카드를 포함한다.
5. 3자리 숫자+와 긴 선수명·다중 선택지에서 1920 레이아웃·독립 스크롤이 유지되는지 확인한다. 숫자만 바꾸고 상세가 기존 10개에 머무르면 미완료다.
