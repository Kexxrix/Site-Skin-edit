사용자 결정
지금까지 세 사이트가 실제 제품처럼 보이지 않는다는 피드백을 받았다. 이번에는 WOG 해외형 스포츠의 요소 종류·순서·배치·정보 밀도·폰트 크기·버튼 크기·패널 크기·스크롤 구조를 구체적으로 이식한다. 새로 미적 구성을 발명하지 않는다. ALDEBARAN의 레터링 로고, 무광 차콜 표면, 플랫 버튼, 주황 강조, 흰색 계열 글자와 아이콘은 유지한다.

이번 범위는 ALDEBARAN 전체 화면이다.
1. 10개 헤더 메뉴, NEW/LIVE 배지, 활성/hover 아이콘, 우측 계정 버튼.
2. 헤더 아래 움직이는 공지 한 줄 + 우측 아이콘/텍스트 메뉴 5개.
3. 좌측: 12개 퀵메뉴, 카지노/슬롯 이미지 2개, 검색 2줄, 종목/국가/리그 목록, 최신 인기 경기.
4. 중앙: 왼쪽 종목 탭 + 리그별 경기/기본 배당 카드, 오른쪽 선택 경기 제목 + 5개 마켓 필터 + 상세 배당 패널. 두 목록은 독립 스크롤.
5. 우측: 계정 정보, 6개 서비스 버튼, 슬립 유지/전체 삭제/폴더 상태, 빈 슬립과 선택 슬립, 금액/빠른 금액, 배당·예상금·한도, 베팅 버튼, 하단 배너 6개.

1920 고정 기준
body grid = 8 + 320 + 10 + 1244 + 10 + 320 + 8 = 1920.
중앙 외곽 패딩/테두리를 포함한 내부 두 패널 = 609 + 8 + 609.
기존 272px 좌측 레일, 1280px 중앙, 632/16/632 및 104px 비대칭 헤더를 유지하라는 과거 지시는 이번 전체 이식 범위에서 대체한다.
헤더 62px + 공지 36px = 98px. 중앙 본문 시작 y=105, 패널 시작 y=114.
1363px 브라우저에서 측정한 카드 폭을 목표 폭으로 복사하지 않는다. reference의 관측치와 implementation/layout-contract.json의 1920 목표치를 구분한다.
첨부 참조 PNG의 실제 크기는 1916×941이며, 정확히 1920 캡처했다고 표시하지 않는다. 1920 목표는 공개 CSS의 데스크톱 규칙으로 산출했다.

이전 트래커 우선 배치/축구만 노출 시도는 이번 기본 해외형 화면에 적용하지 않는다. 기본 화면은 여러 종목의 경기 목록과 상세 마켓이다. 기존 트래커 코드는 남겨도 되지만 이 페이지의 첫 화면에 큰 트래커나 빈 트래커 자리를 넣지 않는다.

읽기 순서
START_HERE → AGENTS → DESIGN_SPEC → implementation/layout-contract.json → implementation/ui-inventory.json.
STATE는 최신 현지 완료 기록과 병합. DECISIONS는 결정 사유.
styles/aldebaran-wog-r5.css와 implementation/AldebaranWogShell.tsx는 치수/스크롤 연결용 시작 코드다. 전체 사이트 구현 완료본이 아니다. 실제 데이터·버튼·슬립·모달은 현지 앱에 연결해야 한다.
reference/components.csv는 필요한 요소만 찾을 때 읽는다. 원본 CSS 전체를 재탐색하거나 WOG에 다시 로그인할 필요가 없도록 수치를 정리했다.

실행
최신 현지 소스의 경기 데이터·마켓·슬립·자산·배포 연결을 재사용한다. 전체 게임/금융 백엔드를 새로 만들지 않는다. 누락 메뉴의 클릭 결과는 implementation/behavior-contract.json에 따라 실제 내용이 있는 데모 패널/모달로 연결한다. WOG 링크로 사용자를 보내지 않는다.
MERCURY/SIRIUS는 수정하지 않는다. 문서 4개는 변경분 병합이며 기존 기록 덮어쓰기 금지.
별도 QA 스레드/Jev/전체 polish/새 설치는 하지 않는다. 기존 빌드 1회와 변경 동작의 짧은 확인 후 기존 ALDEBARAN 주소에 배포한다. 1920 초기 화면 1장, 핵심 변경과 미완료 항목, 실제 commit/deployment ID를 짧게 보고하고 사용자 피드백을 기다린다.

이 자료 작성 단계에서는 실제 Windows 앱을 수정·빌드·배포하지 않았다.
