# ALDEBARAN — 작업 규칙

FRAME R1 · 2026-09-21 · 첫 프레임 구축용 입력 문서

## 범위와 우선순위

- 최신 사용자 지시를 우선한다. 이번 확정 범위는 **MERCURY 프레임 복제 + ALDEBARAN 브랜드 + 차콜/주황 스킨 + 중앙 비우기**다.
- 운영 문서는 `AGENTS.md`, `STATE.md`, `DESIGN_SPEC.md`, `DECISIONS.md` 네 개다. 별도 QA/작업 이력 MD를 늘리지 않는다.
- 사용자 확정 방향과 구현 시작값을 구분한다. CSS 수치·로고 표시 크기는 구현 시작값이며 사용자 시각 승인 결과가 아니다.
- 원본 MERCURY와 SIRIUS, 두 공개 사이트, 기존 사용자 변경을 보존한다. 복제한 ALDEBARAN 디렉터리 안에서만 구현한다.
- 이 문서를 MERCURY/SIRIUS 운영 문서에 덮어쓰지 않는다. 새 ALDEBARAN 문서로 설치한다. ALDEBARAN의 더 최신 문서가 있으면 필요한 지시만 병합한다.

## 구현 원칙

- Windows 현지 최신 MERCURY를 기준으로 한다. 예전 ZIP의 앱 상태나 과거 커밋으로 돌아가지 않는다.
- 헤더·공지·좌우 레일의 위치, 폭, 순서, 기존 기능과 스크롤 체계를 유지한다. SIRIUS의 중앙 브랜드/2단 헤더/개편 레일은 이식하지 않는다.
- 중앙 영역은 폭·높이·스크롤 컨테이너만 보존하고 가시 콘텐츠를 비운다. 카드/트래커 컴포넌트를 마운트한 뒤 CSS로 숨기지 않는다. 해당 중앙 전용 타이머·피드 요청·리스너도 작동시키지 않는다.
- 경기 데이터, 기존 모션, 검색·필터·슬립 함수는 후속 사용을 위해 소스에 보존한다. 초기 슬립에는 가짜 선택 항목을 채우지 않는다.
- 이미지 2개는 사용자 승인 원본이다. 재생성, 리터칭, 윤곽 재작성, 강제 컬러 필터, 자르기, 가로세로 왜곡을 하지 않는다.
- 기존 배너 사진·팀·리그·국기는 재사용한다. UI 아이콘과 팀/리그 사진 자산을 구분해 처리한다.
- 새 디자인 라이브러리·테마 엔진·실시간 피드·실거래 기능을 추가하지 않는다. 기존 React/Next 구조와 설치된 폰트를 재사용한다.
- 설치된 Impeccable 지침이 필요하면 이번 컬러/자산 적용 범위 안에서만 읽는다. 명령 실행이나 설치를 선행 조건으로 만들지 않는다. json-render는 후속 후보로 남긴다.
- 화면에 구현 설명, 작업 중 안내, 디버그 라벨을 추가하지 않는다. 개발 상태는 운영 문서에 기록한다.

## 복제·배포 격리

- `site/`의 필요한 앱 소스·공개 자산·package/lock/config를 복제한다. `.git`, `node_modules`, 빌드 출력, 캐시, 비밀 환경파일, 기존 호스팅 연결 파일은 그대로 이식하지 않는다.
- 공용 저장소를 쓰는 구조라면 기존 원격 설정을 변경하지 않고 신규 앱 경로만 추가한다. 앱별 저장소 구조라면 기존 저장소와 구분되는 ALDEBARAN 대상을 사용한다.
- MERCURY/SIRIUS의 프로젝트 ID, 배포 ID 또는 호스팅 바인딩으로 ALDEBARAN을 배포하지 않는다. 신규 등록/연결 결과를 확인한 뒤 배포한다.
- 상태 저장 키·브랜드 메타데이터·앱 제목·브랜드 버튼 접근성 이름을 ALDEBARAN으로 분리한다. 기존 사용자의 저장값을 삭제하거나 마이그레이션하지 않는다.
- 복제에 없는 비밀값이 필요하면 기존 정상 실행 절차에서 필요한 항목만 확인한다. 값을 로그·문서·ZIP에 노출하지 않는다.

## 확인과 종료

- 구현 담당이 기존 빌드/타입 확인과 이번 변경 부위만 짧게 확인한다. 별도 QA 스레드와 Jev는 실행하지 않는다.
- 같은 내용을 여러 번 검사하거나 전 사이트 미감 감사로 확대하지 않는다. 공개 결과의 미감 판단은 사용자가 한다.
- 이번 단계에서 카드/트래커/배당 선택 검증을 요구하지 않는다. 중앙은 의도적으로 비어 있으므로 이를 미완료로 판정하지 않는다.
- ALDEBARAN만 별도 공개 배포 후 최초 화면 1장, 실제 확인한 내용, 제한, URL/commit/deployment를 STATE에 기록한다. 확인하지 않은 기능을 PASS로 쓰지 않는다.
- 소스 접근 또는 호스팅 권한 때문에 막히면 완료된 작업과 실제 막힌 지점을 구분해 보고한다. 접근할 수 없는 외부 스레드를 조작했다고 주장하지 않는다.
