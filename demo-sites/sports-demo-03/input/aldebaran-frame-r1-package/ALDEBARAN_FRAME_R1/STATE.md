# ALDEBARAN — 현재 상태와 첫 실행

## 상태

**작업 패키지 준비 완료. Windows 앱 구현·빌드·공개 배포는 이 문서 작성 시점에 미실행.**

사용자는 세 번째 브랜드로 ALDEBARAN을 확정했고, 엠블럼과 타이포 로고를 제공했다. 이번에는 MERCURY 프레임을 재사용해 외곽 UI와 색상을 먼저 구축하고 중앙을 비운다. 중앙 경기 카드/매치 트래커 구현은 다음 지시 대상이다.

## 실행 위치

| 용도 | 경로/값 |
| --- | --- |
| 현지 작업공간 | `E:/codexwork/Site-Skin-edit/` |
| 복제 원본 | `demo-sites/sports-demo-01/site/` — 최신 MERCURY, 읽기 전용 |
| 보존 대상 | `demo-sites/sports-demo-02/` — SIRIUS, 수정하지 않음 |

기존 진행/구현 스레드를 재사용한다. 이 문서는 외부 스레드에 전달할 입력이며, 여기에서 그 스레드를 실행하거나 Windows 소스를 복제한 상태가 아니다.

## 바로 실행할 작업

1. 원본과 대상 경로, 현지 사용자 변경을 확인한다. MERCURY의 현재 파일을 별도 앱에 복제한다. 대상에 다른 프로젝트가 있으면 빈 경로를 선택한다.
2. 네 운영 문서를 새 작업 루트에 배치한다. 원본의 오래된 독립 감사 요구나 골드/아이보리 테마 규칙을 ALDEBARAN 요구로 가져오지 않는다.
3. `assets/branding/`의 두 PNG를 새 앱의 `public/assets/branding/`으로 복사한다. 원본 크기와 알파, 내용은 보존한다.
4. 헤더 브랜드 자리에서 왼쪽 엠블럼 + 오른쪽 타이포 로고를 적용한다. 페이지 제목·favicon/아이콘 등 기존 브랜드 노출도 새 앱 안에서 교체한다. favicon은 제공 엠블럼 원본을 연결할 수 있다.
5. 기존 메뉴·서비스·검색/종목·계정·슬립·문의·배너의 구조를 보존하고 DESIGN_SPEC의 면·문자·선택 색을 적용한다. `styles/`의 변수와 부위 속성을 실제 컴포넌트에 연결한다.
6. 중앙의 제목·카드·리그·더보기·추가 베팅·트래커를 렌더하지 않는다. 빈 `main`의 공간과 스크롤 참조 구조는 보존한다. 검색·필터·메뉴 변경 후에도 이번 화면 중앙은 빈 상태로 유지한다.
7. 베팅슬립은 기존의 정상적인 무선택 상태를 유지한다. 저장 키를 분리해 기존 사이트의 선택이 유입되지 않게 한다. 중앙 내용이 없어 스크롤 임계값에 도달하지 않으면 기존 맨 위로 버튼도 나타나지 않는다.
8. ALDEBARAN 전용 호스팅을 연결한다. 기존 설치/빌드 절차로 확인하고 아래 짧은 확인을 수행한다.
9. 별도 공개 주소에 배포하고 최초 화면 1장과 실제 배포 정보를 기록한다. 사용자 피드백을 기다린다.

## 최소 확인 범위

- 기존 프로젝트의 통상 빌드/타입 확인. 같은 빌드가 이미 타입 검사를 수행하면 관행상 필수가 아닌 중복 실행은 생략한다.
- 1920 폭의 최초 화면에서 로고 비율·헤더 잘림·차콜/주황 적용·좌우 레일 배치·빈 중앙을 확인한다. 브라우저 높이를 앱 높이 1080px로 강제하지 않는다.
- 기존 메뉴 1회, 좌측 필터/검색 입력·초기화, 슬립 금액 입력·초기화처럼 변경부에 관련된 대표 조작만 확인한다. 중앙이 다시 렌더되거나 콘솔 오류가 생기지 않는지 본다.
- 배포 연결이 ALDEBARAN인지 확인하고 공개 첫 화면을 확인한다. MERCURY/SIRIUS 파일이 변경 목록에 들어 있지 않은지 최종 diff로 확인한다.

슬립 배당 곱셈·실제 베팅 제출·트래커 동작·전체 모션·전 종목·전 상태·모바일은 이번 확인 대상이 아니다. 별도 QA 및 Jev는 사용자 지시로 생략한다.
