# ALDEBARAN R4 — 실행 규칙 변경분

## 우선순위와 범위

- 사용자가 중앙 콘텐츠 구현을 새로 승인했다. 이전 '중앙은 비움', render_children:false, mount_tracker:false 등의 활성 규칙은 이번 범위에서 대체한다. 과거 단계 기록은 삭제하지 않는다.

## 최소한의 올바른 연결

- 현재 앱에 남아 있는 데이터/필터/마켓/슬립 로직부터 읽는다. 앱을 다시 복제하거나 별도 데모 앱/베팅슬립을 만들지 않는다.

- 선택 경기와 선택 배당을 별도 상태 개념으로 둔다. 선택 경기 ID 하나를 트래커와 세부 마켓이 함께 읽는다. 배당 상태는 기존 슬립 로직에서 읽는다.
- 카드 전체를 button으로 감싼 뒤 그 안에 배당 button을 중첩하지 않는다. 팀/리그 선택 영역과 배당 버튼을 형제 컨트롤로 둔다.
- 표시 배당 텍스트나 배열 인덱스를 선택 ID로 사용하지 않는다. 기존 경기/마켓/라인/선택 ID를 재사용해 좌우의 같은 선택을 연결한다.
- 팀/리그/국기 이미지 원본을 재사용한다. 로고 누락을 모두 회색 원으로 대체해 완료하지 않는다. 소수 누락만 기존 대체 방식으로 처리한다.
- React 참고 코드는 상태를 외부에서 받는다. 복제된 상태, 불필요한 effect, 새 전역 이벤트 리스너를 추가하지 않는다.
- 축구 필드는 자체 SVG/CSS로 구현 가능하다. 외부 iframe, 이미지 캡처, 신규 위젯 계약/인증/API 키를 이번 작업의 의존성으로 만들지 않는다.

## 데이터와 표현

- LIVE/종료 점수는 0도 유효값으로 표시한다. truthy 검사로 0을 숨기지 않는다. 예정 경기는 예정 상태를 분명히 표시하며 임의로 LIVE로 바꾸지 않는다.
- 데모 보완 데이터는 경기 ID 기반으로 안정적으로 만든다. 렌더마다 Math.random으로 숫자가 바뀌지 않는다.
- 카드/트래커/슬립/세부 마켓의 팀명·점수·마켓 값은 같은 원천을 사용한다. 데모 통계/이벤트는 그 점수와 진행 시점에 맞춘다.
- 현재 데이터가 과거 데모 일정이면 그대로 데모 일정으로 유지한다. 실제 생중계 피드를 연결했다고 보고하지 않는다.
- 빈 버튼/무반응 탭/가짜 링크는 만들지 않는다. 첫 버전의 트래커 탭은 경기·통계·타임라인처럼 실제로 동작할 범위로 구성한다.

## 진행·확인

## 범위와 우선순위

- 최신 사용자 지시를 우선한다. 이번 확정 범위는 **MERCURY 프레임 복제 + ALDEBARAN 브랜드 + 차콜/주황 스킨 + 중앙 비우기**다.

## 구현 원칙

- Windows 현지 최신 MERCURY를 기준으로 한다. 예전 ZIP의 앱 상태나 과거 커밋으로 돌아가지 않는다.

- 중앙 영역은 폭·높이·스크롤 컨테이너만 보존하고 가시 콘텐츠를 비운다. 카드/트래커 컴포넌트를 마운트한 뒤 CSS로 숨기지 않는다. 해당 중앙 전용 타이머·피드 요청·리스너도 작동시키지 않는다.
- 경기 데이터, 기존 모션, 검색·필터·슬립 함수는 후속 사용을 위해 소스에 보존한다. 초기 슬립에는 가짜 선택 항목을 채우지 않는다.
- 이미지 2개는 사용자 승인 원본이다. 재생성, 리터칭, 윤곽 재작성, 강제 컬러 필터, 자르기, 가로세로 왜곡을 하지 않는다.
- 기존 배너 사진·팀·리그·국기는 재사용한다. UI 아이콘과 팀/리그 사진 자산을 구분해 처리한다.
- 새 디자인 라이브러리·테마 엔진·실시간 피드·실거래 기능을 추가하지 않는다. 기존 React/Next 구조와 설치된 폰트를 재사용한다.
- 설치된 Impeccable 지침이 필요하면 이번 컬러/자산 적용 범위 안에서만 읽는다. 명령 실행이나 설치를 선행 조건으로 만들지 않는다. json-render는 후속 후보로 남긴다.
- 화면에 구현 설명, 작업 중 안내, 디버그 라벨을 추가하지 않는다. 개발 상태는 운영 문서에 기록한다.

- 이번 단계에서 카드/트래커/배당 선택 검증을 요구하지 않는다. 중앙은 의도적으로 비어 있으므로 이를 미완료로 판정하지 않는다.
- ALDEBARAN만 별도 공개 배포 후 최초 화면 1장, 실제 확인한 내용, 제한, URL/commit/deployment를 STATE에 기록한다. 확인하지 않은 기능을 PASS로 쓰지 않는다.
- 소스 접근 또는 호스팅 권한 때문에 막히면 완료된 작업과 실제 막힌 지점을 구분해 보고한다. 접근할 수 없는 외부 스레드를 조작했다고 주장하지 않는다.

# ALDEBARAN R5 — 운영 지시 변경분

현재 운영 문서 뒤에 병합한다. 이전 실제 완료/배포 이력은 보존한다.

- 최신 사용자 지시는 WOG 해외형 스포츠의 전체 UI 배치를 이식하는 것이다. 헤더/좌우 레일 보존, 중앙만 수정, 기존 272/1280/320 그리드, R4의 공통 중앙 스크롤, 트래커 우선 첫 화면은 현재 범위에서 대체한다.
- 전체 1920px 고정. 더 넓은 화면에서도 중앙이 늘어나지 않는다. 좁은 창에서는 전체 캔버스 가로 스크롤로 접근하며 카드를 줄이거나 열을 접지 않는다. 세로 높이만 viewport 잔여 높이를 사용한다.
- ALDEBARAN의 무광 차콜·오렌지·흰색 계열 유지. WOG의 흰 패널/은색·금색 그라데이션/광택/엠보싱/사자 로고는 스타일로 가져오지 않는다.
- 화면 요소의 수, 순서, 치수는 DESIGN_SPEC과 layout-contract를 따른다. 카드 높이를 임의로 키워 듬성듬성 만들거나 조작 항목을 삭제하지 않는다.
- 참조의 현재 경기 수 55, 점수, 사용자 계정/잔액을 고정 복사하지 않는다. ALDEBARAN의 같은 경기 데이터에서 카운트·목록·상세·슬립을 파생한다. 로컬 데모라는 기존 전제는 유지한다.
- 선택 경기와 베팅 선택 상태는 별개다. 카드/상세의 동일 배당은 동일한 안정 ID와 같은 기존 슬립 함수로 연결한다. 표시 문자열이나 배열 인덱스는 ID가 아니다.
- 좌우 중앙 scroller DOM은 경기 변경으로 remount하지 않는다. 부모에 선택 경기 key를 걸지 않는다. 오른쪽 스크롤로 왼쪽 scrollTop이 바뀌지 않는다. body/main 공통 세로 스크롤로 다시 합치지 않는다.
- 리그/마켓 헤더 접기·펼치기는 기존 승인된 짧은 모션을 재사용한다. 별도 애니메이션 라이브러리/전역 wheel 가로채기/스크롤 상태를 매 프레임 React state로 올리는 구현은 피한다.
- React 참고 슬롯 코드는 상태를 복제하지 않는다. 현재 데이터 어댑터/모달/자산과 연결해 완성한다. 탭/카드/배당을 중첩 button으로 구현하지 않는다.
- 메뉴/사진/배너를 빈 링크, '#'만 있는 버튼, 준비중 안내 하나로 끝내지 않는다. behavior-contract의 기존 목적지 또는 내용 있는 데모 보기와 연결한다.
- 실제 입출금, 외부 베팅 API, WOG 로그인 정보, 세션/cookie, 백엔드 요청을 이식하지 않는다. 참조 로그인 정보는 산출물에 저장하지 않는다.
- 폰트는 우선 기존 프로젝트의 Pretendard 계열을 사용한다. 계열이 이미 로컬 자산에 있으면 재사용. 기존 DIN을 그대로 강제하여 WOG의 14px 배당 정보 밀도가 달라지지 않도록 한다. 브랜드 로고는 승인된 이미지 그대로다.
- 기존 Impeccable이 있다면 layout(치수/스크롤)·typeset(크기/위계)·harden(문자 길이/빈 결과) 지침을 해당 부위에만 참고한다. 별도 명령 순회나 polish 감사는 하지 않는다.
- 별도 QA/Jev/광범위 회귀/새 테스트 스위트/이미지 생성/새 사이트 생성은 이번 요청이 아니다. 기본 빌드와 대표 변경 동작만 확인한다.
- 작업 대상과 배포 대상은 ALDEBARAN 하나다. MERCURY/SIRIUS 및 다른 저장소를 변경하지 않는다.

# ALDEBARAN R6 운영 지시 변경분

현지 운영 문서에 병합하고 기존 완료 기록은 보존한다.

- 최신 사용자 피드백이 R5의 충돌 지시보다 우선한다. 예정 경기의 점수/LIVE, 집 모양 홈 표식, 세 자리 소수 배당, 헤더 전체 메뉴 작동, 중앙 독립 스크롤의 전 모드 강제는 이 범위에서 대체한다.
- 1920 고정 프레임, 무광 차콜/주황/흰색 테마, 좌우 레일, 공지와 기존 카드 밀도는 유지한다. 국내형의 중앙 내용/스크롤 구조만 추가한다.
- 변경 기준은 현재 배포된 실제 소스다. R5 전달용 TSX를 최신 구현 위에 통째로 덮어쓰지 않는다.
- 배당 formatter를 카드/상세/슬립/총 배당에 공통 적용한다. 반올림한 표시 문자열을 저장값이나 계산값으로 사용하지 않는다. 핸디/언오버 기준점에는 배당 formatter를 적용하지 않는다.
- 예정 경기 화면에는 예정 fixture를 연결한다. 실시간 경기의 데이터 자체를 삭제하거나 전역 상태를 예정으로 덮어쓰지 않는다.
- 동일 MatchCard를 두 모드에서 재사용하고 mode에 따라 상세 진입만 분기한다. 데이터/베팅 선택 상태를 복제하지 않는다.
- GNB의 두 스포츠 메뉴만 선택 가능하다. 나머지 8개는 구조와 레이블을 유지하고 포인터·키보드 선택/라우팅을 막는다. 선택·hover의 새로운 시각 디자인은 보류하며 계정/공지/레일 서비스 기능까지 막지 않는다.
- 국내형은 하나의 scroll container다. 두 독립 scroller를 scroll 이벤트로 동기화하는 구현은 금지한다. 해외형은 기존 독립 scroller를 보존한다.
- 기존 selection ID와 슬립 함수를 재사용한다. 모드 전환이나 배당 표시 반올림으로 선택ID·배당원값·잔액·입력금액을 바꾸지 않는다.
- 모드별 스크롤 위치는 ref 또는 기존 저장 방식으로 유지한다. 매 프레임 React state 갱신과 큰 컴포넌트 전면 재구성을 피한다.
- 헤더 로고 잘림 원인은 미확인이다. 실제 원인에 대한 최소 수정만 적용하고 임의로 overflow:visible을 전체 헤더에 퍼뜨리지 않는다.
- 별도 QA/Jev/광범위 회귀/새 테스트 스위트/디자인 명령 순회/새 플러그인/이미지 생성은 하지 않는다. 기본 빌드와 대표 변경 흐름만 확인한다.
- 현재 수정 대상은 ALDEBARAN 하나다. MERCURY/SIRIUS는 사용자 승인 후 별도 이식한다.
