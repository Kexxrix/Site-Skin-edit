## 1. 프레임과 절반 분할

이번 '화면의 절반'은 기존 좌우 레일 사이의 중앙 스포츠 콘텐츠 영역에 적용한다. 왼쪽 빠른 서비스/검색/종목 레일과 오른쪽 계정/베팅슬립 레일은 유지한다.

중앙 안을 왼쪽 카드 열과 오른쪽 트래커/마켓 열로 정확히 동등하게 나눈다. CSS는 `grid-template-columns:repeat(2,minmax(0,1fr))`, 간격 시작값은16px이다. 기존 중앙 폭1280px에서 각 열은 `(1280-16)/2=632px`다. 간격을 50% 한쪽에만 더하거나 width:50% 두 개에 추가 gap을 더해 넘치게 만들지 않는다.

두 열은 같은 위쪽 기준선에서 시작한다. 왼쪽 위에 별도의 대형 소개 패널/배너/히어로를 만들지 않는다. 오른쪽은 위에서 아래로 트래커 → 세부 마켓 필터 → 마켓 패널 순서다. 전체 페이지를 50:50으로 재편하지 않는다.

1920px 고정 셸과 기존 중앙 공통 스크롤 방식을 따른다. 두 열에 각각 독립 스크롤바를 새로 만들지 않는다. 첫 버전은 공통 흐름을 사용하며 큰 우측 전체 패널을 강제로 sticky 처리해 아래 세부 마켓을 가두지 않는다.

## 2. 왼쪽 경기 카드

한 열에 경기 카드를 수직으로 쌓고 카드 간격은12px를 시작값으로 한다. 면은 현재 차콜 패널, 경계는 얇은 중립 회색이며 여백과 정보 위계로 구분한다.

각 카드는 다음 순서로 구성한다.

1. 작은 정보 행: 기존 종목/리그 아이콘, 리그명과 필요한 국기, 경기 시작 시각, LIVE/예정/종료 및 진행 상태.
2. 팀 주행: **홈 팀 로고 — 홈 팀 이름 — VS — 원정 팀 이름 — 원정 팀 로고**.
3. 기본 배당 행: 축구는 홈 승/무승부/원정 승 3개 버튼. 무승부 없는 해당 시장은 홈/원정 2개 버튼. 모든 종목을 억지로3개에 맞추지 않는다.

팀 주행은 좌우 대칭 구조다. 홈 로고는 왼쪽 바깥, 원정 로고는 오른쪽 바깥에 있고 팀명은 각 로고 안쪽에 붙는다. VS는 행 중심에 고정한다. 팀명 길이에 따라 VS가 좌우로 움직이지 않는다.

팀 로고36px, 팀명15px/굵게, 가운데 VS/점수 영역88px를 시작값으로 한다. 팀명은 한 줄 말줄임하며 전체 이름을 title/접근성 이름으로 제공한다. 이미지를 찌그러뜨리거나 크롭하지 않는다.

**스코어를 빠뜨리지 않는다.** LIVE와 종료 경기는 가운데 VS 아래의 별도 점수 행에 홈:원정 점수를 표시한다. VS만 남기고 점수를 배당 쪽으로 보내지 않는다. 예정 경기는 VS와 시작 시각/예정 상태를 사용하며 알 수 없는 점수를 가짜 LIVE 점수로 표시하지 않는다. 농구의 `108 : 102`, 야구의0점처럼 긴 숫자와0도 정상 표시한다. 점수와 배당에는 현재 설치된 DIN 숫자 폰트가 있으면 재사용한다.

리그/팀 영역은 경기 선택 컨트롤, 아래 배당은 베팅 선택 컨트롤이다. 두 기능을 구분한다. 경기 선택은 카드의 얇은 주황 경계로, 배당 선택은 주황색 버튼 면과 짙은 글자로 표시한다. 트래커 선택만으로 슬립에 배당을 자동 추가하지 않는다.

기본 배당 버튼은 높이44~48px 시작값, 작은 시장 라벨과 큰 배당 숫자를 함께 표시한다. 비선택 숫자는 주황, 선택 상태는 기존 주황 면/짙은 글자 스타일을 따른다. 라벨 없는 숫자만 나열하지 않는다. 세 자리 정수나 소수 셋째 자리(`2.125`)가 와도 버튼 밖으로 넘치지 않게 한다.

## 3. 오른쪽 트래커

공식 참조: [Sportradar Live Match Tracker](https://widgets.sir.sportradar.com/live-match-tracker). 세부 테마/경기 URL은 reference-sources.json에 있다.

데모에서 확인한 구조는 상단 확장 스코어보드, 그 아래 홈/원정 이벤트 타임라인, 중앙 필드 표현, 하단 탐색 탭이다. 이번 ALDEBARAN은 이 정보 순서와 밀도를 참고해 현재 테마의 자체 데모 트래커로 구현한다. 데모 사이트 전체의 사이드바/배경/로고를 가져오지 않는다.

### 축구 기본 화면

- 상단: 선택 리그, 홈/원정 실제 팀 로고와 이름, 가운데 큰 점수, LIVE와 진행 분/전후반 상태.
- 타임라인: 홈/원정2행, 전·후반 구분과 시간 눈금, 득점/카드 등 경기 이벤트 표시. 표시된 이벤트는 현재 점수·진행 분과 일치한다.
- 필드: 탑뷰 축구장, 외곽선·센터라인·센터서클·페널티박스·골대. 차분한 녹색 잔디는 필드 내부에만 허용한다. 나머지 면은 무광 차콜이다.
- 공 위치와 짧은 공격 방향 표시, 현재 공격 팀/상황 텍스트. 작은 SVG 이동/상태 전환을 사용하되 화면 전체 점멸이나 계속 떠다니는 장식은 넣지 않는다.
- 하단 탭: 첫 버전은 **경기 / 통계 / 타임라인** 세 가지를 실제 동작하게 구성한다. 동작하지 않는 맞대결/순위/라인업 버튼은 수량을 맞추기 위해 넣지 않는다.
- 통계 탭: 점유율, 슈팅, 유효 슈팅, 코너킥 등 선택 경기의 양쪽 비교. 타임라인 탭: 시간 순 이벤트 목록. 원래 경기 탭으로 돌아가도 점수/선택 경기는 유지한다.

크기 시작값:632px 열에서 트래커 전체 높이 약540~600px, 제공 필드 예제는100:64 비율. 위쪽 점수/타임라인과 아래 탭을 눌러서 잘라내지 않는다. 첫 화면에 트래커 아래 첫 세부 마켓까지 함께 보이도록 밀도를 조정한다. 이 높이는 사용자 확정 픽셀값이 아니다.

UI 강조와 홈팀 표현은 주황, 원정팀은 흰색/옅은 회색으로 구별하고 라벨을 병기한다. Sportradar 참조 URL의 청록/마젠타를 ALDEBARAN 전체 배색에 그대로 적용하지 않는다. 득점/경고 등 의미를 가진 표시는 필요한 범위에서 구별한다.

### 다른 종목과 상태

다른 종목 카드를 클릭해도 축구 경기명·축구 필드를 그대로 남겨두지 않는다. 해당 경기의 로고·팀명·스코어·이닝/쿼터/피리어드와 종목에 맞는 통계 화면으로 전환한다. 비축구 전용 필드 애니메이션 전부를 이번에 새로 만드는 것은 요구하지 않는다.

LIVE는 로컬 상황 단계/공 위치를 실용적인 속도로 전환한다. 예정/종료 경기에는 진행 중인 공격 애니메이션을 보여주지 않는다. 종료 경기의 베팅 가능 여부는 기존 마켓 상태를 그대로 따른다.

로컬 데모 상황은3~5초 간격의 소규모 단계 전환을 시작값으로 한다. 단계마다 득점을 임의로 바꾸지 않는다. 실제 점수 변경을 넣을 때는 같은 원천을 통해 카드/트래커/타임라인을 동시에 갱신한다. 선택 경기 변경 시 이전 타이머를 정리하고 숨겨진 페이지에서는 불필요한 진행을 중지한다. reduced-motion에서는 위치 이동 대신 정적인 단계 표시를 사용한다.

## 4. 트래커 아래 세부 베팅

트래커와12px 정도 간격을 두고 선택 경기의 세부 마켓을 쌓는다. 상단에는 '전체 / 승무패 / 핸디캡 / 오버언더 / 스페셜'처럼 실제 마켓에 연결된 필터를 둔다. 시장이 없는 카테고리는 숨기거나 비활성 처리한다.

축구 첫 구현의 기본 패널은 승무패, 핸디캡, 오버언더다. 데모 추가 패널은 전반 승무패와 첫 득점 팀처럼 이해하기 쉬운 두 가지를 시작값으로 사용한다. 다른 종목에 축구 전용 '첫 골'을 그대로 재사용하지 않는다.

패널은 작은 제목, 필요한 기준점(핸디±0.5, 합계2.5 등), 배당 버튼 묶음으로 구성한다. 왼쪽 카드에 보이는 기본 승무패와 오른쪽 같은 마켓은 동일한 selection ID를 쓴다. 양쪽 어느 쪽에서 눌러도 같은 상태와 슬립 항목을 표현해야 한다.

기존 앱이 이미 가진 마켓/배당을 우선 사용한다. 새 세부 마켓만 로컬 데모 값으로 보완하고 기존 슬립 모델이 요구하는 경기/시장/선택/라인 정보를 채운다. 설명만 있는 가짜 버튼으로 끝내지 않는다.

## 5. 상태 일치와 현실감

- 기존 경기 수·필터·검색 결과를 유지한다. 정렬을 위해 팀/리그/국기 데이터를 다시 발명하지 않는다.
- 최초 유효한 선택이 없고 노출 목록에 LIVE 축구가 있으면 그 경기 한 개를 초기 선택 및 목록 상단에 둔다. 없으면 첫 LIVE, 다시 없으면 첫 경기를 사용한다. 사용자가 선택한 필터를 몰래 축구로 바꾸지 않는다.
- 필터/검색 이후 현재 선택 경기가 여전히 보이면 유지하고, 사라지면 새 결과에서 유효한 경기를 선택한다. 결과0이면 왼쪽 결과 없음과 오른쪽 선택 대기 상태를 함께 표시한다.

- 더보기·접기·맨 위로 이동의 승인된 모션은 기존 구현을 재사용한다. 목록 확장이나 카드 클릭마다 페이지를 갑자기 맨 위로 보내지 않는다.

## 본문과 공유할 기준

본문과 같은 고정 셸 안에서 다음 관계를 만족시킨다.

- 브랜드 오른쪽 경계 = 왼쪽 레일 오른쪽 경계.
- 메뉴 시작 = 중앙 콘텐츠 시작, 메뉴 끝 = 중앙 콘텐츠 끝. 기존 열 사이 간격은 유지한다.
- 계정 버튼 영역 시작/끝 = 오른쪽 레일 시작/끝. 버튼 묶음은 그 안에서 오른쪽 정렬한다.
- 헤더와 본문은 같은 외곽 여백·너비·열 간격을 따른다. viewport 전체를 기준으로 absolute/fixed 위치를 새로 잡지 않는다.
- 브랜드는 왼쪽 레일에 대응하는 폭에서 수평 중앙, 헤더 전체 높이에서 수직 중앙으로 둔다. 셸 바깥쪽 여백이 브랜드 배경에 포함되어도 그 여백 때문에 로고 중심이 치우치지 않도록 한다.

예제의 기존 프레임 대입값은 다음과 같다. **현지 최신 값이 다르면 최신 본문 값으로 연결하며 본문을 예제 숫자로 바꾸지 않는다.**

| 프레임 항목 | 예제 대입값 |
| --- | --- |
| 셸 폭 | 1920px |
| 좌우 외곽 여백 | 각각 12px |
| 왼쪽 레일 | 272px |
| 중앙 | 1280px |
| 오른쪽 레일 | 320px |
| 열 사이 간격 | 각각 12px |

계산: `12 + 272 + 12 + 1280 + 12 + 320 + 12 = 1920`.

셸 왼쪽을 0으로 하면 왼쪽 레일은 `12~284`, 중앙은 `296~1576`, 오른쪽 레일은 `1588~1908`이다. 따라서 예제의 주황선 오른쪽 경계는 `284`에 맞춘다. 브랜드 폭에 단순히 `272px`만 넣으면 외곽 여백 때문에 정렬이 어긋날 수 있다. 이는 좌표 설명 예제이며 공개 사이트를 이번 패키지에서 다시 측정한 결과는 아니다.

## 높이와 크기 — 조정 가능한 시작값

| 요소 | 시작값 | 의미 |
| --- | --- | --- |
| 전체 헤더 | 현재 총 높이 유지. 예제 104px | 높이를 더 늘리지 않음 |
| 공지 행 | 28px | 텍스트 한 줄과 작은 상하 여백 |
| 메뉴/계정 행 | 76px | `104 - 28 = 76` |
| 메뉴 버튼 높이 | 42px | 기존 높이를 유지하고 행 내부 여백 확보 |
| 계정 버튼 높이 | 38px | 현재 디자인 우선, 메뉴 행 중심선에 배치 |
| 레터링 폭 | 216px | 원본 1101×120 비율 유지 |
| 세로선 | 1px × 헤더 전체 높이 | 위아래 여백 없이 연결 |
| 메뉴 사이 간격 | 8px | 7개 메뉴를 가용 폭에 맞게 균등 분배 |

레터링 높이 계산: `216 × 120 ÷ 1101 ≈ 23.54px`. 예제 왼쪽 레일 폭 272px에서 좌우 여유는 `(272 - 216) ÷ 2 = 28px`씩이다. 이 수치들은 사용자가 확정한 픽셀값이 아니며 실제 폰트/여백을 보고 최소 조정한다.

메뉴 예제는 좌우 안쪽 여백 12px씩, 간격 8px 여섯 개를 둔다. 버튼 너비는 `(1280 - 24 - 48) ÷ 7 ≈ 172.57px`다. 기존의 min-width:136px/max-width:180px/flex 배치를 함께 남기지 않는다. 이벤트 버튼의 상자 전체가 메뉴 끝선 안에 들어와야 한다.

- 일반 텍스트와 아이콘은 흰색 계열. 활성 텍스트와 주요 수치에 주황을 사용한다. 모든 문자를 주황색으로 바꾸지 않는다.
- score/odds용 주황 토큰은 준비하되 R1 중앙에 수치나 경기 샘플을 추가하지 않는다. 기존 우측 합계 등 강조 수치에만 적용할 수 있다.
- hover에서 너비/높이/정렬이 움직이지 않게 한다. 색 변화는 약 140ms의 짧은 반응을 시작값으로 하며 새 상시 애니메이션은 넣지 않는다.

## 5. 버튼·아이콘·배너

- 주요 버튼은 주황 단색 면과 짙은 글자, 보조 버튼은 회색 면과 흰 글자를 기본으로 한다. 비활성은 회색으로 구분한다. 기존 버튼 크기/작동/순서는 유지한다.
- 검색/금액 입력은 깊은 회색 면과 흰 글자, 포커스는 주황 선을 사용한다. 이번에는 캡슐화·패널 재배치를 추가하지 않는다.
- UI SVG 아이콘은 `currentColor`로 흰색 계열을 기본으로 하고 활성 시 주황으로 변경한다.
- 기존 금색 **종목 PNG**만 남아 있으면 새 리소스를 생성하지 않고 해당 종목 이미지에 한정해 CSS `grayscale(1)`로 우선 중립화한다. 면과 내부 디테일을 모두 흰색으로 뭉개는 `brightness(0) invert(1)` 처리는 금지한다. 흰색 마스터가 현지에 이미 있으면 그것을 우선 사용할 수 있다. 이 임시 처리는 팀·리그·국기·배너·브랜드 이미지에 적용하지 않는다.
- 사진 배너는 기존 사진/레이아웃을 재사용하고 HTML 제목·강조·버튼을 ALDEBARAN/주황으로 바꾼다. 배너 안에 박힌 MERCURY 글자가 있으면 현지의 기존 무브랜드 원본을 사용한다. 없다면 그 자산 문제만 STATE에 기록하고 승인 없는 이미지 재제작으로 확대하지 않는다.
- 기존 로드된 한글/본문/숫자 폰트를 유지한다. 중앙 DIN 등 세부 숫자 서체 결정은 후속이다. 새 폰트 서비스를 추가하지 않는다.

## 6. 빈 중앙의 정확한 의미

- 중앙에는 경기 카드, 리그 목록, 섹션 제목, 카운트, 필터 바, 트래커, 배너, 안내 문장, 점선 박스, 스켈레톤을 표시하지 않는다. 참조 이미지 2·3을 스크린샷으로 붙여 넣지 않는다.
- 기존 레이아웃의 중앙 슬롯을 남기고 배경색을 적용한다. 의미상 `main aria-label="스포츠 콘텐츠"` 같은 영역을 둘 수 있다. 화면에 보이는 placeholder 문구는 없다.
- JSX에서 해당 중앙 콘텐츠 렌더를 제외한다. `opacity:0`/`display:none`만 덮어놓고 기존 중앙 트리를 계속 실행하지 않는다.
- 데이터·선택 상태를 관리하는 외곽 공통 로직은 필요한 만큼 보존하고, 중앙 전용 관찰자/타이머는 마운트되지 않은 영역을 참조하지 않게 한다. 빈 중앙 때문에 기존 레일 입력이 오류를 내지 않게 한다.
- 후속 2열 분할을 이번 회차에서 미리 렌더하지 않는다. 중앙의 동일 공간을 다음 회차 구현 지점으로 남긴다.

## 7. 첨부 CSS의 적용 방법

- `styles/aldebaran.tokens.css`: 앱 루트의 `.aldebaran-site` 아래에서 사용하는 의미별 컬러 변수다.
- `styles/aldebaran.surfaces.css`: `data-ab-surface`, `data-ab-control`, `data-ab-nav`, `data-ab-input` 속성을 기존 요소에 붙여 사용하는 표면 스타일이다. 자세한 매핑은 `implementation/ui-map.json`에 있다.
- 새 앱 전용으로 import한다. 기존의 골드 배경/의사요소·선택 스타일은 실제 원본 코드를 확인해 새 앱에서 치환한다. 파일 import만 하고 하드코딩된 골드를 그대로 남기지 않는다.
- 변수 파일은 외부 사이트와 공유하지 않는다. 전체 CSS를 `!important`로 덮거나 구조 관련 코드를 대규모 리팩터링하지 않는다.

# ALDEBARAN R5 — WOG 해외형 구조의 고정형 이식 명세

## 1. 목표와 우선순위

WOG 해외형 화면의 요소 수, 배치 순서, 정보 밀도, 글자 크기, 카드/버튼/패널 치수와 작동 관계를 재현한다. 색·재질·브랜드만 ALDEBARAN으로 변환한다. 사용자의 최신 1916×941 참조 이미지(reference/wog-user-wide.png)와 실제 WOG DOM/CSS가 근거다. 이전 R4의 '최신 이미지 사용 금지'는 당시의 별도 모형 이미지에 한정한 지시였다. 이번 WOG 참조 PNG는 사용한다.

측정 우선순위: 현재 적용된 CSS 수치 > 원본 CSS의 최종 데스크톱 규칙 > 사용자 넓은 화면의 배치 > 합리적 연결 구현. 1363px 관측 폭을 1920 목표에 그대로 넣지 않는다. 아래 1920 값은 원본 규칙에서 산출한 목표이며 이 환경의 직접 1920 실측값이라고 보고하지 않는다.

이식 범위는 전체 페이지다. 종전 헤더/레일 폭을 보존해 WOG 밀도가 무너지는 절충안은 채택하지 않는다. 현재의 '큰 트래커 위 / 몇 개 마켓 아래' 구성 대신 WOG 해외형처럼 제목/탭/세부 마켓을 즉시 보여준다. 기존 축구 트래커 코드와 자산은 삭제할 필요가 없지만 기본 페이지에 마운트하지 않는다. 축구만 필터도 강제하지 않는다.

## 3. 헤더

순서: 국내형 스포츠 / 해외형 스포츠 / E 스포츠 / 인플레이 / 카지노 / 슬롯 / 미니게임 / 가상 스포츠 / 자유게시판 / 경기결과.

- 해외형 NEW, 인플레이 LIVE: 28×18, 글자8px/900. 배지는 메뉴 오른쪽 위에 붙인다.
- 기존 승인 ALDEBARAN 레터링 이미지 사용. 브랜드 슬롯360 중 시각적 브랜드 판220, 레터링 목표폭182(비율 유지)·높이약20, x24/y중앙. WOG 120×40 로고를 ALDEBARAN 로고에 강제로 맞춰 찌그러뜨리지 않는다. 엠블럼 재삽입 없음.
- 브랜드 판의 사선 끝 형상은 유지 가능하되 차콜 단색/주황 얇은 선으로 표현한다. 헤더 광택/우주 배경/골드 테두리는 넣지 않는다.
- 활성 메뉴의 작은 종목/카테고리 아이콘, NEW/LIVE 표식을 생략하지 않는다. 기존 아이콘 자산으로 32~40px 포인트를 넣고 레이블 가독성을 유지한다. hover/focus는 주황 글자/아이콘 이동2px/짧은 강조선, 150~180ms. 원본 파티클 수십 개와 금속광 효과는 복제할 필요 없다.
- 우측계정영역320, padding8, gap8. 로그인 상태 로그아웃96×36(13px/900), 비로그인일 때 로그인76/회원가입76/무기명 회원가입126 + gap4. 기존 데모 auth 상태와 일치시킨다. 비실명 가입의 실제 개인정보 수집 기능은 이번 범위에 신설하지 않는다.

## 4. 공지줄

왼쪽은 공지 한 줄이 오른쪽에서 왼쪽으로 흐르고, 오른쪽 5개 아이콘/텍스트 버튼은 고정한다.
순서: 공지사항 / 이벤트게시판 / 출석체크 / 고객센터 / 이용규정.
아이콘12, 아이콘-글자간격4, 버튼간격14, 글자14px/600. 공지13px/500, 줄높이36. 텍스트 길이는 공지 영역 안에서만 잘린다.
마퀴는 CSS 38초 linear infinite를 시작값으로 사용. hover/focus 정지, reduced-motion이면 정적 한 줄. 뒤따르는 메뉴나 사이트 전체가 움직이면 안 된다.
본문 예시: '서비스 점검 및 이벤트 안내는 공지사항에서 확인해 주세요.' 기존 ALDEBARAN 공지가 있으면 재사용한다.

## 9. 스크롤·선택 연결

4개 수직 scroller: 왼쪽 외부 레일 / 중앙 경기 목록 / 중앙 상세 마켓 / 오른쪽 외부 레일. 스크롤바는 시각적으로 숨기되 wheel·터치패드·키보드로 작동. 중앙 전체/main/body는 공통 수직 scroller가 아니다.

- 중앙 좌측 종목바, 우측 경기제목/마켓탭은 각 scroller 밖에 남는다.
- 오른쪽 scrollTop 변경이 왼쪽에 영향을 주지 않는다. 선택 카드가 화면 안에 있는 동안 오른쪽을 내려도 그대로 보인다.
- 다른 경기 클릭 시 왼쪽 scrollTop 보존, 오른쪽만 맨 위로 재설정하고 제목/필터/상세를 함께 갱신. 같은 경기 재클릭은 양쪽 모두 유지.

- 필터/검색으로 선택 경기 제거 시 현재 결과의 첫 경기 선택. 결과 없음이면 오른쪽도 빈 결과 상태. 이전 경기 정보가 남지 않는다.
- 스크롤 이벤트를 body로 넘기지 않도록 overscroll-behavior:contain. overflow:auto만 추가하고 min-height:0/잔여높이 체인을 빠뜨리지 않는다.
- 기존 탑 이동이 중앙 부모를 대상으로 했다면 현재 중앙 목록 scroller로 재연결. 좌우 동시 강제 리셋 금지. 기존 부드러운 스크롤과 reduced-motion 처리 유지.

## 적용 기준

사용자가 R5 작업 완료를 알린 뒤 제시한 피드백을 반영한다. 현재 소스는 현지 구현자가 읽는다. 아래 수치는 기존 R5 계약에서 유지할 값과 이번 작업의 시작값이며, 최신 공개 페이지의 재실측 결과가 아니다.

1920 고정, 외부 320/1244/320, 헤더62+공지36, 무광 차콜/주황 테마와 좌우 레일은 유지한다. 기존 코드가 이미 승인된 치수에 맞춰져 있으면 불필요하게 재작성하지 않는다.

## 1. 배당 소수점

화면의 배당값은 정확히 소수점 두 자리로 표시한다. 일반 반올림을 사용한다.

| 원값 | 표시 |
| --- | --- |
| 3.243 | 3.24 |
| 3.246 | 3.25 |
| 3.2 | 3.20 |
| 2 | 2.00 |

적용: 두 모드의 기본 배당, 해외형 상세 마켓, 슬립의 개별 배당, 총 배당 및 배당 단위 한도. 계산식은 기존 원값을 사용한다. 예를 들어 원 배당 a와 b의 합산 배당은 a×b를 계산한 후 표시만 반올림한다. 먼저 각 배당을 반올림해 곱하지 않는다. 금액 표시는 기존 원 단위 규칙을 유지한다.

핸디 -1.5, 언오버 2.5 같은 기준점·점수·경기 수·금액은 대상이 아니다. 배당 누락/잠김/유효하지 않은 값은 기존 잠김 또는 '—'로 표시하고 NaN/undefined/임의 0.00을 노출하지 않는다.

## 2. 경기 카드 팀 행

이 화면은 예정 경기용이다. 양쪽 모드 모두 팀 사이에는 주황 VS만 표시한다. 스코어, LIVE, 진행 분/쿼터/이닝, 경기중 배지는 제거한다. 시작 일시와 리그명은 메타행에 유지한다. 예정 경기 데이터를 선택하고 실시간 fixture를 외관만 바꿔 예정 경기처럼 위장하지 않는다. 현재 데이터에 예정 경기가 부족하면 기존 데모 모델에 맞춰 안정 ID를 가진 예정 경기 샘플을 보완한다.

팀 행의 왼쪽부터 배치 순서:
홈팀 엠블럼 → 홈팀 이름 → VS → 원정팀 이름 → 원정팀 엠블럼.

| 요소 | 적용 값 |
| --- | --- |
| 팀 이름 | 15px 시작값, 기존 서체/굵기 유지, line-height 22px |
| 팀 엠블럼 | 28×28, object-fit:contain, shrink 금지 |
| 엠블럼-팀명 간격 | 8px |
| 중앙 VS | 기존 20px/주황, 중앙 영역56px 시작값 |
| 팀 행 | 기존38px 유지 |
| 카드/배당 | 카드 높이228, 기본 배당 높이36 유지 |

기존13px → 15px는 이번 확대 시작값이다. 현지 값이 이미 더 크면 오히려 축소하지 않는다. 팀 그룹은 각각 min-width:0, 긴 이름에만 ellipsis를 적용한다. 엠블럼이나 VS를 줄여 이름을 억지로 넣지 않는다. 기존 큰 로고/팀 아이콘 패널을 추가하지 않는다. 집 모양 홈 표식은 숨기되 홈/원정 데이터 의미는 유지한다.

기존 팀 asset mapping과 원본을 사용한다. 원정팀에 홈팀 로고를 반복하거나 종목 공 아이콘을 모든 팀의 로고로 대체하지 않는다. 매핑이 없는 팀은 기존 자산을 찾아 연결하고, 끝내 없으면 같은28px 영역에 해당 팀의 이니셜 fallback을 사용한다. 존재하는 로고를 생략할 이유로 fallback을 일괄 사용하지 않는다.

## 3. 헤더 로고 잘림

사용자 보고: 현재 로고 일부가 잘린다. 원인은 아직 특정하지 않았다.

실제 img의 src/자연 크기/박스 크기와 부모의 overflow, clip-path, mask, 고정 높이, object-fit, flex-shrink, 사선 장식을 확인한다. 이미지 원본의 잘림인지 컨테이너 잘림인지 구분한 뒤 해당 부분만 고친다.

동봉 원본 assets/branding/aldebaran-wordmark.png는 승인된1101×120 레터링이다. 비율을 유지하며 img에 object-fit:contain, flex-shrink:0을 적용할 수 있다. 182px 폭이면 높이는 182×120÷1101 ≈19.84px이다. 현재 승인 크기가 다르면 그 크기 안에서 전체 글자를 보존한다. 사선 장식이 로고를 자르면 장식용 별도 요소에만 클리핑하고 로고 콘텐츠에 적용하지 않는다.

로고 문제를 가리려고 헤더 높이/메뉴 폭/전체 그리드를 바꾸거나 이미지를 왜곡하지 않는다. 헤더 엠블럼을 재삽입하지 않는다.

## 4. 헤더 메뉴와 모드

헤더 선택 상태와 hover의 추가 디자인 작업은 보류한다. 기존 표현은 그대로 두고 새 애니메이션·발광·선택 도형 등을 만들지 않는다. 기존 최소 활성 표식과 접근성 상태로 현재 모드를 식별할 수 있게 한다.

- 선택 가능한 GNB: 국내형 스포츠, 해외형 스포츠.
- 보이는 상태로 비활성: E스포츠, 인플레이, 카지노, 슬롯, 미니게임, 가상 스포츠, 자유게시판, 경기결과.
- 비활성 항목은 클릭/Enter/Space/기존 링크 이동으로 선택되지 않는다. native disabled 또는 적절한 aria-disabled 처리와 핸들러 차단을 함께 사용한다. 선택되는 척하는 임시 팝업을 띄우지 않는다.
- 초기 모드는 해외형이다. 좌측 퀵메뉴 등에 동일한 국내형/해외형 진입점이 있으면 같은 mode 상태와 연결한다.
- 로그인/계정/공지/레일 서비스 전체를 비활성화하지 않는다.

## 5. 해외형 스포츠

현재 구현의 중앙 왼쪽 경기 카드 + 오른쪽 상세 배팅 구조를 유지한다. 카드 자체는 위1~2번 수정사항을 반영한다.

- 왼쪽 경기 목록과 오른쪽 상세 마켓은 서로 독립 스크롤.
- 종목 탭과 선택 경기 제목/마켓 탭은 현재 고정 방식 유지.
- 경기 선택으로 오른쪽 상세가 바뀌고 왼쪽 위치는 보존된다.
- 배당 선택으로 어느 목록도 맨 위로 이동하지 않는다.
- 상세 마켓 진입 버튼/마켓 수/상세 필터는 유지한다.

## 6. 국내형 스포츠

중앙 전체를 경기 카드 2열로 사용한다. 오른쪽 상세 배팅 패널, 상세 필터, 선택 경기 제목, 트래커는 표시하지 않는다. 단순히 해외형 오른쪽 목록에 카드를 끼워 넣고 독립 스크롤을 남기지 않는다.

같은 카드 컴포넌트/기본 배당3줄을 사용하며 하나의 경기 목록을 왼쪽→오른쪽→다음 줄 순서로 배치한다. 같은 경기를 양쪽에 복제하지 않는다. 기존 리그별 묶음은 유지하고 리그 제목 아래에서 해당 경기들을 2열 grid로 표시한다. 홀수인 그룹의 마지막 오른쪽은 비워 두며 가짜 경기로 채우지 않는다.

상단 종목 컨트롤은 중앙 상단에 한 번만 둔다. 현재 왼쪽 탭의 크기/간격을 유지하고 두 배 폭으로 늘리거나 오른쪽에 복제하지 않는다. 그 아래에 단일 overflow-y:auto 영역을 두고 리그 제목과 두 열 카드가 함께 스크롤되게 한다. 각 카드열/리그별 목록에 overflow-y:auto를 추가하지 않는다.

카드 크기는 해외형과 같게 유지한다. 기존 R5 계약을 적용한 치수 예:
- 중앙 내부 폭1226.
- 공통 패널 border 양쪽2 + 목록 padding 양쪽20을 빼면1204.
- 카드587×2 + 열간격30 =1204.
- 따라서 기존 해외형 카드587px를 그대로 쓰면서 중앙 두 열의 카드 시작 위치도 유지할 수 있다.
이 산식은 국내형 공동 패널 구현 예다. 최신 소스의 승인 치수가 다르면 실제 카드 너비를 기준으로 계산하고, 외부 프레임을 변경하지 않는다. 30px는 카드 사이 실제 여백이며 기존 외부 패널간8px와 다른 값이다.

국내형 카드에는 상세 마켓 수/추가 배팅 진입 버튼을 숨긴다. 상세가 없는 곳에 작동하지 않는 버튼을 남기지 않는다. 팀 행을 눌러 해외형으로 강제 이동하지 않는다. 기본 배당 버튼은 기존 슬립으로 정상 연결한다.

## 7. 모드 전환과 스크롤 상태

mode는 domestic/european 두 값으로 관리한다. 기존 슬립/금액/계정 상태는 모드 외부의 현재 저장소를 재사용한다. 같은 경기/마켓/선택은 동일한 안정 ID를 유지한다. 모드가 바뀌어도 베팅 선택을 중복 생성하거나 초기화하지 않는다. 기존 슬립의 종목/마켓 조합 제한이 있으면 그대로 적용한다.

국내형 공동 위치1개, 해외형 목록/상세 위치2개를 각각 보존한다. 처음 국내형에 들어가면 맨 위, 해외형으로 돌아가면 이전 위치와 선택 경기를 복원한다. 두 개 스크롤의 위치를 매번 맞추는 방식은 국내형 공동 스크롤이 아니다.

필터/검색은 활성 모드의 목록에 적용하고 카운트도 실제 결과와 일치시킨다. 데이터가 바뀌어 저장 위치가 범위를 넘으면 유효 범위로 보정한다. 기존 탑 이동은 국내형에서는 공동 목록, 해외형에서는 현재 경기 목록 대상으로 연결하고 승인된 부드러운 모션을 유지한다.

리그 접힘/펼침은 기존 짧은 모션을 재사용한다. 국내형에서 리그 하나를 접으면 그 리그의 양쪽 카드가 같이 접힌다.


## 현지 R6 실측 적용값

# ALDEBARAN R9 — 구현 사양

## 0. 범위

현재 프레임을 기준으로 필요한 요소만 바꾼다. 1920 고정, 플랫한 버튼, 무광 차콜, 주황 `#ff641f`, 흰색 계열을 유지한다. WOG를 새 디자인 기준으로 사용하지 않는다. 이 문서의 사양만으로 작업하며 Figma 링크를 다시 전달하거나 접속할 필요가 없다.

## 1. 헤더의 미반영 항목

### 1-1. 비활성 GNB도 흰색

국내형/해외형 외 메뉴8개의 글자는 `#f5f4f4`, opacity1로 표시한다. 부모/disabled 스타일의 opacity·brightness 저하도 GNB 범위에서 해제한다. 실제 이동/선택 기능은 계속 비활성이며 마우스/Enter/Space로 새 페이지나 팝업을 열지 않는다. 포인터는 기본 커서로 유지한다. 공용 disabled 스타일을 수정해 다른 버튼의 상태까지 바꾸지 않는다.

### 1-2. 로고 오른쪽 여유

원본 워드마크, 현재 표시 폭182px, 비율, 왼쪽 위치를 유지한다. 배경판과 주황 선/사선 장식의 오른쪽 경계를 넓혀 마지막 N과 가장 가까운 장식 사이에 시각적인 여유를 만든다. 시작 기준은 최소12px, 우선16px 정도로 한다. 이는 사용자 지정 치수가 아니라 구현 시작값이다. 기존 브랜드 예약 영역의 여유를 먼저 쓰고 GNB 전체 시작 위치를 밀지 않는다. clip/mask는 장식 요소에만 적용한다. 로고 축소나 원본 이미지 수정으로 해결하지 않는다.

### 1-3. 선택과 hover

선택된 국내형/해외형 한 항목에만 주황 글자와 하단2px 밑줄을 표시한다. 비선택 메뉴는 흰색이다. 선택 이미지, 공/트로피, 배경 전환, 이동/확대/발광을 추가하지 않는다. 이미 v8에서 적용된 부분은 재구현하지 않는다. 잔여 `:hover` 색 변화와 상위 버튼의 hover 효과를 GNB 범위에서 제거한다. 기존 NEW/LIVE 문자 배지와 키보드 focus-visible은 유지한다.

## 2. 공지 행 우측 유틸리티

대상은 공지사항, 이벤트게시판, 출석체크, 고객센터, 이용규정의 아이콘과 텍스트이다. 기본 색을 밝은 흰색 계열 `#f5f4f4`, opacity1로 맞춘다. 아이콘에도 같은 밝기를 적용해 비활성처럼 보이는 인상을 없앤다. 공지 행 높이36px, 기존 간격과 이동 경로/클릭 동작은 보존한다. 새 서비스나 불필요한 hover 연출은 추가하지 않는다.

## 3. 종목 선택바

### 3-1. 내용과 배치

순서: 전체 / 축구 / 농구 / 야구 / 배구 / 아이스하키. 각 버튼 내부는 아이콘 → 종목명 → 경기 수의 한 줄이다. 경기 수는 현재 필터 정책의 실제 예정 경기 데이터에서 산출한다. 예시168/128 또는 스크린샷 숫자를 하드코딩하지 않는다. 0인 종목도 0으로 표시한다. 기존 승인 아이콘과 ALL을 재사용하며 새 종목은 추가하지 않는다.

현재609px 한 패널보다 선택바 자연 폭이 넓다. 중앙1226px 영역 위에 두 열을 아우르는 공통 선택 행을 하나 둔다. Figma의832px은 샘플 내용의 측정 결과이며 고정 폭도, 배치 좌표도 아니다. 공통 행 배치는 기존 컬럼을 유지하면서 폭 충돌을 해결하기 위한 구현 선택이다.

- 행은 중앙 영역의 왼쪽 기준선에서 시작한다. 여분 공간을 버튼 너비에 균등 배분하지 않는다.
- 행 내부 높이34px, 상하 여백8px씩을 시작값으로 사용한다. 종목바 때문에 생긴 이전104px 높이의 빈 래퍼/최소높이를 제거한다.
- 해외형: 선택바는 공통 행에 고정되고, 아래 두 패널은 기존 너비/가로 위치와 독립 스크롤을 유지한다. 오른쪽 선택 경기 제목·마켓 필터도 고정 영역으로 유지한다.
- 국내형: 같은 선택바 한 개, 아래 리그별 카드2열은 한 scroller로 같이 움직인다.
- 사이트를 반응형으로 바꾸지 않는다. 버튼의 내용 기반 가변 폭과 페이지의 고정 폭은 별개이다.

## 6. 배당 데이터

목표는 서로 다른 숫자를 무작위로 늘리는 것이 아니라 한 경기의 전력/득점 가정에서 서로 맞는 가격을 만드는 것이다. 기본/상세/슬립이 동일한 선택 데이터를 사용해야 한다.

### 6-1. 이번 구현 방식

외부 API·유료 구독 없이 경기별 고정 합성 배당 스냅샷을 작성한다. 브라우저에서 새로고침·필터·모드 전환마다 가격을 재생성하지 않는다. 현재61개 예정 경기 각각의 matchId에 연결된 자료를 준비하고 누락된 경기에 옛 고정1.78/2.03 등을 몰래 fallback하지 않는다. 다른 종목을 축구 모델로 일괄 계산하지 않는다.

실제로 확인된 동시점 가격 묶음이 이미 있다면 출처/사업자/시각을 기록한 채 사용할 수 있지만, 이번 완료를 위해 새 API 계약이나 장기 수집을 시작하지 않는다. 합성값은 실제 팀의 분석 결과나 실시간 배당이라고 표현하지 않는다.

### 6-2. 경기별 설계와 연결

- 각 경기에 식별자, 종목, 규칙(정규시간/연장 포함/기간), 전력 차이와 득점 가정, sourceKind, datasetVersion을 기록한다.
- 축구는 홈/원정 득점 확률표에서 승무패·핸디캡·총점·팀 총점·양팀 득점 등을 일관되게 산출할 수 있다. 첨부 계산 예제는 이 방식의 합성 예시이다.
- 농구/미식축구는 득점차·총점 및 경기 규칙을 반영하고, 아이스하키는 낮은 득점과 정규시간/연장 승패 구분을 반영한다. 야구/배구는 실제로 노출되는 경우에만 해당 종목 규칙으로 작성한다.
- 균형 경기, 홈 우세, 원정 우세, 낮은 총점, 높은 총점 등을 경기별로 분산한다. 같은 예제 세트의 단순 순환 배정을 새 다양성으로 취급하지 않는다.
- 배당의 일부 중복은 정상이다. 모든 숫자를 억지로 고유하게 만들지 않는다. 문제는 전 경기의 동일한 쌍 반복이다.
- 기본 라인과 상세 패널의 같은 라인은 반드시 같은 가격이다. 왼쪽과 오른쪽에서 별도 생성 함수를 호출하지 않는다.
- 기존 `markets[0]` 결과 / `[1]` 총점 / `[2]` 핸디캡의 데이터 순서와 선택 ID를 보존한다. 화면의 결과→핸디캡→총점 표시 순서와 내부 배열 순서를 혼동하지 않는다.

### 6-3. 수학적·표시 규칙

- 일반적인 완전한 상호배타 결과 세트에서는 가격 O의 내재확률은1/O이며, 세트 합계가1보다 약간 큰 구조로 모델의 여유분을 반영한다. 이는 실제 수익률을 뜻하지 않는다.
- 단순 예제: 확률 p의 합이1, 설정 여유분 m이면 `O=1/(p×(1+m))`. m은 합성 자료 설정값이지 모든 실제 마켓의 고정 표준이 아니다.
- 적중 시 전액 정산되는 일반/반점 라인에 위 단순식을 사용한다. 푸시/정수 핸디캡/쿼터 핸디캡은 해당 환급·분할 정산을 고려해야 하며 단순 결과 확률 합으로 잘못 처리하지 않는다.
- 같은 규칙에서 오버 기준점이 올라가면 오버 가격은 내려가지 않고, 언더 가격은 올라가지 않는다. 홈에 더 불리한 핸디캡일수록 홈 적중 가격은 내려가지 않는다. 두 자리 반올림으로 같은 가격이 되는 것은 허용한다.
- 모든 선택 배당은 유효한1초과 유한수이다. 원천 가격을 두 자리 소수로 확정해 저장하고 기존 공통 포매터로 두 자리 표시한다. 결합 배당 계산 중간값을 계속 두 자리로 잘라 누적하지 않는다.
- 카드/상세/슬립의 같은 선택은 같은 배당을 보여준다. 현재 저장 영수증을 새 데이터로 소급 변경하지 않는다. 오래된 슬립 처리 정책은 기존 로직을 확인해 유지하며 필요하면 datasetVersion으로 구분한다.
- 데모의 가격 변동 화살표, 가짜 갱신 타이머, 라이브 스코어를 추가하지 않는다. 이번 대상은 예정 경기이다.

- 배너 외곽은 현재 약 306×61px, radius 4px를 유지한다. 기존 CSS 비율 때문에 높이가 약 60.6px이면 이번에 61px로 반올림해 전체 레일 높이를 바꾸지 않는다.
- 원본은 그대로 복사한다. 배경은 중앙 배치·반복 없음, 기존 첫 배너의 맞춤 방식을 사용한다. 별도 우측 megaphone/compass/monitor/users/19 아이콘 요소는 제거한다. 이미지에 이미 들어 있는 그림과 중복되면 안 된다.
- 기존 제목/설명은 실제 HTML 텍스트로 유지한다. 제목 주황색과 서브텍스트 색/굵기/글자 크기는 유지한다. 기존 보고상 제목 17px, 설명 11px이며 이번 요청은 이 폰트 축소가 아니다.
- 두 텍스트를 세로 묶음으로 만들고 배너 높이의 중앙에 정렬한다. 가로는 왼쪽 정렬, 현재 좌측 padding 유지(기존 보고 12px).
- 제목과 설명 사이 간격은 현재보다 작게 한다. 구현 시작값은 명시적 gap 2px를 권장한다. 2px는 사용자 지정 수치가 아닌 구현 제안이다. 현재 값이 이미 2px 이하라면 간격을 키우지 않고 불필요한 margin/큰 line-height로 생긴 공백부터 줄인다.

- 배경의 오른쪽 그래픽 위로 글자를 이동하지 않는다. 검은 라벨 바나 새 어두운 오버레이를 추가하지 않는다.
- 이 정렬 규칙은 이미 이미지가 적용된 첫 고객센터를 포함한 6개 모두에 적용한다. 기존 버튼/링크 전체 클릭 영역과 목적지는 유지한다.

## R10-02 — 좌측 카지노 / 슬롯 이미지 버튼

## R10-03 — 종목 선택 버튼 내부 요소 축소

| 요소 | 확정값 |
| --- | --- |
| 아이콘 | 20×20 CSS px |
| 종목 이름 | 14 CSS px |
| 경기 수 숫자 | 12 CSS px |

- 수정 전 실제 탭 치수를 한 번 읽고, 필요하면 종목별 CSS 폭/최소폭 또는 기존 크기를 보존하는 슬롯을 사용한다. 런타임 DOM 측정/ResizeObserver를 새로 추가하지 않는다.
- 아이스하키의 더 긴 버튼 폭을 유지한다. 모든 버튼을 아이스하키 폭으로 통일하지 않는다.
- 경기 수는 실제 필터 데이터 값을 사용한다. 한 자리부터 세 자리까지 수용하는 공간은 보존한다. 숫자 폰트가 작아지면서 3ch의 실제 폭도 줄어드는 점을 고려한다.
- 숫자 배지와 아이콘·종목명이 기존 버튼 안에서 세로 중앙에 놓이게 한다. 행 높이 조정이 필요하면 종목명 17px/숫자 15px line-height를 시작값으로 사용할 수 있으나 외곽 크기와 정렬 유지가 우선이다.
- 이 축소를 좌측 레일 종목 목록·팀명·마켓 제목·배너 제목에 전역 적용하지 않는다. 중앙 공통 종목 선택 바만 대상이다.

## R10-04 — 중앙 바깥 보드의 시각 표현만 제거

최종 사용자 의도: 중앙 콘텐츠 요소들이 사이트 배경 위에 직접 놓인 것처럼 보이게 한다. 중앙 내부 카드 프레임은 지금 상태가 좋으므로 그대로 유지한다.

- 중앙 전체를 둘러싼 큰 보드의 배경 fill과 외곽선만 보이지 않게 한다. 같은 바깥 보드를 만드는 장식 shadow/가상 요소가 있다면 그 부분만 제거한다.
- 배경을 transparent로 처리한다. 내부 카드와 구분되던 큰 사각형 색면이 남아 있으면 안 된다.
- 외곽 border가 공간을 차지하고 있다면 border-color: transparent처럼 공간을 보존하는 처리를 우선한다. border: 0으로 콘텐츠 위치/폭이 달라지게 하지 않는다.
- DOM 컨테이너를 삭제하거나 display: contents로 치환하지 않는다. 현재 grid/flex, padding, gap, overflow, scroll 높이와 좌표는 유지한다.
- 종목 버튼, 리그 제목/그룹, 개별 경기 카드, 세부 마켓 카드, 배당 버튼의 자체 배경/테두리는 유지한다. 좌우 레일의 패널도 유지한다.
- 활성/선택/키보드 focus 표시를 지우지 않는다. R10-05에 명시된 마켓 왼쪽 강조선 두께만 예외다.
- 국내형과 해외형의 공통 중앙 바깥 보드에 모두 적용한다. 해외형 세부 마켓 영역도 큰 바탕 보드의 일부라면 동일하게 투명화하되 개별 세부 마켓 프레임은 보존한다.
- references/central-board-before.png와 central-board-after.png는 제거할 바깥 보드의 관계를 설명한다. 회색을 실제 테마에 적용하거나 서로 다른 이미지 크기를 레이아웃 수치로 해석하지 않는다.

초기 설명에서 나온 ‘내부 중첩 카드 프레임 정리’ 해석은 사용자가 정정했으므로 실행하지 않는다.

## R10-05 — 세부 베팅 마켓 섹션의 강조선

- 대상: 승패, 핸디캡, 언더/오버, 총 득점 홀/짝, 쿼터, 홈/원정 팀 득점 등 세부 마켓의 각 섹션 왼쪽 주황색 세로 강조선.
- 렌더되는 선의 두께를 정확히 1 CSS px로 만든다. 현재 색상·높이·모서리 표현과 제목 위치는 유지한다.
- border-left/inset shadow/가상 요소 중 실제 그리는 규칙을 좁게 수정한다. 두 규칙이 겹쳐 두꺼워지지 않게 한다.
- 기존 두꺼운 border가 레이아웃 공간을 차지한다면 투명 공간+1px 장식 등으로 기존 제목 좌표를 보존한다. 선을 줄였다는 이유로 글자를 왼쪽으로 이동시키지 않는다.
- 펼침/접힘 상태에 동일하게 적용하고, 클릭/접기 동작은 유지한다.
- 헤더 활성 밑줄, 선택 종목 버튼 테두리, 선택 배당 표시, 다른 카드 테두리에 적용하지 않는다.

| 경기 수 | 12 CSS px, 현재 폰트·굵기 유지 |
| 버튼 높이 | 현지 현재 값 유지, 새 높이로 재설계하지 않음 |
| 버튼 폭 | 내용 너비 + 일정한 내부 간격 + 같은 좌우 패딩 |
| 버튼 좌우 패딩 | 동일하고 현재보다 작게, 종목/선택 상태와 무관하게 같은 값 |

- 기존 종목별 고정 width/min-width, flex: 1, space-between으로 생긴 불균형, 수량 min-width: 3ch 등 불필요한 예약 폭을 제거한다. 아이콘/이름/수량을 실제 내용 크기의 한 줄 inline-flex로 배치한다.
- 한 자리 수량 0/7에 세 자리 공간을 예약하지 않는다. 128처럼 세 자리로 늘어나면 배지와 버튼 전체가 함께 늘어난다. 줄바꿈/말줄임/숫자 잘림을 만들지 않는다.
- 외곽 폭 유지보다 이번 content-fit 지시가 우선이다. 모든 버튼을 아이스하키 최대 폭으로 통일하지 않는다.
- 시작값 제안: 버튼 좌우 padding 8px, 내부 gap 8px, 배지 좌우 padding 4px. 이 세 값은 사용자 지정이 아닌 구현 제안이다. 현재 값이 이미 더 작으면 늘리지 말고, 참조의 균형과 기존 높이에 맞춰 최소 조정 후 최종값을 기록한다.
- 버튼 간 기존 간격, 선택 테두리·색, ALL 표현, 글자 크기, 세로 중앙 정렬은 유지한다. 선택 테두리 때문에 좌우 패딩이 달라지지 않게 box-sizing과 border 공간을 일관되게 유지한다.
- 런타임 DOM 측정/ResizeObserver나 글자 수별 폭 계산은 필요하지 않다. 현재 flex 레이아웃과 콘텐츠 기반 크기로 구현한다.

## R15-05. 실제 마켓 확장과 경기별 차이

resources/market-catalog.json은 115개 재사용 계열, resources/market-generation-plan.json은 적용 순서와 종목별 생성 조건이다. 공식 출처와 개별 종류는 resources/market-research.ko.md를 참고한다. 조사를 다시 처음부터 반복하지 말고 실제 구현에 부족한 명단/규칙만 필요한 범위에서 확인한다.

### 제공 범위

경기/팀/구간 마켓을 먼저 충분히 구현하고, 지원 가능한 코너·카드·기록을 추가하며, 확인된 선수 명단이 있는 경기는 선수 마켓까지 이번 작업 안에서 확장한다. 임의 선수·잘못된 소속으로 채우지 않는다. 선수 확보가 어렵더라도 앞 단계의 종목별 마켓 확장을 완료한다.

| 종목 | 경기·팀·구간 중심의 풍부한 경기 목표 | 선수 데이터 포함 확장 목표 |
| --- | ---: | ---: |
| 축구 | 55–100 | 100–220 |
| 농구 | 60–110 | 150–300 |
| 야구 | 45–90 | 100–200 |
| 아이스하키 | 40–85 | 80–160 |

이 범위는 설계 목표이고 실제 사이트 평균이나 경기별 할당량이 아니다. 모든 경기에 같은 세트를 넣지 않는다. 프리시즌/친선·부족한 지원 조건에 따른 소규모 프로필은 허용한다. 주요 정상 경기에서도 기존 10개 수준을 그대로 유지한 채 숫자만 올리는 것은 미완료다. 지원 가능한 범위를 최대한 구현한 후 실제 최소/중앙값/최대와 제외 이유를 보고한다.

축구 68개 설계 예시의 합은 3+10+13+5+10+10+8+6+3=68이다. 이는 팀·구간만으로 충분히 확장할 수 있다는 예시이며 경기마다 이 구성을 그대로 복제하라는 지시가 아니다.

### 집계 정의

N은 상세에서 제공하는 고유 활성 **개별 마켓 수**다. 미리보기 기본 마켓도 한 번만 포함한다. 하나의 질문에 대한 선택지를 여러 마켓으로 세지 않는다.

- 핸디캡 5라인 × 각 2선택지 = 5마켓 / 10선택지.
- 정확한 스코어 20선택지 = 1마켓.
- 선수 6명의 독립 득점 O/U = 6마켓 / 12선택지.

아코디언/탭/미리보기 중복·빈 항목·렌더러 미지원 유형·유효 배당 없는 항목·동일 조건 별칭은 제외한다. DNB와 동일 범위의 아시안 0, 첫 이닝 득점 유무와 0.5 O/U 등은 중복 제거한다. 스코프·조건이 다르면 별도 마켓으로 구분한다.

집계는 상세의 전체 마켓 배열에서 하고 UI 필터·아코디언 접힘·가상 렌더링 여부에 영향받지 않아야 한다. N+와 상세의 소스가 다르면 안 된다. 접근성 이름은 기존 팀명을 보존하면서 ‘전체 마켓 N개 보기’를 설명한다. 0개 버튼 처리와 국내형의 기존 진입 동작은 현재 정책을 보존한다.

### 현실적인 구성

종목, 경기 형식, 통계 지원, 확인된 로스터, 선발투수·골리, 프로필에 따라 유형·구간·라인 수·선수 수를 다르게 한다. 같은 종목에서 숫자가 우연히 같을 수는 있다. 고의로 모든 숫자를 고유하게 만들 필요는 없다.

기존 합성 배당 모델을 재사용/확장하고 한 경기의 기본 결과·핸디캡·총점·팀 총점은 일관된 모델에서 생성한다. 반대 선택지, 대체 라인 난도, 팀 기준값의 방향과 합리성을 확인한다. 프레임마다 난수를 새로 뽑거나 관련 선택지의 배당을 무조건 곱하지 않는다. 지원하지 못하는 타입은 노출/집계에서 제외하고 이유를 기록한다.

축구는 정규/추가시간과 연장·진출을 구별한다. 농구는 리그의 하프/쿼터와 마켓별 연장 범위를 명시한다. 야구는 첫 5이닝과 단일 5회, 초·말, 2방향 환불/3방향 무승부를 구별한다. 하키는 정규 60분/연장·슛아웃 포함, 1~3피리어드, 팀 점수와 선수 기록을 구별한다. 모든 종목에 축구나 농구의 구간 라벨을 재사용하지 않는다.

시즌 우승/장기 선수상/진행 상태가 필요한 다음 타석·다음 공격 등 인플레이 전용 항목은 프리매치 한 경기의 수량에 섞지 않는다. SGP의 모든 조합도 마켓 수에 포함하지 않는다.
