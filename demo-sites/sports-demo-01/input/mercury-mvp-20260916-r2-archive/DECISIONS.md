# MERCURY — 유지해야 할 결정

문서 세트: MVP R2 · 2026-09-16  
뒤집으면 문제가 되는 결정만 유지한다. LOCKED는 사용자 확정이다. 실제 구현 완료와는 다르다.
수치·세부 시안은 DESIGN_SPEC의 PROPOSED로 관리한다. 수정 이력을 누적하지 않는다.

## D01 — 제품 범위 · LOCKED

MERCURY는 제작 상담을 위한 독립 스포츠 데모 한 페이지다. 헤더·좌측 서비스·중앙 경기·우측 계정/슬립을 유지한다.
실시간 스포츠 기본 선택. 중앙은 실시간 스포츠 → 마감임박 → 인기경기의 3열 목록이다.
히어로·중앙 콘텐츠 바로가기·카지노/슬롯 갤러리를 추가하지 않는다. TITAN 홍보 사이트와 HADES는 수정 대상이 아니다.

## D02 — 1920 고정 화면 · LOCKED

1920×1080 모니터의 일반 브라우저를 기준으로 하며 콘텐츠 높이는 브라우저 상단 UI를 제외한다.
1920 초과 화면에서 중앙·카드 확장 금지. 모바일·태블릿 재배치와 전체 축소 맞춤은 범위 밖이다.
1920 표시 정상이라는 사용자 확인을 보존하고 초과 폭 확장을 별도 결함으로 처리한다.

## D03 — 독립 스크롤과 표시 · LOCKED

좌측·중앙·우측 독립 스크롤은 유지하되 굵은 트랙·손잡이·화살표를 노출하지 않는다.
스크롤바를 숨기려고 콘텐츠 이동까지 막지 않는다.

## D04 — 색상 역할 · LOCKED

전체는 거의 트루 블랙, 패널은 조금 밝은 중립 면과 입체감.
골드는 활성 텍스트·헤더 하단선·주요 악센트에 진하고 선명하게, 아이보리는 LIVE 같은 보조 칩의 면에 사용한다.
전체를 갈색·황색으로 물들이지 않는다. 정확한 HEX는 아직 사용자 승인값이 아니다.

## D05 — 최소 완성도와 감사 기준 · LOCKED

개별 버튼·탭·패널·호버에서도 완성품 수준의 정밀함이 보여야 한다. 기본 박스·색상 통일·기능 작동만으로 완료시키지 않는다.
품질 감사 스레드가 https://wog-1000.com/ 을 직접 보고 전체 완성도의 하한점으로 판단한다.
WOG의 디자인·팔레트·자산을 따라 만드는 지시가 아니다. MERCURY의 합의된 디자인과 배치를 유지한다.
WOG 사이트의 내용을 문서에 재서술할 필요가 없다. 사양 준수와 비교 완성도를 별도로 판정한다.

## D06 — 카드 구조와 밀도 · LOCKED

팀 대결·중앙 점수/진행·마켓 기준·배당의 읽기 관계부터 재설계한다. 반려된 긴 카드의 단순 축소·재색칠로 끝내지 않는다.
기본 마감임박·인기경기에 하나씩만 놓고 남는 넓은 공백을 방치하지 않는다. 수량·치수는 실행안으로 검수한다.

## D07 — 효과 방향 · LOCKED

강한 골드 글로우·광택·대기·호버를 허용하고 과하면 검수에서 줄인다.
반려된 넓고 흐릿한 대각선 카드 오버레이, 프레임과 단절된 굵은 모서리 광택선은 재사용하지 않는다.
효과의 부위·변화·시간은 사양으로 통제한다. 일괄 최소화하거나 사양 밖 효과를 무작정 추가하지 않는다.

## D08 — 첫 결과와 승인 · LOCKED

첫 공개 결과는 기능·구성 일부가 동작했지만 시각적으로 반려됐다. 현재 외형은 보존할 승인 디자인이 아니다.
정상 동작은 보존한다. 지시 기록·구현·직접 검증·사용자 시각 승인은 각각 구분한다.

## D09 — 자산 사용 범위 갱신 · LOCKED

R1의 ‘이미지 없는 사이클’은 후속 지시로 갱신됐다. 수집된 스포츠 식별 이미지와 사용자 제공 브랜드·UI 이미지를 적극 적용한다.
참고 스크린샷은 관찰용이며 사이트 배경으로 붙이지 않는다. 필요한 신규 이미지는 사용자가 제작한다.
임의 이미지 생성·영상 제작은 하지 않는다. 향후 배너·약 6초 WebM은 실제 제공·지시 범위에 따라 적용한다.

## D10 — 진행·구현·감사의 역할 분리 · LOCKED

기존 전체 진행 스레드와 Sites 구현 스레드에 독립 품질 감사 스레드를 추가하는 방식으로 운영한다.
R1의 단일 담당 구현·검수 방식은 대체한다. 감사 스레드 실제 생성·실행 여부는 STATE에서 별도로 관리한다.
감사자는 화면을 직접 보고 문제를 보고하며 소스·합의 기준을 임의 변경하지 않는다. Sites 소스·배포는 해당 Site의 구현 담당자가 소유한다.
다수 서브 에이전트의 자동 병렬 코딩 도입 지시는 아니다.

## D11 — 네 문서와 계속되는 기록 · LOCKED

운영 문서는 AGENTS·STATE·DESIGN_SPEC·DECISIONS만 유지한다. HISTORY/HANDOFF/TASKS/NOTES/별도 감사 MD를 추가하지 않는다.
후속 피드백·지시·자산과 최신 결과를 현재 상태·사양·중요 결정에 반영한다. 접수와 실행을 섞지 않는다.
STATE는 현재 기준으로 교체하고 상세 과거 수정은 기존 대화·버전으로 추적한다.
MD만으로 부족한 디자인 지시는 실제 캡처·상태 비교·주석·원본 자산으로 보완한다.

## D12 — 기존 사이트와 데모 경계 · LOCKED

브랜드 MERCURY와 기존 공개 주소를 유지한다. 임의로 새 사이트를 만들지 않는다.
실제 경기 정보를 가져오는 것은 허용한다. 실제 인증·충전·환전·베팅 거래는 연결하지 않는다.
조작 경험은 데모 상태로 완성한다. 문서 기록 요청을 사이트 수정·배포 요청으로 확대하지 않는다.

## D13 — 폰트 역할 · LOCKED

기본 UI: Pretendard JP / 일본어: Heisei Mincho Std / 필요한 강조: Omnigothic / 스코어: DIN Condensed.
기존 시스템의 설정을 사용하되 파일·등록·실제 적용 상태를 확인한다. 임의 대체 폰트로 완료 처리하지 않는다.
헤더 레터링은 별도 제공 이미지다. 글자 크기·행간·강조 위치의 세부안은 실제 화면에서 검수한다.

## D14 — 스포츠 자산과 슬롯 · LOCKED

수집 루트는 `E:\codexwork\Site-Skin-edit\TEMP\Sports-Images`다. 작업 시작 시 수집 완료·누락 상태와 메타데이터를 확인한다.
국기·리그·팀·종목 이미지는 실제 데이터와 대응시켜 사용한다. 수집 중이라는 설명을 완료 확인으로 바꾸지 않는다.
64×64~256×256은 수집 원본의 목표 크기다. 표시 슬롯에 맞춰 비율을 유지하고 카드·행·패널을 원본 크기에 맞춰 늘리지 않는다.

## D15 — 실제 경기와 데모 배당 · LOCKED

가상 팀·가상 대진만으로 화면을 채우는 R1 방식을 대체한다. 실제 진행 경기·최근 주요 경기·예정 경기를 사용한다.
팀·리그·국기·홈/원정·시각·진행 상태·점수를 일관되게 맞춘다. 실제 경기의 스냅샷으로 구현할 수 있으며 상시 실시간 피드는 필수가 아니다.
배당은 납득할 수준으로 구성하거나 실제 유사 배당을 참고할 수 있다. 데모 배당을 실제 제공 배당으로 주장하지 않는다.
과거 경기나 정적 스냅샷을 현재 진행 중인 실시간 피드라고 속이지 않는다. 실제 거래는 없다.

## D16 — 사용자 이미지 제작·전달 · LOCKED

CSS/벡터로 필요한 품질을 못 내는 서비스 아이콘·패널 등의 이미지는 위치·표시 슬롯·권장 원본·스타일·필요 상태를 적어 요청한다.
사용자가 이 스레드에 원본을 전달하면 다음 지시서에 실제 파일과 적용 매핑을 포함한다. 링크나 참고 설명만으로 전달 완료 처리하지 않는다.
요청 대기는 STATE, 상세 규격·적용 기준은 DESIGN_SPEC에 둔다. 불필요한 제작 요청이나 별도 운영 문서를 늘리지 않는다.

## D17 — 제공 브랜드 이미지 · LOCKED

사용자가 제공한 가로 MERCURY 레터링은 헤더, 원형 행성 엠블럼은 좌측에 적용한다.
전달 파일은 `assets/branding/mercury-wordmark.png`, `assets/branding/mercury-emblem.png`다.
원본 비율·색·투명도를 유지한다. 임시 문자 로고로 교체하거나 잘라내지 않는다. 좌측의 세부 위치·표시 치수는 아직 사용자 확정값이 아니다.
