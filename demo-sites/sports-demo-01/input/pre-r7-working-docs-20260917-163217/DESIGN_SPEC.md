# MERCURY — 전체 페이지 디자인·구현·감사 기준

문서 세트: **MVP R6 · 2026-09-17**  
목표: 블랙·골드·아이보리의 정밀한 스포츠 데모 한 페이지를 전체 구현하고, 독립 WOG 비교 감사·보완 후 기존 공개 주소에 반영한다.

## 0. 기준의 우선순위와 이번 수정

**LOCKED**는 사용자 확정 방향이다. **IMPLEMENTATION DEFAULT**는 바로 작업할 수 있는 실행 기본값이며 사용자 승인 시안이 아니다. 숫자 조정이 필요하면 같은 방향에서 조정하고 진행 담당이 기록한다. 수치 맞추기만으로 시각 품질을 통과시키지 않는다.

이번 R6는 다음 오류를 바로잡는다.

## 1. MVP 범위와 참고의 역할 — LOCKED

- 대상: [MERCURY](https://mercury.kexxadrix.chatgpt.site/). 실시간 스포츠가 선택된 단일 페이지다.
- 헤더 + 좌측 서비스/검색/종목/홍보 + 중앙 실시간/마감임박/인기경기 + 우측 계정/슬립/문의/이벤트.
- 중앙은 3열 경기 카드 목록이다. 히어로, 중앙 콘텐츠 바로가기, 카지노/슬롯 갤러리는 없다.

- 실제 인증·충전·환전·베팅 백엔드를 만들지 않는다. 선택·금액·가상 계정·체험 내역은 로컬 데모 상태로 동작한다.
- **WOG는 완성도 비교 기준:** 감사자가 https://wog-1000.com/ 을 직접 보고 정렬·재질·위계·조작·효과의 정교함을 비교한다. WOG의 팔레트·레이아웃·컴포넌트 외형·코드·자산은 복제하지 않는다. WOG 내용을 이 문서에 상세 재서술할 필요도 없다.
- [COBALT 카드 구성](input/mercury-mvp-r6-package/MERCURY_MVP_R6/references/COBALT_cards_reference.png)은 경기 정보 관계·3열 구성 참고다. 기존 마감 수준은 계승하지 않는다.
- [이전 반려 전체](input/mercury-mvp-r6-package/MERCURY_MVP_R6/references/MERCURY_rejected_overview.png), [반려 호버](input/mercury-mvp-r6-package/MERCURY_MVP_R6/references/MERCURY_rejected_hover.png)는 재발 금지 자료다. [WOG 캡처](input/mercury-mvp-r6-package/MERCURY_MVP_R6/references/WOG_reference.png)는 보조 자료이며 실제 사이트 감사의 대체물이 아니다.

## 2. Global

### 2.1 고정 화면과 밀도 — 방향 LOCKED / 치수 IMPLEMENTATION DEFAULT

1920×1080 **모니터**에서 탭·주소창·즐겨찾기 영역을 제외한 실제 브라우저 콘텐츠 높이를 사용한다. 높이 1080px을 웹 화면에 강제하지 않는다. 1920 미만 모바일/태블릿 지원과 전체 자동 축소는 만들지 않는다.

| 요소 | 기본값 |
| --- | --- |
| shell | width:1920px, box-sizing:border-box, shrink 없음 |
| 헤더 / 공지 줄 | 68px / 32px |
| 본문 바깥 여백 | 상하좌우 12px |
| 좌측 / 중앙 / 우측 | 272px / 1280px / 320px |
| 열 사이 | 12px × 2 |
| 중앙 카드 간격 | 12px |
| 카드 폭 | (1280 − 12×2) ÷ 3 = 약 418.67px |

가로 합계: 12×2 + 272 + 1280 + 320 + 12×2 = **1920px**.
본문 높이: 실제 innerHeight − 68 − 32 − 12×2. 예: 검수용 940px이면 **816px**이며 실제 사용자 viewport 측정값은 아니다.

1920 초과에서는 셸 내부 치수를 그대로 두고 가로 중앙에 놓는다. 2560일 때 양옆 여백은 (2560−1920)÷2=320px. 중앙 칼럼이나 카드를 늘리지 않는다.

헤더/공지 아래 좌·중·우만 각각 스크롤한다. `min-height:0; overflow-y:auto`와 적절한 overscroll 제어를 사용한다. 모든 스크롤 트랙·손잡이·화살표는 숨기고 휠·트랙패드·키보드 이동을 유지한다. 콘텐츠를 잘라 숨기는 방식으로 스크롤바 문제를 덮지 않는다.

### 2.2 컬러·재질 — 방향 LOCKED / HEX IMPLEMENTATION DEFAULT

중립 블랙 바탕 + 조금 밝은 중립 패널 + 선명한 골드 + 아이보리다. **패널 기본 면에 청색을 더하지 않는다.** 기존 푸른 차콜 토큰과 CSS의 파란/남색 그림자·그라데이션·기본 버튼 variant까지 함께 교체한다.

| 역할 | 기본 토큰 |
| --- | --- |
| 전체 바탕 | `#050505` |
| 헤더/프레임 면 | `#0B0B0B` |
| 카드/패널 면 | `#141414` |
| 돌출 버튼 윗면 / 아랫면 | `#292929` / `#171717` |
| 중립 경계 / 반사 | `#3B3B3B` / 낮은 투명도 `#767676` |
| 골드 기본 / 반사 / 음영 | `#D9AD43` / `#FFE6A3` / `#78511C` |
| 아이보리 면 / 문자 | `#F5EEDF` / `#171717` |
| 주요 문자 / 보조 문자 | `#F5F1E8` / `#B8B5AD` |
| 사용불가 | `#1C1C1C`, 낮춘 중립 문자, 잠금 아이콘 |

중립 면은 RGB 채널이 같은 값을 시작점으로 삼는다. 실제 사용되는 면이 파랗거나 갈색이면 토큰 선언만 맞았다고 통과시키지 않는다. 팀/리그/국기 원본의 파랑·빨강 등 고유색은 유지한다.

골드는 헤더 하단선, 활성 메뉴, 중요한 CTA, 선택 배당, 정밀한 베벨/반사에 집중한다. 검정 면 전체를 노란 조명으로 덮지 않는다. 아이보리는 읽기 좋은 문자뿐 아니라 LIVE/보조 칩의 밝은 면으로 드러난다. 모든 패널을 동일한 금색 테두리 박스로 만들지 않는다.

### 2.4 화면 전체의 정보·조작 깊이 — LOCKED

- 같은 의미를 이루는 정보는 같은 면 위에 묶는다. 그룹을 만들기 위해 항상 새 박스를 만들지 않는다.
- 경기 로고·팀명·진행 상태·점수는 **하나의 대결 정보**다. 시각적 바닥면과 기준선을 공유한다.
- 마켓 이름·기준값은 읽는 정보다. 배당 버튼처럼 입체 테두리·호버·포인터를 부여하지 않는다.
- 배당/서비스/실행 버튼은 누르는 대상이다. 금속 면·베벨·눌림으로 조작 가능함을 구분한다.
- 카드 프레임·제목판·작은 상태 칩은 기능에 맞게 사용한다. ‘불필요한 박스 제거’를 전체 프레임과 장식 삭제로 확대하지 않는다.

## 3. Header — 브랜드 결합과 접합부

### 3.1 브랜드 — 위치 LOCKED / 슬롯 IMPLEMENTATION DEFAULT

헤더 브랜드 영역에서 **원형 심볼 → 간격 → MERCURY 레터링** 순서로 가로 결합한다. 세로 중심을 맞추고 하나의 브랜드로 보이게 한다. 사이드바 엠블럼 패널은 제거하며 그 자리에 또 다른 빈 패널을 남기지 않는다.

272px 브랜드 영역의 시작안: 좌우 여백 각 10px + 심볼 48×48px + 간격 8px + 레터링 슬롯 196×58px = 가로 272px. 두 이미지 모두 contain, 원본 비율 유지. 헤더를 키우거나 레터링을 찌그러뜨리지 않는다. 실제 레터링/심볼의 시각 중심을 맞추되 원본을 자르지 않는다.

### 3.2 활성 탭과 하단선 — 접합 품질 LOCKED

**실행 기본안: 탭 좌·상·우 윤곽 + 헤더의 단일 공통 하단선.**

- 탭 하단의 독립 테두리/두꺼운 광택 띠를 없애고, 헤더 하단의 골드 레일 하나가 공통 기준선이 되게 한다.
- 탭 아래 모서리가 레일과 같은 y 기준에 닿게 한다. 1~2px 뜸, 아래로 돌출, 중복 선, 반사 띠와 실제 선의 위치 어긋남을 없앤다.
- 탭 좌/상/우 윤곽과 헤더 레일은 같은 골드 재질 토큰을 사용한다. 미세 반사·음영은 경계 안에서 연결한다.
- 레일은 2px 시작값. 아래 주변광 8~14px은 선의 실제 위치를 기준으로 준다. 흐릿한 빛으로 접합 오류를 가리지 않는다.
- 활성은 골드 문자와 정밀한 중립 면, hover는 해당 윤곽·문자 강조, pressed는 안쪽 음영으로 구분한다. 상태가 바뀌어도 선 위치는 고정한다.
- 사용자 대안인 ‘전체 테두리와 헤더선의 재질·위치 통일’도 가능하다. 선택한 방식은 한 가지로 통일하며 이중선이 남지 않게 한다.

메뉴: 기존 스포츠/실시간 스포츠/E스포츠/카지노/슬롯/미니게임/이벤트 유지. 실시간 스포츠 기본 활성. 로그인은 중립 버튼, 회원가입은 골드 주요 버튼. 공지는 32px 내 한 줄로 정리하고 데모 안내는 한 곳에 명료하게 둔다.

## 5. Main Content — 전체 카드 목록

### 5.1 분류·밀도

순서는 **실시간 스포츠 → 마감임박 → 인기경기**. 각 분류 3열을 유지한다. 실행 기본은 각 3경기, 총 9개의 실제 대진이다. 첫 화면 기본 목록을 1개짜리 행으로 남기거나 같은 경기를 반복해 채우지 않는다. 검색/필터 결과가 적어지는 상태는 정확한 count와 결과 안내로 처리한다.

제목판 기본: 48px, 카드까지 10px, 분류 사이 20px. 제목 부분은 금속 명패 성격, 나머지는 얇은 연결 레일과 상태/개수로 정리한다. LIVE/시간/인기 칩을 아이보리로 사용할 수 있다. 의미 없는 ‘전체 종목’ 별도 줄이나 반복 영문 장식 줄은 늘리지 않는다. 제목판과 레일도 헤더와 같은 접합 검사를 수행한다.

현재 실시간 자료가 부족하면 실제 기록 스냅샷으로 구성할 수 있다. 기준 시각·기록임을 간결하게 밝히고 예정/진행/종료 상태를 정확히 표시한다. 실시간 카테고리와 실제 라이브 피드 제공 여부를 혼동시키지 않는다.

### 5.2 카드 구조와 스코어 — 위계 LOCKED / 치수 IMPLEMENTATION DEFAULT

**카드 바닥 위에 왼쪽 홈팀, 가운데 상태·점수, 오른쪽 원정팀을 직접 배치한다.** DOM의 정렬용 그룹은 가능하지만 점수 그룹에 별도 배경·테두리·오목 음영·베벨·광택·호버를 주지 않는다. 팀 로고·팀명과 같은 깊이에서 크기·굵기·여백으로 읽기 순서를 만든다. 불필요한 HOME/AWAY 장식 문구는 제거한다.

| 카드 부분 | 실행 기본값 |
| --- | --- |
| 바깥 padding/border | padding 상하 각 12px + border 각 1px = 26px |
| 메타 정보 | 22px: 종목/리그/필요 국기/시각 |
| 메타→대결 간격 | 8px |
| 대결 정보 | 82px: 팀 로고·최대 2줄 팀명 / 가운데 상태·점수 / 반대 팀 |
| 대결→배당 간격 | 8px |
| 배당 3행 | 42px×3 + 행간 6px×2 = 138px |
| 목표 총 높이 | 26+22+8+82+8+138 = **284px** |

고정 폭 약 418.67px. 대결 열은 `minmax(0,1fr) 84px minmax(0,1fr)`부터 검토한다. 팀 로고 약 28~32px, 팀명 16px/20px, 점수 30px/32px. 긴 이름 2줄과 로고가 겹치지 않도록 확보한 높이다. 기존 대표 카드 268px은 승인된 고정값이 아니므로 전체를 함께 조정할 수 있다.

모든 기본 카드 높이를 통일한다. 기존 450px 세로 카드와 새 가로 카드를 섞어 두지 않는다. 경기 전은 ‘– : –’, 진행 중은 자료의 실제 점수·진행 상태, 종료는 FINAL/종료 텍스트. 타이머를 무작위로 증가시켜 실제 라이브인 것처럼 꾸미지 않는다.

### 5.4 카드 마감

중립 바닥면, 얇은 외곽, 정밀한 상단 반사와 검정 깊이 그림자로 카드의 물성을 만든다. 골드 강조는 주요 경계·상태·선택에 집중한다. 단순 평면으로 만들라는 지시가 아니다. 버튼과 정보가 같은 깊이가 되거나 카드 안 모든 정보가 별도 버튼처럼 보이지 않게 한다.

- 계정: 방문자/가상 로그인, 잔액, 충전·환전·내역. 164px 안팎의 압축된 모듈부터 검토한다. 상태 칩·금액·액션을 구분하고 단순 갈색 박스를 남기지 않는다.
- 슬립: 핵심 모듈. 제목·선택 목록·금액·총 배당·체험 예상금액·실행 버튼을 선명한 순서로 구성한다. 빈 상태를 과도한 공백이나 반복 설명으로 채우지 않는다.
- 선택 목록: 경기/선택/마켓/기준값/배당/삭제가 카드와 일치한다. 목록은 112~216px 범위에서 검토하고 긴 목록만 내부 스크롤한다. 합계와 실행부가 아래로 무한 밀리지 않게 한다.

- 목표 1920×940 검수에서 계정과 슬립의 핵심 입력·합계·실행부가 접근 가능해야 한다. 선택 수 증가 전후로 확인한다.
- 문의·공지는 짧은 행/내용 패널, 이벤트는 배너용 별도 타이포·면 분할로 처리한다. 경기 카드 프레임을 그대로 복제하지 않는다.

## 7. Interaction / Motion — 실행 기본값

CSS 및 기존 컴포넌트 기본값의 파란 focus ring, 남색 gradient, 위치 이동을 점검한다. 일반/hover/pressed/selected/disabled/focus-visible를 분리한다. 아래 효과는 강도 조절 가능하나 반려 표현으로 되돌리지 않는다.

| 대상 | 기본 → hover | pressed / selected / disabled | 시간 |
| --- | --- | --- | --- |
| 헤더 탭 | 중립 면·문자 → 골드 문자/좌상우 윤곽/정밀 베벨 강조. 공통 하단선 좌표 고정 | pressed는 inset, 활성은 골드 문자·면 경계 지속. 크기/위치 이동 없음 | 진입 160ms, 이탈 220ms |
| 카드 외곽 | 바닥 `#141414` 유지, 골드 경계 opacity .24→.8, 외곽 glow 0→12px 정도 | 카드 전체를 selected 금색 면으로 만들지 않음. 스코어·팀 영역은 그대로 | 160/220ms |
| 배당 버튼 | 중립 `#292929`→`#171717` 수직 베벨, 아이보리 숫자 → 경계 골드/윗면 반사/8~10px 주변광 | pressed는 외광 감소+inset 증가. selected는 골드 면+어두운 문자+작은 체크. disabled는 중립 면+잠금, hover 없음 | hover 140ms, pressed 60ms, selected 140ms |
| 서비스/주요 CTA | 골드 윗면·몸체·하단 음영 → 선명한 반사와 12→20px 주변광 | 눌림 음영, scale/주변 정렬 변화 없음. 보조 버튼은 중립 면 유지 | 160/240ms |
| 종목 행/검색 | 행 중립 명도 상승·이미지/문자 강조, 검색 focus 윤곽 | active는 골드 레일+아이보리 count, focus-visible는 선택과 구분 | 140ms |

공통 easing 시작값 `cubic-bezier(.2,.8,.2,1)`.

- 카드 전체를 덮는 넓고 흐릿한 대각선 gradient overlay 금지. 중립 버튼 베벨·골드 금속 반사에 필요한 그라데이션은 사용 가능하다.
- 카드/버튼 scale·translate로 이웃을 밀거나 글자가 흔들리지 않게 한다. 눌림은 내부 음영으로 표현한다.
- 헤더 레일의 좁은 금속 광택 이동, 주요 버튼의 단발 반사는 허용한다. 반사는 실제 경계와 일치해야 한다.
- 대기: LIVE 점 2.4초 밝기 변화, 헤더 레일 약 5.6초 주기의 짧은 광택을 시작안으로 사용한다. 모든 패널 동시 맥동은 피한다.
- selected+hover는 선택 면을 유지한다. focus-visible는 골드 면에서도 읽히는 아이보리/어두운 이중 윤곽으로 검토한다.
- 효과 레이어는 클릭을 가로채지 않는다. reduced-motion에서는 반복 이동을 멈추고 상태 차이를 유지한다.
- 실제 버튼 상태를 관찰한다. CSS에 효과가 존재하는 것만으로 완성도를 통과시키지 않는다.

검색/금액을 계속 disabled로 두고 최종 기능 완료로 보고하지 않는다. 데모 안내는 명료하되 카드마다 반복하지 않는다. 운영자용 해상도·효과 슬라이더나 개발 용어를 방문자 화면에 넣지 않는다.

총 배당은 선택 배당의 곱이며 중간마다 반올림하지 않는다. 예: 1.84×1.56=2.8704 → 표시 2.870. 입력 10,000원이면 체험 예상금액 10,000×2.8704=28,704원. 정수 원화 표시는 버림을 시작 규칙으로 한다. 실제 지급 규칙이 아니다. 기존 정상 선택/교체/삭제 로직은 보존한다.

가상 팀 이름과 알파벳 원형 배지를 실제 데이터처럼 남기지 않는다. 최근 종료 기록은 종료, 예정은 예정, 진행 스냅샷은 자료 기준 시각을 명시한다. 실제 현재 일정·점수를 새로 표시한다면 작업 시점의 출처를 확인한다.

### 9.3 이미지 제작 요청

충전·환전·고객센터·전체 스포츠·프레임·작은 배너 등에서 표현이 부족하면 아래 정보를 STATE에 남기고 사용자에게 전달한다. 추가 운영 MD는 만들지 않는다.

`자산 ID / 정확한 위치와 캡처 / 표시 슬롯(px) / 권장 원본·비율·PNG alpha 또는 WebM 필요 여부 / 블랙·골드·아이보리 재질·광원 / 필요한 상태 / 적용 파일명 / 자산 부재가 막는 범위`.

사용자가 제작해 이 기획 스레드에 제공하면 다음 전달본에 실제 파일과 적용 매핑을 넣는다. 자동 이미지 생성이나 임의 추가 플러그인은 실행하지 않는다. 자산 대기는 해당 항목만 미완료로 표시하고 다른 화면 작업은 계속한다.

## 10. 독립 품질 감사 — 이번 사이클 실제 수행

### 10.1 담당과 시작

진행 담당은 독립 감사 담당을 지정하고 STATE에 실제 식별자/배정 상태를 남긴다. 감사자는 AGENTS·STATE·본 사양·피드백 캡처를 읽고 **WOG를 직접 열어** 실제 표시·호버·버튼/패널 마감을 관찰한다. 구현자와 같은 사람이 자신의 결과를 독립 통과시킬 수 없다.

감사자에게 전달할 작업:

> MERCURY R6 독립 품질 감사다. WOG를 직접 보고 완성도 하한으로만 비교하라. 색상·외형은 MERCURY의 확정 기준을 따른다. 현재 화면의 초기 문제를 보고하고, 전체 구현본에서 아래 Q 항목과 실제 hover/pressed/selected/disabled를 확인하라. 문제 위치·상태·근거·수정 방향을 구현 담당에게 전달하고 수정본을 재확인하라. 소스·사양·배포는 직접 변경하지 않는다. 확인하지 못한 항목은 미확인으로 남겨라.

실제 브라우저 접근이 안 되면 시각 감사 완료로 표시하지 않는다. 가능하면 접근 가능한 현지 브라우저/동일 버전 미리보기로 확인한다. 불가한 범위와 이유는 진행 담당에게 보고하고 나머지 구현을 전부 멈추지 않는다.

### 10.3 필요한 증거와 판정

- 실제 1920 폭 전체 화면과 중앙을 내려 본 화면. viewport·DPR·확인 가능한 확대율을 기록한다. 1920×940은 권장 시험 조건이며 사용자 실측이라고 주장하지 않는다.
- 2560 등 초과 폭에서 같은 셸·카드 폭인지 확인. 캡처가 도구에 의해 축소되면 실제 이미지 해상도와 DOM 측정을 구분한다.
- 헤더 접합부, 브랜드 결합, 대표 카드/서비스/슬립을 100%로 읽고 접합부는 캡처 확대 또는 브라우저 확대 관찰한다. 확대 화면을 정규 화면 크기 증거로 혼용하지 않는다.
- 같은 요소의 기본/hover/pressed/selected/disabled. 움직임은 실제 브라우저 연속 관찰 또는 짧은 녹화로 확인한다. 정지 사진만으로 모션 통과를 주장하지 않는다.
- 대상 URL·소스/배포 버전·감사 시각·확인 상태와 구체 피드백. 수정본은 해당 지적이 해소됐는지 재확인한다.

판정은 **A 사양 준수 / B WOG 대비 완성도 / C 기능** 각각 통과·수정 필요·미확인으로 남긴다. 사용자 승인은 별도다. 한 항목의 통과로 다른 미달을 상쇄하지 않는다.

### 10.4 피드백 반영과 종료

구체 결함은 구현자가 보완하고 감사자가 재확인한다. 감사자의 취향만으로 새 디자인 목표를 발명하거나 같은 문제를 무한 재정의하지 않는다. 의견 차이와 사용자 판단이 필요한 지점은 근거와 함께 드러낸다. 정해진 토큰 상한이나 대표 요소 완료를 이유로 자동 중단하지 않는다.

**전체 완료:** 모든 영역이 같은 MERCURY 디자인으로 완성되고, 각 Q 항목의 결과와 실제 조작 검증이 있으며, 독립 감사·보완을 수행하고, 기존 주소에 검증본을 공개 반영한 상태다. 남은 결함/자산 대기/감사 불가가 있으면 이를 명시하고 ‘전부 완료’로 포장하지 않는다. 사용자가 중간에 멈추라고 하면 현재 상태와 보존본을 보고한다.

## 11. Visual Locks 요약

1920 고정 / 독립 스크롤·바 숨김 / 블랙·골드·아이보리 / 헤더 심볼+레터링 / 단일 공통 언더라인 접합 / 평면 대결 정보와 입체 조작의 구분 / 실제 경기·수집 자산 / 지정 네 폰트 / 세 분류 전체 카드 / 기능 정상 보존 / 독립 WOG 감사 / 전체 페이지까지 진행 / 임의 토큰 제한 없음.

정확한 치수·HEX·효과 시간의 조정은 가능하지만 위 방향과 최신 사용자 피드백을 뒤집지 않는다. 사이트 배포가 곧 사용자 디자인 승인이라는 표현은 사용하지 않는다.
