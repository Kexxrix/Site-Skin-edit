# MERCURY — 작업 공통 규칙

문서 세트: **MVP R6 · 2026-09-17**  
실행 목표: 기존 공개 v3를 이어서 **한 페이지 전체의 디자인·데모 조작·독립 품질 감사·보완·공개 배포**까지 완료한다.

## 1. 이번 실행에서 가장 먼저 적용할 변경

- R6가 R1~R5의 충돌하는 실행·디자인 기준을 대체한다. 현지 최신 사용자 지시는 R6보다 우선한다.
- **토큰·주간 사용률에 따른 프로젝트 중단 조건은 없다.** 이전 +20%포인트/누적 36% 기준, 사용률 조회 실패·초기화를 이유로 보류하는 조건, 강제 중단 도구 확보 조건은 폐기한다. 실제 플랫폼 한도·도구 장애까지 없어진다는 뜻은 아니다.
- **대표 카드 1개 구현 후 정지하지 않는다.** 대표 요소 검토는 내부 체크포인트다. 사용자에게 진행 상황을 보여주되 전체 작업을 계속한다.
- **독립 감사자를 실제로 배정하고 실행한다.** 구현자 자체 검수만으로 WOG 비교 감사를 대체하지 않는다.
- WOG는 정교함과 완성도의 하한점이다. MERCURY의 블랙·골드·아이보리, 배치, 브랜드를 WOG 색상·외형으로 바꾸지 않는다.
- 원형 심볼은 **헤더의 MERCURY 레터링 바로 왼쪽**이다. 좌측 사이드바 엠블럼 전용 패널은 제거한다.
- 스코어·진행 상태는 팀 로고·팀명과 **같은 카드 바닥면**에 배치한다. 별도 스코어 박스·오목 면·버튼 같은 프레임을 만들지 않는다.

## 2. 문서와 읽기 순서

운영 문서는 프로젝트 루트의 `AGENTS.md`, `STATE.md`, `DESIGN_SPEC.md`, `DECISIONS.md` 네 개만 사용한다. HISTORY/HANDOFF/TASKS/NOTES/별도 감사 MD는 만들지 않는다. 구현용 코드·데이터 JSON·증거 이미지·영상은 별도 운영 문서가 아니다.

시작 순서: AGENTS → STATE → DESIGN_SPEC의 Global 및 담당 영역 → 관련 코드. 중요한 결정의 이유가 필요하면 DECISIONS를 읽는다.

- 전달 ZIP은 입력 묶음이다. input 폴더를 사이트 소스 루트로 착각하지 않는다.
- 진행 담당자가 기존 루트 문서에 R6를 반영한다. 현지에서 새로 확인된 소스/배포 정보·증거 경로·미해결 상태는 보존하고, 과거 보류·예산·단계 정지 문장은 현재 규칙으로 교체한다.
- 오래된 input 아카이브를 삭제하거나 모든 하위 AGENTS를 무차별 변경하지 않는다. 실제 소스에 적용되는 오래된 지시가 충돌하면 R6 최신 사용자 지시로 해소하고 진행 담당에게 보고한다.
- STATE는 현재 결과·현재 쟁점·감사 상태·다음 작업만 관리한다. 과거 전문을 누적하지 않는다.
- 각 수치/치수/HEX/효과 시간은 DESIGN_SPEC의 IMPLEMENTATION DEFAULT다. LOCKED인 사용자 방향을 벗어나지 않으면 구현자가 조정하고 기록할 수 있다. 사용자 승인이라고 표현하지 않는다.

## 3. 역할과 소유권

| 담당 | 실제 수행 | 수정 권한 |
| --- | --- | --- |
| 전체 진행 스레드 | 시작 지시, 구현·감사 배정, 쟁점 통합, 전체 진행·배포 결과 확인 | 운영 문서 관리. 기존 구현 소유권 존중 |
| Sites 구현 스레드 | 기존 사이트 전체 디자인·데모 기능 수정, 빌드, 자체 검수, 공개 배포 | 해당 Site 소스·자산·배포. 할당 밖 타 프로젝트 수정 금지 |
| 독립 품질 감사 스레드 | WOG와 MERCURY 직접 관찰, 비교 판정, 수정 피드백, 수정본 재확인 | 읽기·관찰·증거 수집. 소스/사양/배포 임의 수정 금지 |
| 사용자/기획 스레드 | 디자인 방향·최종 수용 판단, 필요한 이미지 공급 | 감사자의 취향이 사용자 확정 결정을 뒤집지 않음 |

사용자는 독립 감사 실행을 요청했다. 기존 감사 스레드가 있으면 재사용하고, 없으면 현지에서 지원하는 별도 스레드/서브 에이전트 하나를 감사 역할로 배정한다. 사용 가능한 실제 기능을 이용하며 존재하지 않는 스레드 제어 API를 가정하지 않는다. 여러 구현 에이전트의 무계획 병렬 수정은 요청 범위가 아니다.

감사자에게 이 네 문서, 공개 URL/미리보기 URL, 대상 소스 버전, 실제 화면 조건을 전달한다. **감사 담당 식별자·직접 관찰 시각·대상 버전·피드백이 없으면 감사 미실행이다.** 역할 이름을 문서에 쓰는 것으로 실행을 대신하지 않는다.

별도 스레드를 실행/전달할 기능이 없으면 정확한 제약과 넘길 검수 메시지를 보고한다. 이를 전체 구현 보류 이유로 삼지 말고 구현 가능한 범위는 계속한다. 독립 감사는 미확인으로 남기며 자체 검수를 독립 감사로 바꾸어 적지 않는다.

## 4. 전체 실행 순서

1. **현재 소스 확인 및 감사자 착수:** STATE의 소스/프로젝트 정보와 현재 화면을 확인한다. 감사자는 WOG를 직접 열고 초기 MERCURY의 문제를 보고한다. 678개 수집 자산 전체 탐색이나 기존 사전 점검을 불필요하게 반복하지 않는다.
2. **전체 구현:** DESIGN_SPEC에 따라 헤더·좌측·중앙 세 분류의 모든 카드·우측·필요한 데모 오버레이를 완성한다. 대표 카드에도 최신 반려 피드백을 먼저 적용한다. 이전 카드 4개를 남겨둔 혼합 상태로 종료하지 않는다.
3. **전체 검수판 감사:** 구현자 자체 기능/빌드 검증 후 감사자가 같은 버전의 전체 화면과 실제 상태 변화를 확인한다. 직접 본 증거에 근거해 A 사양 준수, B WOG 대비 완성도, C 조작 정상 여부를 따로 보고한다.
4. **보완 및 재확인:** 구현자가 지적을 수정하고 감사자가 해결 여부를 확인한다. 중간 보고만 하고 자동 정지하지 않는다. 새 범위나 취향만으로 같은 요소를 계속 재작업하지 말고 의견 차이는 사용자에게 명확히 제시한다.
5. **공개 배포와 종료 보고:** 검증된 수정본을 기존 MERCURY 주소에 배포하고 공개 화면/자산/핵심 조작을 확인한다. 배포 버전과 감사한 소스의 대응을 확인한다. 전체 결과·남은 문제·감사 판정·사용자 미승인 상태를 보고한다.

사용자가 계속 확인할 수 있도록 전체 화면을 볼 수 있는 주요 진행 지점마다 짧게 보고한다. 실제 사용자 정지 지시는 즉시 따른다. 임의 토큰 상한, 대표 요소 완료, 감사 횟수 숫자만으로 전체 작업을 조기 종료하지 않는다. 도구 실패·필수 자산 부재 등 실제 장애는 영향 범위를 밝히고 가능한 나머지 작업을 수행한다.

## 5. 구현 공통 규칙

- 수정 전 실제 화면과 관련 코드를 읽는다. 현재 외형은 반려 상태다. 기존 정상 선택/해제/교체/슬립/계산은 보존한다.
- 기존 프레임워크·의존성·잠금 파일·Sites 설정은 필요한 이유 없이 교체하지 않는다. 전체 품질 개선은 허용되나 타 프로젝트나 실제 결제/베팅 백엔드로 범위를 넓히지 않는다.
- 1920 고정 폭, 실제 브라우저 콘텐츠 높이, 좌·중·우 독립 스크롤, 숨긴 스크롤바를 유지한다. 모바일·태블릿·자동 축소는 만들지 않는다.
- 모든 기본 면은 중립 블랙/그레이다. 기존 청회색·남색 및 갈색 면을 재사용하지 않는다. 스포츠 로고의 원래 색은 보존한다.
- 지정 폰트: UI Pretendard JP / 일본어 Heisei Mincho Std / 필요한 강조 Omnigothic / 점수 DIN Condensed. 원본 브랜드는 이미지 그대로 사용한다.
- 이미지를 고정 슬롯에 맞추며 패널을 이미지 원본 크기로 늘리지 않는다. 배치·원본 대응은 DESIGN_SPEC의 자산 표를 따른다.
- 표현이 부족한 이미지 자산은 위치·규격·필요 상태와 이유를 정리해 사용자에게 요청한다. 요청 없이 이미지 생성, Photoshop/Higgsfield 등 추가 플러그인 사용을 시작하지 않는다.
- 프레임·선·광택은 연결 위치까지 확인한다. 정보에는 필요한 위계만, 클릭 대상에는 명확한 조작 깊이와 상태를 준다.
- 강한 골드 글로우·광택·호버는 허용한다. 구체 대상과 상태는 사양을 따르며 효과를 일괄 약화하지 않는다. 반려된 넓은 대각선 카드 오버레이는 재사용하지 않는다.

## 6. Sites와 공개 배포

기존 Sites 구현 담당이 실행 환경의 최신 sites-building/필요한 hosting 지침을 읽고 기존 프로젝트를 이어서 작업한다. 고정 화면·원본 자산·합의된 디자인 방향이 일반적인 제작 기본값보다 우선한다.

- `.openai/hosting.json` 및 실제 프로젝트 정보로 대상 확인. 새 사이트를 임의 생성하지 않는다.
- source/hosting 소유권은 기존 구현 담당이 유지한다. 감사자에게 배포를 맡기지 않는다.
- 별도 ‘로컬만/배포 금지’ 지시가 없으면 이번 전체 작업 결과를 기존 공개 주소에 갱신한다. 이미 승인된 공개 범위를 매번 다시 묻지 않는다.
- 배포 성공, 자체 검증 통과, 독립 감사 통과, 사용자 승인 상태를 각각 보고한다.
- 미완료 작업이 남으면 검수판임을 명시한다. 감사 불가 상태를 WOG 하한 통과로 보고하지 않는다.

## 7. 감사 보고 규격

감사자는 DESIGN_SPEC §10의 체크리스트를 사용한다. 보고는 채팅/캡처로 전달하고 진행 담당이 최신 요약을 STATE에 통합한다.

```text
감사 담당 / 직접 확인 시각:
대상 URL / 소스 또는 배포 버전 / viewport·DPR:
직접 본 WOG 화면·상태와 MERCURY 화면·상태:
판정 A(사양) / B(완성도 하한) / C(기능): 통과·수정 필요·미확인
항목 ID / 위치 / 상태 / 관찰 문제 / 증거 / 수정 방향 / 재확인 결과:
확인하지 못한 항목:
```

‘WOG처럼 파랗게/하얗게 바꾸기’ 등의 수정 지시는 금지한다. 같은 MERCURY 팔레트·구조에서 정렬, 재질, 정보 위계, 효과 연결성을 개선하도록 지시한다. 구현 보고의 반복 요약이나 CSS 값 비교만으로 시각 감사를 끝내지 않는다.
