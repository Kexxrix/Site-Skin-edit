# MERCURY — 작업 공통 규칙

문서 세트: **MVP R8 · 2026-09-17**  
대상: 현재 R7 공개본에서 이어가는 수정. 실행 지시와 완료 조건은 STATE, 시각·동작 기준은 DESIGN_SPEC, 사용자 확정 결정은 DECISIONS다.

## 1. 읽기와 작업 범위

읽기 순서: AGENTS → STATE → DESIGN_SPEC의 Global 및 담당 영역 → 관련 코드. 필요한 결정만 DECISIONS에서 확인한다.

- 사용자 최신 지시 > R8 > 충돌하는 과거 문서. 현재 소스·화면을 먼저 확인하고 사용자/다른 작업자의 최신 변경을 보존한다.
- 운영 문서는 AGENTS/STATE/DESIGN_SPEC/DECISIONS 네 개만 유지한다. 별도 HISTORY/HANDOFF/TASKS/NOTES/감사 MD를 만들지 않는다. 자산 매핑 JSON·캡처는 증거/리소스다.
- ZIP은 입력 자료이며 실제 Site 루트가 아니다. 기존 프로젝트 문서에 합치고 과거 입력 ZIP/아카이브는 보존한다.
- 이번 범위는 실시간 현장감, 납작한 한 줄 충전/환전, 새 종목 아이콘8개, 편집 가능한 좌우 이미지 배너다. 기존 페이지를 새로 만들지 않는다.
- **NHL 등 기존 리그 로고 표현과 팀명 표기는 사용자 통과다. 추가 정교화·번역·일괄 로고 크기 보정 과제로 다시 올리지 않는다.** 새 종목 아이콘 교체와는 별개다.
- LOCKED는 사용자 확정 방향이다. IMPLEMENTATION DEFAULT는 실행 시작안이며 사용자 승인 수치/시안이 아니다.

## 2. 역할과 권한

| 역할 | 책임 | 수정 권한 |
| --- | --- | --- |
| 진행 | 범위 배정, 현재 상태 확인, 통합, 독립 감사 배정, 결과 보고 | 운영 문서. 타 작업자 소스 소유권 보존 |
| 기존 Sites 구현 | R8 전체 구현, 자체 검사, 보완, 기존 주소 배포 | 해당 Site 소스·선별 자산·설정 |
| 독립 품질 감사 | WOG 직접 관찰 근거와 R8 변경본을 비교, 실제 화면/조작 확인, 구체 피드백·재확인 | 읽기·관찰·증거. 소스/사양/배포 변경 금지 |
| 사용자 | 디자인 최종 수용, 이미지 공급, 범위 변경 | 사용자 통과 항목을 감사자 취향으로 반려하지 않음 |

STATE의 기존 담당 재사용이 우선이다. 없으면 현지 지원 기능으로 독립 담당을 배정한다. 존재하지 않는 제어 도구/감사 ID를 만들지 않는다. 무계획 다중 구현자 병렬 수정은 하지 않는다.

감사자의 실제 식별자·대상 버전·관찰 시각·지적/재확인 근거를 남긴다. 근거가 전달되지 않았으면 독립 감사 상태는 미확인이다. 자체 검수를 독립 PASS로 쓰지 않는다. 감사 기능 제약이 있으면 가능한 구현을 계속하고 해당 미검증 범위를 보고한다.

## 3. 구현과 자산 규칙

- 고정1920, 브라우저의 실제 내용 높이, 좌·중·우 독립 스크롤 및 숨긴 스크롤바 유지. 반응형 재배치나 자동 축소를 추가하지 않는다.
- 중립 블랙·골드·아이보리, 지정 폰트, 축소된 헤더 브랜드, 공통 언더라인, 평면 점수와 입체 배당 버튼을 보존한다. WOG 외형·팔레트를 복제하지 않는다.
- 현재77개 경기/분류별6개씩 펼침/검색/필터/선택/교체/해제/계산/내역 및 기존 F01/F02 보완을 보존한다. 실행에 불필요한 프레임워크·의존성 교체를 하지 않는다.
- 새 PNG8개가 모든 종목 표시의 우선 자산이다. 팀/리그/국기는 별도 자산이다. 투명도·금속색·실루엣을 보존하고 기존 단색 필터/원형 마스크가 새 이미지에 걸리지 않게 한다. 원본256px에 맞춰 행·카드를 늘리지 않는다.
- 배너는 사진·프레임·텍스트·버튼을 별도 HTML/CSS 요소로 만들고 실제 슬롯에서 얼굴/텍스트 겹침을 확인한다. 배너 합성 이미지 한 장으로 대체하지 않는다.
- 사용자 제공 원본은 보존한다. 새 이미지/영상 생성, Photoshop/Higgsfield 등 추가 플러그인은 사용자 명시 지시 없이 실행하지 않는다. 부족한 자산은 위치·규격·이유를 STATE로 요청한다.
- 데모/체험/가상/수집/실시간 갱신 없음/실제 거래 없음 등 방문자 해설을 재삽입하지 않는다. 배너에도 같은 기준을 적용한다. 실제 인증/입출금/베팅 백엔드는 만들지 않는다.
- 최신 실제 경기라고 주장할 데이터는 출처를 확인한다. 진행 스냅샷/재생용 자료의 기준 시각·출처는 내부에 기록하고 종료 점수에 LIVE만 붙이는 식으로 조작하지 않는다.
- 구조·숫자·CSS 속성만으로 디자인 완료라고 하지 않는다. 실제 크기와 상태에서 마감·가독성·정보 순서를 확인한다.

## 4. 진행과 종료

전체 R8 구현 → 자체 검증 → 독립 감사 → 구체 지적 보완·재확인 → 같은 공개 주소 배포·공개 확인까지 진행한다. 좌측 배너의 첫 적용은 중간 확인 순서이며 그 한 요소만 만든 뒤 전체 작업을 종료하지 않는다.

토큰/주간 사용률 상한은 없다. 강제 중단 도구·사용량 조회 불가를 사전 보류 이유로 삼지 않는다. 사용자 정지와 실제 플랫폼 한계는 따른다. 감사자는 같은 취향 문제를 끝없이 재정의하지 않는다.

현지 최신 sites-building/sites-hosting과 기존 hosting 설정을 따른다. 기존 Site 소유 구현 담당만 소스·배포를 맡으며 새 Site를 만들지 않는다. 사용자는 기존 MERCURY 공개본의 갱신을 요청한 상태다. 검증한 동일 소스를 현재 주소·공개 범위로 반영한다.
