# MERCURY — 작업 공통 규칙

문서 세트: **MVP R7 · 2026-09-17**  
대상: 기존 공개 v5의 후속 수정. `STATE.md`의 R7 작업을 구현·독립 감사·보완·기존 주소 공개 반영까지 진행한다.

현지 완료 상태(2026-09-17): R7 전체 구현·독립 감사·보완·재확인 및 공개 v6 반영을 마쳤다. 현재 결과와 증거는 [STATE.md](STATE.md)가 기준이며, 다음 사용자 검수 지시 전에는 새 사이클을 시작하지 않는다.

## 1. 읽기·우선순위

AGENTS → STATE → DESIGN_SPEC의 Global 및 담당 영역 → 관련 코드. DECISIONS는 결정의 충돌 여부를 확인할 때 읽는다.

- 사용자 최신 지시 > R7 > 충돌하는 R1~R6 지시. R7는 전체 페이지 신규 제작 지시가 아니라 공개 v5에서 이어가는 수정 묶음이다.
- 운영 문서는 루트 AGENTS/STATE/DESIGN_SPEC/DECISIONS 네 개만 유지한다. 별도 HISTORY/HANDOFF/TASKS/NOTES/감사 MD를 늘리지 않는다. 증거 PNG/JPG/영상/검증 JSON은 별도 운영 문서가 아니다.
- ZIP은 입력 묶음이다. 실제 소스 루트와 혼동하지 않는다. 진행 담당은 현재 프로젝트 문서에 R7를 반영하되 현지 최신 소스·배포·증거 정보와 사용자 수정을 보존한다. 과거 입력 아카이브는 수정·삭제하지 않는다.
- LOCKED는 사용자 확정 방향이다. 픽셀/HEX/효과 시간의 IMPLEMENTATION DEFAULT는 검수 시작안이며 사용자 승인 시안이 아니다.
- STATE는 현재 완료/미완료/검증/차단/다음만 갱신한다. 지난 전문을 누적하지 않는다.

## 2. 역할과 수정 권한

| 담당 | 수행 | 권한 |
| --- | --- | --- |
| 진행 스레드 | R7 반영, 기존 구현·감사 담당 배정, 충돌 방지, 결과 통합·종료 보고 | 운영 문서 관리, 타 스레드 소스 소유권 보존 |
| 기존 Sites 구현 담당 | 맡은 Site의 변경·빌드·자체 검사·공개 배포 | 해당 Site 소스·자산·설정·배포 |
| 독립 품질 감사 | WOG와 변경된 MERCURY 직접 관찰, 결함 보고, 보완 재확인 | 읽기·관찰·증거만. 소스/사양/배포 변경 금지 |
| 사용자 | 디자인 최종 수용, 이미지 공급, 범위 변경 | 감사자 취향이 확정 지시를 뒤집지 않음 |

기존 담당 식별자는 STATE에 있다. 사용 가능한 기존 스레드를 재사용하고, 없으면 현지 지원 기능으로 별도 감사 담당을 배정한다. 역할 이름만 써서 실행을 대신하지 않는다. 새 감사 ID를 임의로 만들거나 존재하지 않는 스레드 제어 API를 가정하지 않는다. 무계획 다중 구현자 병렬 수정은 요청 범위가 아니다.

감사자에게 현재 네 문서·대상 URL·소스 버전·실제 viewport를 전달한다. 담당 식별자/관찰 시각/버전/구체 피드백이 없으면 독립 감사 미실행이다. 독립 실행 기능이 없으면 정확한 제약을 보고하되 구현 가능한 작업을 모두 중단하지 않는다. 자체 검수를 독립 감사 통과로 바꾸어 쓰지 않는다.

## 3. 작업과 품질 규칙

- 수정 전 현재 화면·코드·관련 지시를 확인한다. v5의 정상 선택/교체/해제/잠금/슬립/계산/내역 기능과 F01/F02 보완을 보존한다.
- 할당 범위 밖 파일·다른 프로젝트·사용자 변경을 임의로 수정하지 않는다. 기존 프레임워크/의존성/lock/Sites 프로젝트를 이유 없이 교체하지 않는다.
- 고정1920, 실제 브라우저 높이, 좌·중·우 독립 스크롤과 숨긴 스크롤바를 유지한다. 모바일/태블릿 재배치·자동 축소는 만들지 않는다.
- 블랙·골드·아이보리와 지정 폰트를 유지한다. WOG는 완성도 하한이며 외형·팔레트·코드·자산 복제 대상이 아니다.
- 공개 UI의 데모/체험/가상/수집 기록/실시간 갱신 없음/실제 거래 없음 문구는 DESIGN_SPEC §8.1에 따라 전면 제거·일반 명칭으로 교체한다. 공지 한 곳에 남기는 예외도 없다. 내부 데이터 출처/로컬 동작은 보존하고 감사자가 고지를 재삽입하지 않는다.
- 이미지 크기에 맞춰 UI를 늘리지 않는다. 원본 비율/색/내용을 보존한다. 원형 표시와 리그 형태 예외, 아이보리 제거 조건, 실제 도상의 높이 정렬을 따른다.
- 구조가 있다는 이유로 디자인 완료라고 하지 않는다. 정렬·상하 여백·재질·폰트·아이콘·hover/pressed/selected·실제 화면까지 확인한다. 범용 placeholder나 성의 없는 기본 스타일로 대체하지 않는다.
- 강한 골드 효과는 허용하되 대상·상태·범위는 DESIGN_SPEC을 따른다. 반려된 넓은 대각선 카드 오버레이·위치 이동·흉한 스크롤바를 되살리지 않는다.
- 이미지가 더 필요하면 슬롯/규격/필요 상태/이유를 STATE에 요청한다. 사용자 지시 없이 이미지·영상 생성이나 Photoshop/Higgsfield 등 추가 플러그인을 실행하지 않는다.

## 4. 진행·종료

토큰/주간 사용률에 따른 프로젝트 중단 조건은 없다. 이전 +20%포인트/누적36%, 사용량 조회 실패, 강제 중단 도구 확보 조건을 적용하지 않는다. 대표 카드1개 후 정지하지 않는다. 사용자 정지 지시는 즉시 따른다. 실제 플랫폼 한도·도구 장애가 있으면 영향과 수행 가능한 나머지 범위를 보고한다.

STATE의 전체 작업 → 자체 검사 → 독립 감사 → 구체 결함 보완/재확인 → 기존 공개 주소 배포/공개 확인을 완료한다. 진행 상황은 사용자가 확인할 수 있게 짧게 전달한다. 같은 취향 문제를 끝없이 재작업하지 말고 DESIGN_SPEC과 관찰 근거로 범위를 정리한다. 감사 PASS를 사용자 최종 승인으로 간주하지 않는다.

작업 담당 보고: 변경 영역 / 변경 파일 / 구현 내용 / 검증 / 남은 문제 / 사양과 다른 부분. 감사 보고는 DESIGN_SPEC §10을 따른다.

## 5. Sites·배포

- 기존 Site 소유 구현 담당만 실제 사이트 소스와 설정을 수정하고 Sites 배포를 수행한다. 새 프로젝트를 만들지 않는다. 진행/감사 스레드는 소유권을 임의로 가져오지 않는다.
- 현지 최신 sites-building/sites-hosting 지침과 기존 `.openai/hosting.json`을 확인한다. 사용자 지정 고정 화면·자산·디자인·독립 감사 요구가 일반적인 빠른 제작 기본값보다 우선한다.
- 사용자는 기존 MERCURY의 공개 결과 갱신을 요청한 상태다. R7 검증본을 같은 주소·현재 공개 범위로 반영한다. 다시 배포 여부를 묻거나 로컬 완료에서 정지하지 않는다.
- 감사한 소스와 배포 소스의 대응을 확인한다. preview 통과만으로 production/public 통과를 주장하지 않는다. 변경 영향에 해당하는 상태를 실제 공개본에서도 확인한다.
- 완료 보고에 공개 URL·버전·감사 담당과 판정·완료/미완료/미검증을 구분한다. 실제 미완료가 있으면 사용자에게 보고하되 이를 방문자 화면에 데모 고지로 넣지 않는다.
