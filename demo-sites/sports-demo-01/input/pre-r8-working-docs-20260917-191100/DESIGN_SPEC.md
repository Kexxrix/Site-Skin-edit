## 0. 기준의 우선순위와 이번 수정

**LOCKED**는 사용자 확정 방향이다. **IMPLEMENTATION DEFAULT**는 바로 작업할 수 있는 실행 기본값이며 사용자 승인 시안이 아니다. 숫자 조정이 필요하면 같은 방향에서 조정하고 진행 담당이 기록한다. 수치 맞추기만으로 시각 품질을 통과시키지 않는다.

## 1. MVP 범위와 참고의 역할 — LOCKED

- 대상: [MERCURY](https://mercury.kexxadrix.chatgpt.site/). 실시간 스포츠가 선택된 단일 페이지다.
- 헤더 + 좌측 서비스/검색/종목/홍보 + 중앙 실시간/국내형 스포츠/인기경기 + 우측 계정/슬립/문의/이벤트.

- [COBALT 카드 구성](input/mercury-mvp-r7-package/MERCURY_MVP_R7/references/COBALT_cards_reference.png)은 경기 정보 관계·3열 구성 참고다. 기존 마감 수준은 계승하지 않는다.
- [이전 반려 전체](input/mercury-mvp-r7-package/MERCURY_MVP_R7/references/MERCURY_rejected_overview.png), [반려 호버](input/mercury-mvp-r7-package/MERCURY_MVP_R7/references/MERCURY_rejected_hover.png)는 재발 금지 자료다. ## 2. Global

### 2.1 고정 화면과 밀도 — 방향 LOCKED / 치수 IMPLEMENTATION DEFAULT

1920×1080 **모니터**에서 탭·주소창·즐겨찾기 영역을 제외한 실제 브라우저 콘텐츠 높이를 사용한다. 높이 1080px을 웹 화면에 강제하지 않는다. 1920 미만 모바일/태블릿 지원과 전체 자동 축소는 만들지 않는다.

| 요소 | 기본값 |
| --- | --- |
| shell | width:1920px, box-sizing:border-box, shrink 없음 |
| 헤더 / 공지 줄 | 68px / 32px |
| 본문 바깥 여백 | 상하좌우 12px |
| 좌측 / 중앙 / 우측 | 272px / 1280px / 320px |
| 열 사이 | 12px × 2 |
| 중앙 카드 간격 | 12px |
| 카드 폭 | (1280 − 12×2) ÷ 3 = 약 418.67px |

가로 합계: 12×2 + 272 + 1280 + 320 + 12×2 = **1920px**.
본문 높이: 실제 innerHeight − 68 − 32 − 12×2. 예: 검수용 940px이면 **816px**이며 실제 사용자 viewport 측정값은 아니다.

1920 초과에서는 셸 내부 치수를 그대로 두고 가로 중앙에 놓는다. 2560일 때 양옆 여백은 (2560−1920)÷2=320px. 중앙 칼럼이나 카드를 늘리지 않는다.

헤더/공지 아래 좌·중·우만 각각 스크롤한다. `min-height:0; overflow-y:auto`와 적절한 overscroll 제어를 사용한다. 모든 스크롤 트랙·손잡이·화살표는 숨기고 휠·트랙패드·키보드 이동을 유지한다. 콘텐츠를 잘라 숨기는 방식으로 스크롤바 문제를 덮지 않는다.

### 2.2 컬러·재질 — 방향 LOCKED / HEX IMPLEMENTATION DEFAULT

중립 블랙 바탕 + 조금 밝은 중립 패널 + 선명한 골드 + 아이보리다. **패널 기본 면에 청색을 더하지 않는다.** 수정 과정에서 남색 기본 variant를 다시 도입하지 않는다. 현재 v5의 중립 토큰과 정상 렌더를 재사용하고 잔존하거나 새로 생긴 푸른 면만 바로잡는다.

| 역할 | 기본 토큰 |
| --- | --- |
| 전체 바탕 | `#050505` |
| 헤더/프레임 면 | `#0B0B0B` |
| 카드/패널 면 | `#141414` |
| 돌출 버튼 윗면 / 아랫면 | `#292929` / `#171717` |
| 중립 경계 / 반사 | `#3B3B3B` / 낮은 투명도 `#767676` |
| 골드 기본 / 반사 / 음영 | `#D9AD43` / `#FFE6A3` / `#78511C` |
| 아이보리 면 / 문자 | `#F5EEDF` / `#171717` |
| 주요 문자 / 보조 문자 | `#F5F1E8` / `#B8B5AD` |
| 사용불가 | `#1C1C1C`, 낮춘 중립 문자, 잠금 아이콘 |

중립 면은 RGB 채널이 같은 값을 시작점으로 삼는다. 실제 사용되는 면이 파랗거나 갈색이면 토큰 선언만 맞았다고 통과시키지 않는다. 팀/리그/국기 원본의 파랑·빨강 등 고유색은 유지한다.

골드는 헤더 하단선, 활성 메뉴, 중요한 CTA, 선택 배당, 정밀한 베벨/반사에 집중한다. 검정 면 전체를 노란 조명으로 덮지 않는다. 아이보리는 읽기 좋은 문자뿐 아니라 LIVE/보조 칩의 밝은 면으로 드러난다. 모든 패널을 동일한 금색 테두리 박스로 만들지 않는다.

### 2.4 화면 전체의 정보·조작 깊이 — LOCKED

- 같은 의미를 이루는 정보는 같은 면 위에 묶는다. 그룹을 만들기 위해 항상 새 박스를 만들지 않는다.
- 경기 로고·팀명·진행 상태·점수는 **하나의 대결 정보**다. 시각적 바닥면과 기준선을 공유한다.
- 마켓 이름·기준값은 읽는 정보다. 배당 버튼처럼 입체 테두리·호버·포인터를 부여하지 않는다.
- 배당/서비스/실행 버튼은 누르는 대상이다. 금속 면·베벨·눌림으로 조작 가능함을 구분한다.
- 카드 프레임·제목판·작은 상태 칩은 기능에 맞게 사용한다. ‘불필요한 박스 제거’를 전체 프레임과 장식 삭제로 확대하지 않는다.

## 3. Header — 브랜드 결합과 접합부

### 3.1 브랜드 — 위치 LOCKED / 슬롯 IMPLEMENTATION DEFAULT

헤더 브랜드 영역에서 **원형 심볼 → 간격 → MERCURY 레터링** 순서로 가로 결합한다. 세로 중심을 맞추고 하나의 브랜드로 보이게 한다. 사이드바 엠블럼 패널은 제거하며 그 자리에 또 다른 빈 패널을 남기지 않는다.

2026-09-17 추가 사용자 확정: **헤더에 비해 심볼과 레터링이 너무 크므로 둘 다 축소하고 위아래에 충분한 여백을 둔다.** 헤더68px과 브랜드 영역272px, 메뉴 위치는 유지한다. 이전 심볼48×48px/레터링196×58px 시작안은 대체한다. 새 검수 시작안은 심볼36×36px, 간격8px, 레터링144×42px 슬롯이다(IMPLEMENTATION DEFAULT, 사용자 승인 치수 아님). 두 이미지 모두contain으로 비율을 유지하고 세로 중심을 맞춘다. 헤더의 선을 제외한 내용 높이에서도 레터링 위아래 약12px, 심볼은 그보다 여유 있는 공간이 확보되도록 실제 보이는 외곽으로 검수한다. 기존 왼쪽 기준과 브랜드 영역의 폭을 유지하되 늘어난 여백을 채우려고 다시 확대하지 않는다. 헤더 높이를 늘려 여백을 만드는 방식, 이미지crop/stretch, 심볼이나 레터링 한쪽만 축소하는 처리는 하지 않는다.

### 3.2 활성 탭과 하단선 — 접합 품질 LOCKED

**실행 기본안: 탭 좌·상·우 윤곽 + 헤더의 단일 공통 하단선.**

- 탭 하단의 독립 테두리/두꺼운 광택 띠를 없애고, 헤더 하단의 골드 레일 하나가 공통 기준선이 되게 한다.
- 탭 아래 모서리가 레일과 같은 y 기준에 닿게 한다. 1~2px 뜸, 아래로 돌출, 중복 선, 반사 띠와 실제 선의 위치 어긋남을 없앤다.
- 탭 좌/상/우 윤곽과 헤더 레일은 같은 골드 재질 토큰을 사용한다. 미세 반사·음영은 경계 안에서 연결한다.
- 레일은 2px 시작값. 아래 주변광 8~14px은 선의 실제 위치를 기준으로 준다. 흐릿한 빛으로 접합 오류를 가리지 않는다.
- 활성은 골드 문자와 정밀한 중립 면, hover는 해당 윤곽·문자 강조, pressed는 안쪽 음영으로 구분한다. 상태가 바뀌어도 선 위치는 고정한다.
- 사용자 대안인 ‘전체 테두리와 헤더선의 재질·위치 통일’도 가능하다. 선택한 방식은 한 가지로 통일하며 이중선이 남지 않게 한다.

메뉴: 기존 스포츠/실시간 스포츠/E스포츠/카지노/슬롯/미니게임/이벤트 유지. 실시간 스포츠 기본 활성. 로그인은 중립 버튼, 회원가입은 골드 주요 버튼. 공지는 32px 내 일반 서비스 안내 한 줄로 정리한다. 데모·체험·가상·수집/갱신 여부 고지는 표시하지 않는다. 우측 SPORTS DEMO/가상 금액/실제 거래 없음 문구를 없애고 빈 배지나 구분선도 남기지 않는다. 표시 문구는 §8.1을 따른다.

## 5. Main Content — 전체 카드 목록

### 5.1 분류·밀도

순서는 **실시간 스포츠 → 국내형 스포츠 → 인기경기**. 2026-09-17 추가 사용자 지시로 기존 마감임박 제목을 국내형 스포츠로 변경한다. 이는 표시명 변경이며 한국 리그만으로 대진을 제한하라는 요청은 아니다. 접근성 이름·연결된 안내의 기존 제목도 함께 맞춘다. 영문을 유지하면 `DOMESTIC SPORTS`를 실행 시작안으로 사용하고 `CLOSING SOON`은 남기지 않는다. 각 분류 3열을 유지한다. 데이터는 **최소60개의 서로 다른 실제 경기**를 준비하고 검증 가능한 자료·대응 자산이 있으면 더 많이 구성한다. 분류별24개, 총72개는 6개 단위 확장에 맞는 권장 시작안이며 사용자 지정 상한이 아니다. 각 분류의 기본 노출은 **6개(3열×2행)**다. 세 분류 기본 총18개를 한 viewport에 억지로 넣거나 카드를 축소하지 않는다. 중앙 스크롤로 다음 분류에 도달한다. 이전 각3개/총9개 기준은 폐기한다. 같은 경기를 복제하거나 분류 간 중복 집계해서60개를 채우지 않는다. 검색/필터 결과가 적으면 있는 경기만 정확한 count와 함께 표시한다.

제목판 기본: 48px, 카드까지 10px, 분류 사이 20px. 제목 부분은 금속 명패 성격, 나머지는 얇은 연결 레일과 상태/개수로 정리한다. LIVE/시간/인기 칩을 아이보리로 사용할 수 있다. 의미 없는 ‘전체 종목’ 별도 줄이나 반복 영문 장식 줄은 늘리지 않는다. 제목판과 레일도 헤더와 같은 접합 검사를 수행한다.

현재 실시간 자료가 부족하면 실제 기록 스냅샷으로 구성할 수 있다. 자료 출처·기준 시각은 내부 데이터/검수 문서에 보존한다. 방문자 화면에는 예정/진행/종료 등 경기 자체의 상태와 일정만 표시하고 수집본/기록/실시간 갱신 없음 같은 구현 설명은 제거한다. §8.1은 표시 문구 변경이며 데이터 수집 파이프라인 추가를 요구하지 않는다.

### 5.1.1 분류별 더보기와 아코디언 — LOCKED 동작

- 실시간 스포츠·국내형 스포츠·인기경기 각각 독립적인 노출 개수를 가진다. 초기6개, 클릭마다6개 추가: **6→12→18→24→…**. 기존 카드와 선택 상태는 유지한다.
- 남은 경기가 있을 때 해당 분류 카드 목록의 바로 아래, 다음 분류 제목보다 위에 **중앙 정렬한 더보기 버튼**을 둔다. 마지막 인기경기도 같은 방식으로 푸터 앞에 배치한다. 한 번에 모든 분류를 여는 공통 버튼은 만들지 않는다.
- 클릭하면 현재 분류 아래로 다음6개가 아코디언처럼 펼쳐지며 다음 분류 전체가 자연스럽게 아래로 밀린다. 페이지 이동·카드 교체·옆 넘김·별도 팝업·중첩 스크롤은 사용하지 않는다. 한 번 누른 뒤에도 남은 데이터가 있으면 버튼은 확장된 목록 아래에서 계속 작동한다.
- 마지막 남은 수가6개 미만이면 남은 경기만 표시한다. 끝에 도달하면 더보기 버튼은 제거한다. 임의 복제/빈 카드로6칸을 채우지 않는다. 별도 접기·자동 축소 기능은 이번 필수 범위에 추가하지 않는다.
- 펼침 애니메이션은 실제 콘텐츠 높이를 기준으로220ms ease-out부터 검토한다(IMPLEMENTATION DEFAULT). 움직임 감소 설정에서는 즉시 펼친다. 고정 max-height로 카드를 자르거나 큰 빈 공간을 남기지 않는다. 추가 카드와 배너 때문에 새 스크롤바가 나타나면 미완료다.
- 펼침 시 상단으로 이동시키지 않는다. 사용자가 보고 있던 기존 카드 위치와 각 사이드바 스크롤을 유지하고 같은 중앙 스크롤 영역 안에서 확장한다. 다른 분류의 펼침 개수는 바꾸지 않는다.
- 분류 제목의 경기 수와 종목별 count는 **검색/필터에 해당하는 전체 데이터 수**다. 기본 노출6개를 전체 경기 수처럼 표시하지 않는다. 검색은 아직 펼치지 않은 경기에도 적용된다.
- 검색·종목 조건을 바꾸면 새 결과에 대해 분류별 노출을6개부터 시작한다(실행 기본 동작). 검색/펼침 때문에 이미 선택한 슬립 항목이 삭제되면 안 된다. 동일 fixture ID와 market ID를 안정적으로 유지한다.
- 버튼은 실제button이며 키보드로 동작한다. 어느 분류를 더 여는지 접근성 이름으로 식별하고 aria-controls로 연결한다. 아직 숨겨진 경기의 배당 버튼이 먼저 탭 탐색되면 안 된다. 펼친 후 추가 개수는 필요한 접근성 상태로 전달하되 데모 설명을 표시하지 않는다.
- 더보기 버튼은 중립 블랙 바탕·골드 윤곽/문자·펼침 화살표를 사용한다. 표시 문구는 **더보기**, 크기168×36px·위아래16px 간격을 실행 시작안으로 삼는다. hover/pressed/focus가 일반 조작 버튼과 일관되게 작동해야 한다. HTML 기본 버튼으로 남기지 않는다.

검증 예: 분류당24경기면 초기6 → 첫 클릭12 → 두 번째18 → 세 번째24 및 버튼 제거. 분류당20경기면6→12→18→20. 다른 분류는6개 유지, 확장 중 선택/해제/계산 정상, 검색이 숨겨진 경기까지 찾는지 확인한다.

### 5.2 카드 구조와 스코어 — 위계 LOCKED / 치수 IMPLEMENTATION DEFAULT

**카드 바닥 위에 왼쪽 홈팀, 가운데 상태·점수, 오른쪽 원정팀을 직접 배치한다.** DOM의 정렬용 그룹은 가능하지만 점수 그룹에 별도 배경·테두리·오목 음영·베벨·광택·호버를 주지 않는다. 팀 로고·팀명과 같은 깊이에서 크기·굵기·여백으로 읽기 순서를 만든다. 불필요한 HOME/AWAY 장식 문구는 제거한다.

| 카드 부분 | 실행 기본값 |
| --- | --- |
| 바깥 padding/border | padding 상하 각 12px + border 각 1px = 26px |
| 메타 정보 | 22px: 종목/리그/필요 국기/시각 |
| 메타→대결 간격 | 8px |
| 대결 정보 | 82px: 팀 로고·최대 2줄 팀명 / 가운데 상태·점수 / 반대 팀 |
| 대결→배당 간격 | 8px |
| 배당 3행 | 42px×3 + 행간 6px×2 = 138px |
| 목표 총 높이 | 26+22+8+82+8+138 = **284px** |

고정 폭 약 418.67px. 대결 열은 `minmax(0,1fr) 84px minmax(0,1fr)`부터 검토한다. 팀 로고 약 28~32px, 팀명 16px/20px, 점수 30px/32px. 긴 이름 2줄과 로고가 겹치지 않도록 확보한 높이다. 현재 v5의284px 기본 높이를 유지하며 필요한 조정은 같은 역할 전체에 일관되게 적용한다. 사용자 승인 치수로 오인하지 않는다.

모든 기본 카드 높이를 통일한다. 경기 확장 중 과거450px 세로 카드나 다른 임시 컴포넌트를 혼합하지 않는다. 경기 전은 ‘– : –’, 진행 중은 자료의 실제 점수·진행 상태, 종료는 FINAL/종료 텍스트. 타이머를 무작위로 증가시켜 실제 라이브인 것처럼 꾸미지 않는다.

### 5.4 카드 마감

중립 바닥면, 얇은 외곽, 정밀한 상단 반사와 검정 깊이 그림자로 카드의 물성을 만든다. 골드 강조는 주요 경계·상태·선택에 집중한다. 단순 평면으로 만들라는 지시가 아니다. 버튼과 정보가 같은 깊이가 되거나 카드 안 모든 정보가 별도 버튼처럼 보이지 않게 한다.

## 6. Right Panel — 계정·슬립·문의·이벤트

계정 → 베팅슬립 → 문의/공지 → 작은 이벤트 배너 순서. 별도 스크롤과 숨긴 스크롤바 유지.

- 계정: 방문자/로그인 회원, 보유 금액, 충전·환전·베팅내역. 내부 계정 상태는 로컬 동작을 유지하고 화면에서 가상/체험/DEMO라고 부르지 않는다. 164px 안팎의 압축된 모듈부터 검토한다. 상태 칩·금액·액션을 구분하고 단순 갈색 박스를 남기지 않는다.
- 슬립: 핵심 모듈. 제목·선택 목록·베팅 금액·총 배당·예상 당첨금·베팅하기 버튼을 선명한 순서로 구성한다. 빈 상태를 과도한 공백이나 반복 설명으로 채우지 않는다.
- 선택 목록: 경기/선택/마켓/기준값/배당/삭제가 카드와 일치한다. 목록은 112~216px 범위에서 검토하고 긴 목록만 내부 스크롤한다. 합계와 실행부가 아래로 무한 밀리지 않게 한다.
- 합계 숫자는 정보로 읽히게 배치하고 전부 별도 입체 버튼으로 감싸지 않는다. 실제 입력창과 금액 추가 버튼에는 조작 표현을 준다.
- 목표 1920×940 검수에서 계정과 슬립의 핵심 입력·합계·실행부가 접근 가능해야 한다. 선택 수 증가 전후로 확인한다.
- 문의·공지는 짧은 행/내용 패널, 이벤트는 배너용 별도 타이포·면 분할로 처리한다. 경기 카드 프레임을 그대로 복제하지 않는다.

## 7. Interaction / Motion — 실행 기본값

CSS 및 기존 컴포넌트 기본값의 파란 focus ring, 남색 gradient, 위치 이동을 점검한다. 일반/hover/pressed/selected/disabled/focus-visible를 분리한다. 아래 효과는 강도 조절 가능하나 반려 표현으로 되돌리지 않는다.

| 대상 | 기본 → hover | pressed / selected / disabled | 시간 |
| --- | --- | --- | --- |
| 헤더 탭 | 중립 면·문자 → 골드 문자/좌상우 윤곽/정밀 베벨 강조. 공통 하단선 좌표 고정 | pressed는 inset, 활성은 골드 문자·면 경계 지속. 크기/위치 이동 없음 | 진입 160ms, 이탈 220ms |

- 실제 버튼 상태를 관찰한다. CSS에 효과가 존재하는 것만으로 완성도를 통과시키지 않는다.

원형 처리는 **표시 슬롯/받침의 형태**에 적용한다. 팀 엠블럼이나 리그 문자가 잘리는 무조건적인 이미지crop/cover는 금지한다. 슬롯 안에 원본 전체를contain으로 놓고 비율·고유색을 보존한다. 이미지 자체에 박힌 흰 배경과 CSS로 붙은 받침을 구분한다. 원본의 흰 무늬까지 투명하게 지우는 일괄 색상 제거를 하지 않는다. 필요하면 수집 자산 중 동일 대상의 투명 원본을 우선 사용한다.

카드 상단 메타 행(22px 시작안)은 flex/inline-flex와align-items:center를 사용한다. 종목20px/리그20px 공통 표시 높이로 맞추고 img는display:block으로 글자 baseline의 잔여 공간을 제거한다. 종목·리그명·시각도 같은 행의 중심선을 공유한다. 이미지마다 달랐던padding1/2/3px을 일괄 누적하지 않는다.

같은 CSS크기여도 원본 내부 투명 여백 때문에 그림이 작아 보일 수 있다. 실제 그림이 보이는 높이와 중심을 함께 확인하고 원본 전체가 유지되는 슬롯 안에서 자산별 scale/position을 최소 조정한다. 리그 원본을 눌러 늘리거나 글자를 잘라 높이를 맞추지 않는다. 사이드바 종목 및 대결부 팀 로고도 같은 역할끼리 시각적 크기를 맞춘다.

감사자는 [사용자 높이 반려 캡처](input/mercury-mvp-r7-package/MERCURY_MVP_R7/references/feedback-icon-height.png)와 기본·hover·selected 상태를 비교한다. 원형 예외인 리그가 둥글게 잘렸는지, 불필요한 아이보리 면이 남았는지, 나란한 두 이미지의 시각 높이/중심선이 어긋나는지 실제 화면에서 확인한다. CSS높이 숫자가 같다는 이유만으로 통과시키지 않는다.

현지 R7 검수 후 채택한 표시값은 [DECISIONS D23](DECISIONS.md)에 기록한다. 종목 슬롯22px 안 실제 그림20px, 넓은 퍽/NHL15px, 리그폭24px·MLB40px를 사용해 원본비율과 실제 그림 중심을 보존했다. 최종 받침은167개 중40개에만 유지하며127개는 제거한다. 이는 검수한 구현 선택이며 사용자 최종 승인 치수로 바꾸어 읽지 않는다.
### 9.2.2 경기 데이터 확장 — 최소60개

현지 Sports-Images의sources/scoreboard/teams 및 자산 매핑을 활용해 **60개 이상의 중복 없는 실제 fixture**를 준비한다. 24×3=72개는 권장 배분이며 더 확보한 유효 대진을 임의로60/72개에서 잘라내지 않는다. 각 분류가 기본6개와 최소 한 차례 더보기를 시연할 수 있도록12개 이상을 확보하는 것을 실행 기본으로 한다.

실제 경기ID/팀ID/리그/종목/홈·원정/시각/상태/로고가 맞는 대진을 쓴다. 같은 경기를 여러 섹션에 복제해서 최소 수를 채우지 않는다. 현재 자료로 부족하면 필요한 경기 데이터와 대응 자산만 보충한다. 확보 못 한 수는 정확히 보고하고9개를 유지한 채 확장 완료라고 주장하지 않는다. 이번 기획 환경에서60개 자료가 이미 준비됐다고 간주하지 않는다.

경기 수 증가는 고정1920 레이아웃과 카드의 읽기 크기를 바꾸는 이유가 아니다. 기본18개 노출·추가6개 확장으로 처리하고 다음 섹션과 더보기 위치를 검수한다. 자료 출처/수집 시각은 내부에 보존하고 §8.1의 데모 해설 금지는 유지한다.

### 9.3 이미지 제작 요청

충전·환전·고객센터·전체 스포츠·프레임·작은 배너 등에서 표현이 부족하면 아래 정보를 STATE에 남기고 사용자에게 전달한다. 추가 운영 MD는 만들지 않는다.

`자산 ID / 정확한 위치와 캡처 / 표시 슬롯(px) / 권장 원본·비율·PNG alpha 또는 WebM 필요 여부 / 블랙·골드·아이보리 재질·광원 / 필요한 상태 / 적용 파일명 / 자산 부재가 막는 범위`.

### 10.1 담당과 시작

진행 담당은 독립 감사 담당을 지정하고 STATE에 실제 식별자/배정 상태를 남긴다. 감사자는 AGENTS·STATE·본 사양·피드백 캡처를 읽고 **WOG를 직접 관찰한 근거**로 실제 표시·호버·버튼/패널 마감을 비교한다. 기존 독립 감사자의 직접 관찰 증거를 재사용할 수 있으나 부족하거나 달라진 부분은 WOG를 직접 다시 확인한다. 새로운 MERCURY 수정본의 시각·조작 검수는 직접 수행한다. 구현자와 같은 사람이 자신의 결과를 독립 통과시킬 수 없다.

실제 브라우저 접근이 안 되면 시각 감사 완료로 표시하지 않는다. 가능하면 접근 가능한 현지 브라우저/동일 버전 미리보기로 확인한다. 불가한 범위와 이유는 진행 담당에게 보고하고 나머지 구현을 전부 멈추지 않는다.

### 10.3 필요한 증거와 판정

- 실제 1920 폭 전체 화면과 중앙을 내려 본 화면. viewport·DPR·확인 가능한 확대율을 기록한다. 1920×940은 권장 시험 조건이며 사용자 실측이라고 주장하지 않는다.

- 헤더 접합부, 브랜드 결합, 대표 카드/서비스/슬립을 100%로 읽고 접합부는 캡처 확대 또는 브라우저 확대 관찰한다. 확대 화면을 정규 화면 크기 증거로 혼용하지 않는다.
- 같은 요소의 기본/hover/pressed/selected/disabled. 움직임은 실제 브라우저 연속 관찰 또는 짧은 녹화로 확인한다. 정지 사진만으로 모션 통과를 주장하지 않는다.

### 10.4 피드백 반영과 종료

구체 결함은 구현자가 보완하고 감사자가 재확인한다. 감사자의 취향만으로 새 디자인 목표를 발명하거나 같은 문제를 무한 재정의하지 않는다. 의견 차이와 사용자 판단이 필요한 지점은 근거와 함께 드러낸다. 정해진 토큰 상한이나 대표 요소 완료를 이유로 자동 중단하지 않는다.

**전체 완료:** 모든 영역이 같은 MERCURY 디자인으로 완성되고, 각 Q 항목의 결과와 실제 조작 검증이 있으며, 독립 감사·보완을 수행하고, 기존 주소에 검증본을 공개 반영한 상태다. 남은 결함/자산 대기/감사 불가가 있으면 이를 명시하고 ‘전부 완료’로 포장하지 않는다. 사용자가 중간에 멈추라고 하면 현재 상태와 보존본을 보고한다.
