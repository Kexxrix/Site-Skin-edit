# SIRIUS — R7 오른쪽 레일 구현 사양

문서 세트: **RIGHT RAIL VISUAL ALIGNMENT R7 · 2026-09-18**

## R01. 공통 디자인 문법

기준은 지금 공개된 R6 왼쪽이다. 구성 요소의 성격은 유지하면서 같은 모서리·표면·글자 위계를 적용한다. 오른쪽은 베팅 입력과 요약을 담당하므로 콘텐츠까지 왼쪽처럼 교체하지 않는다.

| 항목 | 적용 시작값 |
| --- | --- |
| 오른쪽 폭 | 기존320px 유지 |
| 패널 순서 | 계정 → 베팅슬립 → 고객센터 → 이벤트 배너1개 |
| 패널 사이 |14px |
| 패널 반경/패딩 |12px / 12px |
| 표면/경계 | R6 실제 `#111F3C → #09142D`160도 그라데이션 / `#2B3D5F`1px |
| 일반 제목 |16px/600, 베팅슬립 주제목18px/600 |
| 한글 UI | 현재 Pretendard 계열 연결 그대로 |
| 숫자 | 현재 `din-condensed`400, 용도별17–28px |
| 일반 버튼 반경 |7px, 목록/선택 카드8px |
| 포커스/hover | 골드 포커스2px / 표면·경계 변화140ms 전후 |

사각 제목 바와 패널 맨 위 금색 선을 정리한다. 제목을 패널 안 여백에 놓고, 필요한 정보 구분은 간격과 약한 남색 면으로 만든다. 같은 패널 안에 굵은 테두리를 반복하지 않는다. 검색창과 금액 입력창은 캡슐형이지만 패널·베팅 실행 버튼까지 모두 캡슐로 바꾸지는 않는다.

실제 R6 토큰이 있으면 그대로 참조한다. 공유 토큰을 손대야 할 경우 왼쪽 계산 스타일이 바뀌지 않게 하고, 이번 목적만으로 전역 리팩터링을 벌이지 않는다.

## R02. 계정 패널

- `MY ACCOUNT` 문구는 유지하고 현재 장식적 타이틀 표현을16px/600의 일반 UI 제목으로 정리한다. 오른쪽 GUEST/회원 상태는10–11px 캡슐형 표시로 유지한다. 상태 텍스트를 고정값으로 바꾸지 않는다.
- 인물 아이콘·환영 문구·로그인/계정 접근 동작은 유지한다. 인사 문구는14px/600, 긴 회원명은 줄바꿈하거나 기존 전체 이름 확인 수단을 유지하며 아이콘 버튼과 겹치지 않게 한다.
- 보유 금액 영역은 낮은 대비의 남색 면, 반경8px·패딩10px. ‘보유 금액’12px, 실제 잔액은 기존 DIN28px/400·화이트로 강조한다. 통화 표기·구분 쉼표·값은 그대로다.
- 충전/환전/베팅내역3개는 같은 행, gap8px, 높이38px, 반경7px, 글자13px/600. 기존 칸막이형 바를 독립된 버튼3개로 변경한다.
- 충전은 왼쪽과 같은 샴페인 골드 채움, 환전은 남색 면·얇은 골드 경계, 베팅내역은 낮은 대비 남색 경계. 아이콘14–16px. 버튼 문구가 잘리지 않도록 내부 패딩을 맞춘다.
- 계정 패널 전체 높이는 내용에 따른다. 큰 잔액이나 긴 회원명 때문에 숫자를 잘라내거나 옆 컬럼을 넓히지 않는다.

## R03. 베팅슬립과 선택 항목

- ‘베팅슬립’18px/600 제목, 오른쪽 선택 수는 왼쪽 전체 스포츠 경기 수와 같은 작은 남색 캡슐+DIN17px. 기존 사각 골드 숫자 배지는 교체한다.
- 전체 제거는 제목 옆26–28px 아이콘 버튼. 비어 있을 때 비활성·접근성 이름 유지. 빨간 채움 버튼으로 과하게 강조하지 않는다.
- 단일/다중 등 현재 선택 모드와 BET SLIP 보조 표시는12px/10–11px로 조용히 표시한다. 현재 모드 계산과 표시 문자열을 그대로 사용한다.
- 빈 상태: 기존 티켓 아이콘·‘선택한 배당이 없습니다’·도움 문구 유지. 여백이 있는 안내 영역으로 만들고 강한 테두리 상자를 추가하지 않는다. 최소 높이112px 전후에서 시작하고 이후 항목이 생기면 자연스럽게 대체한다.
- 선택 항목: 카드 반경8px, 패딩10px, 카드 간8px. 패널보다 조금 밝거나 깊이가 구별되는 남색 면과 약한 경계. 리그11px, 팀명13–14px/600, 마켓 설명11px, 선택값13px, 배당20px DIN 골드.
- 리그·홈/원정 팀명·선택 방향·배당·마켓 종류·기준점·정규/연장 조건·잠금/오류 등 기존 정보를 유지한다. 홈/무/원정만 크게 쓰고 경기나 마켓 맥락을 삭제하지 않는다.
- 팀명/마켓 설명은 필요한 만큼 줄바꿈한다. 고정 카드 높이로 자르지 않는다. 배당과 기준점에는 말줄임·반올림을 적용하지 않는다. 긴 배당값은 숫자 영역이 먼저 줄어들지 않도록 한다.
- 개별 제거 아이콘을 명확히 분리한다. 선택·제거로 기존 중앙 배당 상태와 슬립이 계속 연동돼야 한다. 단일/다중 베팅 정책을 임의 변경하지 않는다.
- 기존 슬립의 목록 스크롤 정책을 유지한다. R7 때문에 새 중첩 스크롤이나 별도 고정 바를 추가하지 않는다.

## R04. 금액 입력·합계·베팅 실행

- ‘베팅 금액’14px/600, KRW11px의 기존 라벨 연결을 유지한다.
- 금액 입력 프레임은 높이44px·반경999px, 왼쪽 검색창과 같은 깊은 남색 면/경계/focus. 좌우 패딩14px, 내부 gap8px. 통화 표시·실제 input·MAX를 같은 프레임 안에 놓는다.
- 실제 입력 숫자는 기존 DIN24px/400, 오른쪽 정렬. input에 `min-width:0`를 주고 MAX28px 높이의 소형 캡슐 텍스트 버튼은 축소되지 않게 한다. placeholder는 기존 ‘금액 입력’ 한글 UI 폰트18px 정도로 유지한다.
- input의 현재 문자열 관리, 숫자 입력 처리, 라벨, 입력 모드, 최소/최대 검증을 그대로 둔다. `<input type>`을 스타일 변경을 위해 바꾸지 않는다.
- `+5천 / +1만 / +5만 / 초기화`는 기존4열, gap6px, 높이34px, 반경7px,12px/600. 증액3개는 남색, 초기화는 낮은 대비 면. MAX와 증액의 실제 한도/잔액 처리도 유지한다.
- 최소/최대 안내와 오류 문구를 유지한다. 현재 금액 한도1,000원/100,000원은 관찰값이며 현지 값에서 읽는다. CSS/문구에 새 값으로 하드코딩하지 않는다.
- 오류 입력은 기존 오류색과 메시지가 명확히 보여야 한다. 골드 focus 스타일이 오류 경계를 덮지 않게 한다.
- 총 배당은 라벨12px·DIN22px 화이트, 예상 당첨금은 라벨12px·DIN26px 골드. 후자는 약한 남색 요약 면/반경8px로 구별한다. 전체 합계 영역을 금색 채움으로 만들지 않는다.
- 통화·쉼표·소수점과 기존 계산 정밀도를 보존한다. 공간이 부족하면 라벨과 값이 다른 줄로 흐르도록 하며 값을 잘라 숨기거나 줄임말로 바꾸지 않는다. 기존 표시 가능한 큰 값에서도 읽혀야 한다.
- ‘베팅하기’는 폭100%·높이44px·반경7px·15px/600. **실제로 활성인 경우만** 왼쪽 충전/헤더 회원가입과 같은 골드 그라데이션/짙은 남색 글자다.
- 비활성은 낮은 대비 남색과 흐린 글자·기존 disabled 속성. 선택 없음, 로그인 필요, 입력 오류 등 기존 조건을 골드 버튼을 보이게 하려고 해제하지 않는다.
- 기존 안내 output/확인창/확정 동작/저장·이력·잔액 처리를 유지한다. 이번 작업은 화면 표현 변경이다.

## R05. 고객센터

- 패널 표면/반경/여백을 계정과 통일한다. 헤드폰 아이콘은 기존 골드,24px 전후. ‘무엇을 도와드릴까요?’16px/600, ‘이용 안내’12px의 위계로 정리한다.
- ‘1:1 문의 안내’와 ‘공지사항’은 높이38px 전후·반경8px·14px/500의 메뉴 행. 좌측 고객센터/종목 행처럼 hover 면이 생기는 방식으로 한다.
- 기존 직선 구분선은 정리하고 행간6px 정도로 구별한다. 화살표와 기존 대화창/동작을 유지한다.

## R06. 기존 이벤트 배너

- 현재 오른쪽 이벤트 배너1개를 같은 위치에 유지한다. 사진 `/banners/r8/mercury-event-woman.png`를 그대로 재사용한다. 이 경로 이름을 이유로 MERCURY를 수정하지 않는다.
- 전체 프레임16:9, 폭320px에서 높이 `320 × 9 ÷ 16 = 180px`. 기존220px 높이는 해제한다. 반경8px, 사진cover/center, 얇은 경계, 하단 남색 가독성 그라데이션.
- 왼쪽처럼 사진+작은 영문+제목만 표시한다. 작은 영문은 `SIRIUS EVENTS`, 제목은 기존 ‘당신의 밤을 / 더 특별하게.’ 두 줄을 유지한다. 영문10px·제목20px/600·줄높이25px, 왼쪽 아래14px 여백. 얼굴을 가리지 않는다.
- 내부 ‘이벤트 보기’ 버튼은 없애고 배너 전체를 기존 이벤트 핸들러에 연결한다. 접근성 이름은 `이벤트 보기`. 버튼을 투명하게 겹쳐 두지 말고 바깥 요소 하나만 interactive하게 구성한다.
- 바깥 요소를 button으로 바꿀 때 내부 heading/div를 그대로 중첩하는 대신 이미지와 span 기반의 유효한 마크업으로 정리한다. 기존 흐름이 경로 이동이면 유효한 링크를 사용한다.
- 캐러셀·사진 자동 교체·추가 배너·신규 행사 내용은 넣지 않는다. 기존 이벤트 안내창/메뉴를 재사용한다.

## 적용과 기본 확인

오른쪽 루트에 `.sirius-right-r7`를 추가하고 참고 CSS를 현지 규칙에 병합한다. `right-rail-map.json`에 실제 관찰한 클래스와 필요한 작은 마크업 변경을 정리했다. 계산/인증/선택 상태를 새 컴포넌트로 옮기는 작업은 필요하지 않다.

구현 중 빈 슬립과 한 건/여러 건 선택, 제거, 금액/MAX/증액·초기화, 기존 오류·비활성, 긴 팀명·배당·금액, 이벤트 배너와 오른쪽 하단 스크롤을 대표 사례로 짧게 확인한다. 기존 로컬 테스트/미리보기의 허용된 상태에서 확인하고 실제 베팅 제출을 검수 목적으로 새로 실행하지 않는다. 통상 빌드 후 기존 공개사이트에 반영하고 사용자 피드백을 받는다. 별도 QA 스레드·긴 감사는 없다.
