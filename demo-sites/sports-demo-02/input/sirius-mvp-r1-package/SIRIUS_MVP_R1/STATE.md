## 1. 이 ZIP을 전달할 때의 시작 문장

> 첨부한 SIRIUS_MVP_R1.zip을 풀고 AGENTS.md와 STATE.md부터 읽어 첫 구현을 시작해. 현재 MERCURY의 소스와 공개 사이트를 보존하고 별도 SIRIUS 프로젝트를 만들어. 중앙은 bwin 구조와 국내형 마켓 열을 기준으로 가로 경기 목록으로 변경하고, William Hill 참고 화면의 깊은 청색·화이트·골드로 전체를 마감해. 제공 심볼·레터링과 기존 종목·팀·리그·국기 자산을 사용해. 기존 진행·구현·독립 품질 감사 스레드를 이어서 가동하고, 전체 구현과 감사 보완 후 별도 공개 주소의 실제 화면까지 확인해 보고해. 토큰 제한은 없다.

이 문장은 **진행 담당에게 전달하는 전체 작업 지시**다. 단계별 로컬 확인은 중간 과정이며, 이번 첫 구현의 목표는 전체 SIRIUS 페이지를 검증해 새 주소로 공개하는 것이다. 이 ZIP을 작성한 기획 스레드는 실제 새 사이트를 만들거나 배포하지 않았다.

## 4. 시작 시 한 번 확인할 사항

1. MERCURY 현지 최신 소스·변경 파일·실행 방법·현재 공개 화면을 읽기 전용으로 확인한다. R8 ZIP을 앱 원본으로 쓰지 않는다. 원본 commit과 변경 여부를 기록하고 사용자/다른 작업자의 수정은 보존한다.
2. 새 작업 경로를 확정한다. 새 작업 루트에 이 ZIP의 운영 문서4개와 자산/참고 자료를 두고 `site/`를 별도 소스 디렉터리로 사용한다. 복제본 안에 옛 MERCURY 운영 문서가 있다면 새 작업 지시와 충돌하지 않도록 이관을 정리한다. 원본 문서는 보존한다. 공유 심볼릭 링크로 MERCURY의 수정 가능 파일을 연결하지 않는다.
3. 현지 앱의 경기 고유 ID, 분류, 마켓, 슬립·계정 상태 저장 방식, 폰트·팀/리그/국기·양측 배너 실제 경로를 확인한다. 필요한 파일만 새 프로젝트 안으로 복사한다.
4. 스포츠 수집 루트의 이미지와 메타데이터를 확인한다. 기존 수집 완료 자산을 우선하며, 같은 리소스를 새로 크롤링하는 작업을 반복하지 않는다.
5. 구현 담당이 현지 Sites 스킬을 읽고 새 프로젝트 등록을 시작한다. 소스 코드와 의존성을 재사용하되 MERCURY의 `.git`, 원격 저장소, 자격증명, 배포 캐시, 사이트 식별자 및 리소스 바인딩은 신규 대상으로 승계하지 않는다. 복사한 기존 hosting 설정은 새 프로젝트용 값으로 안전하게 분리하고 검증 전 배포하지 않는다.
6. 이미 등록한 SIRIUS가 발견되면 해당 ID와 저장소를 확인해 재개한다. 등록 응답이 불명확하면 기존 시도를 확인하며 새 사이트를 반복 생성하지 않는다. 새 등록은 그 자체로 공개 배포가 아니다.

폰트나 특정 로고가 없으면 정확한 누락 목록을 남기고 가능한 구조·스킨 작업을 계속한다. 앱 원본 자체에 접근할 수 없으면 그 접근 문제를 구체적으로 보고한다. 없는 소스를 임의로 재구성하고 복제 완료라고 하지 않는다.

> SIRIUS R1을 담당한다. 기존 MERCURY는 보존하고 STATE의 별도 경로/별도 Sites 정체성으로 최신 앱을 복제한다. ### 독립 감사 담당

> SIRIUS R1 독립 품질 감사다. 중앙 구성은 제공 bwin 화면을 최우선, 마켓 열은 국내형 화면, 색감과 골드 재질은 William Hill 화면으로 판단한다. WOG는 직접 열어 완성도만 비교하고 외형을 복제하라고 요구하지 않는다. S02 가로 행 구조와 전체 스킨 완료본을 각각 실제 렌더로 보고, 정렬·정보 깊이·텍스트/로고 크기·버튼 상태·경기 표시·양측 레일/팝업까지 검사한다. 이미 통과된 리그 로고와 팀명은 추가 개선 과제로 올리지 않는다. 지적은 위치/상태/근거/수정 방향/재확인 결과로 반환한다. 소스·배포·사양을 수정하지 않는다. 확인하지 못한 항목은 미확인으로 남긴다.
