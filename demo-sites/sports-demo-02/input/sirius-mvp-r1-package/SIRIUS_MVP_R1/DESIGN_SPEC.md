# SIRIUS — 첫 구현 사양

문서 세트: **MVP R1 · 2026-09-18**  
핵심: **머큐리의 기능과 외곽 구성 위에, 정렬된 가로 경기 목록과 깊은 청색·화이트·골드 스킨을 만든다.**

## 1. 적용 우선순위

사용자 제공 스크린샷은 이번 디자인 판단의 실제 입력이다. 외부 사이트를 다시 열지 못하더라도 제공 화면을 무시하지 않는다. WOG 직접 관찰은 별도 감사 항목으로 기록하며 접근 불가 시 관찰했다고 주장하지 않는다.

## 2. 첫 구현의 완료 범위

신규 SIRIUS 프로젝트에 기존 앱을 복제하고, 중앙 목록을 완성한 뒤 **헤더·공지·양쪽 레일·패널·버튼·슬립·검색·팝업·배너 등 기존 노출 화면 전체**를 SIRIUS로 마감한다. 기존 연결된 페이지/패널이 있으면 함께 검사한다. 중앙만 파랗게 만들고 사이드와 팝업을 MERCURY 상태로 남기지 않는다.

새 심볼/레터링은 이미 제공됐고 종목 아이콘은 기존8종 재사용으로 확정됐다. 새 이미지 제작 대기로 첫 구현을 멈추지 않는다. 로컬 기존 동작을 유지하며 결제·실거래·새 게임/영상 서비스·신규 회원 서버 구축은 이번 범위에 없다.

## 3. 화면 틀·스크롤·밀도

고정1920 화면과 독립 스크롤은 유지한다. 아래 치수는 기존 기준을 잇는 **IMPLEMENTATION DEFAULT**이며, 중앙 카드 치수는 폐기한다.

| 영역 | 시작값 |
| --- | --- |
| 전체 shell | width1920px, border-box, 축소 없음 |
| 헤더 / 공지 | 68px / 32px |
| 본문 외곽 여백 / 열 간격 | 12px / 12px |
| 좌 / 중앙 / 우 | 272px / 1280px / 320px |
| 본문 높이 | 실제 innerHeight − 68 − 32 − 24 |
| 1920초과 폭 | 내부 폭 유지, 가로 중앙 배치 |

합계는24 + 272 + 1280 + 320 + 24 =1920px이다. 예시 viewport1920×940에서 본문 높이는816px이다. 1080px 모니터 해상도를 브라우저 콘텐츠 높이로 고정하지 않는다.

헤더와 공지 아래 좌·중·우가 각각 스크롤한다. `min-height:0`, 적절한 `overflow-y:auto`를 유지하고 트랙/손잡이/화살표 표시는 숨긴다. 키보드·휠 이동은 정상이어야 한다. 좁은 화면용 재배치·전체 자동 축소는 이번 과제가 아니다. 1920보다 작은 viewport 부분 캡처를 전체 시각 검수 증거로 제출하지 않는다.

## 4. 중앙 경기 목록 — 최우선 작업

### 4.1 계층과 시선 흐름

기본 구성은 **기존 섹션 제목 → 리그 그룹 헤더 → 공통 마켓 헤더 → 연속 경기 행 → 중앙 더보기 → 다음 섹션**이다. 처음에는 리그 그룹을 펼친다. 리그 그룹 접기는 제목의 명확한 버튼으로 제공하고 `aria-expanded` 상태를 맞춘다. 경기 수는 원자료 기준으로 계산한다.

`실시간 스포츠 / 국내형 스포츠 / 인기경기`의 기존 섹션 이름과 분류를 보존한다. 경기 카드의3열 그리드는 제거한다. 하나의 경기는 중앙 가용 폭 전체를 사용하는 한 행이다. 다른 섹션을 독립된 큰 금색 테두리 박스로 중첩하지 않는다.

bwin의 연속 목록과 상위 마켓 표기가 우선이다. 첫 구현에서는 기존 분류와6개씩 펼치기를 유지하기 위해 리그 그룹 헤더를 사용한다. 별도 리그 가로 탭까지 중복 추가하지 않는다. 이는 **실행 기본안**이며 사용자에게 새로운 필터 체계를 승인받았다는 뜻이 아니다.

### 4.2 가로 열

| 열 | 표시 내용 | 위계·정렬 |
| --- | --- | --- |
| 시간/상태 | 시작 시각, 날짜, LIVE/경기 단계 또는 예정/종료 | 고정 폭, 단순 텍스트. 의미 없는 상태 박스 추가 금지 |
| 경기 | 홈 로고+팀명+점수 / 원정 로고+팀명+점수 | 두 팀을 위아래로 쌓고 점수는 각 팀과 같은 수평선 |
| 승무패/승패 | 해당 종목 마켓의1/X/2 또는 홈/원정 | 열 폭은 고정, 내부를3개 또는2개 균등 분할 |
| 핸디캡 | 홈/원정, 정확한 기준점과 각 배당 | 방향·기준점·배당의 대응을 분명히 표시 |
| 언더/오버 | 기준점, 언더/오버 각 배당 | 앞뒤 순서는 제목/버튼/슬립에서 일치 |
| 기타 | 실제 제공하는 추가 마켓 펼침 | 추가 데이터가 있을 때만 개수/버튼 제공 |

열 시작 좌표는 리그·종목·경기마다 같아야 한다. 팀명이 길다고 승무패 열이 오른쪽으로 밀리면 실패다. 마켓 헤더와 경기 행에 **같은 grid-template-columns** 또는 동등한 공통 열 정의를 사용한다.

1280px 중앙과 좌우12px 내부 padding 기준의 시작 예:

```css
/* 실행 기본값. 같은 정의를 마켓 헤더와 모든 경기 행에서 공유한다. */
--match-columns: 96px minmax(0, 1fr) 264px 228px 228px 76px;
/* 1256px 내부 폭, gap 8px × 5일 때 팀 열은324px */
```

마켓 내부 간격은4px, 배당 버튼 높이는38px부터 시작한다.3-way 승무패도 숫자와 작은 결과 라벨을 읽을 수 있어야 한다. 전체 행 높이는 약88px, 내부 세로 여백10~12px를 시작값으로 삼는다. 글자를 억지로 줄여 밀도를 올리지 않는다. 과도한 카드형 여백으로 한두 경기만 보이게 하지 않는다.

### 4.3 정보 면과 버튼 면

- 팀 로고20px 내외, 팀명14~16px, 점수20~24px부터 실제 렌더를 확인한다. 로고 슬롯은 동일하고 이미지 자체 비율은 유지한다.
- 홈/원정2줄의 베이스라인·로고 중심·점수 오른쪽 끝을 정렬한다. 점수 열은 짧은 고정 폭으로 예약하고 tabular 숫자를 쓴다. 예정 경기에 임의0:0을 넣지 않는다.
- 팀명은 해당 열 안에서 처리한다. 긴 이름은 다른 열을 밀지 않도록 말줄임하고 전체 이름을 기존 상세/툴팁 등으로 확인할 수 있게 한다. 현재 이름을 임의 축약·재번역하지 않는다.
- 점수/FINAL/LIVE는 별도 입체 박스가 아니다. 팀/점수 영역과 마켓 제목은 기본 커서, 선택 면 없음. 경기 행 자체는 필요 이상으로 통째 클릭되게 만들지 않는다.
- 행 사이에는 얇고 낮은 대비의 청색 경계만 둔다. 각 경기를 둥근 카드로 다시 분리하거나 여러 겹 외곽선으로 감싸지 않는다.
- 리그 헤더에는 기존 리그/국기와 명칭을 정렬한다. 마켓 제목은 그룹 상단에 한 번 표시한다. 매 행에서 긴 마켓 설명을 반복하지 않는다.
- 핸디캡 부호와 홈/원정의 대응, U/O 기준점이 명확해야 한다. 작은 라벨+배당 숫자는 버튼 안에서 구분할 수 있으나 비클릭 마켓 설명을 가짜 버튼으로 만들지 않는다.
- 2-way 종목에서 무승부를 만들어3칸을 채우지 않는다. 마켓이 없거나 잠겼다면 해당 열 정렬을 보존하면서 비활성/잠금 상태를 구별한다.
- `+48`, `+39` 같은 참고 화면 수치를 그대로 복사하지 않는다. 추가 마켓 수는 현재 경기의 실제 추가 데이터에서 계산한다. 없으면 해당 셀은 비워 두거나 비조작 `—`로 처리한다.

### 4.4 경기 수·6개씩 펼치기

- **고유 경기 최소60개**, 현지 최신 MERCURY의77개가 있으면 축소하지 않고 재사용한다. 기존 분류·fixture ID·마켓 ID를 보존한다. 같은 경기를 다른 ID로 복제해 수를 채우지 않는다.
- 각 섹션은 처음6경기, 더보기마다6경기를 추가한다. 단위는 리그 그룹 수가 아니라 **경기 수**다. 전체 초기 렌더는18경기이며,18개를 한 viewport에 압축하라는 뜻이 아니다.
- 섹션별 확장 상태는 독립적이다. 더보기는 해당 섹션 마지막 행과 다음 섹션 사이 중앙에 둔다.6→12→18 순으로 누적하고 마지막 잔여가6개 미만이면 모두 표시한다. 잔여가 없으면 버튼을 제거한다.
- 안정된 정렬의 경기 목록에 표시 개수 제한을 적용한 뒤 리그 그룹으로 그린다. 더보기로 같은 리그 경기가 늘면 기존 그룹에 이어 붙인다. 그룹 접힘은 더보기 수를 임의로 늘리지 않는다. 확장된 경기와 리그 총 경기 수 표기는 혼동하지 않게 한다.
- 더보기는 부드럽게 추가 영역을 드러내되 기존 경기나 스크롤 위치가 튀지 않게 한다. 자동 전체 펼침, 페이지 교체, 다음 섹션을 덮는 오버레이로 대체하지 않는다. reduced-motion에서는 즉시 펼쳐도 된다.
- 검색은 접힌/아직 노출되지 않은 경기를 포함한 전체 데이터에 적용한다. 검색/종목 필터 변경 시 결과를 각6개부터 시작하고 슬립 선택은 유지한다. 새로고침 시 표시6개로 복귀하는 기존 동작을 유지한다.

## 5. 청색·화이트·골드 스킨

### 5.1 면과 색

깊은 청색은 사용자가 지정한 이번 정체성이다. MERCURY의 검정에 파란 선만 넣는 정도로 끝내지 않는다. 헤더/레일의 깊은 면과 중앙 목록/버튼의 밝은 청색 면이 구별돼야 한다. 주요 텍스트는 흰색, 보조 정보는 차분한 청회색, 골드는 선택/주요 버튼/브랜드/정밀한 강조에 집중한다.

제공 William Hill 스크린샷의 단색 영역에서 확인한 색은 헤더 `#060A2A`, 바깥 청색 `#0B173C`, 상단 골드 버튼 `#FCE1A4`다. 이는 **첨부 이미지 픽셀 기준**이며 현행 사이트 CSS 추출값은 아니다. 다음 표는 그 방향에서 정리한 **IMPLEMENTATION DEFAULT**다.

| 역할 | 시작값 |
| --- | --- |
| 바깥 바탕 | `#0B173C` |
| 헤더/가장 깊은 면 | `#060A2A` |
| 레일/기본 패널 | `#101D42` |
| 중앙 목록 면 | `#14244D` |
| 리그 헤더/입력 면 | `#0D1938` |
| 낮은 경계 | `#2D4065` |
| 기본 버튼 위 / 아래 | `#263B63` / `#1B2C4D` |
| 주요 / 보조 문자 | `#FFFFFF` / `#AFBCD4` |
| 골드 반사 / 기본 / 음영 | `#FCE1A4` / `#D7B96C` / `#AF8E45` |
| 골드 버튼 위의 문자 | `#101A34` |
| LIVE / 긍정적 변화 | `#F36C78` / `#66D6AF` |

중앙의 대형 흰색 면은 이번 기본안에 넣지 않는다. **청색 연속 목록 + 흰 텍스트**를 먼저 완성한다. 외부 화면의 흰 광고·대형 흰 카드까지 함께 복제하지 않는다. 아이콘 배경에 아이보리 사각형을 새로 깔지 않는다. 팀/리그 원본 고유색과 사용자가 승인한 기존 표현은 유지한다.

### 5.2 재질과 상태

청색 패널은 차분한 평면을 기본으로 한다. 버튼은 미세한 수직 명도 차이, 위쪽1px 반사, 얇은 경계/눌림 음영으로 구별한다. 금색 면은 주 CTA와 선택 배당에 집중하며 모든 행을 금색으로 둘러싸지 않는다.

| 대상 | 기본/hover | pressed/selected/disabled |
| --- | --- | --- |
| 배당 버튼 | 청색 수직 gradient, 흰 배당. hover는 면 밝기·경계·윗면 반사를 소폭 강화 | pressed는 inset, selected는 골드 면+어두운 숫자+명확한 선택 표시. disabled는 낮은 청색 대비+잠금, 클릭/hover 없음 |
| 충전·가입·주 CTA | 은은한 샴페인 골드 gradient. hover는 위쪽 반사 강화 | 눌림 음영, 글자/아이콘 위치 고정 |
| 환전·보조 동작·더보기 | 청색 면, 흰 문자, 절제된 경계 | 활성 강조는 골드 문자/선. 모든 보조 버튼을 금색 면으로 칠하지 않음 |
| 헤더 메뉴 | 기본 흰색/청회색, hover 골드 문자 또는 미세한 면 변화 | 선택 메뉴의 골드 하단 표시가 공통 하단선과 정확히 연결 |
| 종목/리그 조작 | 행 밝기 변화와 명확한 focus | 선택 레일/텍스트 강조. 원본 금속 PNG의 색과 질감 유지 |
| 경기 정보 행 | 얇은 구분선. 읽기를 돕는 작은 면 변화만 선택적으로 사용 | 행 전체를 선택 버튼처럼 금색으로 채우지 않음 |

효과 시작값: hover140~180ms, pressed60~80ms, easing `cubic-bezier(.2,.8,.2,1)`. scale/translate로 위치나 주변 정렬이 움직이지 않게 한다. 넓고 흐릿한 대각선 금색 막이나 전 패널 맥동을 쓰지 않는다. 키보드 focus-visible는 골드/청색 양쪽 면에서 구별되는 윤곽으로 표시한다. 선택+hover가 선택 상태를 지우면 안 된다.

LIVE 표시는 기존2.4초 안팎의 작은 밝기 변화 정도로 제한한다. 원자료 변화가 없는데 배당 상승/하락이나 스코어 변경을 반복해 만드는 효과는 넣지 않는다. `prefers-reduced-motion`에서는 반복 움직임을 멈추고 상태 의미는 유지한다.

## 6. 브랜드·폰트·이미지

### 6.1 헤더의 SIRIUS

**왼쪽 심볼 → 간격 → 오른쪽 SIRIUS 레터링**을 하나의 브랜드 그룹으로 둔다. 기존272px 브랜드 영역과68px 헤더를 유지한다. 별도 사이드 패널에 심볼을 전시하지 않는다. 로고를 텍스트로 재현하거나 새 이미지를 생성하지 않는다.

| 자산 | 실제 파일 확인 | 적용 원칙 |
| --- | --- | --- |
| `assets/branding/sirius-symbol.png` | 640×640 RGBA. alpha 범위0–255, 비투명 영역 bbox(22,16,640,640) | 표시36×36px부터 검토. 가장자리 궤도·별을 자르지 않음 |
| `assets/branding/sirius-wordmark.png` | 1741×704 RGBA. 비투명 영역 bbox(0,0,1741,588) | 하단116px은 완전 투명. 실제 그림 높이42px 안팎부터 검토 |

두 이미지 모두 진짜 알파 채널이 있다. 미리보기에서 보인 흰/검정 여백을 배경 사각형으로 재현하지 않는다. 레터링 원본 비율을 전체 이미지 박스에만 맞추면 여백 탓에 글자가 작아지거나 위로 치우칠 수 있다.

원본을 수정하지 않는 레터링 처리의 예:

```css
.sirius-wordmark {
  width: 124.36px;
  aspect-ratio: 1741 / 588;
  overflow: hidden; /* 검증된 하단 투명 여백만 제외 */
  flex: none;
}
.sirius-wordmark img {
  display: block;
  width: 100%;
  height: auto;
}
```

이 예는 실제 그림 높이 약42px, 위아래 약12px 여유를 위한 시작값이다. 위쪽 별과 좌우 궤도를 자르는 crop은 금지한다. 이미지 원본의 비율을 왜곡하지 않고 실제 보이는 외곽을 기준으로 심볼/레터링의 세로 중심과 간격8px 안팎을 맞춘다. MERCURY 로고와 다른 종횡비를 무시해 동일 width/height를 강제하지 않는다. 더 크게 보여야 한다는 이유로 헤더 높이를 늘리지 않는다.

페이지 제목·보이는 브랜드·이미지 alt·배너 브랜드 라벨을 SIRIUS로 바꾼다. favicon은 제공 심볼을 적절히 참조한다. 원본 파일명/데이터 출처의 mercury 문자열까지 무차별 치환하지 않는다.

### 6.2 폰트

현지 프로젝트의 파일·family·weight 로더를 재사용한다. CSS 선언, 네트워크 로드, 실제 글리프 렌더를 구분해 확인한다. 일본어 요소가 없다면 실제 사용 검사는 해당 없음으로 기록한다. 이미지 레터링을 폰트로 다시 만들지 않는다. 기본 UI14px, 팀명14~16px, 배당16~18px, 보조 정보12px 이상부터 비교한다. 필요할 때 크기를 조정하되 긴 이름 때문에 전체 글자를 지나치게 줄이지 않는다.

## 7. 양쪽 레일·배너·기타 화면

- 왼쪽: 빠른 서비스 → 검색/종목 → 이미지 배너 → 기존 가이드/바로가기 순서를 유지한다. 오른쪽: 계정/슬립/도움/배너 등 현지 최신 구성을 유지한다. bwin 사이드바나 William Hill 광고 영역으로 교체하지 않는다.
- 충전·환전은 좌우2열의 **`[작은 아이콘] 충전` / `[작은 아이콘] 환전` 한 줄**이다.119×36px, icon14~16px 시작값을 유지하고 세로 아이콘+라벨 형태로 되돌리지 않는다. 청색 스킨의 골드 충전/청색 환전으로 재질만 맞춘다.
- 헤더 활성 표시와 공통 하단선의 위치·두께를 맞춘다. 탭 좌/상/우 윤곽을 사용할 경우 아래쪽을 중복 선으로 닫지 않는다. 언더라인이 탭 밑에서 어긋나는 문제를 다시 만들지 않는다.
- 검색, 잔액, 베팅 슬립, 도움말, 공지, 기존 모달의 정보 밀도와 동작을 보존한다. 선택 수가 늘어도 금액/총배당/예상당첨금/실행 영역으로 이동할 수 있어야 한다.
- 좌우 배너는 현재 사진을 재사용하고 프레임·문구·CTA를 HTML/CSS로 분리한다. 얼굴은 오른쪽, 텍스트는 왼쪽의 안전 영역으로 유지한다. 얼굴 위에 제목이나 버튼을 얹지 않는다. 네이비 오버레이가 필요하면 텍스트 쪽에만 절제해 적용한다.
- 배너 기존 문구/CTA의 동작을 유지하면서 브랜드 라벨을 SIRIUS로 바꾼다. 예: 왼쪽 `SIRIUS SLOTS / 빛나는 밤, 새로운 즐거움. / 슬롯 둘러보기`, 오른쪽 `SIRIUS / 당신의 밤을 더 특별하게. / 이벤트 보기`. 실제 없는 혜택·지급액·당첨 보장을 새로 쓰지 않는다.
- 모든 기본/빈 상태/선택/확인/완료/로그인/내역/서비스 팝업에서 임시 사이트라는 해설을 제거한 상태를 유지한다. `SPORTS DEMO`, `SPORTS EXPERIENCE`, `SNAPSHOT`, `수집 기록`, `실시간 갱신 없음`, `선택 체험하기`, `가상 금액`, `실제 거래 없음`, `스크린샷에 나오는` 같은 표현을 다른 개발 용어로 돌려쓰지 않는다.
- 정상적인 예정/진행/종료 상태, 오류 안내, 기존 미지원 서비스의 실제 상태는 정확히 표현한다. 문구 정리가 실제 서비스 백엔드 구현 완료를 의미하지 않는다.

## 8. 경기 데이터·현장감·기능 보존

실제 경기/팀/리그/국기를 사용한다. 최신 진행 자료, 예정 경기, 최근 주요 종료 경기 모두 사용할 수 있다. 현재 데이터 재사용을 우선하고 필요할 때 `Sports-Images`의 sources/scoreboard/teams 및 수집 메타데이터를 확인한다.

진행 경기는 종목에 맞는 전후반/이닝/쿼터/남은 시간과 원자료의 점수를 표시한다. 현재 피드가 없으면 이미 허용된 실제 진행 스냅샷을 활용할 수 있다. 자료 기준 시각과 정적/재생/갱신 방식은 내부에 기록한다. 종료 점수를 중간 점수로 바꾸거나 모두 같은 진행 상태로 채우지 않는다. 실제 원자료가 없는 수치는 현장감 연출을 위해 만들지 않는다.

배당은 합리적인 수준의 기존 값 사용이 허용됐다. 새로 외부 배당을 가져올 필요는 없다. 화면과 슬립의 경기·마켓·선택·기준점·배당 매핑을 일치시킨다. 기존 fixture/market/outcome 식별자를 유지하고 안정적인 key를 쓴다.

| 기능 | 반드시 유지·확인할 동작 |
| --- | --- |
| 검색/종목 | 전체 경기 대상 팀·리그 검색, 종목 선택, 초기화, 실제 결과 수, 빈 결과 |
| 펼치기/그룹 | 각 섹션6개씩, 독립 확장, 리그 접기/펼치기, 숨겨진 선택 유지 |
| 배당 선택 | 클릭 선택, 재클릭 해제, 같은 경기 선택 교체, 잠금 차단 |
| 슬립 | 행 선택과 즉시 동기화, 개별/전체 삭제, 빈/단일/조합 상태 |
| 금액/계산 | 기존 입력·빠른 추가·초기화·검증·합계·예상당첨금 |
| 계정/내역 | 기존 로컬 로그인/로그아웃/확인/내역 저장 동작, 상태 명칭 정상 |
| 서비스/배너 | 기존 메뉴와 일치한 팝업/이동, 스타일 회귀 없음 |

총배당은 곱한 원값으로 계산하고 중간 반올림하지 않는다. 검산 예:1.84×1.56=2.8704, 표기2.870,10,000원에서 예상28,704원. 이 숫자는 계산 검산 예시이며 특정 경기에 강제로 배정하지 않는다. 실제 거래 연동을 추가하지 않는다.

SIRIUS는 별도 사이트 정체성을 갖는다. 저장 키를 하드코딩했다면 SIRIUS 이름 공간으로 분리하되 스키마와 동작은 유지한다. MERCURY 로그인 정보나 사용자의 실제 비밀값을 새 프로젝트 파일로 옮기지 않는다.
