# SIRIUS — 작업 공통 규칙

문서 세트: **SIRIUS MVP R1 · 2026-09-18**  
목적: 현재 MERCURY를 보존하면서 별도 SIRIUS 사이트를 구현한다. 이 ZIP은 첫 구현 입력 자료다. 구현 완료 보고서나 사이트 소스 배포본이 아니다.

## 1. 읽기 순서와 우선순위

1. AGENTS → STATE의 실행 지시 → DESIGN_SPEC → 관련 코드 순서로 읽는다. 확정 배경은 DECISIONS에서 확인한다.
2. 최신 사용자 지시 > SIRIUS의 확정 결정 > 이 문서의 실행 기본값 > 충돌하지 않는 기존 MERCURY 규칙 순이다.
3. **LOCKED**는 사용자 확정 방향이다. **IMPLEMENTATION DEFAULT**는 구현 시작값이며 실제 렌더를 보고 조정할 수 있다. 실행 기본값을 사용자 승인 시안이나 합격 증거로 쓰지 않는다.
4. 운영 문서는 **AGENTS.md / STATE.md / DESIGN_SPEC.md / DECISIONS.md 네 개**만 유지한다. 새 HISTORY/HANDOFF/TASKS/감사 MD를 늘리지 않는다. 캡처·자산 매핑 JSON은 별도 리소스로 둔다.
5. 입력 ZIP은 보존하고, 새 프로젝트 작업 루트에 네 문서를 배치해 갱신한다. 기존 MERCURY 문서는 SIRIUS 문서로 덮어쓰지 않는다.

## 2. 이번 작업의 경계

- **MERCURY 소스·공개 주소·배포는 보존한다.** 현지 최신 소스를 별도 디렉터리로 복제하고, SIRIUS의 별도 Sites 프로젝트와 공개 주소를 만든다.
- 진행 순서는 **분리·복제 → 중앙 경기 목록 완성 → 전체 SIRIUS 스킨 → 기능 검증 → 독립 감사·수정 → 별도 공개 배포·확인**이다. 복제나 일부 경기 행만 만든 상태로 완료하지 않는다.
- 헤더와 양쪽 레일의 구성·배치를 유지한다. 중앙 카드 격자는 가로 경기 목록으로 교체한다. 패널·버튼·테두리·상태 표현은 SIRIUS의 깊은 청색/화이트/골드로 바꾼다.
- 기존 기능·경기 데이터·팀/리그/국기·종목 이미지·폰트·배너 구성을 재사용한다. 불필요한 프레임워크 교체, 전체 재수집, 새 결제·실거래 백엔드, 새 게임/미디어 서비스는 추가하지 않는다.
- MERCURY의 남색 금지·중립 블랙/아이보리 팔레트·3열 경기 카드·동일 공개 주소 갱신은 **SIRIUS에 적용하지 않는다**. 해당 기준은 MERCURY에서만 유효하다.

## 3. 역할과 작업 소유권

| 역할 | 책임 | 작업 범위 |
| --- | --- | --- |
| 진행 담당 | 범위 배정, 현재 상태 기록, 독립 감사 연결, 결과 통합 | 새 프로젝트의 운영 문서와 전달 |
| Sites 구현 담당 | 복제, 새 프로젝트 등록, 전체 구현, 자체 검증, 수정, 배포 | SIRIUS 소스·자산·설정의 단일 소유자 |
| 독립 품질 감사 | 실제 렌더·조작, 참고 화면 및 WOG와 완성도 비교, 구체 피드백·재확인 | 읽기·관찰·증거. 소스·배포·사양 직접 수정 금지 |
| 사용자 | 디자인 최종 수용, 추가 이미지 공급, 범위 변경 | 사용자 통과 항목을 감사자 취향으로 재반려하지 않음 |

STATE의 기존 담당 스레드를 우선 재사용한다. 현지에서 실제로 접근 가능한 기능으로 연결하고, 실행하지 않은 감사나 존재하지 않는 제어 도구를 만들어 보고하지 않는다. 구현자가 호출한 하위 감사 에이전트는 Sites 소유자가 아니며 등록·소스 변경·배포를 맡지 않는다. 감사의 캡처 저장은 소스 밖에서 수행하고 진행 담당이 필요한 증거만 정리한다.

독립 감사가 연결되지 않아도 가능한 구현과 자체 검증은 계속한다. 그 경우 독립 감사는 **미실시/미확인**으로 남기고 한계를 보고한다. 자체 검수를 독립 PASS로 바꾸거나, 연결 불가를 이유로 시작부터 전체 작업을 보류하지 않는다.

## 4. 디자인·자산 기본 규칙

- 중앙 구조는 bwin 참고 화면을 우선하고, 마켓 열 구성은 국내형 참고 화면, 색감·골드 재질은 William Hill 참고 화면을 따른다. WOG는 완성도 비교 기준이다. 외부 브랜드·코드·이미지·화면 전체를 복제하지 않는다.
- 제공 SIRIUS 심볼은 **헤더 레터링의 바로 왼쪽**이다. 별도 좌측 패널을 만들어 전시하지 않는다. 원본 투명도와 비율을 보존한다.
- 제공된 금속 종목 PNG 8개를 그대로 사용한다. 이미지 크기에 맞춰 행·버튼을 확대하거나 단색 SVG/이모지로 되돌리지 않는다.
- NHL 등 기존 리그 로고와 팀명 수준은 사용자 통과다. 추가 번역·리그 로고 재제작을 이번 과제로 만들지 않는다. 경로 오류나 정렬 회귀는 수정한다.
- 점수·팀명·팀 로고·경기 상태는 같은 정보 면에 둔다. 비클릭 정보를 버튼처럼 박스로 둘러싸지 않는다. 배당 선택만 명확한 조작 면으로 구별한다.
- 화면의 데모/목업/체험/수집본/실시간 갱신 없음/실제 거래 없음 등 구현 해설은 다시 넣지 않는다. 출처·기준 시각·로컬 동작 조건은 내부 데이터와 문서에 보존한다.
- 실제 경기·실제 일정·원자료의 상태를 사용한다. 종료 경기에 LIVE를 붙이거나 무작위 점수·타이머로 실제 갱신을 가장하지 않는다. 합리적인 배당 값 사용은 허용된 범위다.
- 추가 이미지가 필요하면 STATE에 위치·목적·권장 규격·투명도·텍스트 안전 영역을 적는다. 사용자 명시 지시 없이 새 이미지 생성이나 추가 이미지 플러그인을 실행하지 않는다.

## 5. 실행·검수·종료

- **토큰/주간 사용률 제한은 없다.** 과거 20% 사용량 중단 조건은 폐기됐다. 강제 중단 도구나 사용량 조회 기능 부재를 사전 보류 사유로 삼지 않는다. 사용자 정지 요청과 실제 플랫폼 한계는 따른다.
- 실제 화면의 정보 위계·정렬·재질·상태를 확인한다. CSS 속성 존재, 빌드 성공, 구조 구현만으로 디자인 완료를 판정하지 않는다.
- 감사자는 확정 범위 내 결함을 위치·상태·근거·수정 방향으로 제시한다. 수정 후 같은 항목을 재확인한다. 통과 기준을 계속 바꾸거나 같은 취향 의견을 무한 반복하지 않는다. 의견이 갈리면 증거와 미결 판단을 STATE에 남긴다.
- 현지 최신 `sites-building`/`sites-hosting` 절차를 사용한다. SIRIUS 등록 결과를 기록하고 새 프로젝트의 설정·저장소·배포 대상을 교차 확인한다. MERCURY의 프로젝트 ID나 원격 저장소를 SIRIUS의 배포 대상으로 사용하지 않는다.
- 최종 보고에는 새 URL, 실제 변경, 검증 범위, 독립 감사 결과, 잔여 문제, 최신 commit/version/deployment 식별자를 포함한다. 미검증을 PASS로 쓰지 않는다. 배포 성공과 사용자 최종 수용을 구분한다.
