## 2. 헤더 보강

### H1. 상단 로고 영역과 브랜드 확대

중앙 브랜드·2단 메뉴·좌측 공지·우측 계정이라는 R2 구조를 유지한다. 로고가 잘 보이도록 **상단 줄과 브랜드를 약150%로 확대하고 하단 메뉴 줄은 소폭 높인다.** 헤더 전체와 모든 요소를 한 번에150% 확대하지 않는다.

| 대상 | R2 기준 | R3 시작값 |
| --- | --- | --- |
| 상단 브랜드 줄 | 56px | 56×1.5=84px |
| 하단 메뉴 줄 | 44px | 50px |
| 헤더 합계 | 100px | 84+50=134px |
| 심볼 표시 높이 | 32px | 32×1.5=48px |
| 레터링 실제 그림 높이 | 약34px | 34×1.5=51px |
| 심볼–레터링 간격 | 8px | 12px |

- 실제 보이는 그림 기준으로 정렬한다. 84px 줄/51px 그림이면 상하 여유는 (84−51)÷2=16.5px이다. 여백을 먹으며 확대하지 않는다.
- 두 이미지를 한 그룹으로 묶어 좌우 공지/계정 폭과 무관하게 중앙에 둔다. 공지는 한 줄 말줄임하며 브랜드를 침범하지 않는다.
- 심볼640×640은 비율 유지. 레터링1741×704의 실제 그림 높이는588, 아래116px은 투명이다. 기존 CSS 표시창을 재사용하고 원본 파일은 바꾸지 않는다. 그림 높이51일 때 표시 폭은 51×1741÷588≈151px이다.
- 헤더 높이와 본문 높이는 공통 값으로 연결한다. 예: viewport940에서 940−134−24=782px. 현재 헤더100px 전제의 본문 높이/팝업 위치를 방치하지 않는다.
- 1920px shell과 좌272/중1280/우320, 열 간격12px, 각 열의 독립 스크롤은 유지한다. 브랜드 확대 때문에 레일 폭을 변경하지 않는다.
- 기존 공지를 상단에 통합한 상태를 유지한다. 별도 공지 줄을 다시 추가하지 않는다.

### H2. 활성 메뉴 글자에 골드 그라데이션

- 스포츠 / 실시간 스포츠 / E스포츠 / 카지노 / 슬롯 / 미니게임 / 이벤트7개와 현재 주 클릭 목적을 유지한다.
- 현재 선택된 메뉴의 **텍스트 자체**를 밝은 샴페인 골드→중간 골드→짙은 골드로 표현한다. 시작 예: 위 `#FFF2BF` → 중간 `#EFCE79` → 아래 `#C7973C`. 작은 글자에서도 골드 변화가 읽히도록 조정한다.
- 일반 메뉴는 화이트/청회색. 메뉴 글자는17px 전후에서 기존 폰트와 굵기로 조정하고, 활성 상태 때문에 글자 폭과 메뉴 위치가 변하지 않게 한다.
- 기존 골드 활성선2px/약180ms 이동을 유지해 텍스트와 한 쌍으로 보이게 한다. 골드가 메뉴 배경 전체를 채우는 큰 탭으로 되돌리지 않는다.
- hover는 가벼운 명도 변화, 선택은 골드 텍스트+활성선, 키보드 focus는 명확한 윤곽으로 구분한다. 포커스만 옮겼다고 현재 메뉴가 바뀌지 않게 한다.
- CSS 텍스트 그라데이션 미지원 상태에서도 단색 골드로 글자가 남아야 한다. 글자를 이미지로 굽지 않는다. 깜박임·반복 광택 쓸기·바운스는 이번 효과에 포함하지 않는다.
- 기존 종목 탐색의 열기/닫기·필터 동기화·Escape 복귀·오버레이는 보존한다. 커진 메뉴 줄 아래에 붙도록 위치만 연동한다.

### H3. 로그인·회원가입 버튼 스타일 기준

| 버튼 | 기본 표현 | 상태 변화 |
| --- | --- | --- |
| 로그인 | 헤더와 어울리는 깊은 남색, 얇은 밝은 테두리, 화이트 글자 | hover 시 표면/테두리가 조금 밝아짐, pressed 시 표면을 한 단계 낮춤 |
| 회원가입 | 밝은 샴페인 골드 면, 짙은 남색 글자, 낮은 곡률 | hover 시 골드 명도 소폭 상승, pressed 시 명도 소폭 감소 |

- 두 버튼의 높이·모서리·문자 중심을 맞춘다. 시작값 높이36px, 최소폭76px, 좌우 패딩16px, radius3px, border1px, 버튼 사이8px. 글자나 기존 계정 기능에 맞게 폭을 조정한다.
- 로그인 면은 예를 들어 `#080F2C`, 얇은 테두리는 밝은 회백색. 회원가입은 `#DCC58B`→`#FFE4A0` 정도의 부드러운 골드 변화, 글자는 `#111D36`을 시작값으로 삼는다.
- 두꺼운 베벨·여러 겹 테두리·큰 검은 그림자로 머큐리 금속 버튼을 반복하지 않는다. 표면 변화와 얇은 경계로 마감한다.
- 로그인/회원가입의 실제 클릭 흐름과 계정 상태는 보존한다. 새로운 가입 서버나 혜택 문구를 추가하지 않는다.
- 공통 색/곡률/테두리 값을 정리하되 **이번 적용은 헤더 계정 버튼에 한정**한다. 레일과 중앙 전체 버튼을 전역 selector로 바꾸지 않는다. C03의 배당 높이 변경은 별도 범위다.
- 후속 레일/배당 스타일 방향은 남색 기본·골드 주요 행동/선택이다. 이번에 사이트 전체를 골드 버튼으로 바꾸는 지시가 아니다.

## 3. 중앙 경기 목록 디테일

### C01. 간격만으로 승무패·핸디캡·O/U 구분

- 마켓 내부 버튼 간격은4~6px, 마켓 그룹 사이는16~20px를 시작값으로 둔다. 실제 화면에서 한 줄의 등간격 버튼처럼 읽히지 않도록 조정한다.
- **그룹 구분용 새 선·패널·배경 박스·테두리를 추가하지 않는다.** 기존 경기 행 사이 구분선은 유지할 수 있다.
- 열 제목과 경기 행은 동일한 공통 열 정의를 사용한다. 3-way 승무패와2-way 승패는 각 그룹 전체 폭을 유지한 채 내부 버튼만 나눈다.
- 중앙 가용 폭 안에서 팀 영역·마켓 폭·추가 베팅 폭을 함께 조절한다. 새 간격만 추가해 우측이 잘리거나 전체 가로 스크롤이 생기게 하지 않는다.

### C02. 팀 아이콘·이름·점수를 가까운 묶음으로

- 두 팀 각각 `로고 / 팀명 / 스코어` 순서와 공통 칸을 사용한다. 점수가 첫 배당 버튼에 붙어 마켓 숫자로 보이지 않아야 한다.
- 전체 팀 열의 빈 폭을 이름–점수 사이에 남기지 않는다. 내부 팀 묶음을 좁히고 나머지 공간은 **팀 묶음과 첫 마켓 사이**에 둔다.
- 이름 길이에 따라 점수가 움직이지 않도록 점수 칸을 예약하고 두 점수 오른쪽 끝을 맞춘다. 실제 폰트에서 세 자리 숫자와 대시가 들어가는 폭을 확보한다.
- 긴 팀명은 팀명 칸에서만 한 줄 `…` 말줄임한다. 이름 칸의 최소폭/overflow 처리를 맞추고 전체 이름을 확인할 수 있는 수단을 유지한다.
- 점수는 팀과 같은 면에 둔다. 별도 상자·배경·클릭 버튼으로 표현하지 않는다. 팀명 정교화나 로고 교체는 하지 않는다.

### C03. 배당 버튼 높이 소폭 확대

- 현재 약38px에서44~48px를 시작 범위로 검토한다. 두 줄 팀명과2~3줄 상태 정보에 비례해 세로 중심을 맞춘다.
- 경기 행높이88px를 먼저 유지한다. 배당 버튼을 두 팀 전체 높이만큼 늘리거나 전체 행을 함께 크게 만들지 않는다.
- 숫자·라벨의 중심, 두 줄 핸디캡/기준점, 잠금 아이콘이 같이 읽혀야 한다. 잠금·선택·hover·focus의 기존 구별은 유지한다.
- R2의 남색 표면과 버튼/패널 명도 차이는 유지한다. 이번에는 헤더에서 만든 스타일을 모든 배당 버튼에 자동 이식하지 않는다.

### C04. +숫자와 추가 베팅 상세

기존 기타 열의 `—`를 경기별 `+64`, `+128` 같은 추가 베팅 진입 버튼으로 바꾼다. 열 이름은 `추가 베팅`을 기본안으로 사용한다. 작은 폭 안에서 숫자와 간결한 화살표가 읽히게 한다.

| 종목 | 사용자 지정 | 이번 실행 기본값 |
| --- | --- | --- |
| 축구 | 3자리까지 가능 | 24~180 범위로2·3자리 혼합 |
| 야구 | 2자리 | 12~76 범위 |
| 농구 | 빅 스포츠에 포함, 정확한 자릿수 미지정 | 24~128 범위로2·3자리 혼합 — 구현 기본값임 |
| 그 외 | 1자리 정도 | 1~9 범위 |

- 위 범위의 표시 수는 사용자 승인된 **화면용 가상 숫자**다. 고유 fixture ID에 연결한 메타데이터 또는 안정적인 결정값으로 만들고 검색/필터/재렌더/새로고침에 바뀌지 않게 한다. 렌더마다 난수를 뽑지 않는다.
- 기존 실제 additionalMarketCount나 마켓 배열 길이를 덮어쓰지 않는다. 별도 표시 필드(예: displayAdditionalMarketCount)를 사용하고 내부에 출처를 남긴다. 방문자에게 개발 설명을 추가하지 않는다.
- 경기 수·점수·진행 시간·배당 숫자 변경으로 이 허용을 확대하지 않는다. 표시 수를 맞추기 위해 마켓을 수십 번 복제하지 않는다.
- 클릭 시 해당 경기 상세를 연다. 기존 상세/마켓 뷰가 있으면 재사용한다. 없다면 **중앙 열 안에 최소 경기 상세 화면과 목록으로 돌아가기**를 구현한다. 새 독립 사이트·거래 백엔드·대형 서비스 화면은 만들지 않는다.
- 최소 상세에는 해당 경기의 종목/리그·팀·상태·점수와 기존에 보유한 마켓을 연결한다. 추가 유형의 데이터가 없다면 해당 유형을 잠금/비활성으로 구분한다. 새 배당을 임의 산출하거나 표시 수만큼의 전체 마켓이 지원된다고 내부 보고하지 않는다.
- 첫 골·전반 승·후반 승은 축구에서 적용 가능한 예다. 야구·농구·그 외 종목에 같은 항목을 일괄 복제하지 않는다. 실제 데이터가 없는 추가 유형의 보강은 남은 사항으로 짧게 기록한다.
- 목록 복귀 시 검색/종목/6개 확장 수/리그 접힘/읽던 중앙 위치/슬립을 보존한다. 단순 `href="#"`, 아무 반응 없는 버튼, 다른 경기로 연결되는 링크는 완료가 아니다.

## 4. 중앙 스크롤과 모션

### C05. 더보기와 접기의 아코디언

- 기존 세 섹션 모두 최초6개, 더보기 클릭마다6개 추가를 유지한다. 버튼은 섹션 끝과 다음 섹션 사이의 중앙에 둔다. 잔여6개 미만이면 잔여만 노출한다.
- **목록 영역 높이 자체가 펼쳐지고 접히는 모션**을 준다. 기본200ms, 조정 범위180~240ms. 페이드만으로 대신하지 않는다. 시간차 순차 등장·긴 지연·바운스를 넣지 않는다.
- 기존 행을 다시 마운트하거나 이미 읽은 항목을 처음부터 애니메이션하지 않는다. 고유 ID/선택을 유지하고 새6개가 기존 마지막 경기 아래에서 드러나야 한다. 같은 리그에 행이 늘 때와 새 리그가 추가될 때 모두 처리한다.
- 펼침 후 버튼이나 목록 끝을 따라 자동으로 맨 아래로 스크롤하지 않는다. 읽던 위치를 유지한다.
- 기존 리그 접기/펼치기에도 같은 짧은 높이 전환을 적용한다. 더보기의 추가 노출분을 접는 기능이 없다면 섹션 끝에 작은 `접기`를 두어 최초6개로 복귀시킨다. 모든 경기를 펼쳤어도 접기 수단은 남긴다. 다른 섹션의 확장 상태는 유지한다.
- 닫을 때 제거되는 내용 안에 초점을 남기거나 빈 공간을 보여 주지 않는다. 남는 행/제어를 기준으로 필요한 만큼만 스크롤 위치를 보정하고 페이지 전체 상단으로 튀지 않게 한다.
- 실제 내용 높이로 전환하며 완료 후 자연 높이를 사용한다. 거대한 고정 max-height로 속도가 들쭉날쭉하거나 마지막 행이 잘리지 않게 한다.
- 연속 클릭 시 중복 추가나 상태 역전이 생기지 않게 짧게 중복 입력을 막거나 진행 중 전환을 자연스럽게 이어간다. 장시간 조작 잠금은 만들지 않는다.
- 모션 축소 환경에서는 전환을 줄이거나 즉시 처리한다. 행 수/위치/선택 보존은 동일하다.

### C06. 맨 위로 — 순간 이동 없이 부드럽게

- 실제 **중앙 스포츠 스크롤 컨테이너**를 대상으로 한다. 중앙 내용이 넘치고 한 화면 높이 이상 내려가면 표시한다. 시작 조건은 `scrollTop >= clientHeight`다.
- 버튼은 중앙의 보이는 영역 우측 하단, 우측 레일의 바로 왼쪽에 고정한다. 페이지 전체 오른쪽 아래에 붙여 슬립을 덮지 않는다.
- 시작값36~40px 원형/낮은 곡률의 남색 버튼과 간결한 위 화살표, 우측/하단12~16px 여백. 접근성 이름은 `맨 위로`다.
- 클릭 시 현재 위치부터 중앙 scrollTop0까지 **스르륵 이동하고 끝에서 자연스럽게 감속**한다. 시작값 약400ms, 거리 조정하더라도 약500ms를 넘기지 않는 실용적인 속도로 둔다. 정확한 시간은 구현 시작값이며 사용자 고정값은 아니다.
- 기존 smooth-scroll 구현이 적절하면 재사용한다. 별도 애니메이션이 필요하면 중앙 한 곳만 제어한다. CSS/native smooth와 사용자 정의 스크롤을 중복 실행하지 않는다.
- 사용자 휠/터치/키보드 스크롤 입력은 자동 이동을 중단할 수 있어야 한다. 연속 클릭으로 이동 작업을 중첩하지 않는다. 모션 축소 환경에서는 즉시 이동한다.
- 필터/검색·확장 개수·리그 접힘·슬립/금액·좌우 레일 스크롤은 유지한다. 상단 이동은 초기화 기능이 아니다.
- 상단 도달 후 버튼은 숨긴다. 키보드 실행 시 초점이 사라지지 않도록 중앙 상단의 적절한 위치로 연결한다. 숨은 버튼은 Tab/클릭을 가로채지 않는다.
- 배당·추가 베팅·더보기와 겹치지 않게 한다. 필요하면 목록 끝에 작은 하단 여유를 둔다. 헤더 탐색과 모달보다 위로 떠서 조작을 방해하지 않게 한다.

## 5. 유지할 화면과 완료 방식

- R2의 남색 면, 원본 사진/아이콘/글자 밝기, 팀/리그/국기와 폰트는 유지한다. 전역 밝기 필터나 검은 덮개를 쓰지 않는다.
- 레일 순서/폭/기능/배너 위치, 기존 검색/슬립/계정 동작을 유지한다. 모바일 재배치와 전체 서비스 재구현은 제외한다.
- 구현자가 통상 빌드와 수정 동작을 짧게 확인한다. 세 자리 점수나 긴 팀명을 확인해야 하면 실제 데이터 또는 임시 로컬 표시로 확인하고 공개 원데이터를 바꾸지 않는다.
- **별도 검수 스레드, 항목별 PASS 보고, 반복 미감 재감사는 없다.** 기본 오류를 고치고 바로 공개 반영한다. 사용자와 이 대화에서 보고 판단한다.
- 공개 결과 캡처와 실제 적용값·남은 사항을 STATE에 간단히 남긴다. 이번 수정의 완성도를 구현자가 임의로 최종 승인하지 않는다.
