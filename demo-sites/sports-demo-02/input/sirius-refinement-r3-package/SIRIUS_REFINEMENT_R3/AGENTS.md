# SIRIUS — R3 작업 공통 규칙

문서 세트: **REFINEMENT R3 · 2026-09-18**  
목표: **헤더 보강 + 중앙 경기 목록 디테일 + 펼침/접기 모션 + 맨 위로 이동 → 기존 공개사이트 업데이트 → 사용자 피드백**.

## 1. 지시 우선순위와 문서

- 최신 사용자 지시 > 이 R3의 확정 방향 > 실행 기본값 > 충돌하지 않는 이전 규칙 순이다.
- AGENTS → STATE의 바로 실행할 지시 → DESIGN_SPEC 순서로 읽는다. DECISIONS는 결정 이력이다.
- 운영 문서는 AGENTS.md / STATE.md / DESIGN_SPEC.md / DECISIONS.md 네 개만 관리한다. 추가 QA/HANDOFF/README/작업지시 MD를 만들지 않는다. 이미지·자산 매핑·실행 기록 JSON은 허용한다.
- 패키지 입력은 보존하고 현지 네 문서에 최신 지시를 병합한다. 현지 commit·배포·문제·실제 확인 기록을 이 패키지의 실행 전 기록으로 덮어쓰지 않는다.
- 픽셀·시간·색상 시작값은 구현 조정용이다. 사용자 확정 방향과 제안 수치를 구별한다. 실제 적용값은 STATE에 간단히 남긴다.

## 2. 역할 변경 — 별도 검수 단계 중단

**사용자가 다시 명시적으로 요청하기 전까지 검수 스레드의 검수 과정을 제외한다.** 이번 R3부터 지속 적용한다.

| 역할 | 책임 |
| --- | --- |
| 진행 담당 | 범위와 네 문서 관리, 기존 구현 담당에게 전달, 결과 취합 |
| 구현 담당 | 현재 소스 수정, 작업 중 기본 오류 확인, 기존 SIRIUS 공개 배포와 반영 확인 |
| 기존 검수 스레드 | 이번 작업 배정·호출·재감사 없음. 재개 지시 전까지 대기 |
| 사용자와 이 피드백 대화 | 공개 결과를 보고 디자인과 사용감을 판단하고 다음 수정 결정 |

- 독립 QA 호출, 별도 PASS 보고서, QA 완료 대기, 이중 브라우저 검사, WOG 비교, 미감 점수화와 반복 승인 관문을 만들지 않는다.
- 구현자의 통상적인 빌드와 수정 기능의 짧은 동작 확인은 작업에 포함한다. 이를 다른 이름의 별도 감사 단계로 확장하지 않는다.
- 확인된 실행 오류·클릭 불능·잘림은 구현 중 수정한다. 추가 오류가 없으면 같은 검사를 반복하지 말고 배포한다. 검사하지 않은 항목을 통과라고 기록하지 않는다.
- QA 결과를 요구하는 과거 R1/R2 조항은 과거 이력이다. 현재 절차는 **구현 → 기본 오류 확인 → 공개 업데이트 → 사용자 피드백**이다.
- 외부 Windows 스레드를 실제로 연결/중단하지 않았다면 그렇게 주장하지 않는다. 기존 작업 흐름을 이어 쓰며 새 검수 에이전트를 만들지 않는다.

## 4. 유지할 기준

- 기존 경기 데이터와 ID, 77경기 기준, 실시간/국내형/인기 섹션별 최초6·추가6, 검색/필터·슬립·금액 계산을 유지한다. 더 최신의 현지 데이터가 있으면 차이를 기록하고 임의로 되돌리지 않는다.
- 중앙은 리그별 가로 목록을 유지한다. 팀·점수는 같은 정보 면에 놓고, 마켓 그룹은 간격으로만 구분한다. 추가 구분선·마켓 패널·점수 박스를 만들지 않는다.
- 승인 심볼은 레터링 바로 왼쪽, 그룹 전체는 헤더 중앙이다. 원본 PNG와 투명도를 보존한다. 흰 네모 배경을 추가하지 않는다.
- 금속 종목 PNG8종, 팀/리그/국기/배너/폰트를 그대로 쓴다. 다른 대화의 아이콘 실험을 이 사이트에 자동 적용하지 않는다. NHL 로고·현재 팀명은 재작업 대상이 아니다.
- C04 추가 마켓 표시 수에 한해 사용자 승인된 가상 수를 허용한다. 경기별 고정값으로 만들고 내부에서 표시용임을 구분한다. 실제 점수·시간·배당·잔액을 임의 변경할 권한으로 확대하지 않는다.
- 방문자 화면에 데모/목업/체험/수집 시점/구현 해설 문구를 다시 넣지 않는다. 내부 기록과 기능 미지원 상태는 사실대로 유지한다.
- 사용자 지시 없는 이미지 생성·외부 이미지 편집 플러그인 사용은 하지 않는다.

## 5. 실행과 종료

- 토큰/주간 사용률 제한 없음. 과거20% 중단 규칙은 폐기 상태다.
- 필요한 부분을 현재 코드에서 최소 수정한다. 디자인 시스템 엔진, 새 애니메이션 라이브러리나 프레임워크를 선행 도입하지 않는다.
- 기존 빌드 절차를 사용한다. 타입 검사가 빌드에 포함되면 같은 검사를 불필요하게 중복하지 않는다. 실패 원인과 연결된 부분만 보완한다.
- 기본 오류 확인 뒤 기존 공개사이트를 업데이트한다. 검수 스레드 결과나 추가 미감 승인을 기다리는 중간 관문을 두지 않는다. 실제 권한·플랫폼 제한은 사실대로 알린다.
- URL·실제 commit/버전/배포 ID·변경 요약·남은 문제를 STATE에 적고 간단히 보고한다. 별도 QA는 '사용자 지시로 미실시'이며 누락/실패로 처리하지 않는다.
- 종료 상태는 **R3 공개 반영 / 사용자 피드백 대기**다. 사이트 전체 최종 완성이나 미감 승인으로 선언하지 않는다. 레일 다음 단계로 자동 진입하지 않는다.
