# SIRIUS — 헤더·색감 R2 구현 사양

문서 세트: **HEADER R2 · 2026-09-18**  
확정 방향: **중앙 브랜드 + 2단 내비게이션 + 펼쳐지는 종목 탐색**. 전체 면 색감은 현재보다 조금 어둡게 조정한다. 첫 공개 반영 후 사용자와 이 부위를 다듬는다.

헤더의 새로운 외형은 아래 사양을 따른다. 참고 이미지에는 기존 헤더가 남아 있으므로 그 배치를 다시 따라 만들지 않는다. 과거 William Hill은 남색/화이트/골드 방향의 배경이고, bwin/국내형 참고는 이미 구현된 중앙 구조의 배경이다. 이번에 외부 페이지를 다시 모사하거나 WOG 재감사를 수행할 필요는 없다.

## 3. 헤더 구조

### 3.1 두 줄 구성

| 줄 | 왼쪽 | 중앙 | 오른쪽 |
| --- | --- | --- | --- |
| 상단 브랜드 줄 | 작은 공지 아이콘 + 공지 한 줄 | 심볼 + SIRIUS 레터링을 하나로 묶은 브랜드 | 기존 로그인/회원가입 또는 로그인 후 계정 동작 |
| 하단 메뉴 줄 | 전체 가용 폭 안에서 주요 메뉴 묶음을 균형 있게 배치 | 스포츠 계열 / 카지노·게임 계열 / 이벤트의 기능별 묶음 | 새 장식성 수치나 의미 없는 버튼을 채우지 않음 |

상단은 좌우 내용 길이에 영향을 받지 않는 **기하학적 중앙**에 브랜드가 위치해야 한다. 예: `grid-template-columns: minmax(0,1fr) auto minmax(0,1fr)`로 좌·우 여유를 동일하게 확보한다. 공지는 한 줄 말줄임하고 로고 영역을 침범하지 않는다. 계정 상태나 잔액 길이가 바뀌어도 로고가 좌우로 움직이지 않아야 한다.

공지 문구·클릭 연결과 회원 영역의 기존 동작을 재사용한다. 자동 흐르는 공지, 새 계정 서버, 가짜 이벤트/가입 수치는 만들지 않는다. 기존 별도 32px 공지 바는 상단 줄에 통합하여 제거한다. **2단 헤더 아래에 예전 공지 줄을 다시 쌓아 3단으로 만들지 않는다.**

실행 기본값: 상단 56px + 하단 44px = 합계 100px. 기존 헤더 68px + 공지 32px의 공간을 재분배한 값이다. 실제 렌더에 맞춰 소폭 조정할 수 있지만 중앙 콘텐츠를 불필요하게 줄이지 않는다. 전체 헤더 높이와 본문 높이는 하나의 정의를 공유한다.

1920px 고정 shell과 좌272/중1280/우320, 외곽12px·열 간격12px를 유지한다. 본문 높이의 예는 `실제 콘텐츠 높이 - 헤더 합계 - 위아래 여백24px`다. viewport 높이 940px, 헤더 100px이면 940 − 100 − 24 = 816px이다. 모니터 해상도1080을 브라우저 높이로 하드코딩하지 않는다.

### 3.2 브랜드 크기와 여백

`심볼 → 간격 → 레터링`의 순서를 유지한 채 그룹 전체를 중앙으로 옮긴다. 상단 줄 안에서 충분한 상하 공간을 확보한다. 실행 기본값은 심볼32px, 레터링 실제 그림 높이34px, 간격8px다. 56px 줄에 그림 높이34px이면 상하 약11px 여유가 생긴다. 숫자를 절대 기준으로 삼지 말고 실제 보이는 외곽으로 맞춘다.

| 원본 | 규격 | 유의사항 |
| --- | --- | --- |
| `sirius-symbol.png` | 640×640 RGBA | 궤도와 별을 자르지 않고 비율 유지 |
| `sirius-wordmark.png` | 1741×704 RGBA | 비투명 영역 높이588px, 아래116px은 완전 투명 |

레터링은 기존의 투명 하단 여백 처리 방식을 재사용한다. 예: 원본1741:588 비율의 CSS 표시창으로 완전히 투명한 아래쪽만 제외한다. 그림 높이34px 시작값의 표시 폭은 34 × 1741 ÷ 588 ≈ 100.67px이다. 그림 비율을 강제로 늘리거나 별/궤도를 잘라 폭을 줄이지 않는다. 두 원본은 수정하지 않는다. 흰색/아이보리 네모 바탕을 추가하지 않는다.

### 3.3 주 메뉴와 표면

기존 7개 메뉴의 명칭과 주 클릭 목적을 유지한다.

| 묶음 | 메뉴 |
| --- | --- |
| 스포츠 | 스포츠 / 실시간 스포츠 / E스포츠 |
| 카지노·게임 | 카지노 / 슬롯 / 미니게임 |
| 이벤트 | 이벤트 |

각 메뉴를 큰 박스형 탭으로 감싸지 않는다. 글자와 여백으로 수평 리듬을 만들고, 묶음 사이는 조금 넓은 간격이나 매우 절제된 구분선으로 표현한다. 글자 크기는 기존 가독성을 유지한다. 묶음을 구별하기 위해 메뉴 이동이나 기능 누락을 만들지 않는다.

상단의 깊은 남색 계열은 기존 헤더 컬러를 유지해도 된다. 하단은 상단보다 약간 밝은 남색으로 층을 구분하되 밝은 파랑 띠가 되지 않게 한다. 헤더 전체를 골드 프레임으로 둘러싸지 않는다. 상·하단 사이와 본문 경계는 1px 수준의 낮은 대비로 정리한다.

기본 글자는 화이트/절제된 청회색, 현재 메뉴는 골드 문자 + 얇은 골드 하단선으로 표시한다. 활성선은 현재 항목의 너비와 위치를 따라 짧고 부드럽게 이동한다. 실행 기본값은 두께2px·이동160~200ms다. 첫 렌더나 폰트 로드 시 엉뚱한 위치에서 가로지르지 않게 한다.

hover는 텍스트/표면의 미세한 변화, pressed는 짧은 눌림 표현으로 구별한다. 글자·버튼의 실제 좌표나 주변 메뉴 너비는 변하지 않는다. hover나 펼침 상태가 실제 현재 메뉴를 잘못 바꾸지 않게 한다. 회원가입 등 주요 CTA만 절제된 골드 그라데이션을 쓴다. 네온, 금색 맥동, 회전 로고, 긴 광택 쓸기는 추가하지 않는다.

## 4. 헤더 탐색 인터랙션

### 4.1 이번 최소 구현

**스포츠 메뉴에 종목 탐색 펼침을 1개 구현**한다. 모든 메뉴에 내용 없는 드롭다운을 만들 필요는 없다. 기존 주 클릭을 훼손하지 않도록 `스포츠` 본문 동작과 옆의 작은 펼침 버튼을 분리하는 방식을 실행 기본안으로 삼는다. 펼침 버튼에는 `종목 바로가기 열기/닫기`처럼 의미 있는 접근성 이름을 둔다.

패널은 하단 메뉴 바로 아래에 헤더에 연결된 수평 탐색 면으로 나타난다. 현재 메뉴 묶음과 관계있는 폭으로 제한하고, 화면 전체 높이를 쓰는 대형 광고/메가 메뉴로 만들지 않는다. 원본 종목 PNG와 종목명, 전체 스포츠 진입을 제공한다. 개수를 표시할 경우 기존 데이터에서 계산하며 임의 숫자는 넣지 않는다.

| 항목 | 동작 |
| --- | --- |
| 주 메뉴의 텍스트 클릭 | 현재 코드에 있는 이동/섹션 전환/안내 동작을 보존 |
| 펼침 버튼 클릭 | 종목 탐색 패널 열기/닫기. 주 메뉴 이동과 이중 실행되지 않음 |
| 종목 선택 | 기존 좌측 레일과 **동일한 필터 상태/처리 함수**에 연결, 선택 상태 동기화, 패널 닫기 |
| 전체 스포츠 선택 | 기존 전체 스포츠 동작에 연결 |
| 바깥 클릭 / Escape / 같은 펼침 버튼 | 패널 닫기. Escape는 트리거로 초점을 반환 |
| 키보드 | Tab으로 트리거·항목 이동, Enter/Space로 버튼 조작. 초점을 가두지 않음 |
| 다른 주 메뉴 선택 / 기존 모달 열기 | 열린 탐색 패널 정리, 겹친 상태로 남기지 않음 |

종목 선택 시 검색·슬립 유지 여부는 기존 필터 동작과 일치해야 한다. 새 탐색 패널을 위한 별도 fixture 복사본이나 독립 필터 상태를 만들지 않는다. 처음에는 패널이 닫혀 있어야 하며, 포인터를 스쳐 지나가기만 해도 열리는 hover 전용 동작은 쓰지 않는다.

### 4.2 위치·겹침·모션

- 탐색 패널은 헤더 아래 오버레이로 배치한다. 열고 닫아도 본문의 높이·경기 행·레일·스크롤 위치를 밀지 않는다.
- 화면 밖으로 나가거나 부모 `overflow`에 잘리지 않도록 한다. 헤더/패널은 본문보다 위, 기존 로그인·확인 모달은 그보다 위로 정리한다.
- 닫힌 패널은 클릭·Tab 이동을 가로채지 않는다. `aria-expanded`와 실제 표시 상태를 맞춘다. 숨긴 상태의 투명 박스가 남지 않게 한다.
- 간단한 펼침/페이드 정도로 제한한다. `prefers-reduced-motion`에서는 이동 효과를 줄여도 위치·선택 의미는 유지한다.
- 밝기만으로 focus를 구별하기 어려우면 얇은 명확한 윤곽을 사용한다.

## 5. 전체 남색 톤 조정

사용자 요청은 **현재보다 조금 어둡게, 패널과 버튼의 표면 밝기 차이는 더 읽히게** 하는 것이다. 참고2는 색감 정도의 기준이지 픽셀 재현 목표가 아니다. 참고2에서 헤더까지 어둡게 보이더라도 사용자는 헤더 컬러를 유지해도 된다고 명시했다. 상단 헤더에 참고2의 어둠을 강제로 적용하지 않는다.

| 대상 | 조정 방향 |
| --- | --- |
| 페이지 바탕/레일 바닥 | 현재보다 깊은 남색. 청색 정체성을 유지 |
| 중앙 목록/일반 패널 | 바탕과 구별되는 어두운 남색 면. 영역 사이의 명도 단계 유지 |
| 입력창/깊은 내부 면 | 패널보다 한 단계 들어간 느낌. 글자·입력값은 읽혀야 함 |
| 배당/보조 버튼 | 패널보다 조금 밝은 표면 + 미세한 수직 명도 차이 + 상단 반사/하단 음영 |
| 경계/구분선 | 어두운 면에서도 영역을 읽을 수 있는 낮은 대비. 불필요한 다중 테두리 금지 |
| 흰 문자/골드/팀·리그·국기/사진 | 읽힘과 원래 색감 유지. 전역 필터로 함께 어둡게 하지 않음 |

첨부 두 파일의 동일 빈 면 좌표를 확인한 참고값은 아래와 같다. **스크린샷의 픽셀 값이며 공개 CSS 값이나 사용자 확정 HEX가 아니다.** 구현자는 공통 색상 정의와 실제 화면을 기준으로 근접한 결과를 조정한다.

| 표본 위치(x,y) | 수정 전 | 사용자 톤 참고 |
| --- | --- | --- |
| 바깥 면 (800,105) | `#0B173C` | `#060E2D` |
| 중앙 목록 면 (1100,245) | `#14244D` | `#0C183C` |
| 좌측 패널 면 (100,745) | `#101D42` | `#091332` |
| 버튼 윗부분 (1050,265) | `#24385F` | `#18294E` |
| 버튼 아랫부분 (1050,290) | `#1C2D4F` | `#12203E` |

패널과 버튼을 같은 비율로 일괄 어둡게 하면 층이 다시 붙어 보일 수 있으므로 각각 조정한다. 기본/hover/선택/잠금/focus의 구별을 보존한다. 기본 배당 숫자, 작은 마켓 라벨, 보조 정보가 묻히지 않아야 한다. 선택 배당의 골드 면과 흰 문자 사용 규칙은 현재 동작을 유지하되 실제 대비를 확인한다.

공통 토큰 또는 기존 공통 스타일을 우선 조정한다. 페이지 전체 `filter:brightness()`나 반투명 검은 덮개를 사용하지 않는다. 색상 때문에 기존 레일의 배너 이미지까지 새로 보정하거나 현재 폰트를 바꾸지 않는다.

## 6. 기존 기능과 레이아웃 보존

- 중앙 가로 경기 행, 팀/점수의 같은 면, 공통 열, 기존 77경기 기준과 ID를 유지한다. 종료/진행 수치나 배당 데이터는 이번 디자인 변경과 분리한다.
- 실시간 스포츠/국내형 스포츠/인기경기의 처음6개와 섹션별 더보기6개, 검색·종목·접기·슬립을 유지한다.
- 좌우 레일의 독립 스크롤, 납작한 충전/환전, 기존 배너 사진과 얼굴 안전 영역, 우측 계정/슬립/도움말 배치를 유지한다.
- 기존 계정 흐름, 금액 입력·계산·선택 교체/해제는 보존한다. 새 금융 기능을 추가하지 않는다.
- Pretendard JP, Heisei Mincho Std, Omnigothic, DIN Condensed의 기존 실제 자산/용도를 유지한다. 로고를 폰트 텍스트로 대체하지 않는다.
- 화면에 데모/목업/체험/수집 시점/실제 거래 없음 등의 개발 해설을 다시 넣지 않는다. 실제 미지원 서비스의 상태를 허위 서비스 완료로 바꾸지는 않는다.

## 7. 간소화 QA와 공개 확인

다음 항목의 **반영 / 미반영 / 문제 있음 / 미검증**을 보고한다. 디자인 점수나 WOG 동등성 PASS는 요구하지 않는다.

확인된 기능 오류나 잘림은 수정하고 해당 항목만 재확인한다. 정상인 중앙 전체를 다시 설계하거나 무한 미감 재감사를 하지 않는다. 독립 QA 미연결은 사실대로 보고한다.

캡처는 실제 전체 1920px 콘텐츠 폭에서 ①기본 화면 ②종목 패널 펼침 ③필요한 문제/수정 증거만 남긴다. 같은 viewport에서 전후 톤을 비교한다. 실제 viewport·DPR·확대율을 기록하고 작은 viewport 부분 캡처를 전체 화면 검수로 설명하지 않는다. 지원 도구가 제한되면 가능한 범위와 한계를 명시한다.

기본 확인 후 기존 공개사이트를 업데이트하고 공개 결과를 사용자에게 전달한다. **이번 완료는 구현·공개 반영까지이며, 헤더 디자인 확정은 사용자 검수 이후다.** 이후 좌측/우측 레일 작업을 자동 실행하지 않는다.
