# SIRIUS — 작업 공통 규칙

문서 세트: **HEADER R2 · 2026-09-18**  
이번 작업: **중앙 브랜드의 2단 헤더 + 전체 남색 톤 조정 → 기존 SIRIUS 공개사이트 업데이트 → 사용자 피드백 대기**.

## 1. 읽기와 적용

1. AGENTS → STATE의 실행 지시 → DESIGN_SPEC → 현지 코드 순서로 읽는다. 결정 이력은 DECISIONS에 있다.
2. 최신 사용자 지시 > R2 확정 방향 > R2 실행 기본값 > 충돌하지 않는 기존 규칙 순이다. R1의 복제·신규 사이트 생성·헤더 구성 유지·전체 디자인 감사 게이트는 이번 작업에 적용하지 않는다.
3. **확정**은 사용자가 승인한 방향이다. **실행 기본값**은 구현 시작값이며 실제 화면에 맞게 조정할 수 있다. 제안 수치나 CSS 존재를 사용자 디자인 승인으로 기록하지 않는다.
4. 운영 문서는 AGENTS.md / STATE.md / DESIGN_SPEC.md / DECISIONS.md 네 개만 관리한다. 추가 README/HANDOFF/TASKS/QA MD를 만들지 않는다. 자산 JSON과 캡처는 허용한다.
5. ZIP 원본은 입력 기록으로 보존한다. 현지 SIRIUS 루트의 네 문서에 이번 내용을 반영하되, 기존 실제 commit·project_id·배포 기록·미해결 사항을 지우지 않는다. 이 패키지의 미확인 값을 현지 확인값 위에 덮어쓰지 않는다.

## 2. 대상과 작업 경계

- 작업 루트: `E:/codexwork/Site-Skin-edit/demo-sites/sports-demo-02/`. 실제 앱 위치는 이 루트의 현지 구성에서 확인한다.
- 업데이트 대상: **https://sirius.kexxadrix.chatgpt.site/**. 기존 SIRIUS 소스·저장소·호스팅 설정을 이어 쓴다. MERCURY를 다시 복제하거나 새 SIRIUS 사이트를 만들지 않는다.
- MERCURY 소스·문서·공개사이트는 보존한다. MERCURY 프로젝트 ID/원격 저장소로 배포하지 않는다.
- 이번 구조 변경은 헤더에 한정한다. 본문과 양측 레일은 면 색상·버튼 표면·경계 명도만 함께 조정한다. 중앙 경기 목록 및 레일의 순서·크기·기능·배너 위치는 유지한다.
- 레일 재구성과 배너 2개 배치는 이후 사용자 확정 단계다. 향후 두 사이트의 제작, 라이브 데이터 재수집, 팀명 정교화, 모바일 개편, 새 서비스/실거래 백엔드는 이번 범위에 없다.

## 3. 역할과 간소화된 QA

| 역할 | 이번 책임 |
| --- | --- |
| 진행 담당 | 범위·기록 관리, 기존 구현/QA 스레드 연결, 결과 전달 |
| 구현 담당 | 현지 최신 소스 확인, 헤더·톤 수정, 기본 검증, 기존 SIRIUS 배포, 공개 확인 |
| 독립 QA | 구현 반영·메뉴 동작·겹침/잘림·대표 기능 회귀를 실제 화면에서 확인하고 사실 보고 |
| 사용자 | 공개 화면을 보고 미감 피드백, 해당 부위 확정 및 다음 단계 착수 결정 |

기존 담당 스레드를 우선 사용한다. QA는 소스·디자인 사양·배포를 직접 수정하지 않는다. WOG/외부 사이트와의 포괄적 미감 비교, 점수화, 디자인 PASS가 나올 때까지의 자율 반복은 이번 필수 절차가 아니다. 시각 의견은 참고사항으로 분리하며 사용자의 승인 항목을 재반려하지 않는다.

구현자는 배포 전 기본 기능을 확인하고, 사용을 막는 확인된 오류를 고친다. 그 후 공개사이트에 바로 업데이트한다. 독립 QA의 확인은 이 최소 범위를 대상으로 하며, 미감 확정을 기다리느라 첫 공개 업데이트를 미루지 않는다. 확인된 회귀 수정 외에 스스로 시안을 계속 바꾸지 않는다.

독립 QA를 실제로 연결하지 못하면 자체 확인은 계속하고 독립 QA를 미실시로 보고한다. 자체 확인을 독립 PASS로 바꾸거나 연결 불가만으로 구현 전체를 보류하지 않는다. 접근할 수 없는 외부 스레드를 제어했다고 주장하지 않는다.

## 4. 보존 원칙

- 승인된 중앙 가로 목록, 데이터 77경기 기준, 각 섹션 최초 6개/더보기 6개, 검색·선택·슬립·계산을 유지한다. 현지 최신 데이터가 다르면 먼저 차이를 기록하고 임의로 R1로 되돌리지 않는다.
- SIRIUS 심볼은 레터링 바로 왼쪽에 두고, 두 이미지를 묶어 헤더 중앙으로 옮긴다. 별도 전시 패널을 만들지 않는다.
- 금속 종목 PNG 8개와 기존 팀·리그·국기·배너·폰트를 재사용한다. NHL 로고와 현재 팀명은 통과 항목이다.
- 스코어/팀명/로고는 같은 정보 면을 유지한다. 흰 네모 배경, 독립 점수 박스, 오래된 데모 안내 문구를 재도입하지 않는다.
- 이미지 전체에 어두운 필터를 씌우지 않는다. PNG 원본과 투명도를 보존한다. 추가 이미지 생성·편집 플러그인은 사용자 명시 지시 없이 사용하지 않는다.
- 실제 경기 상태·점수·배당의 임의 애니메이션, 가짜 이벤트 수, 실제 없는 혜택은 추가하지 않는다.

## 5. 실행과 종료

- 토큰/주간 사용률 제한은 없다. 과거 20% 사용량 중단 규칙은 폐기됐다.
- 필요한 현지 빌드/타입 검사와 이번 변경에 관련된 대표 기능 확인만 수행한다. 관련 없는 전수 감사나 구현을 그대로 베끼는 테스트를 늘리지 않는다.
- 실제 배포에서는 현지 Sites 절차를 따르고 기존 SIRIUS 대상임을 확인한다. 새 프로젝트 등록 절차를 다시 수행하지 않는다.
- 공개 확인 후 URL, 버전/commit/배포 ID, 변경 요약, QA 수행자·대상·결과·미검증, 캡처, 남은 문제를 STATE에 기록하고 보고한다.
- 종료 상태는 **헤더·톤 R2 공개 반영 / 사용자 피드백 대기**다. 사용자 디자인 확정이나 전체 사이트 완료로 선언하지 않는다. 좌측·우측 레일 작업으로 자동 진입하지 않는다.
