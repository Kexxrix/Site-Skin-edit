## Audience and purpose

방문자의 주요 행동은 종목·리그 탐색, 경기 검색, 스코어와 배당 비교, 선택과 슬립 확인이다. 정보 밀도가 높아도 그룹이 명확하고 숫자가 잘 읽혀야 한다. 사진 배너와 계정·고객센터 동선도 기존 흐름을 유지한다.

## Product commitments

- 이름 SIRIUS/시리우스, 어두운 남색·화이트·샴페인 골드, 제공된 브랜드 자산을 유지한다.
- 실제 서비스처럼 정돈된 정보·상태·상호작용을 보여준다. 이 원칙은 실시간 피드나 실거래 백엔드가 있다는 뜻이 아니다.
- 승인된 데모 데이터는 안정적으로 표시한다. 실제 값과 정밀도, 0과 세 자리 점수를 숨기지 않는다.
- 데스크톱 중심의 기존 지원 범위를 유지한다. 모바일 신규 재배치·신규 게임·실거래 연동은 이번 도구 설정 범위에 없다.
- UI 한글과 현재 보조 영문을 유지한다. 주 사용자와 피드백 언어는 한국어다.

# DESIGN.md

# SIRIUS visual system — approved intent seed

이 문서는 승인 의도의 시작본이다. 현지 실제 코드에서 추출한 확정 토큰 목록으로 간주하지 않는다. 설치 후 document로 최신 소스와 대조해 갱신한다. 최신 승인 구현이 우선이며 R7 오른쪽의 완료 상태는 현지 확인한다.

## Character

깊은 청색과 남색 면의 층위, 읽기 쉬운 흰 텍스트, 샴페인 골드의 제한적 강조. 장식은 헤더·브랜드에 집중하고 경기 정보는 밀도와 명확한 그룹 관계를 우선한다. 일반적인 템플릿 권고로 승인된 골드·그라데이션·DIN을 교체하지 않는다.

## Palette and surfaces

- 승인된 현재 남색 배경·패널 토큰을 재사용한다. 새 팔레트를 일괄 적용하지 않는다.
- 왼쪽 R6 패널 참고: #111F3C→#09142D, 160deg, 경계 #2B3D5F, 반경12px, 내부12px.
- 미선택 배당: #FCE1A4. 선택 면: #FCE1A4→#D7B96C, 선택 글자 #101A34.
- 골드는 활성 메뉴, 주요 행동, 숫자 위계에 사용한다. 비활성 조건을 풀거나 모든 패널을 골드로 채우지 않는다.
- 오류·잠금·라이브 상태의 기존 의미 색을 보존한다.

## Typography

- 기존 한글 UI 폰트(Pretendard 계열 실제 연결)를 재사용한다.
- 스코어와 배당 모두 기존 din-condensed/DIN, weight400. 둘을 다른 서체로 나누지 않는다.
- 스코어는 팀 영역의 흰 숫자, 배당은 버튼 안 골드 숫자로 인지된다. 크기·위치·간격으로 구분한다.
- 과거 배당20px, 배당 버튼46px. 현지 승인 값이 더 최신이면 그것을 유지한다.
- 긴 팀명만 말줄임한다. 배당·점수·금액 값은 잘라내거나 임의 반올림하지 않는다.

## Layout and components

- 중앙 브랜드·2단 헤더, 제공 우주 배경. 과거 높이134px(84+50)은 참고값이다. 자동 추가 확대 금지.
- 리그별 가로 경기 목록. 아이콘·팀명·스코어가 한 그룹이며 점수를 마켓 옆으로 밀지 않는다.
- 승무패/핸디캡/오버언더는 그룹 내부보다 큰 그룹 사이 간격으로 구별한다. 새 구분선·내부 패널 금지.
- 참고값 내부4px / 그룹 사이 보이는 여백42px / 추가 베팅56px / 점수 영역40px. 고정값 복원보다 현재 화면 균형을 우선한다.
- +N 추가 베팅은 우측 끝, 경기별 고정된 데모 수와 기존 연결을 유지한다.
- 왼쪽: 빠른 서비스→3개16:9 사진 배너→캡슐 검색/종목. 배너 내부 버튼 없이 전체 클릭.
- 오른쪽 R7 의도: 왼쪽과 같은 패널·버튼 문법, 폭320px와 계정→슬립→고객센터→이벤트 순서 유지. 완료 여부는 현지 확인.

## States and assets

제공 로고·심볼·헤더 배경·종목 아이콘·팀/리그/국기·사진을 재사용한다. 이미지 생성이나 새 폰트 다운로드 없이 작업한다. 선택/해제·잠금·오류·disabled와 기존 슬립 계산·인증 정책을 보존한다.

더보기/접기·종목/리그 토글·부드러운 맨 위로 이동은 이미 사용자가 좋다고 확인한 구현을 유지한다. 모션 재설계나 전역 애니메이션 추가 없이 기존 감소 모션 처리를 보존한다.
