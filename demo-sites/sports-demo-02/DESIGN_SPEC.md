## 역할과 중복 QA 제거

- Impeccable은 구현 담당 Codex의 부위별 디자인 수정 지침입니다. Jev와 직접 통신하는 공식 연동 기능이 있다는 뜻은 아닙니다.
- 기존 Jev 모델 jev-1.13.0에 DOM·computed style·측정값을 전달합니다. Jev가 스크린샷을 본다고 보고하지 않습니다. Jev는 적용 대상·예외·충분성·불일치를 분류하고 숫자 계산과 결과 조합은 코드가 담당합니다.
- 구조 수집은 한 번만 하고 같은 증거를 Impeccable 전수 audit/critique/detect, Codex 전수 브라우저 감사, 별도 QA 작업으로 반복하지 않습니다. 설치된 스킬 원문은 수정하지 않으며 자동 hook을 끕니다. 도구가 제안하는 자동 검사보다 현재 프로젝트 범위가 우선합니다.
- 빌드·타입 검사·변경 동작의 짧은 확인은 기존 담당자가 유지합니다. Jev는 이를 대신하지 않습니다. 이미 수집한 화면을 공유하고 후보·누락·모순만 필요한 영역으로 확인합니다.
- candidate는 수정 지시가 아닙니다. Codex는 원본 증거와 승인 의도를 확인하고 실제 결함만 국소 수정합니다. unverified/failed/not_run은 pass가 아닙니다.
- 수정 후 변경 부위와 영향을 받는 검사만 한 번 다시 합니다. 입력·버전·상태·viewport·질문 은행·관측 증거가 같은 완료 검사는 재사용합니다. 현재 도구는 원격 URL과 소스 revision 연결 및 캐시 최신성을 자동 증명하지 못하므로 담당자가 같은 버전인지 확인해야 합니다.
- --from-run은 저장한 관측 전달이며 현재 사이트 재검증이 아닙니다. 통과 목록을 다시 읽거나 같은 API를 재호출하지 않습니다. 별도 QA 작업은 중단을 유지하고 사용자 최종 미감 판단은 보존합니다.
- 자동 수정 루프·전체 사이트 PASS·정확도/절감률 추정·새 이미지/폰트·commit/push를 추가하지 않습니다.

## 다섯 명령의 역할과 종료 조건

### bolder — 헤더

시리우스의 브랜드 존재감만 다룬다. 로고의 실제 이미지 여백과 표시 크기, 브랜드 행의 여백, 활성 메뉴 텍스트의 골드 그라데이션을 먼저 본다. 단순히 헤더 전체를 다시150% 확대하거나 높이를 계속 키우지 않는다. 남색 배경·흰 일반 메뉴·골드 활성 메뉴의 위계가 보이면 충분하다. 새 장식·광선·글로우·새 로고를 만들지 않는다. 로그인/가입 및 탐색 패널 동작을 유지한다.

### layout — 중앙 마켓

현재 market wrapper 내부 간격은 작게, wrapper 사이는 확실히 크게 만든다. 이전 기준 내부4px, 그룹 사이 시각적 여백42px, 추가 베팅56px. 중앙 실폭에서 이를 확인하고 필요한 만큼만 조정한다. 추가 베팅을 오른쪽 끝에 붙이고 불필요한 공간을 세 마켓 사이에 배분한다. 각 그룹 제목은 버튼 묶음의 중심에 정렬한다. 축구3개, 야구 등2개인 승패 버튼도 같은 그룹 관계를 유지한다. 팀 영역·점수 묶음은 분리하며 선/패널 추가로 문제를 해결하지 않는다.

### typeset — 숫자 위계

사용자는 배당에도 스코어의 DIN을 쓰도록 지시했다. 이 결정을 바꾸지 않는다. 배당은 버튼 안 골드와 또렷한 수치, 점수는 팀 영역의 흰색으로 구별한다. 두 값의 서체를 달리하지 않고 크기·행 정렬·색·공간 관계를 조절한다. 기존 배당20px/400, 버튼46px를 참고하되 최신 구현을 먼저 확인한다. 선택 상태의 배당 색, 소수점 정밀도, 기존 한글 UI 폰트는 유지한다.

### harden — 데이터와 표시

- 0, 9, 99, 112: 점수를 참/거짓으로 처리해0이 사라지지 않아야 한다. 세 자리 공간을 확보한다.
- 긴 팀명은 팀 영역 안에서만 말줄임하고 전체 이름 확인 수단을 둔다. 숫자는 줄이거나 말줄임하지 않는다.
- 배당2.125 및 실제 데이터의 가장 긴 값: 소수점을 반올림·절삭해 맞추지 않는다. 잠금 아이콘이 있어도 넘치지 않아야 한다.
- 운영 중인 것처럼 자연스러운 데모 값은 경기 ID에 고정한다. 렌더마다 랜덤으로 바뀌지 않게 한다. 기존 라이브/종료 상태에는 점수가 있어야 하고, 예정 경기에는 승인된 데모 표시 정책을 유지한다. 실제로 없는 라이브 데이터 연결을 주장하지 않는다.
- 숫자 영역은 shrink 방지, 팀 문자열 영역은 min-width:0 등 역할에 맞는 레이아웃으로 해결한다. 부족한 폭을 overflow:hidden으로 가려 통과시키지 않는다.
- 기존 지원 화면 폭에서 확인한다. 이 명령을 계기로 별도 모바일 레이아웃을 신규 제작하지 않는다.

### polish — 선택한 부위 마무리

앞 단계나 사용자 피드백으로 지정된 부위만 정렬, 간격, hover/focus/selected/disabled 상태를 정리한다. 전체 사이트 리디자인·audit로 확장하지 않는다. 승인된 모션 속도와 레이아웃을 다시 조율하지 않는다. 이미 균형이 맞으면 추가 장식 없이 마친다.

## 도구 맥락과 설정

`context/PRODUCT.md`는 사용자·목적·제약, `context/DESIGN.md`는 확정된 시각 규칙의 시작본이다. 기존 파일이 있으면 최신 기록과 병합한다. 현지의 `$impeccable document`로 실제 코드와 대조해 한 번 정리하며 생성 메타데이터 `.impeccable/design.json`을 임의 작성하지 않는다. [공식 맥락 문서](https://impeccable.style/docs/context/)

설정은 기존 JSON에 `buildPath: code`와 Impeccable `hook.enabled: false`만 병합한다. 로컬 override가 이미 있으면 같은 두 설정을 맞춘다. 이미지 자동 생성이나 상시 디자인 검사를 켜지 않는다. [공식 설정 문서](https://impeccable.style/docs/config/)

설치·명령 문법의 근거는 [공식 저장소](https://github.com/pbakaus/impeccable), [설치 안내](https://impeccable.style/tutorials/getting-started/)다. Codex 채팅 명령은 `$impeccable`이다. Node 최소 버전과 CLI4.1.0은 [공식 package.json](https://github.com/pbakaus/impeccable/blob/main/package.json)에서 확인했다. 다운로드되는 실제 skill 버전·파일은 현지에서 별도로 기록한다.

## 적용과 기본 확인
