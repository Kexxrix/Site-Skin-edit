## 생성과 검수

Codex 내장 이미지 생성으로 한 호출당 한 장씩 만들었다. 시도 8 / 생성 성공 8 / 실패 0 / 건너뜀 0 / 시각 검수 통과·에이전트 선택 8 / 거절 0. 사용자 최종 승인과 사이트 채택은 각각 0으로 구분했다.

실제 파일을 열어 주 문구의 철자, 16:9에서의 주요 얼굴·손·기기 잘림, 레터박스, 연결되는 장면의 인물·기기·브랜드 구도를 확인했다. 01·02·03·04·05·07·08은 별도 검토자도 같은 파일을 확인했고, 06은 주 작업자가 실제 결과를 확인했다.

`qa/verify-assets.py`로 PNG 디코딩, 16:9 비율의 정수 픽셀 반올림 범위, 고유 SHA-256 8개, 이동 전후 해시 일치, 입력 원본 3개 불변, ZIP 8개 항목의 해시 일치, 프롬프트 참조 번호·필수 문구를 검증했다. 이미지 파일 변경 없이 검사와 포장만 수행했다. ZIP은 기존 원본을 덮어쓰지 않는 새 배포 묶음이다.

## 참조와 원본 보존

실제 제품 캡처 2장과 기존 개발 연출 사진 1장은 제자리에 보존했다. [입력 원본 목록](sources/reference-manifest.json)에 절대 경로·해시·역할을 기록했다. 실제 생성 도구에 첨부한 순서는 `run.json` 각 자산의 `reference_attachment_order`에 기록했다.

01을 타이포 기준으로 사용했고, 02와 04를 03에, 07과 05를 06에, 01을 08에 연결했다. 모든 장면에 같은 배경이나 도형을 반복하지 않았다. 기본 생성 경로의 이번 출력 8개만 새 프로젝트 `results/` 폴더로 이동했으며, 이전 생성물과 `D:/WebDL`은 건드리지 않았다.

## 남은 한계

- 주요 영문 문구는 8장에서 확인했다. 제품 화면의 작은 일본어·한국어는 생성 과정의 차이가 있으므로 원본 UI의 픽셀 단위 복제로 취급하지 않는다.
