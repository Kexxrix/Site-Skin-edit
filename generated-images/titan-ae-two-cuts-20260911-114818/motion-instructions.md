## 형식과 비율

- 새 컴포지션 이름: `TITAN_TwoCuts_75x32_3s_v001`. 같은 이름이 있으면 접미사를 올린다.
- 2400×1024, 정사각 픽셀, 30fps, 3.000초. 프레임 F00–F89, 총 90장.
- 시간 = 프레임 번호 ÷ 30. F89 = 2.9666667초이며 outPoint는 3.0초다.
- 화면비 2400÷1024 = **75÷32 = 2.34375:1**.
- 근거: [현재 히어로 CSS](../../titan_promotion/components/hero.module.css)의 데스크톱 최대 컨테이너 1280, 미디어 gap 30, 열 비율 3:1, 높이 400. 영상 폭은 (1280−30)×3/4 = 937.5, 따라서 937.5÷400 = 2.34375다. 작은 뷰포트까지 항상 같은 비율이라는 뜻은 아니다.
- 참조 PNG는 각각 **1920×819**다. 1920÷(75/32) = 819.2이므로 높이 반올림 차이는 0.2px다. 원본을 자르거나 리사이즈하지 않았다.
- AE에서 가이드는 중앙 정렬하고 균일 스케일 125%로 놓으면 2400×1023.75가 된다. 남는 높이 0.25px는 가이드 비교에만 해당한다. 최종 배경은 네이티브 Solid가 2400×1024를 완전히 채운다.
- 오디오 없음. 카메라·3D·모션 블러 없음. 이 테스트의 끝은 두 번째 컷을 유지하며 정지한다. 루프 연결이나 다음 제품 컷은 만들지 않는다.

## 실제 렌더 구성

이미지 두 장을 각각 `REF_CUT_01`, `REF_CUT_02`로 임포트해 잠근 Guide Layer로 둔다. 정착 프레임 비교에만 번갈아 표시한다. **최종 렌더 전 두 가이드 모두 enabled=false**로 둔다.

최종 화면은 별도의 Solid 2개, 네이티브 Text Layer 5개, Shape Layer 3개(원호·점·밑줄)로 만든다. 차콜 Solid가 장면 전환 역할도 맡는다. 글자 윤곽을 변형할 효과가 없으므로 이번 테스트는 outline 변환이 필요 없다.

| 레이어 이름 | 내용 / 역할 |
|---|---|
| C01_BG_IVORY | 전체 아이보리 배경 |
| C01_TXT_MEET | 정확히 `Meet` |
| C01_TXT_TITAN | 정확히 `TITAN` |
| C01_ARC | 가는 차콜 원호 |
| C01_DOT | 작은 주황 원 |
| C02_BG_CHARCOAL_WIPE | 왼쪽에서 들어와 전체를 덮는 차콜 배경 |
| C02_TXT_CORE | 정확히 `Core systems` |
| C02_TXT_BUILT | 정확히 `Built` |
| C02_TXT_IN_HOUSE | 정확히 `in-house`; 일반 하이픈 U+002D |
| C02_UNDERLINE | Built 아래 주황 직선 |

C02 배경은 C01 전체보다 위, C02 텍스트와 밑줄보다 아래에 둔다. 이름을 고유하게 유지하고 새 레이어 추가 뒤 바뀌는 숫자 인덱스에 의존하지 않는다.

## 색과 글자

색은 가이드의 래스터를 찍어 복제하지 않고 다음 값으로 고정한다. 가이드에 생긴 미세한 얼룩·톤 변화는 재현하지 않는다.

- 아이보리 `#F5F3EE`
- 차콜 `#24262A`
- 주황 `#FA871F`

현재 AE에서 Pretendard의 아래 PostScript 이름을 확인했다. 제작 시에도 조회하고, 누락되면 임의 대체하지 않고 보고한다. stroke, faux bold, faux italic은 모두 끈다. 자간은 0으로 시작하고 실제 경계 측정으로 단어 사이 간격을 만든다. 글자 폭만 별도로 늘리거나 줄이지 않는다.

표의 높이는 **실제로 보이는 글자 경계의 높이**이며 fontSize와 다르다. fontSize는 설치된 글꼴로 측정하면서 맞춘다. 가이드 그림의 글자 모양을 픽셀 단위로 베끼지 않는다. 좌표는 2400×1024 기준이고 아래는 정착 위치다.

| 텍스트 | PostScript font | 보이는 높이 목표 | 정착 배치 |
|---|---|---:|---|
| Meet | Pretendard-Regular | 약 100px | TITAN 앞, 같은 기준선 y=560 |
| TITAN | Pretendard-SemiBold | 약 136px | Meet 뒤 45px 간격, 두 단어 전체 중심 x=1200 |
| Core systems | Pretendard-Medium | 약 112px | 왼쪽 x=670, 기준선 y=440 |
| Built | Pretendard-Bold | 약 145px | 왼쪽 x=670, 기준선 y=630, 주황 |
| in-house | Pretendard-Medium | 약 122px | Built의 실제 오른쪽 끝 +45px, 기준선 y=630 |

높이 ±4px 정도는 폰트 렌더 결과를 보며 조절한다. 공통 기준선·단어 간 여백·굵기 차이를 우선한다. 두 번째 컷 아랫줄은 폭 약 1050–1150px 안에 유지한다. 설치 글꼴 측정값이 벗어나면 두 단어의 크기를 같은 비율로 조절하고 그 변경을 기록한다.

Point Text로 만들고 style 적용 후 `layer.bounds`를 조회한다. 좌측 기준 앵커 `[bounds.left, 0]`와 `[목표 x, 기준선 y]` 위치를 함께 설정하면 글자 바운딩 박스의 위아래 차이로 기준선이 흔들리는 것을 피할 수 있다. 스크립트가 중앙 앵커를 사용한다면 해당 경계의 top/height를 반영해 동일한 기준선을 계산해야 한다.

01의 전체 폭을 Wmeet + 45 + Wtitan으로 측정한 후 첫 단어의 x를 1200−전체폭/2로 정한다. 02는 Built 경계 폭을 먼저 측정한 뒤 in-house의 x를 계산한다.

## 도형의 정착 형태

- 원호: 중심 약 (675, 494), 반지름 358px, 차콜 3px stroke, fill 없음. 오른쪽이 열린 긴 원호. 상단 오른쪽 끝의 각도 −48°에서 각도를 감소시켜 −310°까지 잇는다. 좌표는 x=cx+r·cosθ, y=cy+r·sinθ로 정의한다. 가이드와 비슷한 곡선이 되도록 cubic Bézier 구간으로 작성한다. 글자와 닿지 않는다.
- 점: 주황, 지름 30px. 원호 위를 짧게 이동한다. 정착 각도 −144°의 위치는 약 (385, 284)다.
- 밑줄: (670, 676)에서 오른쪽으로 약 415px, 주황 4px stroke. Built의 실제 폭과 눈으로 맞추되 글자에 닿지 않는다. Trim Paths로 왼쪽부터 드러낸다.

## 속도 곡선

재현 가능한 기준을 위해 각 구간의 정규화 진행값 u를 0–1로 clamp한다. 기본은 catalog 키프레임으로 작성한다. 원하는 곡선이 키프레임 이징으로 맞지 않으면 허용된 `expression.set`으로 해당 속성에만 아래 보간식을 적용할 수 있다. 필수 매개변수는 `comp`, `layer`, `property`(실제 속성 경로 배열), `expression`(문자열)이다. `eval.run`을 켤 필요가 없다.

- 텍스트 위치와 점의 각도: `e(u)=1−(1−u)^3`. 초반 빠르게 이동하고 끝에서 부드럽게 감속한다. overshoot, bounce 없음.
- 배경 와이프: `e(u)=u*u*(3−2*u)`. 시작과 끝의 속도가 0이 되는 부드러운 전환이다.
- opacity: 구간 내 선형 0→100.
- 원호와 밑줄의 Trim End: `1−(1−u)^3`로 0→100.

키프레임으로 구현할 때는 끝 프레임의 시간과 속도 0을 먼저 고정하고, 위 곡선의 중간 진행값을 비교해 influence를 맞춘다. preset 이름이 같다고 동일한 속도 곡선으로 단정하지 않는다. 예를 들어 텍스트 이동의 중간 u=0.5에서 87.5% 이동, 와이프는 50% 이동이 기준이다.

## AE 작업 순서

1. `ae_context`로 현재 프로젝트·dirty 상태·활성 컴포지션을 기록한다. 기존 렌더 큐는 읽기 전용 `ae_do({operation:"render.status",args:{}})`로 별도 조회한다. 기존 Hello World를 수정하지 않는다.
2. 새 이름의 2400×1024 컴포지션만 추가한다. 파일을 닫거나 새 프로젝트로 초기화하지 않는다. 저장본은 새 하위 폴더의 별도 AEP 이름으로 만든다.
3. 두 가이드를 임포트한다. 먼저 F18과 F75의 네이티브 정착 화면을 만들고 글꼴·철자·기준선·여백을 확인한다.
4. 위 타임라인에 따라 속성별 애니메이션을 추가한다. 한 단어를 움직일 때 글자 단위 모핑이나 경로 변형을 추가하지 않는다.
5. 두 가이드를 꺼서 참조 글씨가 렌더에 남지 않게 한다. `ae_render_frame`으로 F00, F05, F10, F18, F24, F28, F33, F40, F49, F55, F61, F75, F89를 우선 검사한다.
6. 같은 컴포지션의 90프레임을 새 폴더에 렌더한다. 모든 child 오류와 색관리 경고를 읽고, 기존 다른 렌더 큐를 실행하지 않는다.
7. 프레임을 30fps H.264 / yuv420p MP4로 인코딩한다. 원본 2400×1024를 유지한다. ffprobe와 전체 디코딩으로 3초·30fps·90프레임·해상도를 검증하고 실제 재생을 본다.
8. AEP, MP4, 비교 PNG 2장, 검증 기록을 보고한다. 첫 컷과 둘째 컷의 구현·전환만 판단하고 전체 콘티는 진행하지 않는다.

## 통과 기준

- 문구 5개가 정확하고 실제 편집 가능한 Text Layer다.
- 정착 화면에서 Meet/TITAN, Core/Built/in-house의 크기·굵기 차이가 유지된다.
- 공통 기준선과 Built 밑줄이 맞으며 선·점·글자가 충돌하지 않는다.
- F33부터 C01 글자·원호·점이 남지 않는다. 다른 컷의 글자 겹침과 잘림이 없다.
- F61 이후 Core systems와 Built in-house가 모두 완전하게 유지된다.
- 최종 렌더에 두 참조 이미지가 들어가지 않는다.
- 3초 영상을 실제 재생해 속도·멈춤·흐름을 확인한다. 기술 검증 통과와 사용자의 미감 승인은 별도로 기록한다.

조사로 확인된 것은 현재 MCP의 해당 명령 지원과 기존 Hello World 렌더 경로다. **이 새 구성의 실제 AE 구현과 최종 움직임은 후속 작업에서 검증할 사항**이다.
