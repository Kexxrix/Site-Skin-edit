사용자는 완성된 iPhone/iPad GLB를 첫 타이탄 두 컷의 배경에 넣는 시험과 모션 강화, 이 지시서의 직접 전달 및 작업 시작을 요청했다. **추가 승인 대기 없이 실제 제작·렌더·검증까지 진행한다.** 이번 범위는 기존 두 컷의 3초 보강본이다.

## 1. 이번 버전의 목표와 우선순위

- 첫 컷은 `Meet TITAN`과 오른쪽 배경의 iPhone, 둘째 컷은 `Core systems / Built in-house`와 오른쪽 배경의 iPad다.
- 기기는 제공된 **네이티브 3D GLB**로 사용한다. 아래 Blender 스튜디오 PNG는 형태 참고 자료이며 영상에 붙일 배경 이미지가 아니다.
- 스크린은 현재 회색 재질을 유지한다. 실제 서비스 UI·이미지·영상 매핑, 모델 수정·재생성, Blender 작업은 이번 범위에 없다.
- 영문 타이포의 표현력을 적극 높인다. 문구 역할·폰트·정착 위계는 보존하고, 전체 단어의 이동·균일 스케일·회전·짧은 속도 효과와 도형 연동을 강화한다.
- **글자별 순차 등장, 글자 윤곽 변형, 비균일 스케일, 문자 scramble은 제외한다.** 단어별 시차 등장은 가능하다. 한국어 전환은 이번 필수 작업이 아니다.
- 우선순위: 현재 사용자 요청과 이 v3 지시서 → 기존 모션 지시서의 변경하지 않은 항목 → 이미지 가이드. 이전 지시서의 ‘3D 없음·스케일 고정·오버슈트 없음·모션 블러 없음’은 이번 허용 범위에서 대체한다.

## 5. 3D 기기의 배치와 화면 내 역할

다음 좌표는 **최종 마스터 화면에 투영된 2D 위치**다. GLB의 실제 XYZ 좌표나 AE import scale로 그대로 입력하는 수치가 아니다. 먼저 회색 화면이 카메라를 향하는 정면 기준을 맞추고, 카메라·스케일로 아래 배치를 만든다. yaw/roll 수치도 그 정면을 기준으로 한 시각적 상대 각도다.

### 컷 01 — iPhone

- 화면 오른쪽에 세로로 선 iPhone을 배치한다. 정착 시 투영 경계의 권장 범위는 x=1820–2340, y=90–950 안이다. 실제 기기 높이 720–820px, 폭은 원본 비율과 사선 원근에 따른다.
- 전면 회색 스크린, 베젤·다이내믹 아일랜드와 얇은 측면이 보이는 가벼운 사선이다. 최종 yaw 약 −10°, roll 약 +3°를 출발점으로 삼는다.
- 중앙 `Meet TITAN` 및 왼쪽 원호·점과 기기가 닿지 않는다. 최종 글자 경계와 기기 사이 최소 100px를 목표로 한다.
- F00–F14에 오른쪽 100px·아래 45px에서 정착 위치로 이동하며 yaw 약 −22°→−10°, roll +9°→+3°, 균일 scale 94→100%로 정착한다. opacity는 F00–F04에 0→100%. F14 이후 기기는 완전히 멈춘다.
- 아이보리 배경에서 회색 화면과 검은 테두리가 또렷하게 보이되, 명도·조명의 관심이 중앙 글자보다 강하지 않게 한다. 기기를 흐릿한 유령 실루엣으로 만들지 않는다.

### 컷 02 — iPad

- 가로 방향 iPad를 오른쪽 배경에 배치한다. 정착 시 **기기의 가장 왼쪽 투영 경계가 x=1850 이상**이 되게 하고 전체 투영 폭은 약 820–900px, 높이는 약 560–650px에서 시작한다.
- 오른쪽 프레임 밖으로 일부 나가는 구도다. 회색 화면·좌측 베젤·상하 모서리로 태블릿임을 인지할 수 있어야 한다. 본체의 절반 이상은 화면 안에 보이게 조절한다.
- 최종 yaw 약 −18°, roll 약 −3°에서 시작해 실제 AE 결과를 보고 전면과 얇은 금속 측면이 함께 보이게 맞춘다. 원근 때문에 좌측 모서리가 문구에 들어오면 중심을 오른쪽으로 옮긴다.
- F34–F54에 정착 위치보다 오른쪽 140px·아래 30px에서 오른쪽 80px·정착 높이까지 이동하며 yaw 약 −30°→−18°, roll −7°→−3°, 균일 scale 94→100%로 맞춘다. opacity F34–F40 0→100%.
- F55에는 왼쪽 투영 경계를 약 x=1930으로 유지하고, F55–F64에 x=1850까지 마지막 80px를 in-house와 함께 감속하며 이동한다. F64 이후 완전히 멈춘다. 이 마지막 이동 중 각도·크기는 고정한다.
- 기존 in-house의 오른쪽 끝은 x≈1741이고 +120px 진입 시 x≈1861이다. 그러므로 기기를 처음부터 x=1850에 두면 겹칠 수 있다. **진입 전 구간에 실제 투영된 기기 경계와 텍스트/블러 사이 최소 약 60px**를 확인하고, 부족하면 기기를 오른쪽으로 조정한다.
- 차콜 배경에서 검은 베젤이 묻히지 않도록 부드러운 중성 조명으로 금속 측면·윤곽을 드러낸다. 회색 화면의 재질은 유지하고 밝은 흰 화면처럼 날리지 않는다.

기기에는 360° 회전·뒤집기·반복 부유·불필요한 카메라 패닝을 넣지 않는다. 짧은 두 컷에서 모델의 형태와 타이포 동작이 동시에 읽혀야 한다. 위 배치·각도는 구현 출발값이며, 글자 가독성과 기기 인지를 지키기 위한 범위 내에서 담당자가 조정하고 실제 값을 기록한다.

### 속도와 효과

- 위치의 주 이동은 초반 빠르게, 마지막 짧고 명확하게 감속한다. cubic-out을 출발점으로 쓰되 TITAN/Built의 오버슈트 구간은 별도 ease-out/settle 키로 만든다. 여러 번 튀는 bounce는 넣지 않는다.
- opacity를 긴 페이드처럼 끌지 않는다. 위 짧은 구간 안에 완전 불투명해져 위치·스케일의 액션이 읽히게 한다.
- Built와 in-house의 가장 빠른 구간에만 짧은 방향성 블러 또는 실제 이동에 대응하는 모션 블러를 사용한다. 예시 blur length 8–16px에서 0px로 빠르게 정리한다. Built는 F54, in-house는 F64 이전에 완전 선명해야 한다.
- 블러는 현재 설치 효과/catalog로 지원을 확인해 구현한다. 특정 구현 경로가 막히면 같은 역할의 지원되는 방식으로 해결하고 결과를 기록한다. 기기 자체가 흐려지거나 텍스트 정착 화면에 블러가 남으면 제거한다.
- 이번 조합에서는 임의의 glow·글자별 애니메이터·모든 단어의 같은 오버슈트를 추가하지 않는다. 핵심은 단어 전체의 액션 대비, 3D 기기의 깊이, 도형과의 동기화다.

## 7. AE/MCP 구현 구조

- 마스터의 기존 2D 타이포·Shape 동작을 유지하기 위해 **기기만 별도 Advanced 3D 컴포지션**으로 구성하는 방식을 우선한다. 각 기기 컴포지션은 2400×1024, 30fps, 3초, 투명 배경, 네이티브 ThreeDModelLayer + 필요한 카메라·조명을 가진다. 기존 iPhone 테스트 컴포지션을 직접 수정하지 않는다.
- 마스터에는 기기 컴포지션을 2D AV 레이어로 배치한다. Collapse Transformations는 기본 off로 두고 화면 경계·합성 순서를 검증한다. 원래 텍스트·Shape 위계가 바뀌는 렌더러 전환을 피한다.
- 첫 컷: 텍스트·원호·점 → iPhone 기기 컴포지션 → 아이보리 Solid 순으로 앞뒤 관계를 만든다. 모두 차콜 와이프보다 아래에 놓고 outPoint=F33/30으로 끝낸다.
- 둘째 컷: 텍스트·밑줄 → iPad 기기 컴포지션 → 차콜 Solid 순서다. iPad와 둘째 컷 타이포의 실제 노출은 F34부터다. iPad가 와이프보다 앞에 미리 나타나면 실패다.
- 카메라는 고정하고 모델의 위치·작은 XYZ 회전으로 깊이와 움직임을 만든다. 모델 정면·내보내기 축·import scale을 실제로 확인한 뒤 회전을 정한다. `rotation` 단일 값만으로 XYZ 제어가 됐다고 간주하지 않는다.
- 현재 MCP catalog의 지원 명령을 조회해 쓰고 `eval.run`을 켜지 않는다. 실패한 atomic/batch 명령을 성공으로 세지 않는다. 필요하면 허용된 속성 expression만 사용한다.
- 기존 Guide 2개는 잠김·enabled=false를 유지하고 최종 렌더에서 제외한다.

## 8. 제작·검증 순서와 완료 기준

1. 원본·현재 AE 상태·두 GLB를 기록하고 새 AEP/복제 컴포지션을 만든다. 사용자 테스트 항목을 원래 자리에 보존한다.
2. 먼저 F18/F75의 기기 포함 정착 화면을 렌더해 검토한다. 회색 스크린의 정면, 베젤/측면, 기기 크기, 글자와의 간격·대비를 확인하고 필요하면 이 범위 안에서 조정한다. 중간 승인 대기로 멈추지 않는다.
3. 위 타임라인의 전체 단어 모션·기기 모션을 구현한다. 전환 F28/F33/F34와 주요 움직임 F05/F09/F14/F45/F49/F54/F57/F64를 확인한다.
4. F33은 완전 차콜 단색, F14–F23과 F64–F89는 정착 유지다. 원호·점·밑줄의 누락, 앞 컷 잔류, 모델 clipping·반전·검은 화면·누락 재질, 타이포 흔들림·철자 오류가 없어야 한다.
5. v001에서 밑줄 소실이 있었으므로, 먼저 새 AEP를 저장하고 대상 컴포지션만 별도 **aerender 프로세스**로 렌더하는 기존 검증 경로를 우선한다. 현재 대화형 AE나 다른 렌더 큐를 전체 실행하지 않는다. 원인 미확정인 과거 사건을 사용자 입력 탓으로 단정하지 않는다.
6. 90프레임 해상도·불투명도·정착 구간, 새 AEP 해시와 렌더 출처를 확인하고 원본 2400×1024로 H.264/yuv420p MP4를 만든다. ffprobe로 3초·30fps·90프레임·75:32·무음, 전체 디코딩, 실제 재생 시작·종료를 확인한다.
7. 이전 v002와 새 F18/F75 및 실제 재생을 비교한다. 두 기기가 각 컷에서 식별되고, 중앙 문구 위계가 유지되며, TITAN/Built의 액션이 기존 짧은 이동+페이드보다 분명하게 강화됐는지 시각적으로 판정한다. 기술 통과만으로 미감 승인을 표시하지 않는다.
8. 새 AEP·MP4·비교 PNG·작업/검증 보고서를 전달한다. 지원되지 않아 대체한 항목, 조정한 배치/속도, 남은 차이는 사실대로 기록한다. 완료 전 원본 AEP/GLB·기존 컴포지션·사용자 기기 테스트가 보존됐는지 확인한다.

이 문서는 **실행 지시서**다. 작성 시점에 새 v3 모델 합성·모션·렌더가 완성됐다는 의미는 아니다.
