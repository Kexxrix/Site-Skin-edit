## 구현

문구는 정확히 `Meet`, `TITAN`, `Core systems`, `Built`, `in-house`입니다. 일반 하이픈 U+002D를 사용했습니다.
편집 가능한 텍스트 5개, Shape 3개, Solid 2개로 제작했습니다. 참조 가이드 2개는 잠금·비활성 상태이며 렌더에서도 Guide Layers All Off를 적용했습니다.

색상은 문서의 아이보리 #F5F3EE, 차콜 #24262A, 주황 #FA871F를 따릅니다. Pretendard Regular / SemiBold / Medium / Bold를 실제 조회하고 사용했습니다. 가이드의 미세한 얼룩이나 글꼴 왜곡은 재현하지 않았습니다.
글자 경계 높이 목표 100 / 136 / 112 / 145 / 122px를 측정해 맞췄으며, 좌표와 fontSize는 [text-layout.json](qa/text-layout.json)에 있습니다.
아랫줄의 실제 폭은 약 1072.45px로 지시 범위 1050–1150px 안입니다. 밑줄은 Built의 실제 폭 약 388.27px에 맞췄습니다.

## 검증 결과

- 규격: 3초 × 30프레임/초 = 90프레임. F00–F89, 마지막 샘플은 89÷30 = 2.9666667초.
- 화면비: 2400÷1024 = 75÷32 = 2.34375. MP4 SAR 1:1, DAR 75:32.
- 90/90 PNG가 2400×1024이고 모두 완전 불투명입니다.
- 67/67 속성 검증 통과. 키프레임 중간 진행값 및 경계값을 검사했습니다.
- F00은 아이보리, F33은 차콜 단색입니다. F14–F24의 픽셀이 동일하며, F61–F89도 밑줄을 포함해 동일합니다.
- 정착 F18/F75 및 전환·진입 경계 프레임을 육안 비교했습니다. 문서의 정확한 폰트·색·타이밍이 래스터 가이드보다 우선합니다.
- Adobe aerender 25.4x86의 별도 프로세스에서 저장된 v002 AEP를 읽어 90프레임 전체 렌더: 종료 코드 0. 성공 렌더 로그에 오류·색상 경고 없음.
- ffprobe: H.264, 2400×1024, 30/1fps, 3.000000초, 90프레임, 오디오 없음.
- ffmpeg 전체 디코딩: 종료 코드 0, 오류 출력 없음.
- 로컬 브라우저에서 처음부터 재생하고 재생 중 상태 및 3초 정상 종료를 확인했습니다. 시작·끝 화면과 최종 밑줄을 확인했으며 콘솔 경고·오류는 없었습니다. 중간 동작은 프레임 검수·속성 검증으로 추가 확인했습니다.

## v001 문제와 복구

v001의 대화형 렌더 도중 밑줄 레이어가 사라졌고 F67 이후 결과가 달라졌습니다. 직접 수정하지 않았다는 사용자 설명을 반영했습니다. PC 동시 사용 중 입력 충돌은 가능한 설명이지만 원인을 확정할 기록은 없습니다.

누락된 `C02_UNDERLINE`만 같은 경로·색·타이밍으로 복구했습니다. v001을 덮어쓰지 않고 v002 AEP를 저장했으며, 화면에서 편집 중인 AE를 재사용하지 않는 별도 aerender 프로세스로 90장을 다시 렌더했습니다. 출력은 저장된 AEP의 동일 해시를 기준으로 고정했습니다.
실패한 출력 모듈 이름 조회·초기 렌더 시도와 읽기 명령 오류도 QA 기록에 남겼으며, 해당 시도는 최종 성공 렌더가 아닙니다.

## 보존과 남은 사항

Creative Production의 원본 보존·정확한 문구·결정적 내보내기 기준을 적용했습니다. 기존 Hello World의 프로젝트 항목 5개와 원본 AEP, 원본 가이드 2장의 해시를 비교해 보존을 확인했습니다. v001 파일도 보존했습니다. 기존 큐 전체 실행, 기존 AEP 덮어쓰기, Git 변경은 하지 않았습니다.

새 저장본의 활성 경로는 v002 AEP입니다. 검증 후 대화형 AE는 dirty=true / 선택 레이어 0 / 대상 레이어 12 / 큐 0 상태이며, 검증에 사용한 저장본을 다시 덮어쓰거나 대화형 프로젝트를 재로드하지 않았습니다.
AEP의 가이드 경로는 원래 results 폴더를 참조하며, 다른 PC에서 편집하려면 해당 참조와 Pretendard 폰트를 유지해야 합니다. 최종 영상 자체는 이 가이드에 의존하지 않습니다.

H.264는 손실 압축입니다. ffprobe에서 색상 행렬 bt709는 확인되지만 primaries/transfer 값은 명시되지 않았습니다. PNG의 RGB 색상 검증과 모든 플레이어에서의 완전 동일한 색 재현을 혼동하지 않습니다.

기술 검증 통과는 사용자 미감 승인 또는 사이트 채택을 뜻하지 않습니다. 전체 콘티·제품 컷·오디오·사이트 적용은 진행하지 않았습니다.
