- **실제 ThreeDModelLayer의 화면 재질**을 유지한다. 2D 평면 추적이나 사전 렌더된 기기 영상으로 바꾸지 않는다.
- 소스 드롭다운 연결은 이전 시험에서 MCP 속성 API에 노출되지 않아 실제 UI로 처리했다. 복제·재연결 후 이 관계를 확인하고, 필요하면 허용된 Computer Use 방식으로 연결한다. 사용한 MCP와 UI 단계를 보고서에 구분한다.

- 기존 기기 방향과 화면 영상의 정립·Fit 관계를 기준으로 하고, 정면/사선 회전 중 상하 반전이나 좌우 반전이 생기지 않게 확인한다. 그림의 핵심은 진입·겹침·반동·3D 각도의 연결이다.

- 과장된 모션 중 잠깐의 의도적 가림은 허용한다. 정착 후 문구를 기기가 계속 가리거나 기기 때문에 타이포를 축소·재배치하면 안 된다.
- 가이드·사용자 주석 이미지는 최종 렌더에 포함하지 않는다.

## 6. 씬 1: Meet TITAN

### 반드시 유지할 동작 관계

```text
M → e → e → t 순차 진입
M 최종 정착 = 작은 원호 생성·확대 시작
원호 확대 완료 = 도트 전체 경로 이동 시작
t 최종 정착 = TITAN 수평 진입 시작
도트 끝점 도착 = TITAN 최종 정착
```

이번 제작 초안에서 **도착은 easeOutBack의 반동을 마친 최종 정착 시점**으로 정의한다. 목표 위치를 처음 지나치는 시점과 혼동하지 않는다. 연결이 둔하게 느껴지면 담당자가 구간 길이와 글자 간 시차를 조정하되 실제 적용 기준과 결과를 기록한다.

### 크게 움직이되 최종 구도는 유지

- M의 시작은 최종 위치 아래 약 620px, 첫 e 약 460px, 둘째 e 약 330px, t 약 230px를 출발값으로 삼는다. M이 가장 먼 거리에서 빠르게 올라온다는 차이가 보여야 한다.
- 네 글자는 모두 `easeOutBack`을 적용한다. 짧은 불투명도 전환이 필요해도 이동·반동이 실제로 읽히게 한다. 긴 페이드로 액션을 가리지 않는다.
- 원호는 M 글리프의 실제 중심 근처에서 최종 크기의 약 27%로 시작한다. 원호 전체를 균일하게 확대하며 최종 중심으로 이동한다. 작은 상태부터 **긴 열린 원호의 전체 형태**가 존재해야 한다. 닫힌 원을 만들었다가 선을 그리거나 열어 가는 별도 연출을 추가하지 않는다.
- 원호의 최종 기준은 중심 약 (675,494), 반지름 358px, 차콜 3px 선이다. 위치·크기 모두 `easeOutQuint` 진행값으로 연결한다.
- 도트는 원호 확대 완료 시 위쪽 오른쪽 시작점에서 보이게 하는 것을 초안으로 한다. 확대 도중 경로 이동은 하지 않는다.
- 도트 하나가 원호의 위쪽 오른쪽 → 위 → 왼쪽 → 아래 → 아래쪽 오른쪽 끝까지 진행한다. 기존 원호의 방향은 각도 −48°에서 감소해 −310°로 가는 경로다. 실제 Shape Path와 동일한 경로를 사용하고, 별도 직선 보간이나 짧은 호 이동으로 축소하지 않는다.
- 도트의 **경로 진행률**에 `easeInOutQuad`를 적용한다. 도트가 선에서 이탈하거나 원호의 열린 부분을 가로질러 지름길로 이동하면 실패다.
- TITAN은 전체 단어가 화면 오른쪽 밖에서 수평으로 진입한다. 회전/대각선 진입으로 바꾸지 않는다. 초기 곡선은 `easeInOutQuad`를 권장하며 이는 담당자 초안이다. 큰 이동과 중간 속도감, 도트와의 동시 정착이 느껴져야 한다.
- 필요한 속도 블러는 짧게 사용하고 최종 읽는 상태에서는 선명하게 한다. 새 glow·파티클·글자 모핑을 추가하지 않는다.

## 7. 씬 2: 기존 레터링 → iPad 접촉 → 문구 복귀

1. 기존 **Core systems → Built/밑줄 → in-house** 등장 순서와 로컬 속성 애니메이션을 그대로 진행한다. 이 구간을 글자별 등장으로 새로 만들지 않는다.
2. 등장 완료 직후 iPad가 **오른쪽 화면 밖에서 전면을 카메라로 향한 상태**로 빠르게 들어온다. 긴 페이드나 처음부터 사선으로 들어오는 방식으로 바꾸지 않는다.
3. 기기가 문구에 도달하는 시점부터 **Core systems / Built in-house와 밑줄 전체**가 왼쪽으로 튕겨 나간다. 모델이 앞에 잠깐 겹치는 스케치의 관계를 구현한다.
4. 가장 왼쪽으로 밀린 뒤 텍스트 블록은 오른쪽으로 반동하며 원래 좌표로 돌아온다.
5. 이 복귀와 겹쳐 iPad는 오른쪽으로 물러나며 정면에서 **깊이가 읽히는 사선**으로 회전해 자리 잡는다. 2D 왜곡으로 3D 회전을 흉내 내지 않는다.

구현 출발값:

- 텍스트 블록의 최대 왼쪽 이동량 약 **190px**. 30–50px 정도의 작은 흔들림으로 축소하지 않는다. 실제 화면을 보고 큰 반응과 가독성이 함께 확보되게 조정할 수 있다.
- iPad의 시작은 실제 투영된 왼쪽 경계가 화면 오른쪽 밖에 있도록 한다. 정면 기준은 실제 모델·카메라로 확인하며 원본 축의 0°와 같다고 가정하지 않는다.
- 기기의 이동·회전은 네이티브 3D 모델 또는 그 3D 부모의 변환으로 제어하는 것을 우선한다. 마스터 AV 레이어 이동 등 합성 보정을 함께 사용하면 실제로 어느 계층의 어떤 속성을 제어했는지 보고한다. 3D 회전은 실제 모델에서 평가돼야 한다.
- 접촉 순간에는 iPad 왼쪽 경계가 원래 문구의 오른쪽 끝 부근에 오게 하고, 이후 문구의 밀림과 기기의 추가 접근을 연결한다. 접촉보다 먼저 문구가 움직이거나, 멀리 떨어진 상태에서 반응하면 안 된다.
- 접근의 마지막 구간은 기기가 약 150px 더 왼쪽으로 진행하고 텍스트가 약 190px 밀리는 것을 출발값으로 삼는다. 기기가 문자 전체를 오래 덮지 않게 실제 투영 경계로 조정한다.
- 복귀 시 기기는 기존 오른쪽 정착 영역으로 이동한다. 전면과 얇은 본체 측면이 함께 읽히는 약 25–35° 사선을 출발점으로 삼고, 스케치처럼 정면과의 차이가 분명하게 보이게 한다. 실제 회전축·부호는 모델을 보고 정하며, 영상이 뒤집히지 않아야 한다.
- 문구는 정확한 원위치로 돌아오고, 기기는 최종 문구와 간격을 확보한다. 최종 가독성·기기 식별과 화면 영상의 재생을 함께 확인한다.
- iPad 진입은 `easeInQuad`, 문구 밀림과 기기의 접촉 직후 이동은 `easeOutQuint`, 문구 복귀는 `easeOutBack`, 기기의 후퇴·사선 회전은 `easeOutCubic`을 **초안**으로 삼는다. 이 네 선택은 사용자가 직접 지정한 곡선이 아니라 이번 동작을 위한 구현 출발값이다. 변경하면 이유와 실제 곡선을 기록한다.
- 모션은 실제 충돌 물리 시뮬레이션이 아니라도 된다. 지시한 접촉·관성·반동 관계가 재현 가능하고 편집 가능한 시간/속성 제어로 연결되면 된다.

## 9. 이징을 실제로 적용하고 검증하는 기준

참고: [easings.net](https://easings.net/) 및 확인한 [공식 저장소의 함수 정의](https://github.com/ai/easings.net/blob/master/src/easings.yml), 확인일 2026-09-11.

이름을 붙이거나 AE Easy Ease를 설정한 것만으로 지정 곡선 적용을 주장하지 않는다. 현재 MCP의 기본 preset은 위 함수 이름 전체를 직접 제공하지 않는다. 허용된 `expression.set`과 실제 속성 경로를 사용해 함수식을 적용하는 방법을 우선한다. 정확도를 입증할 수 있다면 다른 편집 가능한 구현도 가능하다.

정규화 시간과 속성 보간:

```text
u = clamp((time - start) / (end - start), 0, 1)
property = startValue + (endValue - startValue) * E(u)
```

- 제한하는 것은 **시간 u**다. easeOutBack의 출력 E(u)는 1을 넘을 수 있으므로 0–1로 다시 clamp하지 않는다.
- 이미 이징한 값을 범위 밖에서 잘라내는 보간 함수에 넣어 반동을 없애지 않는다.
- 벡터 위치는 각 성분에 동일한 진행값을 적용하고, 공간 경로는 그 경로의 진행률에 이징을 적용한다.
- 시작·끝 시점을 연결하는 최소한의 공통 값/마커를 사용한다. 관련 속성마다 서로 다른 임의 종료시간이 생기지 않게 한다.

검증할 기준 함수:

```text
easeOutBack:
  c = 1.70158
  E(u) = 1 + (c + 1)*(u - 1)^3 + c*(u - 1)^2

easeOutQuint:
  E(u) = 1 - (1 - u)^5

easeInOutQuad:
  u < 0.5: E(u) = 2*u^2
  그 외:   E(u) = 1 - (-2*u + 2)^2/2
```

실제 적용된 속성의 시간별 평가값을 읽어 시작값·종료값으로 정규화한 후 위 함수와 비교한다. 입력한 식을 따로 계산한 로그만으로 AE에 적용됐다고 판정하지 않는다.

- 최소 표본: u=0, 0.25, 0.5, 0.75, 1. easeOutBack은 오버슈트 최대 부근도 포함한다.
- Back 최대 시점은 미분으로 얻는 `u=1-2*c/(3*(c+1))`을 사용한다.
- 프레임 경계로 반올림해 조회했다면 실제 조회 시간의 u로 기대값을 다시 계산한다.
- 정확한 함수 적용 속성은 정규화 오차 0.0001 이하를 목표로 하며, 샘플 시간·단위·허용 오차·최대 오차를 기록한다.
- 도트는 실제 경로 좌표와의 일치도 함께 확인한다. 위치의 단순 X/Y 직선 보간을 이징 검증으로 잘못 통과시키지 않는다.
- 수식 정확도와 화면에서 느껴지는 힘·리듬·동시 도착은 별도 항목이다. 이징이 맞아도 거리·시간·간격 때문에 약하거나 어색하면 해당 값을 수정한다.

- 두 씬을 연결한 원본 해상도의 H.264/yuv420p MP4. `review-01`과 실제 수정본이 있으면 각각 구분하고, 보고서에서 검토할 주 파일 하나를 명시.
- 주요 프레임: M 반동/정착, 원호 시작/중간/완료, 도트의 전체 경로 중간, 도트·TITAN 동시 정착, 와이프 완료, 씬2 레터링 완료, iPad 접촉/최대 밀림/중간 회전/최종 정착.
- `TIMELINE.csv` 또는 동등한 읽기 쉬운 실제 적용 시간표.
- `EASING-VERIFICATION.json` 또는 동등한 기대값/실제 AE 평가값 비교 기록.
- `VERIFICATION.json`: 원본/출력 해시·크기·메타데이터·전체 디코딩 결과·시각 점검·MCP/UI 구분·보존 확인.
- `RESULT.ko.md`: 구현 결과, 실제 조정, 첫 출력/개선본 구분, 편집 가능성 시험, 미검증·남은 개선점을 담은 짧고 정확한 보고서.

검증 항목:

- 정확한 문구·네이티브 Text·최종 기준선·색·밑줄·원호 형태·새 도트 정착점.
- 지정한 세 곡선의 실제 적용과 오버슈트 보존.
- M→원호, 원호→도트, t→TITAN, 도트 끝=TITAN 끝의 실제 시간 관계.
- 씬2 레터링 완료 전에 iPad가 노출되지 않음. 접촉에 맞춘 블록 전체 밀림과 원위치 복귀.
- 네이티브 GLB의 실제 정면→사선 회전, 순간 가림과 최종 가독성. 사전 렌더/2D 가짜 기기로 대체하지 않음.
- 기기 화면의 영상이 시간에 따라 변함. 3초 이후 새 사용 구간에서도 재생·매핑이 유지됨. 화면 소스 사각형이 모델 밖에 이중 노출되지 않음.
- 최종 AEP 저장·재열기 후 화면 매핑과 주요 모션 유지. 다른 사용자 편집을 보존한 후 시행.
- 전체 출력 해상도·30fps·75:32·실제 길이·프레임 수·무음, 전체 디코딩, 정상 속도 실제 재생.
- 주요 프레임만 본 경우 전체 실시간 재생을 확인했다고 쓰지 않음. 디코딩 성공만으로 연출 완성도를 통과시키지 않음.
- 원본 AEP·GLB·MP4·PNG와 관련 없는 작업 항목 보존.
- 기술 통과, 담당자의 시각 검토, 사용자 최종 승인·사이트 채택을 구분.

## 12. 완료 후 원래 작업으로 보고

사용자가 완료 후 이 작업으로 돌아오는 결과 보고를 명시적으로 요청했다. 제작 담당은 파일 저장·검증 후 **send_message_to_thread**로 아래 대상에 실제 결과를 보낸다.

```text
threadId: 01a084c3-735f-7fd2-8ef7-a044226bd7a3
hostId: local
```

메시지에는 다음을 포함한다.

1. 이번 두 씬 테스트의 완료 상태와 실제 재생 시간.
2. 주 검토 MP4, 작업 AEP, 결과 보고서, 검증 기록의 **정확한 절대 경로**.
3. 씬1 이벤트/세 곡선 검증 결과, 씬2 기기·문구 연동과 영상 화면 유지 결과.
4. 첫 출력 이후 수정한 값과 차이, 편집 가능성 시험 결과.
5. MCP만으로 한 단계와 UI가 필요했던 단계, 미검증 또는 지원되지 않은 항목.
6. 사용자 미감 승인은 아직 대기라는 점.

복구 가능한 문제는 맡은 범위에서 해결한다. 사용자 입력이나 외부 상태 변경 없이는 더 진행할 수 없는 구체적 문제가 입증되면, 지금까지의 산출물·오류·보존 상태와 함께 같은 대상에 알린다. 완료를 가장하거나 새 기능으로 우회하지 않는다.

이번 전달은 **실제 작업 시작 지시**다. 설명만 작성하고 종료하지 말고, 두 씬을 제작·렌더·검증한 후 결과를 회신한다.
