## 4. 전체 플레이타임 검토와 적용

시간 기준은 제품 순서 변경 후 정리된 전체 콘티 `english-storyboard-v2.md`의 **20초 / 16비트**다. 더 초기의 12초 탐색안이나 두 씬의 8초 기능 시험은 현재 전체 콘티의 시간표가 아니다. 현재 새 참조의 02씬은 원래 비트 02·03·04를 합친 한 장면이고, 새 참조 03씬은 원래 비트 05다.

본 제작 마스터의 길이는 20초로 설정하고, 이번 렌더 범위/작업 영역은 0–5.7초로 지정한다. 이후 미제작 구간을 검은 화면으로 붙인 20초 파일을 완성본처럼 제출하지 않는다. 전체 타임라인의 나머지 시작점은 마커로 남긴다. 3씬 검토본을 오프닝으로 억지 루프시키지 않으며, 전체 엔딩의 자연스러운 루프는 비트 16의 후속 작업이다.

내부 등장·정착 시점은 아래의 제작 타이밍을 사용한다. 정상 속도 검수에서 가독성이 부족하면 같은 구간 안에서 대기·보조 동작을 줄이고 동작을 겹친다. 전체를 타임 스트레치하거나 씬 경계를 밀어 느리게 만들지 않는다. 경계 변경이 필요하다는 판단이 생기면 먼저 차이와 이유를 보고한다.

## 5. 새 AEP와 작업 환경

1. 기존 작업을 닫기 전에 열린 프로젝트의 실제 경로·미저장 상태를 확인한다. 미저장 변경이 있으면 기존 파일을 덮어쓰지 않는 별도 보존본으로 저장한다. 그 보존본은 이번 제작의 출발 파일이 아니다.
2. **File > New > New Project**에 해당하는 새 프로젝트를 만든다. 빈 상태를 확인한 뒤 새 AEP를 저장한다. 이전 프로젝트·컴프를 가져오거나 복제하여 시작하지 않는다.
3. 실제 사용하는 After Effects Beta의 버전·빌드와 현재 연결 대상 앱을 읽는다. 이전 시험 보고의 환경은 Beta 27.0x43 / Advanced 3D이며, 현재 환경은 실행 시 다시 확인한다.
4. 이번에 필요한 PNG 참조, 지정 GLB, 지정 MP4만 새로 가져온다. Text·Shape·카메라·3D 기기·화면 프리컴프를 새로 만든다. PNG는 가이드로만 두고 최종 출력에서 제외한다.
5. 폰트는 기존 디자인 계열인 Pretendard의 실제 설치된 PostScript 이름과 굵기를 확인해 사용한다. 새 구도의 Regular/Medium/Bold 위계와 자간을 맞추고 누락 폰트를 임의 대체하지 않는다.
6. 이전 운영 보고와 Beta 연결 클라이언트는 API 사용법만 참조할 수 있다. 기존 AEP의 레이어 ID·좌표·키프레임·카메라를 복사하지 않는다. 네이티브 MCP가 지원하지 않는 재질 항목은 실제 지원되는 조작 경로를 확인하여 설정한다. 성공 반환만으로 화면 매핑이 됐다고 판단하지 않는다.

## 6. 모델·영상 매핑

### 모델에서 확인한 식별 정보

- GLB: iPad10 v001, 1,714,248 bytes, glTF 2.0. 파일 해시는 관리 manifest와 일치한다.
- 화면 노드: **`iPad10.Screen`**, 메시: **`iPad10.Screen.Mesh`**, 재질: **`iPad10.SCREEN`**. 해당 메시의 UV `TEXCOORD_0`가 있다.
- 모델 내 설명: 로컬 +Z가 앞면, +Y가 위, UV 원점은 아래 왼쪽. AE 가져오기 후 축 방향과 화면 상하·좌우는 렌더로 확인한다.
- 화면 비율: **2360:1640 = 59:41 ≈ 1.439024**. 참조 그림의 태블릿 비율을 맞추려고 GLB를 4:3이나 16:9로 비균일 변형하지 않는다.
- 내장 이미지 텍스처는 없고 현재 화면 재질은 회색 자리 표시자다. 제공 영상을 **새로 연결**해야 한다.

### 영상과 사용할 소스 구간

`아이패드.mp4` 실측: **1920×1080, H.264, 정사각 픽셀, 60fps, 1454프레임, 24.233333초**. AAC 오디오 트랙이 있으므로 최종 무음 조건에 맞게 오디오를 끈다.

0초 프레임에는 한국어 전체화면 안내 오버레이가 보인다. 이를 피하려고 이번 03씬의 소스 시작을 **원본 2.000초**로 지정한다. 2.000·2.950·3.900초 샘플에서 안내가 사라진 CAT VILLAGE 화면과 라이브카지노 화면으로의 실제 변화가 확인됐다. 이 UI 변화는 제공 영상의 내용이며, 생성한 03 이미지와 동일한 정지 화면으로 고정하지 않는다. 원본에 포함된 포인터를 AI로 지우거나 화면을 다시 그리지 않는다.

- 마스터 F114 / 3.800초에서 소스 2.000초를 시작한다.
- 소스 시간은 `2.000 + (마스터 시간 − 3.800)`이다. 재생 속도 100%, 원본 60fps 해석을 유지한다.
- 마스터 F170 / 5.666667초에서는 소스 3.866667초다. 종료 경계 5.700초는 소스 3.900초에 해당한다.
- 1.900초 구간은 소스 114프레임 분량이고, 30fps 출력에서는 57프레임이다. 60fps를 30fps로 잘못 재해석하여 두 배 느리게 만들지 않는다.

### 비율 보존과 재질 연결

영상 16:9와 모델 화면 59:41은 다르다. 기본 매핑은 **영상 전체가 보이도록 비율을 유지한 contain**으로 한다. 원본 MP4는 변환·자르기·덮어쓰기하지 않고 AE 화면 프리컴프에서 배치한다.

예: 화면 프리컴프 2360×1640에 1920×1080 영상을 `2360 ÷ 1920 = 1.2291667배`로 배치하면 콘텐츠는 2360×1327.5가 된다. 남는 높이는 `(1640 − 1327.5) ÷ 2 = 156.25px`씩 위아래에 생기므로 화면 내부의 어두운 바탕으로 처리한다. 홍보영상 바깥에 레터박스를 넣는다는 뜻이 아니다. 가로·세로를 따로 늘리거나 제품 UI를 임의 크롭하지 않는다.

이 화면 프리컴프 또는 이에 해당하는 실제 영상 레이어를 **`iPad10.SCREEN`의 재질 소스**로 연결한다. 모델 앞에 떠 있는 사각형 오버레이로 영상 매핑을 대신하지 않는다. 영상 레이어가 메인 화면에 이중 노출되지 않게 하면서 재질에서는 계속 재생되게 한다. 앞·비스듬한 자세·회전 중·정면 정착 모두에서 화면이 베젤 안에 붙어 있어야 한다.

최종 PNG의 가상 UI보다 사용자 지정 MP4와 실제 GLB가 우선한다. 네 모서리, 베젤, 카메라, 뒷면을 보존하고 기기는 받침대 없이 부유한다.

## 7. 씬별 모션과 전환 타이밍

아래 F 번호는 모두 30fps 마스터의 절대 프레임이다. 주 동작은 겹쳐 진행하되, 읽히는 문구의 기준선·자간·최종 크기는 정착 후 안정적으로 유지한다. 큰 움직임은 이동 거리와 속도 차이로 만들고 전체 재생 시간을 늘려 만들지 않는다.

### 01 — Meet TITAN, F000–F038

- **F000–F010:** Meet의 M/e/e/t가 짧은 시차로 진입하고 TITAN이 뒤따라 마스크/문자 애니메이터로 정착한다. 큰 아웃라인 TITAN은 다른 배율·속도로 따라오며 전경 문구를 가리지 않는다. 원호와 도트도 같은 시작 신호를 공유한다.
- **F010–F030:** 전경 Meet TITAN을 읽힌다. 주변 원호·큰 아웃라인은 통제된 이동을 이어 간다. 모든 요소를 계속 흔들지 않는다.
- **F031–F038:** 도트가 원호의 끝에서 수평선으로 이어지고, 그 움직임을 따라 전경 글자가 정리된다. 아웃라인 획·선의 진행 방향으로 차콜 배경이 들어오기 시작한다.

- **F039–F046:** Core systems가 선의 진행에 맞춰 단어 단위로 등장하고 작은 문맥 위치에 정착한다.

- **F074–F092:** Built를 읽히면서 밑줄이 시작된다. 도트와 선은 동일한 경로의 끝점 관계를 유지한다.

- **F108–F113:** 프레임이 다음 씬의 입장 경계를 준비하고 02 전경 글자는 그 경계 뒤로 정리된다. F113까지 CAT VILLAGE / Casino Slot은 완성 상태로 노출되지 않는다.

### 2→3 — 문구 자체의 등장을 포함, F108–F124

기존 모션 가이드는 ‘3씬 시작은 중앙의 Fill 문구’로 설명했으며 **문구가 02에서 이어져 등장하는 동작을 지정하지 않았다. 이번에는 아래 과정을 반드시 구현한다.**

### 03 — Fill 정착 → 회전 접근 → Outline 도착, F114–F170

- **F114–F135, 0.700초:** iPad가 원거리에서 회전하며 전진한다. 화면상 작은 크기에서 시작해 중앙의 정면 도착 크기로 커진다. 실제 3D 자세가 변해야 하며 평면 PNG 확대가 아니다. 회전량은 옆면이 읽히고 화면이 뒤집히지 않는 범위에서 설정한다. 짧은 구간에 완전한 360도 회전을 억지로 넣지 않는다.

- **F138–F163:** 정면 기기와 Outline 문구를 안정적으로 읽힌다. 글자 내부로 영상이 보이고 화면 영상은 계속 재생된다. 전경은 실제 화면에 투명한 글자 내부를 만들며, 가짜 화면 스틸이나 배경색 채움으로 구멍을 흉내 내지 않는다.

## 8. 프리셋과 모션 리소스 활용

사용자가 요청한 프리셋 활용을 실제 작업에 반영한다. 설치된 네이티브 `.ffx` 또는 조사한 공개 텍스트 애니메이터 정의를 문자·단어 등장에 적용하고, 결과를 현재 글꼴·배치·타임라인에 맞게 조정한다. 프리셋 이름만 나열하거나 모두 같은 Easy Ease로 만든 뒤 ‘프리셋 활용 완료’라고 기록하지 않는다.

| 적용 위치 | 시작 후보 | 반드시 조정할 부분 |
|---|---|---|
| 01 Meet / TITAN | 설치 Text 프리셋의 문자별 회전/깊이 등장, 또는 aftr `charScale` / `bunchRotate` 정의 | F000–F010 안의 시차·이동량·회전·정착, 최종 서체·크기 보존 |
| 02 Built / in-house | 단어 reveal·문자 스케일 정의 | 원래 의미 순서와 F066·F093 시작점, 완성 구절의 기준선 |
| 2→3 CAT VILLAGE / Casino Slot | aftr `wordReveal` 정의 또는 대응 네이티브 프리셋 | F114/F117 시작, 선·프레임과 같은 방향의 진입, F122/F124 정착 |
| 도트·선·태블릿 | 네이티브 곡선과 필요시 조사된 Rebound/DuAEF 보간 정의 | 빠른 출발→도착 감속, 연결되는 속도, 잔진동 억제 |

현재 파일 존재를 확인한 예: `C:/Program Files/Adobe/Adobe After Effects (Beta)/Support Files/Presets/Text/3D Text/3D Basic Rotate X Cascade In.ffx`, 같은 폴더의 `3D Basic Position Z Cascade In.ffx`, `3D Flip In Rotate X.ffx`. 개별 결과의 품질·Beta 호환을 이번 지시서 작성에서 시험한 것은 아니다.

기존 조사에서 확인한 `.ffx` 경로는 `timeline.set_time` → `layer.apply_preset`, 텍스트 정의 구성은 `text.add_animator`·`property.set`·키프레임 작업이다. 현재 연결의 카탈로그와 대상 속성을 확인한 뒤 적용한다. 프리셋 기본 길이·기본 카메라·폰트·색·레이어 추가를 그대로 남기지 않는다. 필요 없는 새 효과와 중복 애니메이터는 이번 생성분만 정리한다.

aftr·Rebound 등의 별도 패널이나 새 MCP 설치를 전제로 시작하지 않는다. 공개 소스 일부를 활용하면 원본 URL·커밋·라이선스·수정 범위를 기록한다. 정확한 사용 파일/정의, 대상 레이어, 시작 프레임, 변경값, 표현식 오류, 렌더 판정을 결과 보고에 남긴다. 적용이 실패한 후보는 대체한 것과 구분한다.

## 9. 검증과 결과 제출

### 실제 영상 검수

1. 5.700초 출력을 **정상 1배속으로 처음부터 끝까지** 보고 텐션·문구 판독·전환·정면 정착을 검수한다. 느린 확인용 재생이나 일부 스틸 관찰을 전체 재생 확인으로 기록하지 않는다.
2. 1→2 경계 F030/38/39/44/47에서 도트·선·배경·문구의 이어짐을 확인한다.
3. 2→3 경계 F107/113/114/118/122/124에서 **CAT 문구가 없음 → 등장 중 → Fill 정착**으로 바뀌는지 확인한다. 이 과정이 없으면 실패다.
4. F124/131/135/138/155/170에서 **Fill + 후방 기기 → 회전 접근 → 정면 + Outline → 화면 재생 유지**를 확인한다. 앞의 Outline 내부로 실제 영상이 보이는지 확인한다.
5. 화면의 원본 2.000초와 3.866667초에 대응하는 프레임을 비교한다. 프레임 번호만 바뀌고 화면은 정지한 경우 영상 재생 검증에 실패한 것이다. 정상·비스듬한 자세에서 상하 반전, 미러, UV 미끄러짐, 화면 이탈, 이중 노출을 확인한다.
6. 누락 폰트/소스/효과, 표현식 오류, 클리핑, 레이어·깊이 순서, 비균일 왜곡, 의도하지 않은 한국어 오버레이를 확인한다. 원본 제품 UI의 일본어는 유지한다.

### 기술 검증

- 실제 새 AEP 경로와 새 프로젝트로 시작한 기록, 사용한 Beta 버전·렌더러, 입력 소스 경로를 남긴다.
- 저장 후 **이번 새 AEP를 다시 열어** 소스 연결·텍스트·카메라·재질을 확인하고 대표 프레임을 재검사한다.
- `ffprobe` 등으로 최종 MP4의 실제 2400×1024 / 30fps / **5.700초 / 171프레임 / 오디오 트랙 없음**을 확인한다. 전체 디코딩 오류도 검사한다.
- master duration **20.000초 / 600프레임**, 이번 render span **0.000–5.700초**, 다음 시작점 **F171**을 프로젝트에서 실제 조회하여 기록한다.
- 출력의 `실측값 − 계획값`을 기록한다. 20초 마스터가 존재한다는 이유로 아직 만들지 않은 전체 20초 영상을 완성했다고 보고하지 않는다.
- 본 문서와 JSON의 시간은 제작 지시다. 실제 AEP·출력이 없으면 실측값은 `null`/미실행으로 둔다.

### 제출 내용

새 AEP와 5.700초 MP4, 실측 시간표, 실제 사용한 프리셋/공개 정의 기록, 1→2·2→3 검수 프레임, 모델·영상 경로, 저장 후 재열기 결과, 남은 문제를 제출한다. 새 폴더 안에서 수정본을 구분하고 기존 시험 AEP·MP4·모델·원본 영상·이전 생성 이미지는 보존한다. 사이트 코드 수정·배포나 나머지 씬 제작을 완료했다고 보고하지 않는다.
