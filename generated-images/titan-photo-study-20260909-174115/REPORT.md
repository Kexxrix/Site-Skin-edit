# Titan 독립 업무 화보 연구

## 결과와 판정

새로운 촬영 콘셉트 두 개를 Codex 내장 image_gen으로 각각 한 장씩 생성했다. 두 장 모두 원본과 실제 CSS 표시 크기를 직접 확인했다.

- A `01-light-and-structure`: **우선 후보, selected_by_agent**. 코발트 의상의 큰 색 면, 사선 햇빛, 금속 작업대의 대각선이 좁은 사진 영역에서도 남는다. 기존 네 장의 창가·식물·노트북·미소 조합에 비해 촬영 기획의 차이가 분명하다.
- B `02-the-review-moment`: **보조 후보, selected_by_agent**. 큰 얼굴에서 손, 연필 끝, 종이 접점으로 이어지는 근접 구도가 읽힌다. 이전 사진보다 전체적으로 더 아름답다고 단정할 근거는 없으며, 구도 변주의 가치가 주된 성과다.

사용자 승인과 사이트 채택은 모두 **아직 없음**. 두 장으로 연구를 마쳤으며 수정 재생성은 하지 않았다. 물리적으로 명백한 결함을 발견하지 못했기 때문이다.

## 사진별 관찰

### A — 빛과 구조

- 얼굴, 피부, 양손, 의상, 작업대와 팔의 접촉에서 명백한 재생성 사유가 보이지 않았다.
- 인물이 충분히 크며 사선 빛이 얼굴을 가리거나 눈을 과노출하지 않는다.
- 313 × 400과 238 × 400에서 얼굴·양손·코발트 의상·사선 햇빛·작업대 대각선이 남는다.
- 좁은 크롭의 왼팔 바깥과 무릎 끝은 자연스럽게 잘린다.
- **약점:** 구체적인 소프트웨어 업무나 엔지니어 역할의 정보가 적다. 특정 작업을 설명하는 사진보다 인물·브랜드 화보에 적합하다.
- **프롬프트와 차이:** 곡면 벽의 곡률과 앉은 자세의 구조는 지시만큼 명확하지 않으나 핵심인 인물·색·빛의 구도는 남았다.

### B — 검토의 순간

- 연필을 잡은 손, 연필의 연속성, 종이 접촉, 얼굴과 내려다보는 시선에서 큰 오류는 보이지 않았다.
- 적당한 심도로 얼굴과 활성 손이 읽히며, 왼쪽의 흐린 전경과 경사진 종이가 앞뒤 깊이를 만든다.
- 313 × 400과 238 × 400에서 얼굴·활성 손·연필 끝·종이 접점이 유지된다. 머리 위 여백은 타이트하지만 크롭 결함은 아니다.
- **약점:** 경사진 기계식 제도대가 소프트웨어 업무보다 설계·제도 작업을 연상시킨다. 미간의 긴장이 강해 어려운 문제를 고민하는 분위기다. 왼쪽 흐린 전경도 모니터로 명확히 읽히지는 않는다.
- **판정 범위:** 집중과 검토를 표현하는 연출 사진으로는 가능하지만, 실제 소프트웨어 개발 장면의 증거 또는 특정 서비스 설명용으로 바로 채택하지 않는다.

## 검증 방법

1. 기본 생성 위치의 이번 두 파일만 새 프로젝트 폴더로 Move-Item 처리했다.
2. 이동 전후 SHA-256 일치, PNG 읽기, 실제 크기와 파일 크기, 기존 기본 위치에 잔여 파일이 없는지 확인했다.
3. 실제 요청 인자를 `prompts/*.request.json`에, 같은 프롬프트의 읽기 쉬운 원문을 `prompts/*.txt`에 보존했다. 이미지 참조 첨부는 없다.
4. 설치된 Edge를 Playwright로 별도 headless 실행해 `qa/display-proof.html`을 읽었다. 생성 사진 네 표시 예시와 기존 네 사진을 포함한 이미지 8개의 decode와 CSS 크기를 확인했다.
5. `313 × 400`, `238 × 400`, deviceScaleFactor 1, object-fit cover의 실제 브라우저 스크린샷을 직접 보았다. `qa/display-metrics.json`에 원본 및 표시 크기, 위치, 실제로 보이는 원본 좌표와 브라우저 오류 0건을 기록했다.
6. 독립 검토자가 원본 두 장 및 좁은 크롭과 비교 화면을 확인했다. A 우선·B 보조 후보, 현재 크롭 유지 의견을 받았다.

`qa/a-313.png`, `a-238.png`, `b-313.png`, `b-238.png`는 CSS 표시 검수 스크린샷이며 새로운 원본 사진이나 채택본이 아니다. 원본 PNG 자체는 리사이즈·보정·합성하지 않았다.

## 기존 네 장과 비교할 때의 한계

동일한 CSS 크기에서 비교했으나 인물·행동·배경·구도 모두 달라 통제된 인과 A/B 시험이 아니다. AI 생성이 스톡보다 보편적으로 낫다거나, 이런 사진을 스톡에서 구할 수 없다는 점은 확인하지 않았다. 확인된 것은 A의 색과 빛의 기획, B의 근접 구도가 현재 표시 크기에서도 읽힌다는 점이다.

## 범위와 다음 판단

시도 2, 생성 2, 도구 실패 0, 건너뜀 0, QA 통과 2, 에이전트 선택 2, 사용자 승인 0, 거절 0, 사이트 채택 0.

사이트 코드·현재 적용된 사진·영상 첫 프레임·영상 프롬프트는 변경하지 않았다. 기존 D:/WebDL 네 장은 읽기 전용 비교 참조로 사용했다. 생성한 두 장의 기본 도구 출력 파일만 승인된 규칙에 따라 이동했다.

연구의 우선 방향은 A처럼 **한 장의 색 면·빛의 형태·인물 자세를 함께 설계하는 방식**이다. B를 후속 탐색한다면 제도대가 만든 직무 혼동을 줄이는 것이 먼저다. 이번 실행에서는 추가 생성하지 않았다.
