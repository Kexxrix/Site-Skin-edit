# PARTNER EARNINGS 긴 문구 Grok 시험

사용자 요청: 12초 콘티 중 가장 긴 정산 문구부터 첫 프레임 이미지와 영상 프롬프트를 만들어 시험한다.

현재 상태: 사용자가 제공한 MP4 2개를 [실제 의도 비교와 다음 작성 기준](qa/video-review-20260910/README.md)으로 검토했다. 긴 문구의 선명한 유지와 도형 모션은 확인했으나 중앙 본문의 큰 퇴장·복귀, 온전한 단어별 이동, 후반 무가림 조건은 완전히 구현되지 않았다. 두 파일은 매우 유사해 독립 생성 2회로 세지 않는다.

최신 V2 결과: 사용자가 같은 이미지의 후속 MP4 1개를 제공했다. [V2 실제 검토](qa/video-review-wipe-v2-20260910/README.md)에서 0.875~2.291667초 완전 검정과 이후 재등장을 확인했다. 핵심 기법은 구현됐으나 하단 문구의 분해·중복으로 단일 블록 등장 조건은 미달이며, 판독 후보는 약 4.25~6초다. 에이전트는 새 이미지나 영상을 생성하지 않았다.

현재 제작 기준은 [화면 밖 퇴장·복귀 V3 프롬프트](prompts/04-grok-partner-earnings-offscreen-v3.txt) 방식이다. [사용자가 제공한 V3 실제 결과](qa/video-review-offscreen-v3-20260910/README.md)에서 처음 구성이 보인 뒤 실제 문구·도형이 왼쪽으로 빠지고 약 2.25초에 배경만 남았다가 복귀하는 흐름을 확인했다. 사용자는 이 방식이 더 자연스럽고 편집하기 편하다고 채택했다. 이는 제작 방식의 승인으로, 완성 편집본·사이트 적용 선택은 아니다. 도형별·이미지별 진입 방향을 세밀하게 제어할 수 있는지는 후속 연구 항목이다. 암전이 불안정의 원인이라는 가설은 여전히 미확정이다.

최신 [낱글자 낙하·자석 복귀 V4](prompts/05-grok-partner-earnings-gravity-magnet-v4.txt)는 [실제 결과 검토와 경험적 제어 범위](qa/video-review-gravity-magnet-v4-20260910/README.md)에서 핵심 동작 실패로 기록했다. 사용자는 배경 액션은 좋지만 의도와 다르다고 평가했다. 중앙의 회색 원본문구가 남은 채 추가 글자가 낙하하고, 개별 자석 복귀 대신 원래 문구가 다시 밝아졌다. 도형도 상단 완전 퇴장 없이 화면 안에서 회전·확산했다. 제작 기준은 사용자가 채택한 V3로 유지하고, 낱글자별 정밀 경로·동일성·순서 제어를 검증된 방식으로 취급하지 않는다.

## 바로 사용할 파일

후속 조사: [Seedance 2.5 / Higgsfield와 중간 참조 6장](research/seedance-2.5-higgsfield-20260910.md). 실제 모델 선택 화면과 공식 참조 기능, 공개 UI·타이포 모션 사례를 확인했다. 시간별 강제 키프레임 6개와 긴 문구의 낱글자 퇴장·복귀 성공은 미검증이며, 이번에는 참조 업로드·영상 생성을 실행하지 않았다. Grok의 실제 시험 기록과 별개로 보관한다.

기존 첫 프레임 PNG와 각 버전 프롬프트를 보존한다. 제작 기준은 V3이며 V4는 후속 경계 확인에 참고할 실패 시험이다. 사용자는 결과를 이 이미지의 영상이라고 제공했지만 실제 입력 프롬프트 전문은 확인하지 않았다. 에이전트는 Grok 영상 생성을 제출하지 않았다.

V2는 0~1.3초 전면 가림, 1.3~2초 완전 검정, 2~3초 원래 타이틀 한 묶음의 재등장, 3~6초 판독 구간을 요청한다. 후반 4초는 등장 1초와 판독 3초를 합친 편집 후보이며 4초 전체가 정지 판독 구간이라는 뜻은 아니다. 실제 시간과 완전 가림은 결과로 검증하고, 편집 시작점은 실제 가려진 프레임을 기준으로 정한다.

V3의 시간 목표는 0~0.6초 첫 화면 유지 → 0.6~1.6초 실제 요소 퇴장 → 1.6~1.9초 원래 배경만 유지 → 1.9~3초 동일 요소 복귀 → 3~6초 판독이다. 퇴장·복귀 시 글자 분해와 복제는 금지하고, 판독 구간에는 글자를 고정한 채 주변 도형만 움직인다. 첫 화면 유지 시간과 전환 방식이 함께 바뀌므로 결과가 개선되어도 암전만을 원인으로 단정하지 않는다.

V4의 시간 목표는 0~0.6초 첫 화면 유지 → 0.6~1.7초 낱글자 하단 퇴장·도형 상단 퇴장 → 1.7~2초 빈 배경 → 2~3.5초 낱글자 자석 복귀·도형 위에서 복귀 → 3.5~6초 판독이다. 판독 목표는 `6 - 3.5 = 2.5초`이며, 후반 약 4초에는 복귀 과정도 포함된다. 낱글자 이동, 반대 방향, 도형별 경로가 함께 바뀌는 표현 가능성 시험이므로 단일 변수 비교로 취급하지 않는다.

## 정확한 화면 문구

첫 줄: PARTNER EARNINGS  
둘째 줄: AUTO-CALCULATED & RECORDED

두 줄 구성을 유지한다. 정산 의미는 파트너 수익금 자동 계산과 기록이며, 송금·지급 완료를 표현하지 않는다.

## 이미지 생성과 검수

Codex 내장 imagegen에 [이전 C 시험 이미지](../titan-grok-type-stress-20260910-144248/results/01-titan-solution-start.png)를 실제로 첨부했다. 파란 리본·은색 링·유리 패널·흰색 타이포 스타일을 유지하고 제목을 교체했다. 첫 줄보다 긴 둘째 줄은 크기를 줄여 한 줄 안에 담았다.

1회 생성, 1장 저장, 실패 0, 정지 입력 검수 통과 1, 사용자 승인 0. 실제 출력은 PNG RGB **1916 × 821**, 약 21:9, 1,245,904바이트다. 리사이즈·크롭·형식 변환은 하지 않았다. 기본 생성 위치에서 이번 실행 폴더로 이동했고 전후 SHA-256 일치를 확인했다.

육안으로 두 줄 철자, 하이픈, 앰퍼샌드, 문구 잘림과 가림을 확인했다. [정지 검수 기록](qa/static-review.json)과 [실행 기록](run.json)을 함께 보관했다.

## 영상 시험의 의도

- 0~1.5초: 서로 반대 방향으로 강한 이동·복귀. 초반의 잠깐 가림·프레임 밖 이동은 허용.
- 1.5~3초: 단어 묶음이 움직인 뒤 원래 두 줄로 정렬. 이전 C 시험의 글자별 분해를 단어별 이동으로 변경.
- 약 3~6초: 정확한 전체 문구가 읽히는 구간 확보. 배경 도형은 주변에서 계속 움직임.

이는 프롬프트에 요청한 동작이며 실제로 달성한 결과가 아니다. 긴 문구, 움직이는 단위, 회복 시점이 함께 바뀌므로 성공·실패 원인을 한 변수로 단정하지 않는다.

## 결과 검토와 다음 확인

실제 영상에서 선명한 두 줄 표기는 확인했다. 다만 중앙 본문이 계속 남아 있으므로 이를 단어별 재조립 성공으로 설명하지 않는다. 후반의 링 가림 때문에 원래 목표인 연속 약 3초의 무가림 구간도 확보됐다고 판정하지 않았다. 더 짧은 후보 구간과 다음 수정 방향은 위 검토 문서에 기록했다. 다음에는 완전히 가려지거나 비워진 시작점과 이후 재등장, 정확한 문구, 실제 사용 구간을 함께 검수한다.

이 시험은 [12초 전체 텍스트 검토안](../../.agents/skills/theme-image-pipeline/references/titan-type-story-20260910.md)의 장면 04만 먼저 진행한 것이다. 나머지 장면, 완성된 12초 편집, 사이트 적용은 이번 범위에서 실행하지 않았다.
