아래는 제공된 시험 영상들의 결과에 근거한 작업 판단이다. Grok 전체의 보편적 가능·불가능 목록이나 성공률 추정이 아니다. 일부 파일은 매우 유사한 저장본이어서 독립 생성 횟수도 확정할 수 없다.

핵심 경계는 단순히 ‘액션이 크고 복잡한가’보다 **움직이는 동안 개별 요소의 정체성·개수·문자·순서·좌표를 얼마나 정확히 유지해야 하는가**로 보는 편이 현재 관찰을 더 잘 설명한다. 이는 출력 패턴에 대한 추론이며 모델 내부 동작 원인을 입증한 것은 아니다.

추상 도형은 변형·증식이 매력적인 연출로 받아들여질 수 있지만, 글자는 같은 변화가 철자·중복 오류가 된다. 배경 모션의 시각적 성공을 글자별 정밀 제어 능력의 증거로 쓰지 않는다.

## 암전 가설과 다음 작업 판단

V4는 암전 없이 시작했지만 원본문구 잔류·추가 글자 효과가 다시 나타났다. 따라서 암전 제거만으로 이 문제가 해결된다는 설명은 지지되지 않는다. 암전이 품질에 전혀 영향을 주지 않는다고 입증한 것도 아니다. V3→V4에서 이동 단위·방향·경로·타이밍이 함께 바뀌어 특정 한 요인을 원인으로 확정할 수 없다.

- **실사용 기준:** 사용자가 채택한 V3의 완성 화면 → 실제 퇴장 → 빈 배경 → 복귀를 유지하고, 큰 방향·속도감·도형 움직임을 중심으로 설계한다. 결과를 보고 실제 편집 지점을 정한다.
- **경계를 좁히는 다음 시험 제안:** V3와 같은 나머지 조건에서 텍스트 이동 단위만 두 줄 전체 → 각 줄 → 단어 묶음 → 낱글자로 단계적으로 나눈다. 도형의 반대 방향까지 동시에 바꾸지 않는다. 이는 아직 작성·생성하지 않은 시험 제안이다.
- **약속하지 않을 것:** 금지 문구를 더 많이 쓰거나 프롬프트를 길게 만들면 낱글자의 동일성·경로·시점을 정확히 제어할 수 있다는 보장은 없다. 현재 V4를 낱글자 애니메이션의 검증된 제작법으로 채택하지 않는다.
