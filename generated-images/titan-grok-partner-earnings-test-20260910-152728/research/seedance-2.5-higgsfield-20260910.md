# Seedance 2.5 / Higgsfield 모션그래픽 조사

조사일: 2026-09-10. 범위: 사용자 제안인 ‘중간 상태 참조 이미지 6장으로 원하는 모션그래픽을 한 번에 생성’의 기능·공개 사례 확인. 여기서 원샷은 생성 1회로 완성 클립을 얻는 의미로 해석했다. 이미지 6장을 새로 만들거나 업로드하지 않았고, 영상 생성·결제·기존 초안 수정은 실행하지 않았다.

## 판단

Seedance 2.5를 다음 시험 대상으로 삼을 근거는 충분하다. 이미지 기반 UI·타이포그래피 모션 제작 사례가 있으며, 다중 참조와 시간 구간 지시를 지원한다. 그러나 ‘이미지 6장이 지정 시각의 정확한 키프레임이 된다’거나 ‘TITAN의 긴 두 줄을 글자별로 낙하·복귀시키는 동작이 첫 생성에 정확히 구현된다’는 근거는 확인하지 못했다. 동일 조건의 Grok/Seedance 비교 생성도 하지 않았으므로 개선 폭·성공률·점수를 제시하지 않는다.

## 기능: 확인된 범위와 미확인 범위

| 항목 | 확인 결과 | 의미 |

| 출시와 모델 | ByteDance가 2026-07-31 출시를 발표. 현재 Higgsfield 생성 화면에서도 Seedance 2.5 선택 상태 확인 | 실제 사용 가능한 조사 대상 |
| 한 번에 생성할 길이 | ByteDance 공식 최대 30초 | 현재 짧은 동작 시험과 전체 홍보 영상 후보를 한 생성에 담을 수 있는 길이. 완성도 보장은 아님 |

| 시간 지시 | 생성 단계에서 시간 구간별 행동·카메라·리듬을 프롬프트로 지정한다고 설명 | 특정 구간의 연출 지시는 가능. 참조 이미지와 해당 출력 프레임의 픽셀 일치 보증은 확인되지 않음 |

| 해상도 | 현재 Higgsfield 선택창은 480p·720p·1080p를 표시 | UI의 출력 선택지까지 확인. 실제 결과의 네이티브 해상도·업스케일 여부는 미검증 |

기능의 근거: [ByteDance 출시 발표](https://seed.bytedance.com/en/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5), [실제 확인한 Higgsfield 생성 페이지](https://higgsfield.ai/ai/video?model=seedance_2_5).

Higgsfield 최신 안내의 참조 번호는 인물·제품·장소 등의 역할을 연결하는 표기다. 번호 자체가 시간 순서를 뜻하지 않는다. 이미지 6장을 중간 상태로 쓰려면 각 이미지가 어느 단계인지 따로 지정해야 한다. 최신 두 안내에서도 여섯 장의 시간별 강제 키프레임 기능은 확인하지 못했다. [8월 6일 사용 안내](https://higgsfield.ai/blog/seedance-2-5-on-higgsfield-2026), [8월 13일 프롬프트 가이드](https://higgsfield.ai/blog/seedance-2-5-prompting-guide).

Dreamina 공식 안내에는 최대 10개 참조 프레임과 사용자 지정 지속시간을 쓰는 별도 Multiframes 도구가 언급된다. 이것이 Higgsfield에서도 제공되거나, Seedance 단일 생성에서 모든 중간 프레임을 강제한다는 근거는 아니다. ‘중간 프레임 기능이 어디에도 없다’고 단정하지 않는다. [Dreamina 안내](https://dreamina.capcut.com/seedance/seedance-2-5-prompt).

## 공개 모션그래픽 사례

### Zane Hoyer, 2026-08-07

[원본 제작 영상](https://www.youtube.com/watch?v=JNTLEj46KPI)의 설명과 자동 자막을 읽고 일부 구간을 브라우저에서 재생·탐색해 확인했다. 자동 자막에는 모델명·일부 단어의 전사 오류가 있어 실제 제목·화면과 구분했다. 추천 링크가 포함된 제작자 사례이며 독립적인 전수 평가가 아니다.

- 약 2:06–2:31: 한 장에서 UI 막대의 상승과 커서 클릭을 지시하는 과정을 설명한다.
- 약 2:49–3:10: 사진 카드의 바운스 등장과 연결선을 지시하고 결과를 제시한다.
- 약 3:31–3:50: 위젯 등장과 짧은 문구의 글자별 등장을 설명한다. 직접 확인한 약 3:48·3:50 화면에서 카드 내부 제목·본문·버튼이 읽혔고 손글씨 라벨의 등장 상태가 달랐다. 모든 프레임의 철자·형상·속도를 전수 검수한 것은 아니다.
- 약 4:13–4:32: 체스 말의 회전과 짧은 문구의 등장을 설명한다. 이 구간은 설명 근거로만 사용하며 회전 궤적을 직접 검수했다고 하지 않는다.
- 약 4:33 이후: 여러 스타일 참조를 함께 넣는 방식을 설명한다. 여섯 개 시간 고정 중간 프레임의 성공 증거로 세지 않는다.

이 사례는 단순한 추상 배경 이외에도 UI·읽히는 문구를 포함한 모션 제작이 가능함을 뒷받침한다. 긴 두 줄의 모든 글자가 원본 위치에서 출발해 화면을 벗어나 각자의 자리로 돌아오는 조건은 별개다.

## 제안: 여섯 장을 준비한다면

아래는 아직 실행하지 않은 제작 제안이다. 기존 V4 동작을 유지한 시험용이며, 전체 홍보 영상의 확정 콘티가 아니다.

1. 원래 두 줄 타이틀과 도형이 모두 보이는 시작 상태.
2. 글자는 아래로 떨어지고 도형은 위로 퍼지는 진행 상태.
3. 모든 전경 요소가 화면 밖으로 나가 원래 배경만 남은 상태.
4. 글자는 아래에서, 도형은 위에서 복귀하는 진행 상태.
5. 각 글자가 원래 자리 근처까지 돌아온 상태.
6. 정확한 두 줄과 도형 배치가 복원된 판독 상태.

여섯 이미지는 같은 화면 비율·카메라·폰트·문구·색·도형 수를 공유하고 동작 상태만 달라야 비교하기 쉽다. 각 이미지의 단계와 그 사이의 이동 방향·순서를 별도로 지시한다. 참조 추가만으로 결과를 고정했다고 기록하지 않는다.

첫 시험에서는 전체 홍보 영상보다 기존 긴 문구 한 장면의 출발·완전 퇴장·복귀·판독을 평가하면 제어 범위를 빠르게 확인할 수 있다. 전체 영상을 한 번에 만드는 접근을 부정하는 의미는 아니다. 생성 1회로 얻었는지와, 원하는 동작·정확한 문구가 같은 연속 구간에 들어 있는지를 각각 확인한다. 여러 번 생성해 고른 결과를 첫 생성 성공으로 기록하지 않는다.

이미지 여섯 장으로 경로·리듬 전달이 부족하다면 간단한 모션 가이드 영상도 다음 참조 방식으로 비교할 수 있다. ByteDance는 동작·화이트 모델 영상 참조를 공식 지원한다. 정지 이미지보다 시간·방향 정보를 직접 전달할 수 있다는 것은 제작상 추론이며, TITAN 낱글자 제어의 검증된 해법은 아니다. [모션 참조 설명](https://seed.bytedance.com/en/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5).

## 출처 불일치와 검증 범위

- 일부 Higgsfield 블로그는 참조 이미지 50장으로 표현하지만 ByteDance 공식은 이미지 30장·전체 멀티모달 50개를 구분한다. 이 조사에서는 ByteDance의 구분을 사용했다.
- [BytePlus LAS 문서](https://docs.byteplus.com/en/docs/byteplus_las/video_gen_enhanced)는 해당 2.5 API의 출력 규격을 480p/720p로 설명하지만 실제 Higgsfield UI에는 1080p가 있었다. 위의 최신 Higgsfield 블로그 두 편은 네이티브 1080p라고도 설명한다. 서비스별 출력과 네이티브 규격을 동일시하지 않으며 실제 파일과 해당 서비스의 기술 안내로 확인해야 한다.
- [Higgsfield의 모델 비교 글](https://higgsfield.ai/blog/ai-video-prompt-adherence-comparison)은 문자가 흐려졌다는 표와 읽을 수 있는 글자를 금지하는 공개 프롬프트가 함께 있어, 이 표를 타이포그래피 성능의 결정적 근거로 채택하지 않았다.
- [Higgsfield의 AI vs VFX 제작기](https://higgsfield.ai/blog/ai-vs-vfx)에는 실패 후 I2V로 전환하고 샷을 편집한 과정이 포함된다. 모든 복잡한 장면의 원샷 성공을 입증하는 자료로 취급하지 않는다.
- 이번 확인은 공식 문서·최신 안내·실제 생성 UI·원제작자의 일부 화면과 설명에 한정된다. 생성 원본 전수 검수, 여섯 장 직접 입력, 비용·반복 성공률 측정은 하지 않았다.
- 기존 Grok 결과·프롬프트·첫 프레임·사이트 소스는 보존했다. 기존 [V3 방식 채택](../qa/video-review-offscreen-v3-20260910/README.md)과 [V4 실패 기록](../qa/video-review-gravity-magnet-v4-20260910/README.md)을 Seedance의 검증 결과로 옮기지 않는다.
