# Titan 이미지 생성 방식 감사와 수정

## 결론

확인된 문제는 사용자 목적과 시각적 참조를 프롬프트로 옮기는 과정에서 중요한 정보가 약해지고, 필요 없는 금지가 더해졌으며, 기술 검사를 통과한 결과를 실사용 후보로 추천한 판단이다. 프롬프트 길이나 Codex/일반 채팅의 내부 모델 차이가 원인이라고 입증된 것은 아니다.

이번 작업은 기존 제출 프롬프트·결과·검수 기록을 읽고 제작 규칙을 수정했다. 새 이미지·영상은 생성하지 않았고 현재 사이트와 기존 생성물은 변경하지 않았다.

## 사용자가 제공한 비교 조건

사용자 원문:

> 이 사이트의 우측 하단의 회색 부분에 들어갈 이미지가 필요합니다. 스톡사진같은 느낌이 나지않게 세련된 실제 사진느낌의 이미지 입니다. 개발실의 프로그래머 기획자들의 모습, 상담원의 모습, 기술담당자가 회의를 진행하는 모습 아이디어 회의를 하는 모습의 4가지 이미지를 각각 생성하세요 인물은 동양계 인물로 하고 이미지는 최대한 세련된 화보형태의 고품질 이미지로 생성하세요

사용자는 사이트 상단 화면도 참조로 첨부했다고 설명했다. 당시 첨부한 사이트 화면의 정확한 파일은 이 감사에 제공되지 않았으므로 그 입력을 완전히 재현했다고 주장하지 않는다.

추가로 제공된 [4장면 비교 이미지](sources/user-four-scene-reference.png)에는 개발 화면 공동 검토, 태블릿을 설명하는 회의, 헤드셋 상담, 보드 앞 설명이 구분된다. 이는 비교용 한 파일이며 네 개의 독립 출력 파일이 검증됐다는 의미는 아니다. 앞서 로컬 사이트에 적용한 네 개의 개발 협업 사진과 다른 자료다.

이전에는 사용자가 밝기, 개성 있는 얼굴, 동양계 인물, 사진별 독립성 등을 직접 요청했다. 그 지시를 따르는 것과 사용 목적을 놓치는 것은 다른 문제다. 새로운 어두운 사무실 사진이 좋다는 이유로 앞으로 모든 사진을 어둡게 만들거나 같은 팀으로 묶는 규칙을 추가하지 않았다.

## 검증 범위

`quick_validate.py`의 스킬 구조 검증을 통과했다. 문서 안의 로컬 참조 연결도 검사했다. 원인 분석에 참여하지 않은 독립 검토자에게 수정된 스킬과 다음 세 요청을 제공했다. 의도한 정답은 알려주지 않았다.

- 사이트용 네 업무 사진: 사이트 화면을 참조로 사용하고 개발·상담·기술회의·아이디어회의의 행동을 분리했다. 독립된 스타일을 허용하면서 사용 맥락을 유지했다.
- 사이트와 무관한 작가 소개용 단독 초상: Titan·업무 소품·회의를 요구하지 않고 얼굴의 인상을 중심으로 판단했다.
- 기존 COBALT 첫 프레임에 중앙 기준 15% 확대: 파일과 비율은 정상이어도 폰 상하단의 잘림을 발견해 준비 완료를 보류했다. 중앙 확대의 원본 보존 경계는 `(1−1/1.15)÷2 ≈ 6.52%`이며, 이미지의 실제 여백은 충분하지 않았다.

이 검증은 잘못된 목적 치환과 섣부른 합격을 줄이는 절차 검증이다. 새로운 생성 결과의 품질 향상이나 특정 도구의 우열은 아직 검증하지 않았다. 다음 생성에서 실제 결과를 같은 기준으로 확인해야 한다.
