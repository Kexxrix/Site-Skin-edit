# TITAN 히어로 영상 인계

작성 상태: 네 첫 프레임을 직접 확인하고 모션 프롬프트를 준비했다. Grok에서 실제 영상을 생성하거나 결과를 검수한 상태는 아니다. 사이트 적용도 이번 문서 범위에 포함되지 않는다.

## 바로 사용하는 순서

1. 아래 씬에 해당하는 **최종 첫 프레임 파일 한 장**을 Grok Imagine에 첨부한다.
2. 같은 번호의 `*-grok.txt` 파일 전체를 복사해 모션 프롬프트로 사용한다.
3. 생성된 영상의 시작 4초를 확인한다. 동작이 약 3.2초까지 끝나고 나머지가 정지 상태인 구간을 목표로 한다.
4. 기기·화면 내용·정산 기록판 보존을 확인한 뒤 후반 편집에서 자막을 얹는다. 음성·음악·효과음이 생성되었다면 편집에서 오디오를 제거한다.

**4초는 편집에서 사용할 목표 구간이다.** Grok 웹 UI에 정확히 4초 길이 선택이 제공되는지는 확인하지 않았다. 더 긴 영상이 생성되어도 첫 4초 안에 동작을 마치고 이후에는 유지하도록 프롬프트를 작성했다. 약 3.2초 종료와 아래 이동량은 모델에 주는 목표이며 실제 준수가 확인된 수치가 아니다.

## 첫 프레임별 확인 내용

- **01:** 오른쪽 태블릿에 실제 CAT 화면과 고양이 캐릭터가 합성되어 있다. 기기 전체와 왼쪽 여백을 유지한다. 고양이·꼬리·게임 카드·문자까지 화면 안의 모든 요소를 정지 이미지로 보존한다.
- **02:** 실제 COBALT 경기 목록 화면을 휴대폰 비율로 크롭해 합성한 이미지다. 새 모바일 UI를 생성한 결과로 설명하지 않는다. 화면 경계에서 잘린 원본 내용도 임의로 복원하거나 추가하지 않는다.
- **03:** 세 층의 프로스트 유리와 무문자 흰 줄을 직접 확인했다. 계산이 끝난 결과를 기록·정렬한다는 은유다. 실제 백오피스 화면이나 송금 완료 장면으로 표현하지 않는다. 판마다 화면상 폭과 원근이 다르므로 좌우 이동으로 중앙 기준선을 맞추되, 모서리 전체를 억지로 일치시키는 변형은 요구하지 않는다.
- **04:** 실제 UI가 합성된 최종 `derived/04-products-start.png`를 확인했다. 태블릿은 왼쪽, 휴대폰은 오른쪽이며 기기 상단 높이와 바닥선이 안정된 정면 구성이다. **빈 화면인 `results/04-products-plate.png`는 Grok에 첨부하지 않는다.**

모션·첨부 상태: 01·02·03·04 모두 첫 프레임 확인 완료, 프롬프트 준비 완료. 처음 보류했던 03·04도 현재 파일로 확인을 마쳤다.

## 자막과 사운드

자막은 Grok에 생성시키지 않고 편집 프로그램 또는 이후 사이트 텍스트 레이어에서 넣는다. 각 씬에서 자막은 약 00:00.3–00:03.8 사이 읽히도록 두는 것을 편집 시작점으로 삼는다.

- 01은 왼쪽 여백, 02는 오른쪽 여백을 활용한다.
- 03은 기록판을 가리지 않는 위쪽 여백을 활용하고 보조 문구를 함께 둔다.
- 04는 제품 위쪽 여백에 `TITAN SOLUTION`을 둔다.
- 최종 히어로가 원본 16:9보다 가로로 긴 비율이면 위아래가 잘릴 수 있으므로, 실제 표시 크롭을 보고 자막과 제품의 안전 영역을 확인한다.
- 무음 히어로다. 영상에 별도 오디오가 포함되더라도 최종 편집에서 제거한다.

## 생성 후 통과 기준

01·02·04의 화면 고정은 **내용과 화면 내부 상대 배치를 유지한다는 의미**다. 카메라 이동에 따라 화면 전체의 크기·위치·원근은 변할 수 있다. 화면을 영상 좌표의 같은 픽셀 위치에 묶어 두라는 뜻은 아니다.

- 모든 순간에 기기 전체가 프레임 안에 있고 베젤·모서리·화면 평면이 변형되지 않아야 한다.
- 실제 UI의 글자·숫자·스코어·배당률·아이콘·카드·고양이가 바뀌거나 살아 움직이면 해당 클립은 보존 조건 미달이다.
- 03은 끝까지 판이 세 장이어야 하며, 흰 줄과 재질을 유지하고 한 번만 정렬해야 한다. 돈·송금·지갑·통화 기호·새 UI를 추가하면 안 된다.
- 첫 4초에 필요한 동작이 끝나는지, 정지 구간에서 떨림·형태 변화가 없는지 확인한다.
- UI 보존이 실패하면 해당 생성 클립을 그대로 채택하지 않는다. 원본 첫 프레임의 실제 UI를 유지하는 외부 편집의 단순 확대·이동 효과가 대체 방법이다.

## 공식 자료와 확인 범위

xAI의 image-to-video 문서는 원본 이미지와 프롬프트를 받아 움직임을 생성하는 방식을 설명하며, 예제에는 API의 `duration` 인자가 있다. 이 API 예제에서 Grok 웹 UI의 정확한 4초 선택 기능을 추론하지 않았다. [xAI Image-to-Video 문서](https://docs.x.ai/developers/model-capabilities/video/image-to-video)

Grok의 공식 영상 안내는 장면·행동·카메라 움직임·분위기를 자연어로 지정하는 방식을 설명한다. 여기서 사용한 움직임과 시간은 첫 테스트를 위한 제작 지시이며, 화면 보존이나 정확한 타이밍 성공을 공식 보장으로 해석하지 않는다. [Grok 공식 영상 생성 안내](https://x.ai/grok/use-cases/video-generation)

공식 페이지 확인일: 2026-09-09. 실제 Grok 웹 UI의 현재 길이 설정, 생성 결과 품질, 최종 영상 파일, 사이트 적용은 아직 검증하지 않았다.
