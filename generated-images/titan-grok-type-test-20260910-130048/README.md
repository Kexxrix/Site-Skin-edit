# Grok 텍스트 모션 시험과 짧은 컷 제작 계획

2026-09-10. 현재 상태: 공개 근거 조사·시작 이미지 정지 검수 완료 / 사용자가 제공한 A 영상 3개 검토 완료 / B 미검증. [A 영상 결과와 의도 비교](qa/video-review-20260910/README.md)를 따른다. 아래는 최초 시험 준비 시점의 계획이며, 실제 결과를 합격으로 미리 간주하지 않는다.

## 현재 사용자 방향

6초 단일 영상 세 개를 각각 4초씩 사용하는 계획에서 변경한다. 짧은 문구·제품·패널·도형 등 다양한 장면을 6초 후보로 만들고, 실제 결과에서 쓸 만한 연속 2~3초를 선택한다. 최종 12초 컷 편집은 사용자가 직접 한다. 이 실행에서는 테스트 입력 한 장과 비교 프롬프트 두 개만 준비하며, 대량 후보 영상은 텍스트 모션의 사용 가능성을 확인한 뒤 확장한다.

예를 들어 최종 5컷은 3+2+2+2+3=12초, 6컷은 2×6=12초다. 생성 후보 수는 최종 컷 수보다 많아도 된다. 통과 뒤 서로 다른 역할의 후보 6~8종을 먼저 검토할 수 있으나 확정 수량이나 실행 요청으로 간주하지 않는다. 메시지 세 개를 전달하더라도 메시지당 영상 한 개라는 제한은 없다.

## 이번 시험 입력

[시작 이미지](results/01-titan-type-start.png)는 Codex 내장 이미지 생성으로 만든 Grok 영상 입력이다. Grok의 정지 이미지 생성 성능을 시험한 결과가 아니다. 본 제작의 색·장식·로고 디자인을 확정하는 이미지도 아니다.

- 문구: 짧고 판독이 쉬운 영문 대문자 `TITAN` 한 단어.
- 이미지의 세 보조 요소는 이후 복합 모션 확장에 활용할 수 있다. 최초 A·B에서는 움직이지 않게 요청해 글자 동작을 분리해 본다.
- [기존 사이트 화면](../titan-four-scenes-retry-20260909-195824/qa/adopted-20260910/after-desktop.png)은 브랜드 표기와 넓은 영상 사용 위치의 참조로 실제 첨부했다. 사이트 전체나 주황색 스타일의 복제는 요청하지 않았다.
- 실제 PNG는 1916×821px, 비율은 1916÷821≈2.33374로 약 21:9다. 출력 후 리사이즈·크롭·합성을 하지 않았다.
- 정지 검수와 해시·파일 검증은 [정지 검수 기록](qa/static-review.md), 경로·상태는 [실행 기록](run.json), 실제 이미지 프롬프트는 [원문](prompts/01-start-image.txt)에 보존한다.

## 프롬프트 설계 방법

입력 이미지가 이미 주는 글자·재질·구도는 보존 조건으로 짧게 지정한다. 영상 프롬프트의 중심은 **무엇이 → 어느 방향으로 → 어떤 속도와 순서로 → 어디에 멈추는지**다. 이번 A·B는 같은 이미지, 같은 배경, 고정 카메라, 같은 목표 길이를 사용하며 문구의 동작 방식만 바꾼다.

초 단위 표현은 목표 진행을 전달하는 자연어 지시다. 편집 프로그램의 키프레임이나 API 정밀 시간 제어로 설명하지 않는다. 프롬프트가 길수록 잘 된다고 가정하지 않으며, 모호한 '화려하게' 대신 확인할 동작을 쓴다.

처음부터 문구가 보이는 원본이므로 '0초에는 글자가 없는 화면'과 같은 상충 지시를 넣지 않는다. 최초 B는 **보이는 글자의 시차 동작 후 재정렬**을 평가한다. 완전히 없던 글자의 순차 등장까지 검증한 것으로 기록하지 않는다.

## A·B 실행 방법

같은 시작 이미지 원본을 매번 다시 첨부해 별도 생성한다. A의 생성 결과를 B의 참조로 넘기지 않는다. 사용자 Grok 화면에서 6초를 선택할 수 있으면 선택하고, 입력 이미지 비율을 유지하는 옵션을 사용한다. 실제 선택 가능 모델·옵션과 반환 MP4의 길이·비율은 결과를 받을 때 기록한다. 이번에는 Grok에 제출하지 않았다.

| 시험 | 복사할 프롬프트 | 확인할 차이 |
| --- | --- | --- |
| A | [단어 전체 이동](prompts/02-grok-a-word-motion.txt) | 철자·글자 간격·기준선을 유지하며 전체가 실제로 좌우 이동하는가 |
| B | [글자별 시차 동작](prompts/03-grok-b-letter-motion.txt) | 다섯 글자가 왼쪽부터 시차를 두고 위로 움직였다가 제자리로 돌아오는가 |

두 시험 모두 첫 약 3초 안에 주요 동작을 끝내고 나머지 시간에는 읽을 수 있는 문구를 유지하도록 요청한다. 6초 전체를 최종 편집에 사용하거나 정확히 3초에 자를 필요는 없다. 각각 한 번 비교한 뒤 결함에 맞는 한 변수 수정 여부를 결정한다. 한 번의 성공은 보편적 재현성의 증거가 아니다.

## 결과 판정

1. **정지 입력 합격:** 정확한 철자·여백·판독성. 이번 생성은 이 범위만 통과했다.
2. **동작 합격:** A의 전체 이동 또는 B의 개별 시차 움직임이 실제로 보이는지, 최종 철자·순서·형태가 보존되는지 확인한다. 빛만 변하거나 정지 상태를 유지한 결과는 모션 합격이 아니다.
3. **편집 구간 확보:** 요청한 동작과 읽히는 메시지가 포함된 연속 2~3초를 타임코드로 표시한다. 멀쩡한 정지 구간만 존재하면 '텍스트 유지 가능 / 원하는 모션 미달'로 기록한다.
4. **실제 사용 크기:** 선택 구간에서 사이트의 넓은 표시 영역과 모바일 크롭·축소 시 문구가 남고 읽히는지 확인한다. 원본 해상도에서만 보고 최종 사용 가능으로 판정하지 않는다.
5. **검증 범위:** 전체 재생으로 리듬을 보고, 프레임시트로 변형 위치를 찾는다. 문제 구간은 더 촘촘히 확인한다. 드문 프레임 샘플만으로 모든 프레임의 무결성을 주장하지 않는다.

기록값: 입력·프롬프트·표시된 모델·선택 옵션·실제 파일 길이/크기·전체 클립 결함·사용 가능 in/out 구간·해당 구간 동작/문구 판정·편집 시 주의점·생성/에이전트 선별/사용자 채택 상태.

## 통과 뒤 다양성을 늘리는 방식

먼저 통과한 동작에 리본·패널·도형 움직임을 더한 복합 시험을 한다. 텍스트 보존, 주연의 크기와 배경 대비 등 몇 가지 연결 요소는 유지하되 모든 컷을 같은 소재와 구도로 복제하지 않는다.

그 뒤 브랜드 타이포, 핵심 메시지 타이포, 태블릿 제품 공개, 휴대폰 제품 공개, 시스템 연결을 설명하는 연출 그래픽, 패널 전환, 로고 마무리 등 서로 다른 역할을 가진 후보를 기획한다. 이 목록은 제안이며 실제 기능이나 미제공 제품 UI를 꾸며내는 근거가 아니다. 각 6초 후보는 한 가지 핵심 시각 사건을 선명하게 보여주게 하고, 사용자가 2~3초씩 추려 전체 12초를 편집한다.

A만 통과하면 전체 단어 이동·가림 후 재노출 등의 후보를 우선 시험하고, B까지 통과하면 글자별 시차 동작으로 확장한다. 긴 문구·한글·작은 UI까지 자동으로 통과했다고 보지 않는다. 정확한 UI나 텍스트에서 실패한 경우에 한해 해당 부분의 별도 합성·편집을 검토하며 처음부터 사용자의 원샷 실험을 제외하지 않는다.

새 영상 생성, 대량 후보 생성, 최종 편집, 사이트 적용은 아직 수행하지 않았다.
