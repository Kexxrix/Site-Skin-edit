## 현재 사용자 지시와 변경 경계

사용자는 캐릭터가 알아볼 수 있고 레이아웃에 영향이 없으면 크게 배치하고 일부가 화면 밖으로 나가도 된다고 명시했다. 현재 캔버스에서 사용자가 이미 캐릭터를 x=-162, y=1086, 573×749로 확대한 것을 확인했으며, 그 배치와 크롭을 그대로 유지했다. 이전 실행의 '전체 실루엣 보존' 검수 기준을 이번 지시에 강제하지 않았다.

새 헤더 이미지를 생성해 적용하고 본문 배경은 불투명도만 낮췄다. 카드·버튼·로고·텍스트·간격·레이아웃·다른 테마·웹 코드는 변경하지 않았다.

## 새 헤더 이미지

- [실제 이미지](results/together-pink-fantasy-header-v1.png)
- [실제 프롬프트](prompts/header.txt)
- 생성: built-in image_gen 1회. 시도 1 / 성공 1 / 실패 0 / 건너뜀 0 / 작업자 검수 통과 1 / Figma 적용 1.
- 기존 핑크 판타지 환경의 곡선 바위·아치·진주광 구체·블랙베리 명암을 반영했다.
- 프롬프트는 8:1 가로형 아트를 요청했으나 실제 출력은 PNG RGB 2172×724, 3:1이다. 파일은 추가 크롭·리사이즈하지 않았고 Figma에서 1920×88 헤더의 중앙 FILL 크롭으로 표시했다. 실제 잘린 결과를 검수했다.
- 원래 도구 출력 경로에서 이번 성공 파일만 프로젝트로 이동했다. SHA-256 전후 동일, PNG 실제 형식과 읽기를 확인했다. [검증 기록](qa/asset-move.json).
- 사용자 첨부 예시와 실제 페이지를 열람했으나 생성 입력에는 이미지를 첨부하지 않았다.

## 적용 수치

| 대상 | 이전 | 현재 |
|---|---|---|
| 본문 배경 IMAGE 불투명도 | 80% | 38% |
| 헤더 | 기존 단색 채움 | 기존 단색 + 새 IMAGE 채움 60% |
| 헤더 크기 | 1920×88 | 동일 |
| 캐릭터 위치·크기 | x-162 y1086 / 573×749 | 동일 |
| 캐릭터 이미지·불투명도 | 기존 투명 PNG / 100% | 동일 |

헤더는 원본 인스턴스를 유지한 채 배경 채움만 덧붙였다. 기존 숨겨진 GoldFlow 이미지와 하위 기능 요소도 보존했다. 새 노드 생성은 없다.

1920px 전체 화면과 1920×88 헤더 확대를 확인했다. 캐릭터 얼굴과 특징은 왼쪽 크롭 이후에도 식별되며 콘텐츠 가림을 추가하지 않았다. 헤더의 풍경이 보이고 로고·공지·퀵링크·회원 버튼이 구분된다. 본문 배경의 존재감을 낮춰 캐릭터와 콘텐츠의 대비를 유지했다.

배경 레이어를 제외하고 헤더의 의도한 채움 변경만 정규화한 원본 UI 해시는 전후 3eab0228로 동일하다. 기존 인스턴스 94개 유지, 캐릭터 이미지·위치·크기 보존, 다른 화면 11개와 공유 마스터 44개의 해시·캔버스 위치 불변을 확인했다. 기존 생성 이미지 파일은 덮어쓰기하거나 다시 생성하지 않았다.

생성·작업자 검수·Figma 적용은 완료됐으나 이번 수정 결과에 대한 사용자 최종 승인과 웹 채택·배포는 기록하지 않는다. 웹 반응형 동작은 이번 범위가 아니다.
