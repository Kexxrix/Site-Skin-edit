## 3. 제작 캔버스와 프레임 계약

2400 × 1024, 픽셀비 1:1, 30fps, 무음. 프레임은 0부터 시작하며 구간의 끝 번호는 제외한다. 모든 표의 프레임은 마스터 절대 프레임이다. 프리컴프의 시작 시간을 옮겼다면 내부 시간과 마스터 프레임의 변환을 명시하고, 프리컴프 내부 F250과 마스터 F250을 혼동하지 않는다.

## 4. 공통 제작 방식

가이드 PNG는 비교·정렬용으로 잠그고 출력에서 제외한다. 글자는 편집 가능한 네이티브 Text, 면·선·마스크는 네이티브 Shape/Mask, 제품은 실제 3D 모델과 원본 영상으로 구성한다. 기존 Pretendard 계열의 무게와 폭을 이어 쓰고, refined의 기울기는 가이드처럼 유지한다. 적용한 실제 폰트와 기울기 구현을 기록한다.

CAT VILLAGE→06의 스크롤, 5의 면 정렬, 6의 오버레이·레일은 따로 구성해 조절 가능하게 한다. 08씬은 배경·마스크·양쪽 레일·문구를 모두 포함하는 하나의 전체 컨테이너로 이동해야 한다. 초기 600% 확대에서도 타이포·선이 흐려지지 않도록 네이티브 벡터의 래스터화·프리컴프 동작을 실제 렌더로 확인한다.

새 씬에 이징과 모션블러를 적용한다. 기존 마스터 전역 설정을 바꿔 기존 제작 구간의 결과가 달라지지 않도록 새 씬/컨테이너에 범위를 한정한다. 설정 변경이 필요하면 앞부분 비교 렌더로 영향이 없음을 확인한다. 카메라·3D 모션은 06씬 제품에 필요한 범위에 한정한다.

## 5. CAT VILLAGE→06: 같은 도트·경로를 따라 아래로 스크롤

실제 기존 마지막 화면은 [F170](../qa/actual-scene03-F170.png)이다. 현재 마지막 선분은 (2040,750)→(2120,830)의 짧은 대각선이다.

- F164~170: 마지막 부분을 중심 (2040,830), 반지름 80의 오른쪽→아래 방향 90도 곡선으로 보정한다. 시작 (2040,750), 끝 (2120,830)을 유지한다. 베지어 접선은 시작 out=(44.18278,0), 끝 in=(0,-44.18278)을 초기값으로 쓴다. 끝 방향은 수직 아래다.
- 기존 공용 선의 전체 길이나 pointOnPath 매개변수가 달라지면 이전 구간의 도트까지 움직일 수 있다. F164 이전에는 기존 식·경로 평가 결과를 그대로 유지하는 방식으로 분기하고 실제 비교한다.
- F171~180: CAT VILLAGE 구간 원점 Y=0, 06씬 원점 Y=1024인 공통 공간을 Y=0→-1024로 이동한다. 화면은 아래로 내려가고 기존 CAT VILLAGE 구간은 위로 빠진다. CAT VILLAGE 구간의 마지막 자세를 유지해 퇴장 구간을 필요한 만큼 연장한다.
- 도트는 (2120,830)에서 같은 경로를 따라 월드 Y=1760까지 내려간 뒤, 중심 (2240,1760)·반지름 120의 곡선을 지나 (2240,1880)에 도착한다. 스크롤 완료 후 화면 좌표는 (2240,856)이다.
- 스크롤과 경로 진행률은 같은 q=6u^5−15u^4+10u^3, u=clamp((F−171)/9,0,1)을 사용한다. 기존 CAT VILLAGE 구간 도트가 사라진 뒤 06씬 도트가 다른 위치에서 새로 생기지 않는다. 선 끝·도트·접선의 연속성을 렌더로 확인한다.
- 06씬에는 왼쪽 아래 커브를 다시 만들지 않는다. 최종 수정 가이드의 밝은 빈 공간, 왼쪽 세로 폰, 오른쪽 Sportsbook, 오른쪽 주황 경로를 유지한다.

F180~182에 짧게 정착하고 F182~220은 제품·타이틀 판독 구간으로 둔다. 이 구간에서 불필요하게 제품을 계속 흔들거나 큰 타이틀을 움직이지 않는다.

- [1.0초](qa/iphone-source-0100.png), [1.9초](qa/iphone-source-0190.png), [2.866667초 부근](qa/iphone-source-0287.png)을 실제로 확인했다. 원본 내 스크롤·내비게이션 강조 변화가 있으며 스포츠 카드 내용이 보인다. 가이드의 재생성된 작은 숫자·문구로 바꾸지 않는다.
- 실제 iPhone17.SCREEN 재질에 영상 컴프를 연결하고, 서로 다른 두 시점의 대응 원본/화면을 비교한다. 단순히 평면 영상을 폰 앞에 겹쳐 둔 상태나 회색 재질을 완료로 보고하지 않는다. 화면 안의 상단 상태바·녹화 표시를 포함한 원본 UI는 보존하고, 모델의 물리적 전면 부품과 겹쳐 보이는지 확인한다.

영상 소스는 332×720이라 작은 글자 품질에 한계가 있다. 원본 화질 한계를 명시하되 임의 AI 업스케일·UI 재제작으로 대체하지 않는다. 출력 오디오는 비활성화한다. 기존 아이패드 모델과 영상 연결은 보존한다.

## 7. 06→07와 07씬: 큰 면의 정렬, 배경 글자의 반대 이동

F220~222에 오른쪽 주황 도트가 짧은 가로 리본으로 늘어난다. F222~228에는 연결된 차콜 면이 오른쪽에서 왼쪽으로 화면을 덮고, 주황 리본이 07씬의 넓은 주황 면으로 이어진다. 새로 얇은 사각 테두리를 그리는 반복은 넣지 않는다.

07씬은 가이드의 넓은 면 세 개와 큰 외곽선 OPERATIONS가 화면 규모로 움직인다. 흰 면·차콜 중앙 면·주황 하단 면을 서로 다른 방향에서 들어와 정렬되게 만든다. 초기 범위는 F222~234이며 전경 문구를 읽는 F234에는 도착한다. 정확한 최종 윤곽·비중은 Operations 가이드를 따른다.

| 구간 | 동작 |
| --- | --- |
| F228~232 | Operations, 단어 블록 진입. 쉼표 보존. |
| F230~234 | refined가 짧게 가로로 늘어났다 정상 폭으로 정렬. 소문자·주황·기울기 유지. |
| F234~250 | 두 줄의 전경 문구를 읽게 유지. |
| F228~252 | 배경 외곽선 OPERATIONS 상단 줄은 왼쪽 24px/F, 하단 줄은 오른쪽 18px/F로 이동. 전경과 독립. |

배경 글자는 실제 단어 폭+간격을 한 주기로 복제하여 빈틈 없이 반복한다. BUILT를 넣지 않는다. 배경 레이어는 전경보다 낮은 대비로 유지한다. F250부터 위에 08씬이 겹쳐 들어올 때 07씬의 전체 컨테이너는 위치·크기를 유지한다.

## 8. 최우선: 07→08은 확대된 08씬 전체의 오버레이 줌아웃

사용자의 당시 가이드 묶음 번호를 사용한 설명: “6번째 씬을 5번째 씬 위에 확대해서 오버레이 하고 원래 사이즈로 이동하는 방식.” AE 마커 기준으로는 08씬 전체를 07씬 위에 확대 오버레이하는 동작이다.

실제로 이동하는 대상은 08씬 전체다. 07씬을 작은 카드로 축소하거나 SHIFT 칸 안으로 보내지 않는다. 08씬 네이티브 프리컴프가 07씬보다 위에 있어야 하며, 초기에는 확대된 왼쪽 상단 SHIFT 한 칸이 화면을 채운다.

| 속성 | F250~252 확대 오버레이 | F260 도착 |
| --- | --- | --- |
| 08씬 내부 기준 셀 | x=0, y=55, w=420, h=300 | 동일 |
| Anchor Point | (210,205), 계속 고정 | (210,205) |
| Position | (1200,512) | (210,205) |
| Scale | (600%,600%) | (100%,100%) |
| Opacity | F250=0 → F252=100 | 100 |

F252~260의 u=clamp((F−252)/8,0,1), q=6u^5−15u^4+10u^3.

Scale = (6−5q)×100%, Position = (1200−990q, 512−307q). Scale과 Position은 동일한 q를 쓰고 Anchor를 바꾸지 않는다. 초기 셀은 420×6=2520, 300×6=1800으로 2400×1024 화면을 덮는다. 도착에서는 Position=Anchor, Scale=1이므로 원래 08씬 좌표가 정확히 복원된다.

위 셀 좌표는 2400×1024 가이드 재구성의 초기값이다. 실제 네이티브 셀 위치가 달라지면 도착 구도를 유지한 채 셀 중심으로 Anchor, 화면 중심으로 초기 Position, 셀의 화면 덮임을 만족하는 초기 Scale을 다시 계산한다. 변경 좌표와 확대→원위치 검증값을 기록한다.

F250~252는 2프레임 오버레이, F252~260은 8프레임 줌아웃, 합계 10프레임/0.333333초다. 모션블러 초기 검토값은 shutter angle 180도다. 가장 빠른 구간에는 블러가 생기고 F260 도착은 선명해야 한다. 실제 렌더에서 불연속·가장자리 노출·픽셀 확대·과도한 잔상을 확인한다.

양쪽 SHIFT 셀은 줌아웃과 F260~262 정착 중에는 움직이지 않는다. 결과 문구는 확대 시작부터 보이면 안 되며 아래 지정 시점에 등장한다. 별도의 07씬 썸네일, 카드 테두리·그림자, 셀 내용 교체 와이프, 레터박스, 또 다른 셔터 진입을 추가하지 않는다.

## 9. 08씬: 레일 가속 → 같은 프레임에서 정지 → 결과 문구

중앙 보라·파랑 면과 양쪽 레일 폭은 자동 차단 가이드를 따른다. 왼쪽은 위, 오른쪽은 아래로 이동한다. 검정·아이보리·주황 배경과 외곽선 SHIFT 문자를 한 셀로 묶어 함께 이동시킨다. 글자 따로, 색 따로 점멸시키지 않는다.

| F262~267 | 양쪽 반대 방향으로 14px/F. |

## 11. 실행과 검증 순서

사용자가 다른 작업을 할 수 있도록 화면 점유를 줄이되 품질 검증 수준은 유지한다. 타이포·키프레임·전환·3D 위치/회전·카메라·렌더 등 이미 가능한 작업은 MCP로 묶어 처리하고, 같은 품질의 렌더 이미지·MP4를 중심으로 검수한다. 필요한 상태 확인과 정상 속도 재생은 생략하지 않는다.

직접 화면 조작이 꼭 필요하면 먼저 알리고 짧게 진행한다. 영상 재질 메뉴에서 같은 실패가 반복되면 조기에 중단하고 필요한 단일 조작만 요청한다. 검증되지 않은 연결 경로를 작동한다고 가정하지 않는다. 이미 연결된 아이패드 재질은 유지한다. 직접 조작 구간을 기록하되 실측 없이 화면 점유 감소율을 주장하지 않는다. MCP도 같은 AE 인스턴스와 렌더 자원을 사용하므로 완전한 무간섭을 보장하지 않는다.

1. 현재 AE 버전·활성 프로젝트·소스 경로·입력 해시를 확인한다. 기존 작업은 Beta 27.0x43에서 제작됐지만 현재 실제 상태를 다시 읽는다. 필요 시 기존 ae-client.mjs의 Beta 대상 연결 설정을 참고하되 새 로그 위치를 쓴다.
2. 현재 AEP를 새 경로에 저장하고, 2절의 이전 보고서 대비 해시 차이를 기존 네이티브 기록·기준 MP4와 대조한다. 추가 전 동일 환경의 기준 프레임을 확보한다. 기존 제작 구간의 원본 파일과 입력 자산은 그대로 둔다.
3. CAT VILLAGE→06 연결, 06씬 제품·영상, 06→07 면 연결, 07씬 문구·배경, 08씬 전체 오버레이, 레일·정지를 순서대로 구성한다. 각 경계는 프레임 렌더로 확인하고 문제를 고친 뒤 전체 검토 렌더로 진행한다.
4. 새 AEP 저장 후 재열기하고 화면 재질·소스·폰트·프리컴프 시간·글자·표현식 평가·누락 파일을 다시 확인한다. 이전에 아이패드 재질의 마지막 선택이 사용자 조작을 필요로 했던 이력이 있으므로, 아이폰 재질도 실제 연결값과 재열기 렌더를 확인한다. 미연결 회색 화면을 숨겨 완료 처리하지 않는다.
5. F0~315의 MP4를 출력해 ffprobe와 전체 ffmpeg 디코딩으로 해상도·프레임수·fps·길이·무음을 확인한다. AEP 마스터 20초와 검토 출력 10.5초는 각각 검증한다.
6. 완성 MP4를 1배속으로 처음부터 끝까지 재생하고 실제 프레임·전환 시트를 확인한다. 정지 가이드의 미감과 움직임의 가독성·속도감을 각각 평가한다. 정지 프레임만 보고 모션이 자연스럽다고 단정하지 않는다.

## 12. 완료 전달

새 출력 폴더에 AEP, MP4, RESULT.ko.md, actual-timeline.json, verification.json, preset-usage.json과 필요한 qa/ 프레임·전환 시트를 남긴다. 결과 보고에는 변경 파일, 변경 내용, 검증 방법·결과, 보존 항목, 남은 실제 위험을 포함한다. 제작·기술 검증·사용자 승인 상태와 기준 대비 바뀐 세부값을 구분한다.

완료 시 부모 작업 “이미지와 영상 제작”(task id 01a084c3-735f-7fd2-8ef7-a044226bd7a3, host local)에 결과 파일의 절대 경로, 실측 10.5초/315프레임 여부, AEP 재열기·화면 재질 결과, 07→08의 실제 동작 대상, F279 정지 검증과 남은 문제를 전달한다. 이후 9.5초 제작, 사이트 적용·배포, 원본 삭제나 정리는 이번 작업에 포함하지 않는다.

## 작성 시점 확인 상태

입력 19개 경로·바이트·SHA-256, 관리 모델 해시·GLB 화면 구조, 아이폰 소스 프로브·선택 1.9초 디코딩·샘플 3장, 가이드 3장과 최신 프레임 설계를 확인했다. 현재 AEP와 과거 보고 해시의 차이는 발견·기록했으며 실제 콘텐츠 대조는 제작 작업의 첫 검증이다.
