# TITAN — 피드백 01 반영 및 3→4→5→6 모션 설계

최신 5→6 전환은 **6씬 전체를 확대해 5씬 위에 오버레이한 뒤, 6씬을 원래 크기·위치로 되돌리는 줌아웃**이다. 시작에는 6씬 왼쪽 상단의 SHIFT 한 칸이 화면 전체를 채우고, 빠져나오면서 6씬의 전체 구성이 드러난다. 확대·이동하는 대상은 6씬이며 5씬은 뒤에 고정한다.

현재 상태는 **4씬 가이드 수정 완료 + 구체적인 모션 설계 완료**다. 이 설계를 AE에 적용하거나 새 MP4를 렌더한 상태는 아니다.

## 적용 범위

- 피드백에 들어 있는 Core systems / Built in-house 이미지는 사용자가 확인한 **반복 금지의 예시**다. 기존 2씬 수정이나 새 5씬 문구 교체 지시로 해석하지 않는다.
- 새 5씬 문구는 Operations, / refined를 유지한다.
- 4씬의 반복된 왼쪽 커브는 [수정 가이드](results/04-sportsbook-no-repeated-arc-v002.png)에서 제거했다. 오른쪽 주황 경로는 장면 연결을 위해 유지한다.
- 6씬의 기본 구도는 모션이 좋아야 통과한다는 조건부 방향이다. 정지 이미지의 생성·파일 검수와 영상 미감 승인은 별개다.
- 기존 AEP, 기존 1·2·3씬 MP4와 이전 가이드 원본은 수정하지 않았다.

## 실제 3씬 끝 프레임과 연결

현재 MP4에서 [F170을 다시 추출](qa/actual-scene03-F170.png)해 확인했다. 실제 끝은 도트가 짧은 우하향 직선 끝에 멈춘 모습이며, 피드백 상단의 예상 연결 이미지와 같지 않다. 기존 제작 식에서도 마지막 경로가 베지어 접선 없는 점 연결임을 확인했다.

향후 AE 수정은 마지막 F164–170의 경로 끝부분으로 제한한다. (2040,750)에서 (2120,830)으로 가는 반지름 80의 90도 곡선을 만들고, 끝 접선이 수직 아래를 향하게 한다. 마지막 도트 좌표는 유지한다. 기존 아이패드 화면·타이포와 F0–163은 이 연결 수정의 대상이 아니다.

F171–180에는 위아래로 놓인 두 씬의 공통 컨테이너를 1024px 위로 이동한다. 보는 화면은 아래로 내려가고, 3씬은 위로 빠지며 4씬은 아래에서 들어온다. 도트와 선은 두 장면을 가로지르는 동일한 경로를 사용한다. 4씬에서 같은 커브가 새로 등장하거나 도트가 초기 위치로 돌아가면 안 된다.

30fps, 프레임 번호는 0부터 시작한다. 아래 구간의 끝 프레임은 제외한다.

4씬 57프레임 + 5씬 30프레임 + 6씬 57프레임 = **144프레임 / 4.8초**다. 기존 171프레임에 더하면 **315프레임 / 10.5초**다. 전체 기획은 600프레임 / 20초를 유지한다. 5→6 전환이 F258의 장면 경계를 가로지르지만 길이를 추가하지 않는다.

## 5→6 줌아웃의 정확한 구성

6씬의 배경·양쪽 SHIFT 레일·타이포를 모두 포함한 네이티브 프리컴프를 하나 만든다. 그 레이어를 5씬 위에 둔다. 6씬의 결과 문구는 지정한 등장 시간 전에는 숨긴다.

다음 값은 2400 × 1024 제작 캔버스의 초기 배치값이다. 실제 6씬을 재구성하면서 셀 좌표가 바뀌면 같은 계산식으로 갱신한다.

| 속성 | 확대 오버레이 상태 | 6씬 전체 도착 상태 |
| --- | --- | --- |
| 기준 SHIFT 칸 | x=0, y=55, width=420, height=300 | 동일한 6씬 내부 좌표 |
| Anchor Point | (210,205), 이후 고정 | (210,205) |
| Position | (1200,512) | (210,205) |
| Scale | (600%,600%) | (100%,100%) |
| Opacity | F250=0 → F252=100 | 100 |

- 420 × 300 셀을 6배 확대하면 2520 × 1800이므로 시작 화면 전체를 덮는다. 원래 5씬을 다른 비율의 칸에 끼워 넣는 계산은 필요 없다.
- 도착에서는 Position과 Anchor가 같고 Scale이 1이므로, 화면 좌표 = Position + Scale × (원래 좌표 − Anchor) = 원래 좌표다. 즉 6씬이 정확히 제 위치로 돌아온다.
- Scale과 Position은 **같은 진행률**로 움직인다. 중간에 Anchor를 바꾸거나 레일만 따로 이동하지 않는다.
- 오버레이 초기 2프레임에는 큰 SHIFT와 5씬의 내용이 잠깐 겹쳐 보인다. F252 이후에는 6씬이 완전히 덮고, 줌아웃하면서 전체 구도가 나타난다.
- 모션블러는 확대·이동의 최고 속도 구간에 생기도록 한다. 초기 검토값은 shutter angle 180도이며, 실제 렌더에서 블러 양과 정착 프레임의 선명도를 확인한다.
- 확대용 타이포와 도형은 네이티브 레이어로 만든다. 정지 가이드 PNG를 6배 키운 것을 완성 영상으로 사용하지 않는다.
- 현재 MCP 카탈로그에서 comp.precompose를 확인했다. 실제 프로젝트에서는 프리컴프 안의 시간·표현식 참조, 확대 시 선명도, 모션블러 전달을 별도로 검증해야 한다.

AE에서 프리컴프를 한 레이어로 다루는 구조는 [Adobe 공식 문서](https://helpx.adobe.com/after-effects/desktop/work-with-compositions/precomposing-and-nesting/precomposing-nesting-pre-rendering.html)를 기준으로 한다.

## 5씬 배경과 6씬 SHIFT의 구별

**5씬:** 내부 사각 테두리를 그리는 연출은 사용하지 않는다. 넓은 면 세 개가 서로 다른 방향에서 들어와 맞춰진다. 큰 외곽선 OPERATIONS의 위쪽 줄은 왼쪽으로 24px/프레임, 아래쪽 줄은 오른쪽으로 18px/프레임 움직인다. 단어와 간격을 포함한 한 주기를 복제해 빈 구간 없이 흐르게 한다. 전경의 두 문구는 배경보다 명확하게 읽힌다.

**6씬:** 세로로 이어진 색 면과 SHIFT 글자를 하나의 셀로 묶는다. 왼쪽은 위, 오른쪽은 아래로 움직인다. 색이 따로 점멸하지 않으며 검정·아이보리·주황 셀이 이동하면서 순서가 바뀐다.

속도는 F262–267에 14px/프레임, F267–273에 36px/프레임, F273–279에 60px/프레임이다. 누적 이동은 5×14 + 6×36 + 6×60 = 646px이다. F279에서 양쪽 위치를 동시에 홀드한다. 정지 위치를 맞춘다고 그 프레임에 새 셀로 점프시키지 말고, 초기 루프 위상을 역산한다. 차단 후에도 계속 흐르는 무한 스크롤은 사용하지 않는다.

## 프리셋과 공개 소스 사용 지시

효과 이름만 골라 넣지 않고, 아래 역할과 지정 프레임에 맞춰 조절한다. 아래는 **선정·적용 계획이며 아직 새 씬에 적용하지 않았다.**

| 대상 | 시작점으로 사용할 자료 | 조절할 내용 |
| --- | --- | --- |
| Operations, | Adobe Straight In By Word.ffx | 4프레임의 단어 진입. 최종 폰트·위치·문구를 유지. |
| refined | Adobe Stretch In Each Word.ffx | 짧은 가로 스트레치와 정렬. 불필요한 회전·반복 제거. |
| Sudden odds shift | aftr의 wordReveal 정의 | revealFrames=4, stagger=1로 기존 MCP의 네이티브 텍스트 애니메이터에 이식. |
| Bets | Adobe Scale In By Word.ffx | 한 단어의 118→100% 진입으로 수정. 탄성 반복 제거. |
| auto-blocked | 네이티브 마스크 공개 | 6프레임에 걸친 좌→우 공개. 글자별 산개 없음. |

위 Adobe .ffx의 로컬 파일 존재를 확인했다. 프리셋 적용 후 크기·위치가 제작 캔버스에 맞는지 확인하는 절차는 [Adobe 텍스트 애니메이션 문서](https://helpx.adobe.com/after-effects/desktop/animating-text/text-animation/animating-text.html)를 따른다. aftr의 [실제 텍스트 구현](https://github.com/Arman-Luthra/aftr/blob/628397d700d6282fe2be4d42f4a388392250947a/panel/jsx/commands/text.jsx)을 확인했으며, 새 컨트롤러 설치가 완료됐다고 가정하지 않는다.

## 확인한 것과 남은 것

- **확인:** 실제 기존 MP4의 F170, 기존 경로 식, 수정 4씬의 커브 제거·주 문구·폰 외곽, 생성 파일 PNG 1920×819 및 이동 전후 SHA-256 일치.
- **수치 확인:** 스크롤 중 도트의 화면 이탈 없음, 6씬 확대 레이어가 전환 내내 화면을 덮음, 100% 도착에서 원래 좌표 복원, 화면비 보존, 전체 프레임 수 유지.
- **미검증:** 실제 AE 이징·모션블러의 인상, 줌아웃 속도감, 1초 5씬의 가독성, F279 정지의 타격감. 수치 계산 통과를 영상 통과로 보지 않는다.
- **실제 화면:** 폰 안의 작은 글자·숫자는 생성 과정에서 바뀔 수 있으므로 제작 시 원본 아이폰 영상을 합성한다.
- **원본 보존:** 기존 AEP·MP4·이전 가이드·사용자 피드백 원본은 변경하지 않았다.
