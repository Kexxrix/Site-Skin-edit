# Titan Solution 이미지 제작 규칙

적용 범위: Site-Skin-edit의 Titan Solution 소개 페이지에 쓸 생성 이미지와 Grok 영상 제작용 첫 프레임·프롬프트. 현재 사용자 지시와 실제 페이지를 우선한다. 아래 기준은 다른 브랜드의 고정 스타일로 확대하지 않는다. 사진·영상 첫 프레임은 [장면 기획과 목적 검수](scene-intent-and-review.md)를 함께 적용한다.

## 사용자가 정한 조건

- 이미지와 영상에 사이트 UI의 주황색을 테마로 적용하지 않는다. 주황빛 조명·색보정·의상·소품으로 일관성을 만들지 않는다. 사이트의 기존 UI 색 변경은 이번 범위가 아니다.
- 어디에나 쓸 수 있는 스톡 사진 같은 장면을 피하고 Titan의 실제 소개 내용과 밀접한 장면을 만든다. 이는 현재 사진의 출처를 확인했다는 뜻은 아니다.
- 포트폴리오의 실제 게임 화면 원본은 보존한다. 정확한 표시가 필요한 작업은 캡처를 활용하고, 사용자가 원샷 생성·참조 재생성을 요청하면 그 경로로 시도한다. 생성된 UI를 원본과 동일한 복제라고 설명하지 않는다.
- 수량·언어·비율·영상 길이·사이트 적용 여부는 현재 요청에서 정한다. 초기의 ‘두 장’, ‘16:9’, ‘공통 공간’ 조건을 이후 작업에 자동 적용하지 않는다.
- 사진 자체의 매력과 완성도가 우선이다. 사이트의 어두운 배경에 맞춘다는 이유로 어둡고 밋밋한 사진을 만들지 않는다. 밝은 사진과 어두운 사진 모두 얼굴·행동·빛이 잘 읽히는지 실제 결과로 판단한다.

## 업무와 장면의 연결

현재 hero.tsx, platform.tsx, why-titan.tsx에서 확인한 것은 사이트의 서비스 설명이다. 실제 사무실 모습이나 직원의 신원은 제공되지 않았다. 생성 결과는 Titan용 연출 이미지이며 실제 촬영 기록으로 설명하지 않는다.

| 사이트에서 설명하는 업무 | 사용할 수 있는 장면 단서 |
| --- | --- |
| 카지노·슬롯 벤더 연동 | 엔지니어가 API 연결 흐름과 응답 상태를 점검하는 워크스테이션 |
| 스포츠북 운영·마켓 관리 | 운영자가 이벤트 목록과 모니터링 추이를 확인하는 상황 |
| 통합머니·정산 | 지갑 연결과 정산 흐름을 동료와 대조하는 작업 |
| 운영·개발팀 연결 | 동일 화면을 보며 문제 위치를 확인하는 구체적인 협업 동작 |

업무 장면을 요청하면 중심 업무와 그에 맞는 행동을 정한다. ‘기술담당자’, ‘CS’라는 직함만 붙이지 말고 검토·설명·응대 등 필요한 상황이 보이게 한다. 초상 자체가 요청된 경우에는 단독 인물사진도 가능하다. 화면·문서·장비는 해당 장면을 뒷받침해야 한다. 대규모 서버실이나 인력을 실제 회사 규모인 것처럼 설명하지 않는다.

연출 사진의 일반 코드 화면·시스템 스케치·업무 도식은 상황을 설명하는 단서로 사용할 수 있다. 실제 제품 UI, 고객 데이터, 거래 내역이나 검증된 실적으로 소개하지 않는다. 실제 화면을 요구한 경우에는 제공된 캡처와 보존 수준을 별도로 확인한다. 화면 방향 오류를 피한다는 이유로 모니터 뒷면만 보이게 고정하지 않는다.

## 시각적 맥락

- 사진 표현: 맞춤 기업 에디토리얼 사진. 자연스러운 원근, 읽히는 중간 명도, 현실적인 피부·원단·표면 질감.
- 현재 페이지 또는 사용자가 제공한 화면을 보고, 필요하면 생성 참조로 첨부한다. 사용 위치·브랜드·이미지 역할의 근거로 쓰며 특정 의상·벽색·조명을 고정하지 않는다.
- 사진별 공간·색·캐스팅은 현재 요청에 맞춘다. 사용자가 독립된 사진을 허용하면 동일 인물·공간·톤의 연속성을 강제하지 않되, 각 사진의 사용 목적은 유지한다.
- 브랜드 표식이 장면에 도움이 되면 정확한 `TITAN SOLUTION` 표기를 사용할 수 있다. 전면적인 ‘로고 금지’를 기본값으로 추가하지 않는다. 브랜드 표식만으로 장면의 설득력을 대신하지 않는다.

## 역할과 구도

- 영상 첫 프레임: 현재 페이지의 표시 영역과 현재 콘티를 먼저 확인한다. 넓은 PC의 약 2.34:1 영역과 21:9 생성 시험 이력이 있지만, 실제 목표 비율과 반응형 표시를 다시 확인한다. 첫 프레임에서 디자인과 메시지를 읽을 수 있게 구성하되 최종 편집의 시작점으로 고정하지 않는다. 의도적인 퇴장·가림을 허용하며, 재등장 후 정확한 문구와 필요한 제품 형태를 보존한다. Grok 영상은 아래 필수 편집 구조를 따른다.
- 오른쪽 정지 이미지: 세로 슬롯 안에서 얼굴·시선·행동에 필요한 단서가 읽히도록 한다. 기존 약 313×400px 및 좁은 화면의 크롭을 확인하되 원본 비율과 인원수를 고정하지 않는다. 실제 배치와 미감에 맞춰 선택한다.
- 이전 결과의 참조 사용 여부는 필요한 연속성과 품질을 보고 결정한다. 첫 결과가 부적합하면 그 구도·소재를 다음 이미지에 상속하지 않는다.

## 타이탄용 Grok 영상의 필수 편집 구조

2026-09-10 사용자 지정. 앞으로 제작하는 **타이탄용 Grok 영상에는 반드시 적용**한다. 다른 브랜드나 도구 전체의 공통 규칙으로 확대하지 않는다.

- **장면마다 독립된 디자인:** 배경색, 텍스트 외 도형·소재·배치와 모션 구성을 장면별로 다르게 설계한다. 기존 시험의 파란 리본·은색 링·유리 패널을 모든 장면의 고정 세트로 반복하지 않는다. 공통 전환 기법이 장면 디자인까지 같게 만드는 이유가 되어서는 안 된다.
- **완성된 첫 화면을 먼저 보여 줌:** 문구와 구성 요소가 원래 첫 이미지 상태로 보이는 구간을 잠깐 유지한 다음 퇴장·가림을 시작한다. 가려지거나 전환이 진행 중인 상태로 시작하지 않는다. 이 초기 상태는 디자인 참조이자 편집에서 버릴 수 있는 준비 구간이며, 유지 시간은 현재 프롬프트에서 정한다.
- **현재 채택한 기본 방식:** V3 실제 결과에 대해 사용자가 편집하기 더 편리하고 자연스럽다고 확인했다. 이후 타이탄용 Grok 제작은 원래 배경을 유지한 채 텍스트·도형이 화면 밖으로 나갔다 돌아오는 방식을 기본으로 삼는다. 별도의 가림 전환은 현재 장면의 사용자 지시에 따라 선택한다. 이 방식의 채택과 요소별 정밀 방향 제어 성공은 구분한다.
- **초반 퇴장 또는 전면 가림은 필수:** 현재 6초 클립에서는 초반 약 1~2초에 텍스트와 구성 요소를 화면 밖으로 완전히 내보내거나, 검정·흰색 등으로 화면 전체를 불투명하게 가리는 전환을 만든다. 단순 흑백 색보정이나 일부만 가리는 효과를 전면 가림으로 취급하지 않는다. 완전히 비워지거나 가려진 상태를 잠깐 확보해 편집 시작점을 만든다.
- **이후 재등장과 판독 구간:** 후반 약 4초에 문구·요소가 다시 등장하고 읽히는 과정을 구성한다. 초반의 퇴장·가림 구간을 제외한 뒤 후반부를 잘라 속도를 조절하고 다른 장면과 연결한다. 첫 프레임부터 끝까지 완성 문구만 유지하는 구조는 이 필수 조건을 충족하지 않는다.
- **실제 결과로 컷 선택:** 1~2초와 후반 4초는 설계 목표다. 무조건 정확히 2초에서 자르지 않고, 실제 생성본에서 완전 퇴장·전면 가림이 확인된 프레임을 시작점으로 선택한다. 이어지는 재등장, 정확한 문구 회복, 판독 시간과 사용할 연속 구간을 검수한다. 프롬프트 작성만으로 달성됐다고 기록하지 않는다.

이 규칙 지정 전의 시험 이미지·프롬프트·결과는 당시 기록으로 보존한다. 후속 제작에서는 이 규칙을 우선하며, 과거 프롬프트를 재사용할 때는 필수 구조를 반영한 새 버전으로 준비한다. 현재는 사용자가 정한 제작 요구이며 실제 완성 영상에서의 성공은 별도 검증 대상이다. 적용 경위는 [12초 타이포 구성안의 후속 기록](titan-type-story-20260910.md)을 참고한다.

### 다음 Grok 프롬프트 작성 시 참고할 실제 결과

[긴 정산 문구의 영상 검토](../../../../generated-images/titan-grok-partner-earnings-test-20260910-152728/qa/video-review-20260910/README.md)에서는 정확한 두 줄 문구와 입체 도형 모션을 확인했다. 그러나 본문이 중앙에 남은 채 앞에 글자 조각·잔상이 움직였고, 후반에도 링이 마지막 단어를 가렸다. 원래 본문이 실제로 움직였는지와 장식만 움직였는지를 구분한다. 다음에는 필수 가림·재등장 사건에 집중하고 판독 구간의 도형 경로를 분리하는 방향을 시험한다. 이는 다음 수정 제안이며, 같은 현상이 반복되지 않는다는 검증은 아직 없다.

[동일 이미지의 검정 가림 V2 후속 결과](../../../../generated-images/titan-grok-partner-earnings-test-20260910-152728/qa/video-review-wipe-v2-20260910/README.md)에서는 실제로 전체 화면이 0.875~2.291667초 완전 검정이 된 뒤 다시 나타났다. 핵심 편집 기법의 1개 성공 사례로 기록한다. 다만 하단 문구가 흩어지고 중복되며, 정확한 문구의 판독 후보는 약 4.25~6초로 늦어졌다. 가림 성공과 단일 블록 등장·충분한 판독 시간 확보를 별개로 검수한다. 링도 문구 아래에 완전히 분리되지 않았다. 정상 속도의 리듬·최종 편집·반복 재현성은 미검증이다.

후속 사용자 지적으로 V2가 완성된 첫 화면을 잠깐 유지하지 않고 바로 가림을 시작했다는 누락을 확인했다. 사용자는 이것이 모션 불안정의 단서일 수 있다고 제안했다. 원인으로 확정하지 않으며, [V3 프롬프트](../../../../generated-images/titan-grok-partner-earnings-test-20260910-152728/prompts/04-grok-partner-earnings-offscreen-v3.txt)는 같은 이미지를 먼저 보여 준 뒤 실제 텍스트·도형을 화면 밖으로 이동시켰다가 복귀시키도록 작성했다.

[V3 실제 결과와 사용자 채택](../../../../generated-images/titan-grok-partner-earnings-test-20260910-152728/qa/video-review-offscreen-v3-20260910/README.md)에서 문구·리본·링의 왼쪽 퇴장·복귀, 약 2.25초의 빈 배경과 후반 문구 회복을 확인했다. 사용자는 이 방식이 편집하기 더 편하고 자연스럽다고 평가했다. 앞으로의 기본 제작 방식으로 유지하되, 실제 결과의 시간·도형 변형·가림은 별도 검수한다. 공통 진입 방향 변경 → 요소 묶음별 방향 분리 → 개별 도형·제품/인물 이미지의 방향·각도 제어 순서로 후속 시험을 제안한다. 후속 시험은 아직 실행하지 않았으며 유리 패널의 정확한 경계 통과, 요소별 독립 방향, 반복 재현성도 미확인이다. 최종 영상 선택·12초 편집·사이트 적용은 이 승인에 포함되지 않는다.

이후 사용자는 위 단계별 제안 대신 난도를 높인 [V4 낱글자 낙하·자석 복귀 시험](../../../../generated-images/titan-grok-partner-earnings-test-20260910-152728/prompts/05-grok-partner-earnings-gravity-magnet-v4.txt)을 요청했다. 텍스트는 글자마다 독립적으로 아래로 떨어져 나갔다 원래 위치로 끌려오며, 도형은 반대로 위로 넓게 퍼져 나갔다 돌아오게 작성했다. 최신 요청에 따라 V3의 단일 블록 이동 제한은 이번 시험에 적용하지 않았다. 각 글자를 조각으로 부수는 것과 온전한 낱글자를 따로 움직이는 것은 구분한다.
