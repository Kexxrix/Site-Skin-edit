# 사진·광고 장면·영상 첫 프레임의 기획과 검수

사용자의 짧은 요청과 참조가 충분하면 그것을 생성 브리프의 중심으로 유지한다. 샘플 프롬프트의 세부 묘사를 많이 추가하는 것이 목표가 아니다. 프롬프트 길이나 생성 경로의 차이만으로 품질 차이의 원인을 단정하지 않는다.

이 절차가 바뀐 이유와 실제 확인 수준은 [사이트 이미지 누적 교훈](site-image-lessons.md)과 연결된 사례 이력에 기록한다. 후속 미감 제안을 이미 검증한 효과로 옮겨 적지 않는다.

## 원래 목적을 보존하기

- 이미지가 들어갈 곳, 전달할 인상, 필요한 주체·행동, 수량·형식을 먼저 확인한다. 사용자가 구체적으로 요청한 사건을 다른 장르로 바꾸지 않는다. 예를 들어 회의를 진행하는 장면을 회의가 끝난 뒤의 단독 초상으로 바꾸면 스타일 보강이 아니라 내용 변경이다.
- 인물의 신뢰감 자체가 목적이면 초상도 적절하다. 모든 이미지에 업무·장비·도식을 넣는 고정 공식을 만들지 않는다.
- 여러 업무 장면을 요청했다면 각 이미지의 역할을 구분한다. 얼굴·의상만 바꾸고 같은 행동을 반복하는 것은 역할의 다양성을 대신하지 못한다.
- 이전 피드백을 반영한 뒤에도 원래 목적을 다시 확인한다. 밝기·얼굴·구도 수정이 사용 위치와 전달하려는 내용을 지워서는 안 된다.

## 참조에 맡길 정보

기존 페이지용 이미지는 현재 페이지나 사용자가 준 화면을 실제로 본다. 사용 맥락이 중요한 참조는 이미지 생성에도 첨부하고 역할을 명시한다. 직접 제공받은 참조를 이유 없이 일반적인 텍스트 설명으로 축소하지 않는다.

| 참조 | 맡길 정보 | 자동으로 복제하지 않을 정보 |
| --- | --- | --- |
| 사이트 화면 | 사용 위치, 브랜드 표기, 정보 위계, 이미지의 역할 | 사이트 배경색을 사진의 의상·조명·배경 전체에 강제 |
| 마음에 든 사진 | 사용자가 좋아한 구도·빛·공간·행동 또는 표현력 | 요청하지 않은 동일 인물·동일 포즈·소품 |
| 실제 제품 화면 | 제품 내용과 배치, 필요한 정확한 표시 | 주변 사진의 구도나 모든 컷의 소재 |

‘각 이미지가 독립적이어도 된다’는 말은 공통 사용 맥락을 버리라는 뜻이 아니다. 반대로 사이트와 관계없는 독립 작품에 웹 화면을 필수로 요구하지 않는다. 참조가 여러 장이면 각 역할에 필요한 것만 선택한다.

## 프롬프트를 보강할 때

사용자의 브리프에서 출발해 해당 이미지의 중심 장면을 명확히 한다. 고품질·세련됨을 피부와 원단의 미세 묘사로만 치환하지 말고, 시선의 흐름·표정·제스처·공간의 깊이·빛과 초점으로 구현한다. 샘플은 해결하려는 문제에 필요한 부분만 가져온다.

- 새 금지조건에는 사용자 요구, 보존해야 할 자료, 실제 관찰된 결함 중 근거가 있어야 한다. 실제 제품 UI의 정확성 요구를 일반 코드 화면·업무 도식·브랜드 표식의 일괄 금지로 확대하지 않는다.
- 장비의 물리적 방향을 바로잡되, 항상 뒷면만 보이게 해서 필요한 업무 단서를 없애지 않는다. 기기 사용자와 카메라 양쪽에서 화면이 자연스럽게 보이는 구도를 선택할 수 있다.
- 나이·헤어·렌즈·소품·색상을 세밀하게 고정하는 것은 그 선택이 목적에 기여할 때 한다. 서로 다른 샘플의 좋은 표현을 무조건 누적하지 않는다.
- 프롬프트를 정리한 뒤 원래 요청과 비교한다. 핵심 사건이 빠지거나 필요 없는 제약이 추가됐다면 생성 전에 수정한다. 모든 작업에 동일한 줄 수·단어 수를 강제하지 않는다.

## 검수와 다음 행동

각 결과를 해당 작업에 맞춰 다음 항목으로 나누어 기록한다. 수치 점수의 평균으로 핵심 실패를 덮지 않는다.

1. **요청과 목적:** 실제 이미지에서 요청된 역할·사건·인상이 읽히는가. 파일 이름이나 설명문만으로 의미를 부여하지 않는다.
2. **사진 자체의 효과:** 구도·표정·빛·색·초점이 매력적인가. 비교 참조가 있으면 같은 표시 크기에서 구체적으로 비교한다. 피부나 손에 결함이 없다는 것만으로 충분하지 않다.
3. **배치 적합성:** 실제 크롭에서 얼굴뿐 아니라 장면을 설명하는 손·화면·보드 등의 필요한 단서가 남는가. 원본 사진의 품질과 사이트 색상 조화는 별도로 판단한다.
4. **기술·보존:** 파일·비율·수량·독립 출력, 기기 구조·해부학, 실제 자료와 정확한 문구의 보존 조건을 확인한다.

핵심 목적이 약하면 ‘파일 정상, 외형 검수 통과, 사용 목적 미달’로 남긴다. 사용자가 허용한 수정 범위에서 장면·구도·참조 또는 불필요한 제약 중 원인이 있는 부분을 고친다. 장면이 잘못됐는데 피부 수식어만 더하지 않는다. 위임된 수량은 완수하되 같은 결함의 무한 재생성은 기존 중단 규칙을 따른다.

원인 비교가 필요하면 목적·참조·비율·생성 경로를 가능한 한 같게 두고 문제되는 요소를 바꾼다. 조건이 여러 개 달랐던 비교는 가설로 남긴다. 문서 검증이나 과거 사례 재평가는 새 생성 품질이 향상됐다는 증명이 아니다.

## 영상 첫 프레임의 추가 기준

- 생성 전에 실제 표시 비율과 예정된 움직임을 확인한다. 16:9를 관성적으로 선택한 뒤 더 넓은 영역에서 잘림을 발견하는 순서를 피한다. 요청 비율과 도구가 반환한 실제 비율은 구분한다.
- 프레임은 전달할 메시지와 동작을 담는 시작점이다. 다른 컷을 같은 소재·구도의 제품 사진으로 반복해도 되는지 콘티의 역할과 함께 판단한다.
- 기기·문구의 여백은 예정된 이동·확대와 표시 크롭에 맞춰 검토한다. 프롬프트에 적힌 여백 비율이 실제로 지켜졌다고 가정하지 않는다. 현재 정지 화면에서 안 잘린다는 사실만으로 영상에서도 안전하다고 판단하지 않는다.
- 사용자가 요청한 원샷 생성은 먼저 그 범위에서 시도할 수 있다. 글자·UI의 정확성이나 기기 보존에 실패하면 그 지점에 한해 별도 합성·후편집을 검토한다. 처음부터 불필요한 분리 공정을 늘리지 않는다.
- 정지 이미지, 움직임을 가정한 표시 검수, 실제 생성 영상 검수는 다른 단계다. 실제 영상의 문구 이동·UI 변화·카메라 경로·정지 시점은 출력 파일로 확인한다. 프롬프트 수정만으로 해결됐다고 보고하지 않는다.
