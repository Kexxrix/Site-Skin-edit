# 사이트 이미지 제작: 누적 교훈과 적용 방법

기준일: 2026-09-10. 사진·광고 장면·영상 첫 프레임을 다른 사이트 컨셉에 맞춰 만들 때 같은 실수를 줄이기 위한 기록이다. 실행 절차는 [장면 기획과 목적 검수](scene-intent-and-review.md), 실제 문제와 수정의 시간순 근거는 [TITAN 작업 이력](titan-image-history-20260909-10.md)을 함께 참고한다.

TITAN의 결과를 모든 사이트의 스타일 규칙으로 바꾸지 않는다. 사용자 목적과 현재 자료가 먼저이며, 이 문서는 그 목적을 잃지 않게 하는 판단 근거다.

사이트 작업에서는 받은 명세와 맡은 범위를 먼저 읽고, 지정된 컨셉에 맞춰 이미지·영상·허용된 레이아웃 수정을 수행한다. 기존 테마 리소스 생성 방식은 이 과정에 필요한 제작 수단으로 사용한다. 이 문서의 역할은 실제 생성 방식과 개선 결과를 보존하고 다음 개선 방향을 판단할 근거를 제공하는 것이다.

## 1. 무엇이 문제였고 어떤 판단으로 바꿨는가

| 반복될 수 있는 문제 | 이번 작업에서 관찰한 사례 | 다음 작업의 판단 |
| --- | --- | --- |
| 사이트의 어두운 색을 사진의 필수 톤으로 적용 | 어두운 벽·의상·전경 모니터가 겹친 초기 사진을 사용자가 어둡고 밋밋하다고 평가 | 사진 자체의 목적과 매력을 먼저 본다. 사이트 배경색을 조명·의상 전체에 자동으로 옮기지 않는다 |
| 여러 표현 변화의 효과를 한 속성에 귀속 | 서양인으로 바꾼 컷이 더 자연스럽다는 피드백이 있었지만 헤어·수염·주근깨·표정 등도 함께 달라짐 | 캐스팅 집단 자체가 원인이라고 단정하지 않는다. 실제로 바뀐 얼굴 특징·빛·표정·구도를 분리해 기록한다 |
| 업무를 인물 외형으로 대체 | 기술 담당자 컷을 검토가 끝난 뒤의 단독 초상으로 구성해 업무 행동이 약해짐 | 사용자가 요청한 주체·사건을 먼저 보존한다. 초상이 목적일 때는 초상을 유지한다 |
| 목적보다 촬영 수식어를 늘림 | 얼굴·의상·빛을 자세히 쓰고도 역할이 불분명한 사진을 추천 | 부족한 것이 역할, 구도, 표현, 오류 중 무엇인지 먼저 정한다. 필요한 부분을 고치며 프롬프트 길이를 목표로 삼지 않는다 |
| 사이트 맥락을 첨부하지 않음 | 사이트용 사진인데 이미지 참조 없이 생성한 실행이 존재 | 중요한 사이트·사진·제품 참조를 실제로 보고 역할을 구분해 첨부한다. 파일명만 쓰는 것은 첨부가 아니다 |
| 참조의 주변 요소까지 반복 | 재생성 네 컷에서 유리 사무실·흑백 의상·표어·머그·식물 전경이 반복됨 | 연속성이 필요한 요소와 복제할 필요가 없는 요소를 분리한다. 반복이 실제 문제일 때 해당 요소를 줄이는 비교안을 검토한다 |
| 금지 조건의 범위를 과도하게 확대 | 실제 제품 UI 보호를 일반 코드·도식·로고의 일괄 금지로 확장 | 정확히 보존할 자료와 연출 가능한 업무 단서를 구분한다. 금지 조건에는 사용자 요구나 관찰된 문제의 근거가 있어야 한다 |
| 외형 정상을 목적 적합성으로 간주 | 물리적 결함이 없어도 역할 전달이 약한 연구 후보를 우선 추천 | 목적·시각적 효과·실제 배치·기술 상태를 따로 판단한다. 핵심 목적이 약하면 파일 검증 통과만으로 추천하지 않는다 |
| 역할 구분을 사진 완성도와 혼동 | 새 네 장은 업무가 구분됐지만 사용자가 여전히 부족함을 느낌 | 역할 전달을 확인한 뒤에도 주연의 크기, 표정·행동의 자연스러움, 배경 밀도, 컷별 변화가 충분한지 본다 |
| 원본만 보고 배치에 적합하다고 판단 | 좁은 슬롯의 중앙 크롭에서 개발 사진의 손끝·코드 일부가 잘림 | 실제 표시 크기에서 핵심 얼굴·손·도구의 연결을 확인한다. 단순 위치 조정으로 해결되면 원본 재생성보다 작은 수정을 먼저 한다 |
| 넓은 영상 슬롯에 관성적으로 16:9 사용 | 시작 프레임과 실제 약 2.34:1 표시 영역의 차이로 기기 잘림 문제가 발생 | 표시 비율과 예정된 이동·확대를 생성 전에 확인한다. 요구 비율과 실제 출력 치수를 구분한다 |
| 정지 프레임 안전을 영상 안전으로 간주 | 정지 이미지에서 보존된 기기와 문구가 줌·이동에 따라 달라짐 | 필요한 프레임 경계와 동작 여유를 함께 확인한다. 실제 생성 영상의 경로·문구·UI 변화는 출력으로 검수한다 |
| 프롬프트의 시간·고정을 달성 결과로 보고 | 4초 요청 결과가 약 6.04초, 정지 구간·문구 고정도 일부 불일치 | 프롬프트는 요청 기록이다. 길이·정지·움직임은 실제 파일로 확인하고 편집 계획과 완료 상태를 구분한다 |
| 생성·검수·적용·만족을 한 상태로 처리 | 로컬 적용 후에도 사용자가 미감 개선을 요청 | 사용자 선택의 범위를 기록한다. 시험 적용은 최종 미감 만족을 뜻하지 않으며, 후속 피드백을 별도 이력으로 덧붙인다 |

이 표는 관찰된 문제에 대한 판단 변경이다. 모든 수정의 효과가 단일 변수 비교로 입증된 것은 아니다. 구체적인 검증 수준은 사례 이력을 따른다.

## 2. 다음 컨셉으로 가져갈 원칙과 가져가지 않을 설정

| 가져갈 원칙 | 새 작업에서 다시 정할 값 |
| --- | --- |
| 이미지가 전달할 사건과 인상을 먼저 정함 | 개발·상담 등 업무 종류, 제품·인물·풍경 중 주체, 인원과 캐스팅 |
| 페이지가 시각적 사용 맥락을 제공함 | 사이트 색, 사진의 색조·밝기, 사진과 UI의 관계 |
| 역할별 참조를 실제 첨부함 | 사용할 파일, 상속할 구도·빛·인물·제품 정보 |
| 실제 슬롯과 움직임 안에서 주연·도구를 보존함 | 4:5·21:9 등 비율, 화면 크기, 카메라 이동, CSS 정렬 |
| 정확한 문구와 실제 제품 자료의 보존 범위를 확인함 | 언어, 문구, 원샷 생성 또는 별도 합성 방식 |
| 사용자 지시와 실제 도구 출력을 구분함 | 생성 장수, 영상 길이, 편집 길이와 사용할 구간 |
| 현재 저장 규칙과 충돌을 먼저 확인함 | 프로젝트 출력 폴더, 파일명, 복사·이동 방식 |

TITAN의 동양계 인물 네 장, 검정·흰 의상, 주황색 사진 테마 배제, 312.5×400px 슬롯, 20%·70% 정렬, 영문 문구, 6초 생성 후 4초씩 사용하는 계획은 해당 사례의 조건이다. 다른 사이트의 기본값으로 쓰지 않는다. 업무 사진의 교훈을 작가 소개 초상이나 제품 사진에 적용해 불필요한 동료·도구·회의를 추가하지 않는다.

## 3. 다음 작업에서의 사용 순서

### 생성 전

- 해당 사이트의 지침·제작 의뢰서에서 납품물, 변경 가능한 범위, 보존할 기능과 담당 구분을 확인한다. 원문 명세와 이후 사용자 변경 지시를 구분해 현재 유효한 요구를 기록한다.
- 현재 요청의 사용 위치, 전달할 인상, 주체와 행동, 장수·독립 출력, 실제 표시 영역을 확인한다.
- 참조마다 맡길 정보와 상속하지 않을 요소를 정한다. 독립적인 사진을 요청해도 사용 맥락을 버리지 않는다.
- 프롬프트를 사용자 원문과 대조한다. 장면을 다른 사건으로 바꾸거나, 근거 없는 제약을 늘리지 않았는지 확인한다.
- 영상 첫 프레임이면 비율·동작·문구 계획까지 포함한다. 연출 UI와 정확한 원본 복제를 같은 것으로 취급하지 않는다.

### 생성 후

- 실제 파일 수·형식·치수와 독립 이미지를 확인하고, 원본을 보존한다.
- 파일 이름을 보지 않아도 역할이 읽히는지, 사진 자체가 매력적인지, 실제 크롭에서 핵심 행동이 남는지 각각 본다.
- 미달한 축에 맞춰 수정한다. 장면 자체가 약하면 행동·참조·구도를, 배치에서만 잘리면 정렬·프레이밍을 검토한다.
- 비교가 필요하면 나머지 조건을 가능한 한 유지한다. 여러 조건을 함께 바꿨다면 어느 하나의 효과라고 단정하지 않는다.
- 사이트 적용이 요청됐으면 실제 로드된 자산과 전환·반응형 표시를 확인한다. 저장·빌드 성공만으로 적용 완료를 선언하지 않는다.

### 피드백을 받은 후

기존 실행의 프롬프트와 결과를 덮어쓰지 않는다. [검토 기록 양식](../assets/generation-review.template.md)에 관찰 → 수정 또는 제안 → 확인한 결과 → 남은 문제를 추가하고 관련 실행·파일을 연결한다. `run.json`은 파일·참조·상태를, 검토 기록은 판단이 바뀐 이유를 담당한다. 같은 내용을 길게 중복하지 않는다.

다음 개선안을 정할 때는 관련 사례의 생성 방식·수정 이유·실제 결과를 읽고, 현재 작업과 같은 조건 및 다른 조건을 확인한다. 선택한 개선 방향에는 근거와 확인할 항목을 남기고, 실행 뒤 확인한 결과를 다시 이력에 추가한다. 과거 기록만으로 새 사이트의 결과를 미리 합격 처리하지 않는다.

## 4. 확인된 효과와 아직 시험하지 않은 방향

TITAN에서 실제로 확인한 것은 네 업무 장면의 구분, 일부 크롭 문제의 정렬 조정, 와이드 출력과 표시 보존, 파일·로컬 적용의 일치다. 프롬프트 길이나 생성 경로에 따른 보편적인 품질 우열은 확인하지 않았다.

2026-09-10의 추가 미감 제안은 주연과 핵심 도구를 더 가까이 담기, 전형적인 제스처를 실제 작업 순간으로 바꾸기, 반복 표어·브랜드 소품의 존재감을 낮추기다. 당시 적용 원본과 작은 슬롯을 보고 제안했으며, 이 방향의 새 비교 이미지나 영상은 아직 생성하지 않았다. 이를 검증된 해법이나 모든 장면의 필수 제한으로 사용하지 않는다.

## 5. 기록 상태의 의미

- **관찰 확인:** 실제 이미지·영상·페이지·파일 기록에서 본 사실. 판단 근거와 확인 범위를 연결한다.
- **수정 후 확인:** 수정이 실행됐고 관련 결과를 확인함. 통과한 항목과 남은 불일치를 함께 쓴다.
- **사용자 선택·적용:** 사용자가 선택하거나 적용을 요청한 범위. 미감에 관한 최종 만족과 구분한다.
- **제안·미검증:** 아직 실행하지 않았거나 결과를 확인하지 않은 개선 방향.
- **원인 추정:** 여러 변수가 달라 인과관계를 분리하지 못한 설명.

문서 구조 검사나 검토자의 동의는 새 이미지의 개선 효과를 입증하지 않는다. 다른 사이트에서 사용한 뒤에는 그 사이트의 입력·결과·피드백으로 이력을 이어간다.
